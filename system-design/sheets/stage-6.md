從需求與數字出發，同步路徑只放顧客在等的事，其餘交給 outbox；每個機制單獨看都對，組起來還要決定誰包住誰。[回 系統設計 學習地圖](../index.html)

## A 先把需求改寫成可以量測的目標 {span=2}
| 老闆說的 | 可以量測的目標 |
|---|---|
| 結帳要快 | 尖峰時段，下單 API 的 p99 小於 500ms |
| 不能掛 | 每 30 天可用性 99.9%（停機預算約 43.2 分鐘） |
| 不能多扣錢 | 同一張訂單最多扣款 1 次 |
| 不能賣超過庫存 | 預留庫存成功才付款；付款失敗要釋放 |
| 點數不用馬上到 | 付款成功後 1 分鐘內入帳 |
| 做好要通知 | 訂單狀態 5 秒內推送到 App |

第 1 課寫的是 p99 小於 300ms，這裡變成 500ms：需求會在討論中改變，改了就要更新估算、SLO、設計文件這些依賴它的地方。

## B 架構：顧客在等的只有同步路徑
```flow TB
App -> nginx -> *[API 多台：限流、冪等]
*[API 多台：限流、冪等] -> [(PostgreSQL)]
*[API 多台：限流、冪等] -> [Redis 軟相依]
*[API 多台：限流、冪等] -> [金流閘道 硬相依]: 逾時、重試、斷路器
[(PostgreSQL)] --> [outbox relay]
[outbox relay] --> [佇列]
[佇列] --> 廚房 & 集點 & 通知
```
只在金流這一層重試。SSE 推送只是通知，訂單的真實狀態以 API 為準。

## C 組起來的順序 {span=2}
```flow LR
(限流) -> 冪等 -> 驗證 -> 下單
下單 -> [隔艙] -> deadline -> 重試 -> *斷路器 -> [單次呼叫金流]
```
| 決定 | 放錯會怎樣 |
|---|---|
| 限流放在冪等之前 | 失控的 App 每次重送都打到冪等鍵表，資料庫先倒 |
| 驗證失敗不保存冪等結果 | 修好內容用同一把 key 重送，永遠被回放 400 或判成 422 |
| 重試在外、斷路器在內，同一把冪等鍵 | 斷路器太晚打開；換 key 就是重複扣款 |
| 付款是 pivot | 確認失敗就釋放庫存：錢收了、咖啡沒了 |
| 狀態和事件在同一個交易 | 廚房永遠收不到單 |
| 只推送投影真的改變的狀態 | App 從「做好了」跳回「已付款」 |

重試會吃掉 p99；剩下的時間不夠再呼叫一次就不要送。

## D 逾時代表結果未知
```flow TB
(付款逾時) -> {結果確定了?}
{結果確定了?} -> [往前或補償]: 是
{結果確定了?} -> *[needs-attention]: 否
*[needs-attention] -> [對帳：用同一把冪等鍵向金流查詢]
```
```callout err 不要把逾時當成失敗
逾時的付款可能已經扣款，直接取消訂單就是「扣了錢、沒有咖啡」。pivot 之後只能往前，做不完交給人。
```

## E 故障模式：每個依賴壞掉時
| 依賴 | 系統怎麼做 | 告警 |
|---|---|---|
| PostgreSQL primary | 切到 replica；期間下單回 503 加 Retry-After，菜單照常 | no 立刻呼叫值班 |
| Redis | 限流 fail open 加本機粗略限流；菜單讀資料庫並限制並發 | warn 告警，不用半夜叫人 |
| 金流變慢 | 重試受 deadline 限制；斷路器打開、快速失敗；隔艙保護其他 API | no 立刻呼叫值班並通知廠商 |
| 佇列或 relay | 事件留在 outbox，恢復後補送，消費者冪等 | warn outbox 最老一筆超過 1 分鐘 |
| SSE 連線 | Last-Event-ID 重連，補不了就 reset | warn 重連率異常升高 |

軟相依壞了要能降級，硬相依壞了要快速失敗並告警。

## F 上線準備度與放量
| 檢查點 | 問自己 |
|---|---|
| 容量與 N+1 | 週年慶尖峰壞一台還撐得住嗎？ |
| 尾延遲與逾時 | 逾時從下游 p99 算出來？deadline 有往下傳嗎？ |
| 冪等與重試 | 被重試的操作都冪等嗎？只在一層重試嗎？ |
| saga | 補償也失敗呢？結果未知的付款誰去對帳？ |
| 旗標與回滾 | 出事時幾分鐘內能關掉新功能？ |

清單對照全課程逐項審查，答不出來的寫進設計文件。上線時用 `online-ordering` 旗標逐步放量，每一步看下單 API 的 RED、付款成功率、斷路器狀態、outbox 年齡。每個訊號事先定好超過多少就回滾。

```callout info 止血手段事先做好、演練過
旗標調回上一個百分比或關掉；kill switch 暫停推薦、行銷活動頁；金流出事時降級成到店付款，只在事故期間開。
```
