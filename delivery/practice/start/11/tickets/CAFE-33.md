# CAFE-33：修正重複發放的點數

- 提出：會計（美玲）
- 優先序：P2（重複發放已經停止，要在月底結算點數前處理完）

CAFE-35 修好之前，webhook 重送會讓同一張訂單加兩次（偶爾三次）點數，正式環境這樣跑了兩週。
`data/prod-snapshot.sql` 是 11/8 早上匯出的正式資料（只有顧客、訂單、點數，名稱已去識別化）。

店長的決定（11/9 會議）：

1. 同一張訂單的 `order_paid` 只能算一筆。第二筆以後是重複的，要扣回。
2. `manual` 是店員手動補的點數（例如客人說沒拿到點數），就算金額、訂單跟 `order_paid` 一樣，也不是重複，不要動。
3. 已經把多的點數兌換掉的顧客不追討：如果扣回全部重複點數之後，這位顧客的點數會變成負的，這位顧客的重複點數**全部先不扣**，列給店長，由店長個別聯繫。
4. 所有紀錄都要留著，會計要能查到「哪一筆被誰、哪一次修復扣回」。不可以刪除或修改原本的紀錄。

執行方式（維運：建國）：

- 先跑試跑（dry-run），把 `plan.json` 的數字貼到這張單上，店長和會計確認後才正式執行。
- 正式執行在晚上離峰時段，分批做；中途被中斷要能接著做。
- 執行完用核對查詢確認；出問題要能撤回這一次執行。

plan.json 的欄位：

- `duplicates`：重複的紀錄有幾筆（包含不扣回的顧客）
- `affectedCustomers`：有重複紀錄的顧客有幾位（包含不扣回的顧客）
- `totalPoints`：這次會扣回的點數合計（正數，不包含不扣回的顧客）
- `skipCustomers`：不扣回、要由店長聯繫的顧客 id，由小到大
