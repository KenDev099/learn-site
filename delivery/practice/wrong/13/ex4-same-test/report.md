# CAFE-50 驗收報告

## 範圍

- API：POST /orders/:id/cancel（要登入）。paid 的訂單改成 cancelled、CafePay 全額退款（Idempotency-Key 是 refund:<訂單 id>）、點數寫 order_cancelled 補償紀錄、釋放取餐時段
- 畫面：訂單頁的「取消訂單」按鈕（只在 paid 時出現）、原生 dialog 確認、取消後顯示「已取消，款項將退回」、409 時顯示原因
- 測試：api/src/orders/orders.cancel.spec.ts（npm test）
- 不做：未付款訂單自動作廢（CAFE-51）、部分退款、POS 退款流程

每一條驗收條件（acceptance-cafe50.json 的 id）對到一個測試名稱：npm test 裡真的有、而且通過的 it(…)，名稱一字不差。

| AC3 | AC1 付好款、還沒開始製作：本人取消成功，全額退款、扣回點數、釋放時段 |

## 已知限制

- 退款結果不明（CafePay 逾時）時，訂單已經是 cancelled、付款留在 paid，要等顧客再按一次取消才會用同一把 key 重試；還沒有排程自動補退款（建議開單：reconcile 一併處理 cancelled 但付款仍是 paid 的訂單）
- 點數已經在櫃台兌換掉的顧客，扣回後點數可能變成負數；店長同意先這樣，之後再定規則
