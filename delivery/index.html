實戰：咖啡店產品交付 學習地圖

前面每一門課各自教一種技術，期末專題也都從零開始做。真實的工作不是這樣：你接手的是別人寫了兩年、文件過時、測試會亂紅、還有幾個沒人敢碰的地方的系統；需求單寫得含糊，bug 回報沒有重現步驟，CI 在你一推上去就紅了，同事的 PR 等你審，正式資料裡躺著過去的 bug 留下的錯帳。這門課讓你在同一個咖啡店點餐系統（Vue 3 前台、NestJS 12 API、Prisma 7＋PostgreSQL、BullMQ 背景工作）上，像在團隊裡一樣連續交付 13 張工作單。

這門課不重教理論。每一課開頭列出會用到的課（例如「NestJS 課第 15 課：交易與並發」），只在需要時用幾句話複習，重點放在判斷：證據夠不夠、先做哪一步、怎麼改才不會弄壞線上、怎麼證明做完了。故事是連續的：第 3 課做的預約取餐，第 4 課要讓舊版前端也能用，第 8 課的付款 bug 留下的重複點數，第 9 課要修正式資料；每一課的起始程式就是前一課的標準答案。

判分在你自己的 Mac 上跑：功能用 Vitest＋supertest 打真的 API 與資料庫、用 Playwright 開 Chrome 走完整個畫面流程；PR 說明、review 意見、事故報告這類文件也要寫成固定格式，測試會拿去和程式庫裡的實際檔案、log、資料比對，空泛的文字過不了。先備（每課開頭列出確切課號）：NestJS、Vue、工程實務第 1–8、10 課、部署與維運（第 10、14–17、21–22、24–25 課）、系統設計（第 2–3、8–9、11–13、16、19–21 課）、認證與資安（第 7、17、19、21 課），以及 PostgreSQL、Node、TypeScript 課的少數幾課；不需要 Kubernetes、API 風格、資料儲存（Redis 基本用法 NestJS 課已教）、AI 課。

這門課的練習都在同一個既有專案 delivery/practice 裡進行：每一課是一張工作單，在本機跑起來、修改、執行檢查。題目會寫清楚指令。
