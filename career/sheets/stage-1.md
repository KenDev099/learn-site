公司怕錄取錯人，所以每一關都要主動拿出證據。履歷寫成可以被追問的影響力句子；作品要幾分鐘看得懂、照 README 跑得起來。[回 面試與職涯 學習地圖](../index.html)

## A 每一關在檢查什麼 {span=2}
| 關卡 | 時間與誰 | 主要訊號 | 常見的淘汰原因 |
|---|---|---|---|
| 履歷篩選 | HR 或主管，幾十秒 | 具體成果與數字；條件對得上 | no 只寫職責 |
| HR 電話 | HR，15～30 分鐘 | 動機與條件對得上 | no 期望薪資差太多、說不出為什麼想來 |
| 技術概念問答 | 工程師或技術主管，口頭 20～40 分鐘；也可能是面試前的線上筆試（選擇題、簡答、SQL） | 說得出原因與取捨：資料庫、交易與鎖、JWT、API 設計、資料表設計 | no 從定義背起、不會的硬編 |
| 線上測驗 | 自動判分，60～90 分鐘 | 結果正確、處理邊界 | no 沒處理空輸入、超時 |
| 帶回家作業 | 自己在家，數小時到數天 | 有測試、知道做什麼不做什麼 | no 沒測試、沒 README、做了沒要求的功能 |
| 現場寫程式 | 1～2 位工程師，45～60 分鐘 | 邊寫邊說、先把題目問清楚 | no 全程沉默、沒問清楚就寫 |
| 系統設計 | 資深工程師，45～60 分鐘 | 說得出取捨、會估算量級 | no 直接畫架構圖、沒有數字 |
| 行為面試 | 主管或跨部門，30～60 分鐘 | 過去實際怎麼做事 | no 只講「我們」、講假設不講實例 |
| 主管面 | 未來的直屬主管 | 成果、判斷力、動機 | no 對職缺沒興趣、問不出問題 |
| team match | 不同團隊的主管 | 和團隊對得上 | warn 面試通過也可能停在這裡 |

漏斗把便宜、粗略的關卡放前面，昂貴、精細的放後面。答案正確只是一部分；履歷、HR 電話、行為面試、主管面、team match 都不寫程式，要準備的是故事、數字和問題。本土公司與中階職缺最常見的技術關卡是概念問答（答法在第 5 課）；資深職缺常在系統設計和行為面試決定結果。

## B 讀 JD、問 HR
```kv cols=1
必要條件: 每一條對到證據：做過的事、連結、數字。「看過」「上過課」不算
值得投嗎: 必要條件最多缺一項、其他證據很強就投；缺兩項以上先補
年資: 多半是參考值；用證據說明，接受可能被定在較低職級，不能灌水
轉職定位: 從前端轉後端是換職能，年資不會整包帶過去；先瞄準全端或中階後端，資深後端看正式環境經歷，作品補不了
前端經驗: 翻成後端在意的事：串 API 的錯誤格式與狀態碼、重複送出與並發、先量測再優化、測試習慣
用作品補缺口: 交易與並發、測試、部署維運、把取捨寫下來；一律標明是個人練習專案
職級可能低一級: HR 電話就問職級與範圍；請公司把「到職 6 個月依職級標準重新評估」寫進書面；先算好底線，低於就不接
HR 電話要問: 關卡與時程、職級、薪資範圍、工作方式（遠端、加班、on-call）、團隊
期望薪資: 給有依據的範圍（市場資料與目前總報酬），並反問這個職缺的預算
```
缺的必要條件，就是接下來要補的東西。

## C 要投幾家、怎麼追蹤 {span=2}
```flow LR
saved -> applied: apply
applied -> screen: pass
screen -> interviewing: pass
interviewing -> offer: pass
offer -> *accepted: accept
offer -> declined: decline
```
applied、screen、interviewing、offer 收到 reject 變成 rejected（offer 被撤回也算）；saved、applied、screen、interviewing 收到 withdraw（你主動退出）變成 withdrawn。accepted、declined、rejected、withdrawn 是終點。

這課的示範比率：履歷加 HR 電話 30%、技術面 50%、最後一關 50%、拿到 offer 80%，相乘是每投一家平均 0.06 個 offer；要 2 個 offer 就是 33.3，無條件進位成 34 家。比率先換成整數千分比再算，避開小數誤差；投了 10 家以上就改用自己的紀錄。

```callout warn 讓 offer 同時出現
把面試集中在 2～3 週：流程慢的（外商）先投、快的（新創）晚投。每一關寫紀錄：公司通常不會告訴你被拒絕的原因。
```

## D 影響力句子：動作＋範圍＋結果
```flow TB
[動作：具體動詞開頭] -> [範圍：哪個系統、多大規模]
[範圍：哪個系統、多大規模] -> *[結果：從多少到多少]
```
| 版本 | 句子 |
|---|---|
| no 職責 | 負責訂單 API |
| warn 動作 | 用 NestJS 重寫訂單 API |
| ok 影響力 | 用 NestJS 重寫咖啡店訂單 API（日均 2 萬筆），p95 延遲從 800 ms 降到 180 ms，逾時客訴約減少 40% |

用設計、重寫、導入、遷移、降低、自動化開頭；不用負責、參與、協助、熟悉、處理開頭。資深的句子寫範圍更大的改變：系統、決策、帶人、跨團隊。

## E 沒有營收數字時找什麼數字
| 類別 | 可以寫的數字 |
|---|---|
| 效能 | p95／p99 延遲、吞吐量 |
| 可靠性 | 錯誤率、可用性、事故次數 |
| 交付速度 | 部署時間、部署頻率、CI 時間 |
| 成本與人力 | 主機費用、節省的工時 |
| 規模 | 處理量、資料量、使用者數 |
| 品質 | 測試案例數、覆蓋率、線上 bug 數 |

說「降低、提升」就寫出基準，0 也是基準。估計值寫「約」，並說得出怎麼估。每一條都要能被追問 10 分鐘：怎麼量的、你做了哪部分、為什麼這樣做。練習專案標明是練習專案。

## F 篇幅、ATS 與個資
- 維護一份主清單，投遞時依 JD 關鍵字挑選、排序；初階 1 頁，資深 1～2 頁。中英文各寫一份，英文版用動詞開頭、不寫 I。
- 技能區只列能被問的。
- ATS 會把 PDF 解析成文字：單欄、文字可以選取、標準標題、技術名詞照 JD 的拼法。

| 資料 | 履歷上 |
|---|---|
| 身分證字號 | no 錄取後辦到職才需要 |
| 完整住址 | no 寫到縣市和區 |
| 出生日期、婚姻狀況 | no 跟工作無關 |
| 手機號碼 | warn 自己決定 |
| 前公司未公開的數字 | no 改用量級或比例 |

## G 作品：面試官怎麼看、README 寫什麼 {span=2}
```flow LR
[README 前 20 行] -> 快速開始 -> 資料夾結構 -> 測試 -> [commit 歷史] -> [面試時深問一個設計決定]
```
每一步都可能是最後一步。作品集放 2～3 個對應目標職缺、能被追問 30 分鐘的專案；期末專題加上你自己的延伸、真實數字，並標明是學習專案與你的角色。

| 段落 | 回答的問題 | 常見的錯 |
|---|---|---|
| 簡介 | 這是什麼、你做了哪部分、是不是學習專案 | 只有專案名稱 |
| 架構 | 有哪些元件、資料怎麼流 | 只列技術名詞，沒有圖 |
| 快速開始 | 怎麼在自己電腦跑起來，3 步以內 | 少了 `.env.example`、依賴你電腦上才有的東西 |
| 測試 | 怎麼跑、測了什麼 | 寫了但跑不過 |
| 設計決定 | 決定、替代方案、理由 | 只寫「使用 Redis」 |
| 已知限制 | 哪裡不夠、下一步 | 不寫，假裝完美 |

個人頁 README 要同時符合：repo 名稱與帳號相同、public、根目錄有 README.md、有內容。釘選最多 6 個，放最好的 2～3 個。不放公司的程式碼。資深的作品展示判斷：為什麼不用、為什麼選、測試策略、流量變 10 倍先改哪裡。

## H 公開前檢查與機密外洩
| 要找的東西 | 處理 |
|---|---|
| `.env`、`.env.production` | no 加進 .gitignore；只提交 `.env.example` |
| 寫死在程式裡的金鑰 | no 改從環境變數讀 |
| 私鑰檔（.pem、id_rsa） | no 永遠不進 Git |
| `node_modules/`、`dist/` | warn 安裝與建置的產物，加進 .gitignore |
| 資料庫備份 | no 改用 seed 程式產生假資料 |
| 測試資料裡的個資 | no 換成假資料 |

```callout err 機密 push 過就當作外洩
再 commit 一次刪掉沒用，舊 commit 裡還在；改成 private 也不能取代輪替，已被複製走的金鑰仍然有效。順序：先輪替並撤銷金鑰 → 查紀錄 → 用 git filter-repo 清歷史 → 預防。
```
