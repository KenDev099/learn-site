## A 求職包：一張事實表、六個步驟 {span=2}
```flow LR
*[(事實表)] -> [1 缺口分析]
[1 缺口分析] -> [2 履歷] -> [3 作品] -> [4 故事庫] -> [5 系統設計計畫] -> [6 offer 與一年計畫]
```
目標是虛構的「豆香咖啡｜全端工程師（後端為主，中階）」，對象是從前端轉職的人（前端 4 年、沒有後端正式經歷）。履歷上的每一個數字都要能在事實表找到。同一件事出現在故事、作品 README 時，數字也要一樣：面試官會交叉比對，數字不一致比沒有數字更傷。Learn 的專題寫明是練習專案，不混進工作經歷。

## B 缺口分析
| 必要條件 | 證據 | 強度 |
|---|---|---|
| TypeScript | 工作 4 年；TypeScript 課期末專題 | ok 強 |
| Vue | 工作 4 年；Vue 課期末專題 | ok 強 |
| NestJS | NestJS 課期末專題（個人練習專案） | warn 中 |
| PostgreSQL | 期末專題的交易與條件更新；交易與鎖的練習 | warn 中 |
| REST API 設計 | 工作上和後端訂 OpenAPI 規格；期末專題的 API 與文件 | warn 中 |
| 2 年以上後端開發經驗 | 沒有後端的正式經歷；Learn 的作品不能充當年資 | no 缺 |

缺 1 項（後端年資），可以投，JD 自己寫了「有相關作品可討論」。每個證據寫出出處。

```callout err 缺口不能補成假的
三種處理：用相近的真實經驗回應（和後端訂 API 規格、處理重複送出事故）並說清楚範圍；用作品證明做得到並標明是練習專案；寫進一年計畫（第一季交付第一個後端功能）。把前端 4 年寫成「全端 4 年」，第一個追問「上線後多少人在用、怎麼值班」就答不出來。
```

## C 履歷、作品、故事庫對著 JD
- 履歷：主清單照第 2 課規則寫，用 tailor 依 JD 關鍵字選句子；keywords 照實填，跟後端職缺無關的成果不會被選，這是對的。
- 作品：NestJS 專題談交易、佇列、快取；DevOps 專題談容量、不可變映像、備份與還原。兩張卡寫同一組決定，等於只有一個作品。作品專案課（製作中）的多租戶 SaaS 後台完成後，會取代訂單 API 成為第一張卡。公開前跑 auditRepo，只動有問題的檔案，`.env.example` 留著。

| JD 的描述 | 能力 | 準備的故事 |
|---|---|---|
| 和產品一起規劃 | 衝突 | 集點功能的範圍協商 |
| 熟悉後參與值班 | 失敗 | 結帳頁重複送出事故 |
| 協助新進同事上手 | 帶人 | onboarding：第一個 PR 從 10 天縮到 4 天 |
| 2 年以上後端開發經驗 | 主導 | 第一次改後端程式；再加一個作品的除錯故事 |

最弱的證據（後端年資）最需要準備好的故事：面試官一定會問「你為什麼覺得自己做得來後端」。中階職缺常把系統設計改成概念問答，仍準備到完整程度。

## D 系統設計：咖啡外送即時追蹤 {span=2}
```flow LR
[外送員 App] -> [API 伺服器]: 每 5 秒
[API 伺服器] -> [最新位置快取]: 覆蓋
[API 伺服器] -> [位置寫入佇列]: 軌跡
[位置寫入佇列] -> [(PostgreSQL)]: worker 批次寫入
[最新位置快取] -> *[推送閘道]: 有更新就通知
[推送閘道] -> [顧客瀏覽器]: SSE
```
| 這題給的數字 | 估算 |
|---|---|
| 直接算 | 3,000 筆配送中 × 每 5 秒一次 = 每秒 600 次寫入 |
| 用 estimate 交叉檢查 | 30 萬人 × 100 次 → 平均 348、尖峰 1,044、尖峰寫入 627 |
| 軌跡保存 30 天 | 約 54 GB |

兩種算法同一個量級。顧客只需要最新位置，所以最新位置放 Redis、軌跡進佇列批次寫入。只需要伺服器往顧客單向推，SSE 就夠。長連線一定會斷：EventSource 會自動重連，帶 `Last-Event-ID` 讓伺服器補送最新位置；外送員離線時畫面標示「位置更新中斷」。

## E Offer：看時間軸，不看第一年
| | 豆香咖啡 | 快送豆 |
|---|---|---|
| 月薪 × 保障月數 | 72,000 × 14 | 70,000 × 14 |
| 預期績效獎金 | 1 個月 | 0 |
| 簽約金 | 0 | 200,000，未滿 1 年全額退回 |
| 第一年 | 1,080,000 | 1,180,000 |
| 穩定年度 | 1,080,000 | 980,000 |
| 勞退提繳估計（另列，不加進總額） | 51,840 | 50,400 |

兩個都是轉職者實際會拿到的條件：職級中階、月薪和現在的前端差不多。第一年快送豆多 10 萬；從第二年起豆香每年多 10 萬，兩年累計追平（2,160,000 對 2,160,000），第三年起豆香領先；所以用穩定年度比較。決定前問清楚 on-call、職級重新評估的時間、技術債，以及有沒有資深後端帶你、PR 有沒有 code review。權重先寫下再算；決定和排名不同時，寫出「排名不同的原因」。

## F 一年成長計畫
```kv cols=1
容量: 這課的示範：40 小時扣 8 小時會議、20% 中斷、on-call 週打 7 折、只承諾 80%，得到 14 小時
學習時數: 取容量的 25%：14 × 25% = 3.5，四捨五入是每週 4 小時；用最緊的 on-call 週來算
為什麼是這個: 對到缺口（後端年資）或職缺條件（AWS、系統設計）
從哪裡學: 每季至少連到一課 Learn；之外寫 external: 加主題
怎麼算完成: 別人看得到的產出：repo、文章、內部分享、被合併的 PR
```
```callout ok 可以檢查的計畫
目標是一年後能獨立負責一個功能，從規格到上線與值班。四季順序通常是：交付第一個完整的後端功能，把缺口變成正式經歷 → 值班與效能 → 補加分條件 → 主導一個功能的設計。「學會 AWS」沒辦法檢查；「用 OpenTofu 把作品部署到 AWS，repo 公開、README 通過第 3 課的檢查」可以。求職包是活的文件：每季更新事實表、故事庫與計畫。
```
