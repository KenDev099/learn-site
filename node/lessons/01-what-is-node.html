階段 1：Node 與開發環境 · 第 1 課

Node 是什麼：在瀏覽器外跑 JavaScript

你寫的 Vue 程式跑在使用者的瀏覽器裡：畫面、按鈕、表單驗證，都發生在使用者自己的電腦上。咖啡店還有另一類工作不能放在那裡：訂單要存起來、庫存要扣、收據要寄出去。這些事要在一台一直開著、由店家掌控的電腦上做，那台電腦上的程式就是後端。這門課用 Node.js 寫後端，語言還是你熟悉的 JavaScript／TypeScript。

這課從一件小事開始。店長把菜單存成店裡電腦上的 data/menu.json，想要一支程式讀這個檔案，印出最便宜的品項：最便宜：可頌 70 元。用寫 Vue 的方式，你會發現寫不出來。整課就是把這支程式做出來（練習 3 的 cheapest.ts）：先弄清楚為什麼瀏覽器做不到、Node 為什麼做得到，再學怎麼在終端機執行它、它和瀏覽器差在哪、該裝哪一版，最後照課程的流程動手寫、讓測試判分。

這課的路線：
  1. 瀏覽器裡的 JavaScript 為什麼讀不到菜單檔、Node 為什麼可以：語言一樣，差在執行環境給的能力。後端為什麼常用 Node，它不擅長什麼。
  2. 程式要在哪裡執行：終端機和工作目錄，為什麼同一個指令換個資料夾就找不到檔案。
  3. 怎麼用 node 執行 .ts、讀進菜單檔；程式跑完就結束，後端伺服器怎麼一直開著。
  4. 從前端搬來的程式碼為什麼會 ReferenceError；該裝哪一版 Node，查文件時怎麼判斷一個 API 能不能放心用。
  5. 這門課的練習流程：改檔、跑 check.mjs 判分，把店長的程式和另外兩支小程式做完。
這課會用到：
  • TypeScript 課第 25 課的 import／export：一個檔案用 export 交出名字，另一個檔案用 import 拿來用。
  • TypeScript 課第 9 課的 async／await：await 等 Promise 完成才往下走。
  • TypeScript 課第 4 課的 throw／try/catch：遇到不合理的輸入就丟出錯誤中止，由呼叫端的 catch 接住；catch 到的錯誤型別是 unknown，要先檢查再用（第 17 課）。

瀏覽器裡的 JavaScript，為什麼讀不到電腦上的菜單檔？

先用你熟悉的方式想：在 Vue 元件裡寫一行「讀出 data/menu.json」。你會找不到這樣的 API。網頁可以用 fetch 向伺服器要資料，也可以讓使用者自己用檔案選擇框挑一個檔案交給網頁，但網頁不能自己去翻電腦硬碟上的任意檔案。這是瀏覽器刻意的限制：你打開的每個網頁都是別人寫的程式，如果網頁能隨意讀寫檔案，逛一個網站就可能把你電腦裡的資料全部讀走。

這帶出這一課最重要的觀念：JavaScript 這個語言本身只定義了變數、函式、物件、Promise 這些東西，沒有「讀檔案」的能力，也沒有「畫按鈕」的能力。你天天用的 document.querySelector、localStorage 不是語言的一部分，是瀏覽器另外提供給 JavaScript 用的。

讓一段程式跑起來的整套環境，包含執行程式碼的引擎，和環境另外提供的 API，叫做執行環境（runtime）。同一份 JavaScript 放進不同的執行環境，能做的事就不一樣，因為每個環境依自己的工作決定要給什麼能力：

  • 瀏覽器給你 DOM（document）、window、localStorage，因為它的工作是顯示網頁；它同時要保護使用者的電腦，所以不給你任意讀檔。
  • Node 給你讀寫檔案、收送網路資料、管理程序這些能力，因為它的工作是在一台電腦上跑程式，要跑什麼由那台電腦的主人決定。一支程式被執行起來，作業系統裡就多了一個正在跑的實例，叫程序（process）；同一支程式執行兩次就是兩個程序。

Node.js 就是一個執行環境。它不是新的語言，語法和你在瀏覽器裡寫的完全一樣；它也不是框架。框架是規定程式該怎麼組織的函式庫，例如這門課之後會學的 NestJS，它是建在 Node 上面的。

Node 和瀏覽器的關係，從它們的組成看最清楚。真正把 JavaScript 程式碼變成電腦能執行的指令的部分叫引擎。Chrome 用的引擎叫 V8，負責把 JavaScript 編譯成機器碼執行。Node 直接拿 V8 來用，所以同一段 JavaScript 在 Chrome 和 Node 裡跑出來的結果一樣，差別全在引擎外面包了什麼。

Node 在 V8 外面加的東西，都跟「和外界交換資料」有關。程式和外界交換資料的動作，例如讀檔、透過網路收送資料、等計時器到期、把文字印到螢幕上，統稱 I/O（input/output）。V8 只會執行 JavaScript，不會做 I/O，所以 Node 加了兩樣東西：

  • libuv：Node 底層的一個 C 函式庫，專門替 Node 跟作業系統打交道，處理檔案、網路、計時器這些 I/O。第 7 課詳講。
  • 內建模組（core module）：Node 自帶、不用安裝的模組，用 node: 開頭引入，例如 node:fs（讀寫檔案）、node:http（開 HTTP 伺服器）。你寫的程式透過這些模組使用 libuv 的能力。

所以店長那支程式的答案是：不放在瀏覽器裡跑，交給 Node 執行，用 node:fs 讀進菜單檔。不過「Node 能讀檔」不代表「後端就該用 Node」。咖啡店的後端將來要扛訂單、會員、報表，下一節看 Node 適合哪些工作、不適合哪些。

後端為什麼常用 Node？它不擅長什麼？

判斷一個工具適不適合，要先看工作本身長什麼樣子。一個「查菜單」的請求進到後端：程式送一條查詢給資料庫，資料庫在另一台機器上找資料、透過網路傳回來。這段時間後端程式自己什麼都沒做，只是在等。等資料庫回答、等另一個服務回應、等檔案讀完，這些 I/O 佔了後端程式大部分的時間。

Node 的設計正好針對這種「大多在等」的工作。要看懂它，先認識一個名詞：執行緒（thread）是作業系統裡實際一行一行執行程式碼的單位，一條執行緒同一時間只能做一件事。Node 的三個特點都跟它有關：

  • 一條執行緒：你寫的 JavaScript 都在同一條執行緒上跑，一次只做一件事。好處是不用處理「兩段程式同時改同一個變數」的問題；在多條執行緒同時跑的語言裡，這要另外加鎖來防止，寫錯就會出現很難重現的 bug。
  • 非阻塞 I/O（non-blocking I/O）：「阻塞」指程式停在原地，等某件事做完才往下走。只有一條執行緒，如果每次讀檔、查資料庫都停下來等，一個請求在等的時候，其他請求就全部排隊。Node 的做法是發出讀檔或網路請求之後不呆等，交給 libuv 去處理，執行緒先去處理別的請求，結果回來再接著做。所以一個 Node 程序可以同時「等」上千個請求。第 7 課會講它怎麼做到。
  • 前後端同一種語言：型別、驗證邏輯可以共用，也能直接用 npm 上的套件，前端團隊也看得懂後端的程式。

同一個設計也決定了它不擅長什麼。長時間的 CPU 運算，例如壓縮大檔、算報表，不是在「等」，而是那條唯一的執行緒一直在算。算的期間它沒辦法處理任何其他請求，所有使用者一起卡住。第 9 課教你怎麼避開。

其他常見的後端技術各有不同的取捨。下面這張表不是要你現在學它們，而是建立判斷力：

常見的後端選擇強項代價

選技術時要看工作是「等 I/O」還是「算東西」，以及團隊會什麼，沒有哪一個永遠最好。

💡 實務上：選後端技術先看工作內容和團隊，不是看流行
咖啡店後台的 API 大多在等資料庫：查菜單、寫訂單、查會員點數，這種工作用 Node 很合適，前端團隊也能直接接手。但「每晚把整個月的訂單算成營收報表」「把上傳的商品照片縮圖」這類吃 CPU 的工作，就要另外規劃，不能直接塞在處理請求的那個程序裡。公司已經有一套穩定的 Java 或 Go 系統時，不會為了「大家都用 JS」整個重寫。資深工程師提技術選型前會先問：主要的工作是等 I/O 還是算東西？團隊誰會維護？出事時誰看得懂？

程式要在哪裡執行？終端機與工作目錄

決定用 Node 之後，下一個問題很實際：店長的程式要怎麼啟動？後端程式沒有畫面可以點，要在終端機（terminal）裡用指令執行。終端機是一個輸入文字指令的視窗，你在 Vue 專案裡執行 npm run dev 的那個視窗就是。負責解讀你輸入的指令、把它交給對應程式的那個程式叫 shell，macOS 預設是 zsh。在 VS Code 按 Ctrl+`（反引號）就能打開內建的終端機。

終端機永遠「站在」某個資料夾裡，這個資料夾叫工作目錄（current working directory，cwd）。它決定了路徑怎麼解讀：

  • 相對路徑（relative path）從工作目錄開始算。寫 data/menu.json，意思是「從我現在站的資料夾往下找 data 資料夾裡的 menu.json」。
  • 絕對路徑（absolute path）從根目錄 / 開始寫完整，例如 /Users/you/Desktop/ME/learn，在哪裡執行都指向同一個地方。

這對店長的程式很重要：它要讀 data/menu.json，這個相對路徑是從工作目錄算的。站在 work/01 裡執行，Node 會去找 work/01/data/menu.json，找得到；站在 learn/ 執行同一個指令，Node 會去找 learn/data/menu.json，那裡沒有這個檔案，程式就失敗。程式碼一個字都沒改，結果卻不一樣，差別只在你站在哪裡。

移動和查看工作目錄用這幾個指令：

怎麼用 node 執行程式、讀進菜單檔？

這門課以 Node 24 為準（這台電腦是 v24.22.1），為什麼是這一版，在後面「該裝哪一版 Node」一節說明。先確認裝好了，再看執行程式的幾種方式：

$ node --version
v24.22.1
$ node hello.ts 小明         # 執行一個檔案，後面可以接參數
$ node --watch hello.ts 小明 # 存檔就自動重跑，改程式時很方便
$ node                       # 不給檔名：進入 REPL，打一行執行一行，輸入 .exit 離開
  • node 檔名 是最基本的用法。檔名後面接的 小明 叫命令列參數，程式讀得到它，放在 process.argv[2]，後面講 ReferenceError 的那一節會講怎麼讀。店長的程式就是靠參數知道要讀哪個菜單檔：node cheapest.ts data/menu.json。
  • --watch 讓 Node 盯著檔案，一存檔就重新執行，效果類似你在前端習慣的存檔就重新整理。
  • REPL（Read-Eval-Print Loop）是互動模式：讀一行、執行、印出結果、再等下一行，適合試一小段 JavaScript。REPL 只吃 JavaScript，打 const a: number = 1 會出現語法錯誤。

TypeScript 檔為什麼能直接執行？

這門課的練習檔都是 .ts，但 V8 只認得 JavaScript。TypeScript 課第 13 課講過，TypeScript 做兩件事：檢查型別，以及把型別擦掉、變回普通的 JavaScript。在 Vue 專案裡，這兩件事有編輯器和建置工具替你做掉，你不太會意識到。

Node 24 只做第二件：執行 .ts 時先把型別標註刪掉，剩下的 JavaScript 再交給 V8 執行，這叫擦掉型別（type stripping）。它不檢查型別，所以型別寫錯照樣執行：

const price: number = '110'   // 型別錯了
console.log(price + 10)       // node 照樣執行，印出 11010

擦掉 : number 之後，剩下的是 const price = '110'。price 在執行時是字串，+ 10 變成字串串接，印出 11010。編輯器會在這行畫紅線，但 Node 不管。型別檢查要另外跑 tsc，第 5 課詳講。這項功能從哪一版開始預設開啟、哪一版變成穩定，細節見課末。

店長的程式只有一個檔案，但程式一變大就會拆檔。練習 2 的收據程式就是這樣：receipt.ts 要從 price.ts 拿 lineTotal，從 orders.ts 拿訂單和它的型別。檔案之間互相 import 時，「只擦掉型別」帶來兩條規則，不照做程式根本跑不起來：

  • import 自己的檔案要寫 .ts 副檔名：import { lineTotal } from './price.ts'。Node 照你寫的路徑去找檔案，不會幫你猜副檔名；寫成 './price' 會得到 ERR_MODULE_NOT_FOUND。
  • 只引入型別要寫 import type：import type { OrderLine } from './orders.ts'。型別在執行時已經被擦掉，orders.ts 執行起來根本沒有 OrderLine 這個東西；不寫 type，Node 會去找這個匯出，然後找不到。寫了 import type，整行會跟著型別一起被擦掉。

讀進菜單檔

能執行 .ts 之後，就可以寫店長程式的核心：讀檔。node:fs/promises 的 readFile 會回傳 Promise，讀檔是 I/O，要等它完成才拿得到內容，所以要 await。

平常 await 要寫在 async function 裡面。這個練習資料夾的 package.json 寫了 "type": "module"，所以每個 .ts 都是 ES module，也就是用 import／export 的模組格式（第 4 課詳講）。ES module 可以把 await 直接寫在檔案最外層，這叫頂層 await（top-level await）。練習 3 就這樣讀檔：

import { readFile } from 'node:fs/promises'
const text = await readFile('data/menu.json', 'utf8')   // 讀完才往下走
console.log(JSON.parse(text).length)                     // 6

readFile 讀進來的是一整段文字，JSON.parse 把它變成陣列，.length 是 6，代表菜單上有 6 個品項。接下來只要在陣列裡找出價格最低的那一個，店長的程式就完成了。頂層 await 也有代價，第 4 課會講。

注意 'data/menu.json' 是相對路徑，而 readFile 的相對路徑是從工作目錄算，不是從程式檔所在的資料夾算。這就是上一節講的：要在 work/01 裡執行。

程式跑完就結束，後端怎麼一直開著？

店長的程式讀檔、印出結果，然後就結束了。這種程式叫命令列工具，執行一次做一件事。咖啡店真正的後端不能這樣：點餐 App 隨時可能送訂單過來，後端必須一直開著等。這種一直開著、等別人連進來的程式叫伺服器（server）。

一台電腦上可以同時跑好幾個伺服器，別人連進來時要指明找哪一個，這個號碼叫 port，像總機的分機號碼。同一個 port 同時只能有一個程式在聽。第 12 課和第 13 課會從頭講 HTTP，現在先看一個最小的伺服器跑起來：

$ node examples/hello-server.ts
伺服器已啟動：http://localhost:3000（按 Ctrl+C 停止）
收到請求： GET /
收到請求： GET /favicon.ico

用瀏覽器打開 http://localhost:3000 會看到「☕ 歡迎光臨咖啡店！」。注意三件事：

  • 終端機停住了：這不是當機，伺服器正在等請求，所以程式不會自己結束。這正是它和店長那支程式的差別。按 Ctrl+C 停止。
  • 瀏覽器多送了一個請求：/favicon.ico 是瀏覽器自己去要分頁的小圖示。
  • port 會被佔用：同一個 port 已經有程式在聽，就會出現 Error: listen EADDRINUSE: address already in use :::5000，例如在這台 Mac 上用 5000，就會撞到 macOS 的 AirPlay 接收器。這不是程式寫錯，是要換 port 或關掉佔用的程式。範例預設用 3000；要換就執行 PORT=3001 node examples/hello-server.ts。這台 Mac 上哪些 port 已經被佔用，見課末。

不管是讀菜單的小程式還是伺服器，都是在 Node 上跑你寫的 JavaScript。從前端轉過來，最容易踩的坑是把瀏覽器裡用慣的東西直接帶過來。

從前端搬來的程式碼，為什麼在 Node 會 ReferenceError？

假設店長的程式寫好後，你想把前端專案裡現成的「印收據」函式搬過來共用，省得重寫。那個函式裡有一行用 document.querySelector('h1') 讀頁面上的店名。一在 Node 執行，就得到 ReferenceError: document is not defined。

原因要回到第一節：哪些東西能直接用，是執行環境決定的。不用 import 就能直接用的名字叫全域物件，例如瀏覽器的 window、document。Node 也有自己的一組全域物件，但和瀏覽器只有部分重疊。在練習資料夾執行 node examples/globals.ts 可以自己確認，它用 typeof 一個一個檢查，typeof 一個不存在的名字會得到 'undefined'，不會出錯。這台 v24.22.1 的結果：

名字瀏覽器Node 24說明
window、document有沒有沒有網頁，就沒有 DOM
localStorage有沒有資料要存在檔案或資料庫
globalThis有有兩邊都指向全域物件
fetch、setTimeout、crypto有有Node 也實作了這些 Web 標準 API
navigator有部分只有少數欄位，例如 CPU 核心數
process、Buffer、setImmediate沒有有Node 專屬：程序資訊、位元組、事件迴圈
require、__dirname沒有ES module 裡沒有改用 import 和 import.meta.dirname（第 4 課）

所以在 Node 執行 document.querySelector('h1')，錯誤不是「找不到 h1」，而是 document 這個名字根本不存在：這裡沒有網頁。在瀏覽器裡找不到元素會回傳 null，那是「有 document，但頁面上沒有 h1」，兩件事不一樣。

反過來，Node 專屬的全域物件裡，這課要用的是 process。它代表目前這個程序，也就是正在執行的這支程式，這課用到它的兩個屬性：

  • process.argv：執行程式時的參數陣列。執行 node hello.ts 小明 時，process.argv[0] 是 node 的路徑、[1] 是 hello.ts 的路徑、[2] 才是 '小明'。沒給參數時 [2] 是 undefined。店長的程式執行 node cheapest.ts data/menu.json，菜單路徑就在 process.argv[2]。第 2 課詳講。
  • process.version：目前 Node 的版本字串，例如 'v24.22.1'。練習 1 要用它印出版本，不要寫死。
💡 實務上：前後端共用的程式不能碰瀏覽器專屬的東西
前後端同一種語言的好處，是能把「訂單金額計算」「Email 格式驗證」寫成一份共用。代價是這份程式一用到 window、document、localStorage，拿到 Node 執行就會丟 ReferenceError，就像上面那個印收據的函式。做 Nuxt、Next.js 這類伺服器端渲染（SSR）的專案時，常見的錯誤就是頁面在伺服器上渲染時出現 window is not defined。共用的程式只放純計算和 fetch、crypto 這類兩邊都有的 API；要存取瀏覽器的部分，留在前端那一層。

該裝哪一版 Node？查文件時怎麼判斷 API 能不能放心用？

上一節 process.version 印出 v24.22.1。打開 Node 官網，你會看到不只一個版本可以下載，而且同一個 API 在不同版本可能行為不同。後端程式要在正式環境跑好幾年，選錯版本的代價比前端大得多，所以先搞懂版本怎麼發布。

到 Node 26 為止，Node 每年 4 月和 10 月各發一個主版本。新版先當 Current：最新版，給想先試新功能的人。LTS（Long Term Support，長期支援）是官方承諾長期修 bug 和安全問題的版本，它會依序走過這幾個階段：

階段意思Node 24「Krypton」Node 26「Lithium」
Current剛發布，還在加功能2025-05-06 起2026-05-05 起
Active LTS修 bug、安全問題，也會帶進新功能2025-10-28 起2026-10-28 起
Maintenance LTS只修重大 bug 和安全問題2026-10-20 起2027-10-20 起
終止支援（EOL）不再有任何修正，有漏洞也不補2028-04-302029-04-30

到 Node 26 為止，只有偶數主版本會進 LTS，奇數版（例如 25）只當大約半年的 Current 就停止支援。之後的版本規則有變，見課末。

知道這些階段，就能照資深工程師的做法選版本：

  • 正式環境只用 LTS。看到新的主版本不急著升，先確認用到的套件支援它，再跑完整的測試。
  • 新專案選 Active LTS：2026-11 是 Node 26（2026-10-28 進 Active LTS，2026-11 查證時最新是 v26.13.1），支援期最長。本課程用 Node 24（已進 Maintenance LTS），是因為練習的驗證環境鎖在 24。
  • 用版本管理工具：nvm 或 fnm 能在同一台電腦裝好幾個 Node 版本，進到不同專案就切換。專案根目錄放一個 .nvmrc（內容只有一行，例如 24），兩個工具都看得懂；package.json 的 engines 欄位也能寫專案要的版本（第 3 課）。

選定版本之後，查 API 一律看對應版本的官方文件：https://nodejs.org/docs/latest-v24.x/api/。看 Node 26 的文件寫 Node 24 的程式，可能用到 24 還沒有的功能。每個 API 旁邊標有穩定性等級（stability index），代表官方對它的承諾，決定你能不能放心把它放進正式環境：

等級意思正式環境
0 Deprecated（已棄用）可能印出警告，不保證相容換掉
1 Experimental（實驗中）不受版本號規則保護，任何版本都可能改掉或移除。再分 1.0 早期開發、1.1 開發中、1.2 候選不要依賴
2 Stable（穩定）以相容為最優先可以用
3 Legacy（舊版保留）不會移除，但不再積極維護，有更好的替代品新程式改用替代品

文件裡還有 History 表，列出每個功能在哪一版加入、哪一版改變。兩者一起看，就能回答「這個 API 在我的版本上有沒有、能不能放心用」。課末補充裡 type stripping 的版本資訊，就是從 TypeScript 那一頁的 History 和 Stability 查到的。

💡 實務上：接手專案時，先確認 Node 版本在哪裡被決定
CI 是程式推上 GitHub 後自動跑測試的流程；Dockerfile 是描述部署環境的設定檔。「我電腦上可以跑，部署就壞掉」常見的原因之一，是開發機、CI 和正式環境裝的 Node 主版本不一樣。CI、Dockerfile 和 .nvmrc、package.json 的 engines 都會寫到 Node 版本，接手專案時先把它們找出來，確認寫的是同一個主版本。如果正在用的版本快要 EOL 了，要先排進待辦、預留時間做升級和測試，不要等漏洞出現才緊急處理。排進待辦時跟 PM 說清楚要花多少時間、要重測哪些功能，升級才不會被當成「沒產出的工作」一延再延。

怎麼動手做，又怎麼知道自己做對了？

到這裡，店長那支程式需要的東西都講過了：交給 Node 執行、站對工作目錄、用 process.argv[2] 拿路徑、用 readFile 讀檔。這課的練習就是把它和另外兩支小程式寫出來。練習在你自己的電腦上做，由測試程式判分。資料夾長這樣：

learn/
  check.mjs                 ← 在 learn/ 執行它來跑測試
  node/practice/
    package.json            ← 練習需要的套件清單
    start/01/               ← 起始檔（不要改這裡）
    work/01/                ← 你的練習檔：第一次跑測試時從 start/01 複製過來
      hello.ts  price.ts  receipt.ts  cheapest.ts  …
      ex1.test.ts …         ← 測試檔，每次跑都換成最新的；不用改，但可以打開看要求
      examples/             ← 這一課內文提到的範例
    results/01.json         ← 測試結果，課程頁讀這個檔判分
  1. 第一次：在 learn/node/practice 執行 npm install，下載練習需要的套件（第 3 課詳講）。
  2. 回到 learn/ 執行 node check.mjs node 01：第一次會建立 work/01/，然後跑測試，這時候每一題都還沒過，是正常的。
  3. 用 VS Code 打開 work/01/ 裡的檔案，照題目改好、存檔，再執行一次 node check.mjs node 01。
  4. 切回課程頁（要用 http://localhost:8000 開，不要用 127.0.0.1，不然讀不到進度），每一題下面會顯示哪些測試過了、沒過的原因。

注意兩個工作目錄：check.mjs 要站在 learn/ 執行；自己試跑練習檔（例如 node cheapest.ts data/menu.json）要站在 work/01 執行，相對路徑才找得到檔案。

改壞了想重來：刪掉 work/01/ 裡那個檔案，再跑一次 check.mjs，它只會補回不見的檔案，你改過的其他檔案不會被蓋掉。

測試看的是行為：印出來的內容、結束碼、函式的回傳值，不是比對你的程式碼長得跟答案一不一樣。測試會用隨機的名字和資料，所以把結果寫死過不了；店長的程式也一樣，測試每次給不同的菜單檔。

練習

練習 1：改好 hello.ts，執行 node hello.ts 小明 時印出 ☕ 小明，歡迎光臨！（Node v24.22.1）；沒給名字時印出 ☕ 歡迎光臨！（Node v24.22.1）。名字用 process.argv[2]，版本用 process.version（不要寫死版本號），整個程式只能印這一行。可以先在 work/01 裡自己執行 node hello.ts 小明 看看結果。

練習 2：在 price.ts 匯出 lineTotal(price, qty)，回傳小計 price × qty；qty 不是正整數（0、-1、1.5）時 throw new RangeError(…)，不要回傳 NaN 讓錯誤一路傳下去（throw 和 Error 在 TypeScript 課第 4 課）。接著讓 receipt.ts 用 import 引入 lineTotal，照 orders.ts 的訂單印出收據：每一行 拿鐵 ×2 = 220，最後一行 合計 300。測試會換一張訂單、也會換掉 lineTotal 來確認你真的有用它。

練習 3：完成 cheapest.ts：執行 node cheapest.ts data/menu.json 時，用 node:fs/promises 的 readFile(path, 'utf8') 讀進參數指定的菜單，JSON.parse 之後印出 最便宜：可頌 70 元。檔案不存在時，用 console.error 印出 找不到菜單：<路徑>，並設定 process.exitCode = 1。只有「檔案不存在」要這樣處理；其他錯誤（例如 JSON 格式壞掉）不能說成「找不到」，要照樣丟出去。

怎麼分辨：readFile 找不到檔案時丟出的錯誤有一個 code 屬性，值是 'ENOENT'（Error NO ENTry，找不到這個檔案或資料夾；第 10 課會整理常見的錯誤碼）。catch (err) 的 err 型別是 unknown，先用 err instanceof Error && 'code' in err 確認它有 code，再比對值；不是 ENOENT 就 throw err。

console.error 印到 stderr（標準錯誤輸出），和 console.log 的 stdout（標準輸出）是兩條不同的管道，讓別的程式能把正常結果和錯誤訊息分開。結束碼（exit code）是程式結束時交給呼叫者的數字，0 代表成功，其他代表失敗。第 2 課會詳講這兩件事。測試每次給不同的菜單檔，所以要讀參數指定的路徑，不能直接 import 起始的 data/menu.json。

練習 4：「Node.js 是一種新的程式語言」這句話對嗎？

✓ Node 是執行環境（runtime）。語言和瀏覽器裡的 JavaScript 一樣，差別在環境提供的 API：Node 有 node:fs、process，沒有 DOM。它也不是框架，框架（例如之後的 NestJS）是建立在 Node 上面、規定程式怎麼組織的函式庫。

練習 5：在 Node 裡執行 document.querySelector('h1') 會怎樣？

✓ document 是瀏覽器為網頁提供的全域物件，Node 沒有網頁，所以這個名字根本不存在，存取它就是 ReferenceError。回傳 null 是瀏覽器裡「有 document 但找不到元素」的情況。

練習 6：hello.ts 裡寫了 const n: number = 'abc'，執行 node hello.ts 會怎樣？

✓ Node 24 執行 TypeScript 的方式是擦掉型別再執行，不做型別檢查，n 在執行時就是字串 'abc'。型別錯誤要靠編輯器或另外執行 tsc 才看得到（第 5 課）。Node 也不會幫你轉型。

常見錯誤

  • 在錯的資料夾執行指令：相對路徑從工作目錄算起，站錯地方就找不到檔案。先用 pwd 確認；check.mjs 要在 learn/ 執行，練習檔要在 work/01 執行。
  • 以為 Node 有 window、document、localStorage：那是瀏覽器給的。Node 的資料要存檔案或資料庫，畫面交給前端。
  • import 自己的檔案漏了 .ts：Node 不會猜副檔名，會得到 ERR_MODULE_NOT_FOUND。寫 './price.ts'。
  • 以為 Node 會檢查型別：Node 只擦掉型別，型別錯了照樣執行。要檢查就跑 tsc（第 5 課）。
  • 伺服器跑起來後以為終端機當機：伺服器本來就會一直等請求。用 Ctrl+C 停止。
  • 看到 EADDRINUSE 就去改程式：是 port 被別的程式佔用。換一個 port，或找出佔用的程式關掉。
  • 看到新的主版本就升級：先看它是不是 LTS、用到的套件支援了沒，再跑完整測試。正式環境只用 LTS。
  • catch 住所有錯誤都說「找不到檔案」：JSON 壞掉、沒有權限也會被說成找不到，害人查錯方向。先檢查 err.code，只處理你預期的那一種。
  • 用 127.0.0.1:8000 開課程頁：進度存在 localhost:8000 這個網址底下，換網址就看不到。一律用 http://localhost:8000。

小結

  • 瀏覽器為了保護使用者，不讓網頁讀任意檔案；店長讀菜單檔的程式要交給 Node 執行。
  • Node.js 是 JavaScript 的執行環境：V8 引擎＋libuv＋node: 內建模組，不是新語言也不是框架。能做什麼由執行環境決定：瀏覽器給你 DOM，Node 給你檔案、網路、程序。
  • Node 用一條執行緒加非阻塞 I/O，擅長大量「等 I/O」的工作，不擅長長時間 CPU 運算。
  • 相對路徑從工作目錄算起，readFile 也一樣；找不到檔案先 pwd。
  • Node 24 直接執行 .ts，只擦掉型別、不檢查型別；import 自己的檔案要寫 .ts，只引入型別要用 import type。ES module 可以用頂層 await。
  • 伺服器一直開著等請求，用 port 區分；同一個 port 只能有一個程式在聽。
  • process、Buffer 是 Node 專屬的全域物件，document、window 在 Node 不存在；參數在 process.argv[2]。
  • 正式環境只用 LTS（這台是 Node 24 Maintenance LTS）；查文件看對應版本，只依賴 Stability 2 的 API。
  • 練習流程：改 work/01 的檔案 → 在 learn/ 執行 node check.mjs node 01 → 回課程頁看結果。

下一課把 process 看清楚：參數、環境變數、stdout／stderr 和結束碼，讓你的程式能被別的程式和部署工具正確地呼叫。
