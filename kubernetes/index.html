Kubernetes 實戰 學習地圖

咖啡店的點餐服務越做越大：API 要跑好幾份、尖峰要自動加機器、每週部署好幾次不能停機、背景 worker 要寄收據、資料庫 migration 要在新版上線前跑完。devops 課用 Docker Compose 在一台主機上做到了一部分，但主機壞了、要擴到好幾台、要讓不同團隊共用平台時，就需要 Kubernetes。大部分公司的後端服務都跑在 Kubernetes 上（AWS 的 EKS、Google 的 GKE 或自己架的叢集），資深後端工程師要能自己部署、除錯、維運服務，也要能和平台團隊用同一套語言溝通。

這門課從「期望狀態與控制迴圈」這個核心想法開始，在你的 Mac 上用 kind 開一個三個節點的本機叢集，一步步學 Pod、Deployment、Service、Gateway API、ConfigMap 與 Secret、健康檢查與優雅關機、資源與自動擴展、不停機部署、Job 與 migration、儲存、RBAC 與 NetworkPolicy、Helm，最後練資深工程師最常做的事：從 Pod 的狀態一路查到根因，並理解正式環境的 GitOps 與 EKS。期末專題把 NestJS 課的咖啡店 API、worker 與 migration Job 部署到叢集，做到不停機更新與自動擴展，再修好三個被埋進去的事故。

練習在你自己的電腦上做：你寫 YAML（之後是 Helm chart）與小腳本，執行 node check.mjs kubernetes <題號>，測試會把你的 manifest 套用到一個專屬的 namespace、等它跑起來、用真的流量與 kubectl 檢查結果，最後把 namespace 刪掉；不需要叢集的題目用 kubeconform 與 YAML 解析做靜態檢查，幾秒就跑完。少數純邏輯的題目（控制迴圈、HPA 公式、GitOps 同步計畫）在頁面裡用 TypeScript 完成。每課至少 3 題選擇題針對常見誤解。這門課假設你學完 devops 課（Docker、Compose、CI/CD、AWS），用到前面任何一課都會寫出是哪一課並附上連結。
