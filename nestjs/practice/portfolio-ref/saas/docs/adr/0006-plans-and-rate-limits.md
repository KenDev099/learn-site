# 0006. 方案上限與每租戶限流

## 狀態

已採用（2026-11-19）

## 背景

免費方案要限制 project 數、成員數（含待接受的邀請）、檔案總容量；一個租戶的大量請求不能拖慢其他租戶。

## 決定

方案是程式常數＋`tenants.plan`。用量檢查在交易裡先 `SELECT … FOR UPDATE` 鎖住租戶列，再數、再新增。限流用 @nestjs/throttler＋Redis（固定視窗），tracker 是 tenantId，每租戶每分鐘 300 個請求；超過回 429＋`Retry-After`。超過方案上限回 403 `PLAN_LIMIT_REACHED`。

## 後果

- 同一個租戶的建立操作會排隊；對這個規模可以接受。
- 方案改成可以由營運調整時，把常數搬進資料表（寫新的 ADR）。
- 固定視窗在視窗交界可能放過兩倍的量；需要時換成滑動視窗。
