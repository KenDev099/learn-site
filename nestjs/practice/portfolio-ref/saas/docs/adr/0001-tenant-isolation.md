# 0001. 租戶隔離：共用資料表＋tenant_id

## 狀態

已採用（2026-11-19）

## 背景

這是給小型團隊用的 SaaS 後台，預計有數百到數千個租戶，每個租戶的資料量小。隔離方式有三種：共用資料表加 `tenant_id`、每個租戶一個 schema、每個租戶一個資料庫。

## 決定

所有租戶共用資料表，每張租戶資料表都有 `tenant_id`。租戶只從 access token 的 `tid` 來，不接受請求送來的租戶 ID。

## 後果

- 好處：migration 只跑一次、連線池共用、新增租戶不用建資源。
- 代價：漏一個條件就是跨租戶洩漏。用兩道防線補：Prisma extension 自動加條件（0002）、PostgreSQL RLS（0002）；再加跨租戶 E2E 測試。
- 大客戶要求實體隔離時，再為他們另開資料庫（寫新的 ADR 取代這份）。
