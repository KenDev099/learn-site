階段 3：資料庫（Docker、Prisma 7 ＋ PostgreSQL） · 第 12 課

Docker 入門：用容器跑 PostgreSQL 與 Redis

到目前為止，咖啡店 API 的商品和訂單都放在記憶體的陣列裡，伺服器一重啟就全部不見。第 11 課的 .env 裡已經有一個 DATABASE_URL，ConfigModule 啟動時會檢查它的格式，但它指向的位址上，現在還沒有任何資料庫在等連線。

在 PostgreSQL 課你用的是瀏覽器裡的 PGlite，它跟著網頁一起載入、一起消失。後端程式要連的是另一種東西：一個獨立執行的資料庫伺服器（server）程式，在某個 port 上等連線，Nest 是連過去送查詢的客戶端。這一課的任務是：在你的 Mac 上跑起一台 PostgreSQL（加上之後做快取和佇列要用的 Redis），拿到一個真的連得上的 DATABASE_URL，並確定服務重啟之後資料還在。下一課的 Prisma 一開始就要用這個位址。做法不是直接安裝，而是用 Docker 把它們跑在容器裡；最後也要練到連不上時知道從哪裡查。

這課的路線：
  1. 為什麼不直接裝在 Mac 上、怎麼把它跑起來：容器解決什麼問題，一個指令之後資料庫在哪個位址等你。
  2. 那個指令照什麼做事：逐行讀 compose.yaml，port 為什麼是 5433、資料存在哪、怎樣才算「可以連了」。
  3. 它現在有沒有在跑、哪些操作會弄丟資料：讀 docker compose ps 的狀態，分清 restart、stop、down、down -v。
  4. 怎麼進去看資料、Nest 用什麼位址連：容器裡的 psql 和 redis-cli，以及 DATABASE_URL 每一段代表什麼。
  5. 連不上的時候：看到 ECONNREFUSED 先別改程式，用錯誤代碼判斷是哪一層出了問題。
這課會用到：
  • PostgreSQL 課第 1 課的伺服器與客戶端：資料庫伺服器是獨立執行的程式，負責存資料；你的程式和 psql 都是連上它、送出查詢的客戶端。
  • Node 課第 13 課的 port：伺服器在某個 port 上等待連線，客戶端要知道主機和 port 才連得到。
  • 第 11 課的設定：.env 裡的 DATABASE_URL 由 ConfigModule 在啟動時讀取並驗證。

為什麼不直接在 Mac 上安裝 PostgreSQL？

要讓 Nest 有資料庫可以連，最直覺的做法是用 Homebrew 在 Mac 上裝一台 PostgreSQL。這樣做跑得起來，但只要專案多一點、團隊多一個人，就會遇到三個問題。

第一個是版本對不齊。你裝的是 17，課程用 18.6，同事裝的是 16。同一段 SQL 在三台電腦上的行為不一定一樣，有人說「我這邊可以」的時候，你很難判斷是程式的問題還是資料庫版本的問題。

第二個是互相占位。用 Homebrew 裝的 PostgreSQL 會在背景一直執行，占著 5432 port。另一個專案需要別的版本時，兩台都想用 5432，只能停掉一台、手動切換。

第三個是很難重來。練習時把資料弄亂了，想「整個重來」，得自己找到資料夾、刪檔、重新初始化，弄錯一步就起不來。

這三個問題的根源相同：資料庫被裝成你電腦的一部分，跟其他東西攪在一起。Docker 的做法是反過來，把「一個程式和它需要的所有檔案」打包成一份固定的內容，執行時跟你的電腦隔開。這裡要先認識兩個名詞。

第一個是映像檔（image）。它是一份唯讀的範本，裡面有一個精簡作業系統的基本檔案、PostgreSQL 程式本身和預設設定。映像檔用 名稱:tag 指定，例如 postgres:18.6-alpine：名稱是 postgres，tag 是 18.6-alpine，意思是 PostgreSQL 18.6、建立在很小的 Alpine Linux 上。同一個名稱加同一個 tag，在每台電腦上下載到的內容都一樣，版本對不齊的問題就是這樣解決的。

第二個是容器（container）。它是用映像檔跑起來的程式，有自己的檔案系統、自己的 port，和你的電腦以及其他容器隔開。兩個容器都可以在「自己裡面」用 5432，不會打架，這解決了互相占位。容器可以隨時刪掉再用同一個映像檔建一個新的，這解決了很難重來。代價是：容器被刪掉時，寫在容器檔案系統裡的檔案跟著消失。資料庫的資料當然不能這樣丟，所以後面會用 volume 把資料放到容器外面。

可以這樣類比：映像檔像 App 的安裝檔，容器像正在執行的那個 App。同一個安裝檔可以開好幾個互不干擾的 App，把 App 刪掉也不影響安裝檔。

知道了容器是什麼，下一個問題是怎麼讓它跑起來：映像檔要有人下載，容器要有人建立和管理，這個角色在 Mac 上由 Docker Desktop 擔任。

怎麼把資料庫跑起來？

在 Mac 上提供 Docker 的是 Docker Desktop 這個應用程式。它啟動後，會在背景執行一個常駐程式，叫 Docker daemon。daemon 是「在背景一直執行、等別人送要求來的程式」的通稱，真正下載映像檔、建立和停止容器的都是它。你在終端機打的 docker 指令只是客戶端，負責把要求送給 daemon。這個關係跟資料庫一樣：伺服器沒開，客戶端什麼都做不了。所以 Docker Desktop 沒開時，所有 docker 指令都會失敗。

open -a Docker      # 打開 Docker Desktop，等選單列的鯨魚圖示不再轉動
docker info         # 有印出 Server: 那一段才代表 daemon 在跑
docker compose version

daemon 沒在跑時，docker info 會在最後印出類似 Cannot connect to the Docker daemon at unix:///…/docker.sock. Is the docker daemon running? 的錯誤。看到這句，問題不在你的程式，是 Docker Desktop 還沒開，或還在啟動中。

daemon 準備好之後，就可以啟動課程的服務。課程把要跑哪些容器、怎麼跑，寫在 learn/nestjs/practice/compose.yaml，所以一定要在這個資料夾執行：

cd learn/nestjs/practice
docker compose up -d --wait

第一次執行會先下載映像檔（大約一兩百 MB），之後就直接用已經下載好的。成功時會看到 Container learn-nestjs-postgres Healthy、Container learn-nestjs-redis Healthy。如果在別的資料夾執行，會看到 no configuration file provided: not found，意思是 Compose 在目前資料夾找不到 compose.yaml，換到正確的資料夾再執行就好。

💡 實務上：新人第一天就靠一個 compose.yaml 跑起整套環境
團隊專案通常會把 compose.yaml 放在 repo 裡，README 只寫「先 docker compose up -d」，新同事不必照著十幾步安裝說明裝資料庫，就像你剛剛做的。它解決的是「開發環境每個人都一樣」，所以映像檔版本最好對齊正式環境的大版本（18、16 這種主要版本號），例如正式機是 PostgreSQL 18，本機就別跑 16。要注意的是：正式環境的資料庫多半用雲端代管服務（例如 AWS RDS），不是把這份 compose 搬上去跑；本機這份只負責開發和測試。資深工程師加入新專案時會先問：「本機怎麼把依賴服務跑起來？版本跟正式環境一致嗎？」

到這裡，開場的任務已經有了最小答案：PostgreSQL 在 127.0.0.1 的 5433 port 等連線，使用者和密碼都是 learn；Redis 在 127.0.0.1 的 6380。但這些數字是從哪裡來的？為什麼不是 PostgreSQL 預設的 5432？資料又存在哪裡、重啟會不會掉？答案都寫在剛剛那份 compose.yaml 裡。

那個指令照什麼做事？逐行讀 compose.yaml

剛剛的 docker compose up 讀的就是 compose.yaml。Docker Compose 是 Docker 附的工具，用一個檔案描述好幾個要一起跑的容器，一個指令全部啟動或停止。檔案裡每一個要跑的東西叫一個 service（服務），這一課用到 postgres 和 redis 兩個。下面是 learn/nestjs/practice/compose.yaml，省略了註解，也省略了作品專案課才用到的 mailpit：

name: learn-nestjs
services:
  postgres:
    image: postgres:18.6-alpine
    container_name: learn-nestjs-postgres
    environment:
      POSTGRES_USER: learn
      POSTGRES_PASSWORD: learn
      POSTGRES_DB: learn
    ports:
      - "127.0.0.1:5433:5432"
    volumes:
      - pgdata:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U learn -d learn"]
      interval: 2s
      timeout: 3s
      retries: 30
  redis:
    image: redis:8.10.3-alpine
    container_name: learn-nestjs-redis
    ports:
      - "127.0.0.1:6380:6379"
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 2s
      timeout: 3s
      retries: 30
volumes:
  pgdata:
    name: learn-nestjs-pgdata

先看這份檔案建出來的全貌，再逐段看每一行為什麼這樣寫：

name、image、environment：建什麼、用哪個版本、初始帳號是誰

name: learn-nestjs 是 Compose 專案名稱。Compose 用它幫容器、網路、volume 分組，所以你在別的專案資料夾執行 docker compose down，不會動到這裡的容器。

image: postgres:18.6-alpine 指定映像檔，而且鎖定到小版本。如果寫 postgres:latest 或只寫 postgres，今天下載到的是 18，哪天你清掉映像檔重新下載，可能拿到下一個大版本。PostgreSQL 的大版本不能直接讀舊版本留下的資料檔，結果是容器一啟動就失敗。課程鎖 PostgreSQL 18.6、Redis 8.10.3。

environment 是傳給容器的環境變數。postgres 映像檔只在第一次建立資料時讀這三個值：建立使用者 learn、設定密碼 learn、建立資料庫 learn。資料建好之後，改這裡的密碼不會改到既有的使用者；要改密碼得進資料庫用 ALTER USER，或刪掉資料從頭來。這一點在連不上、排查密碼錯誤時會再遇到。

ports：為什麼從 Mac 要連 5433

第一節說過容器有自己的 port。容器裡的 PostgreSQL 照預設在 5432 等連線，但這個 5432 是「容器裡面的」，你的 Mac 直接看不到。要讓 Mac 上的程式連得進去，得請 Docker 在 Mac 上開一個 port，收到連線就轉進容器，這叫 port 對應（port mapping）。

"127.0.0.1:5433:5432" 的格式是 本機位址:本機 port:容器裡的 port，意思是「你電腦上 127.0.0.1 的 5433，轉到容器裡的 5432」。所以從你的 Mac 連 PostgreSQL 要用 5433，Redis 同理要用 6380。

為什麼不直接對應到 5432、6379？因為你的電腦上可能已經有用 Homebrew 裝的 PostgreSQL 或 Redis 占著這兩個 port。換成 5433、6380 就不會衝突，也不會不小心連到另一台資料庫，卻以為自己連的是容器。

為什麼前面要加 127.0.0.1？一台電腦通常有好幾個網路介面：一個只給自己用的 127.0.0.1，加上 Wi-Fi、有線網路各自的位址。只寫 "5433:5432" 時，Docker 會在所有網路介面上開這個 port，在咖啡店連同一個 Wi-Fi 的人也連得到你的資料庫，而密碼只是 learn。綁在 127.0.0.1，就只有你自己這台電腦連得到。

volumes：資料存在哪，為什麼刪掉容器資料還在

第一節說過，容器被刪掉時，寫在容器裡的檔案會跟著消失。volume 就是為了這件事存在的：它是由 Docker 管理、放在容器外面的一塊資料空間，容器刪掉之後仍然保留，新的容器可以再接上同一個 volume，看到原本的資料。

pgdata:/var/lib/postgresql 的意思是：把名為 pgdata 的 volume 接到容器裡的 /var/lib/postgresql 這個路徑。PostgreSQL 往這個路徑底下寫的資料，實際上寫進了 volume。檔案最下面的 volumes: 區塊宣告這個 volume，並把它的實際名稱定為 learn-nestjs-pgdata。

掛載的路徑必須是 PostgreSQL 真正寫資料的地方。路徑掛錯時不會報錯，PostgreSQL 照樣啟動、照樣能用，只是資料其實寫在容器裡，刪掉容器才發現資料不見了。網路上很多舊教學的路徑跟 18 版的映像檔對不上，原因見課末「補充與查表」。

對照之下，Redis 沒有掛 volume。這門課只把 Redis 當快取和佇列用，資料可以丟。這個差別會在後面直接看到：同樣一個指令，對 PostgreSQL 和 Redis 的資料會有不同的結果。

healthcheck：怎樣才算「可以連了」

容器「啟動了」不等於「能連線」。PostgreSQL 第一次啟動要先初始化資料，那幾秒連進去會失敗。如果 Nest 剛好在這幾秒啟動，就會看到連線錯誤，而且下次再試又好了，很難查。

healthcheck 是健康檢查：Docker 每 2 秒在容器裡執行一次 test 的指令，成功才把容器標成 healthy，最多試 30 次。PostgreSQL 用的 pg_isready 是 PostgreSQL 附的檢查工具，回報伺服器能不能接受連線；Redis 用 redis-cli ping，收到 PONG 就代表可以用了。「怎麼把資料庫跑起來」那節用的 --wait，等的就是這個狀態，所以指令結束時印出 Healthy，代表真的連得上，不只是程式開了。

💡 實務上：審 compose.yaml 時先看這四件事
同事送來一份新的 compose.yaml，或你從網路上複製一份時，先檢查：tag 有沒有鎖到明確版本、port 有沒有綁 127.0.0.1、volume 掛的路徑對不對（PostgreSQL 18 就是課末那個坑）、有沒有 healthcheck。learn／learn 這種密碼只能用在本機；共用環境或正式環境的真正密碼不要寫進會 commit 到 git 的檔案，放在 .env 這類不進版控的地方。之後要升 PostgreSQL 大版本時，不是改個 tag 就好：舊 volume 裡的資料檔新版本讀不了，得先匯出再匯入，所以升級前要先跟團隊說好，並提醒大家自己的本機資料會重來。

到這裡你知道 Docker 照這份檔案建了什麼。接下來每天會碰到兩個問題：服務現在到底有沒有在跑？哪些指令會把資料一起帶走？而 PostgreSQL 有 volume、Redis 沒有，這個差別會決定第二個問題的答案。

它現在有沒有在跑？哪些操作會弄丟資料？

要回答「有沒有在跑」，用 docker compose ps。它列出這個 Compose 專案的容器和狀態，跟前一節的 healthcheck 直接相關：

NAME                    IMAGE                  COMMAND                  SERVICE    CREATED       STATUS                 PORTS
learn-nestjs-postgres   postgres:18.6-alpine   "docker-entrypoint.s…"   postgres   8 hours ago   Up 3 hours (healthy)   127.0.0.1:5433->5432/tcp
learn-nestjs-redis      redis:8.10.3-alpine    "docker-entrypoint.s…"   redis      8 hours ago   Up 3 hours (healthy)   127.0.0.1:6380->6379/tcp

最右邊的 PORTS 就是 ports 那一節說的 port 對應。CREATED 是容器建立多久了，STATUS 的 Up 是這次啟動多久了。兩者會不一樣，是因為同一個容器可以停下再啟動：restart 之後 Up 從頭算，CREATED 不變，因為還是同一個容器。STATUS 可能出現這幾種狀態：

  • Up … (healthy)：在跑，健康檢查也通過，可以連。
  • Up … (health: starting)：剛啟動，健康檢查還沒通過，等幾秒。
  • Up … (unhealthy)：程式在跑，但檢查一直失敗。看 logs。
  • Restarting 或 Exited (1)：程式一啟動就結束了。一定要看 docker compose logs postgres，原因寫在最後幾行（例如資料檔是別的大版本建立的）。
  • 列表是空的：容器不存在（還沒 up 過，或 down 掉了），執行 up -d --wait。

第二個問題「哪些操作會弄丟資料」，要回到前面兩個觀念：容器可以刪，volume 獨立於容器存在。所以判斷一個指令會不會弄丟資料，只要問它刪了什麼：只停止程式的，什麼都不會丟；刪掉容器的，只有沒掛 volume 的 Redis 會丟；連 volume 一起刪的，PostgreSQL 的資料也沒了。Redis 為什麼是「刪掉容器才會丟」，而不是一停就丟？Redis 的資料平常放在記憶體裡，正常關閉時會先把資料存成一個檔案，這個檔案屬於這個容器。restart 和 stop 時容器還在，Redis 重新啟動後會把檔案讀回記憶體；down 把容器刪掉，下次 up 建的是新容器，Redis 從空的開始。以下指令都在 learn/nestjs/practice 執行，最後一欄最重要：

指令做什麼資料
docker compose up -d --wait建立並啟動所有服務。-d（detached）在背景執行、把終端機還給你；--wait 等到每個服務都是 running／healthy 才結束，沒過就以錯誤結束保留
docker compose ps列出這個專案的容器和狀態—
docker compose logs -f postgres看 postgres 容器印出的訊息，-f 持續跟著看（Ctrl+C 離開，容器不會停）—
docker compose exec postgres …在執行中的容器裡執行一個指令—
docker compose restart postgres重新啟動 postgres 容器裡的程式（還是同一個容器）；不寫服務名稱就重啟全部保留（Redis 也是：關閉前會先把資料存成檔案）
docker compose stop／start停止／再啟動，容器還在。不用時讓它少吃記憶體保留
docker compose down停止並刪除容器和 Compose 建立的網路PostgreSQL 保留（在 volume 裡）；Redis 清空
docker compose down -v同上，再加上刪除 volume全部刪掉：所有課程的練習資料庫都不見
down -v 不是「重新開始」的安全按鈕。它刪掉的是整個 learn-nestjs-pgdata，這門課每一課的開發資料庫都在裡面。只是想讓服務重新跑一次，用 restart；想釋放記憶體，用 stop。真的要清掉某一課的資料，進 psql 刪那一個資料庫就好。

開場任務的「重啟之後資料還在」，現在有了根據：PostgreSQL 的資料在 volume 裡，restart、stop、down 都不會動到它。不過到目前為止，你都是從外面看容器的狀態。要親眼確認資料真的在，得進到資料庫裡看。

怎麼直接進到資料庫裡看？psql 與 redis-cli

表格裡的 docker compose exec <服務> <指令> 就是進去的方法：它在執行中的容器裡面執行一個指令。PostgreSQL 和 Redis 的映像檔都附了自己的命令列客戶端，所以你的 Mac 不必另外安裝任何東西。

psql 是 PostgreSQL 的命令列客戶端：

docker compose exec postgres psql -U learn -d learn

-U 是使用者、-d 是資料庫。這裡不會問密碼。在容器裡面，psql 不經過網路的 port，而是透過一個特殊檔案（Unix socket）直接和同一台機器上的 PostgreSQL 溝通；映像檔設定成直接信任這種本機連線，從你的 Mac 經過 5433 連進來時才要密碼。提示字元變成 learn=# 後，可以打 SQL（要以 ; 結尾），也可以打 psql 自己的指令（反斜線開頭，不用分號）：

psql 指令作用
\l列出所有資料庫
\c nest_12切換到 nest_12 資料庫，提示字元會跟著變
\dt列出目前資料庫的資料表
\d visits看 visits 的欄位、型別、預設值、索引
\q離開 psql（回到你的終端機，容器繼續跑）

\l 和 \c 背後有一個要先弄清楚的觀念：一台資料庫伺服器裡可以有很多個資料庫，每個資料庫的資料表彼此分開。compose.yaml 建立的 learn 只是其中一個，這門課每一課還會有自己的資料庫。CREATE TABLE 會建在你「目前所在」的資料庫，所以建表之前先看提示字元是不是你要的那一個。

redis-cli 是 Redis 的命令列客戶端：

docker compose exec redis redis-cli
127.0.0.1:6379> PING
PONG
127.0.0.1:6379> SET menu:today latte EX 60
OK
127.0.0.1:6379> GET menu:today
"latte"
127.0.0.1:6379> TTL menu:today
(integer) 57
127.0.0.1:6379> SELECT 1
OK
127.0.0.1:6379[1]> GET menu:today
(nil)

從上往下對照：

  • SET key value EX 60：設定值，60 秒後自動刪掉。TTL 看剩幾秒；-1 是沒有期限，-2 是 key 不存在。
  • Redis 也把資料分成幾個編號的資料庫，預設有 16 個（DB 0 到 15），一連進來在 DB 0。SELECT 1 切到 DB 1，提示字元變成 [1]，DB 0 的 key 在這裡看不到。
  • 提示字元顯示 6379，因為你在容器裡面；從 Mac 連要用 6380。

最後一點是下一節的起點：你在容器裡用的是容器裡的位址和 port，不需要密碼；Nest 卻是從 Mac 這一側連進去，要經過 port 對應，也要帶帳號密碼。這些資訊要怎麼交給 Nest？

Nest 要用什麼位址連過去？連線字串

程式連資料庫時，用一個連線字串（connection string）一次說清楚四件事：用什麼協定、以誰的身分、連到哪台主機的哪個 port、要用哪個資料庫。把前面幾節的答案填進去，就是這樣：

postgresql://learn:learn@127.0.0.1:5433/nest_13
└─ 協定 ─┘   └使用者┘└密碼┘ └─ 主機 ─┘└port┘└資料庫┘

redis://127.0.0.1:6380/0
                       └ Redis 的 DB 編號

使用者和密碼來自 environment，主機和 port 來自 ports 對應出來的 Mac 這一側（5433，不是容器裡的 5432），最後一段是上一節說的「伺服器裡的哪一個資料庫」。第 11 課的 .env 裡的 DATABASE_URL 就是這個字串，開場任務要的位址到這裡完成。主機課程一律寫 127.0.0.1，不寫 localhost；密碼裡有特殊字元時要先編碼。這兩點的原因見課末「補充與查表」。

連線字串最後那一段資料庫名稱，牽涉到這門課怎麼分配資料庫。所有課程共用同一台 PostgreSQL 和 Redis，用名稱分開，互不干擾：

用途PostgreSQLRedis誰管
你開發時用（npm run start:dev）nest_<題號>，例如 nest_13DB 0，key 以 nest-<題號> 開頭你。判分程式不會動它
判分（node check.mjs）nest_<題號>_testDB 1，key 以 nest-<題號>-test 開頭判分程式，每次判分前刪掉重建
你自己寫的資料庫測試（第 17 課）nest_<題號>_spec—你的測試

開發和判分分開，是為了讓兩邊互不影響：你在開發資料庫裡手動加的資料，不會讓判分忽然通過或失敗；判分每次刪掉重建自己的資料庫，也不會清掉你的資料。這也是正式環境的基本做法：測試永遠不連正式資料庫。

照這個格式寫，大部分時候就連得上了。但只要任何一段寫錯，或 Docker 沒開，Nest 啟動時就會印出一行錯誤。這時候該從哪裡查起？

連不上的時候：從錯誤代碼判斷是哪一層

Nest 啟動時印出 connect ECONNREFUSED 127.0.0.1:5433，第一反應常是去改程式。先別動程式。連線失敗的原因幾乎都在程式外面，而且錯誤裡已經帶著一個代碼，告訴你是哪一層出了問題。

要讀懂這些代碼，先看連線是怎麼一步步建立的。客戶端先要找到那個 port 上有程式在等（像打電話先要有人接），接著向 PostgreSQL 證明自己的身分（帳號密碼），最後才指定要用哪個資料庫。每一步失敗，錯誤代碼都不一樣，而且來自不同的地方：

  • 第一步失敗時，連線根本沒到 PostgreSQL，是作業系統回報「這個 port 上沒有人」，代碼是 ECONNREFUSED。Node 的 pg 套件把它放在錯誤物件的 code 上。
  • 後兩步失敗時，連線已經到了 PostgreSQL，由 PostgreSQL 回報錯誤。它的每種錯誤都有一個固定的五碼代碼，叫 SQLSTATE，例如密碼錯是 28P01、資料庫不存在是 3D000。SQLSTATE 跟錯誤訊息用什麼語言無關，程式要判斷錯誤種類時比對它，不要比對訊息文字。

所以從最外層往裡查。下面這張表是遇到時查的，不用背；記住順序就好：

看到意思怎麼查、怎麼修
ECONNREFUSED那個位址和 port 上沒有任何程式在等連線。連線根本沒到 PostgreSQL依序確認：Docker Desktop 有沒有開（docker info）→ 容器在不在、是不是 healthy（docker compose ps）→ port 是不是寫成 5433，而不是容器裡的 5432
28P01 password authentication failed for user "learn"連到 PostgreSQL 了，帳號或密碼不對對照 compose.yaml；記得 POSTGRES_PASSWORD 只在第一次建立資料時生效
3D000 database "…" does not exist登入成功，但沒有這個資料庫拼字？還沒建立？在 psql 用 \l 看有哪些
up 時出現 port is already allocated／address already in use你電腦上已經有別的程式占用這個 portlsof -nP -iTCP:5433 -sTCP:LISTEN 看是誰，關掉它
ps 看到 Restarting、Exited容器裡的程式啟動就失敗docker compose logs postgres，看最後幾行

前三列的順序就是連線的過程：先要有人接電話（port），再驗證身分（密碼），最後才找資料庫。所以修的時候一次只修一個，每修一個就再試一次。修對了，錯誤代碼會往下一層走，例如從 ECONNREFUSED 變成 28P01，代表 port 這一層已經通了，接下來只剩密碼。一次改好幾個地方，錯誤消失了也不知道是哪個改動有效；錯誤沒消失，更不知道哪個改壞了。練習 3 就是照這個順序走一遍。

💡 實務上：回報「資料庫連不上」時附上錯誤代碼
在團隊裡說「資料庫壞了」，別人只能從頭問起；說「本機連 127.0.0.1:5433 得到 ECONNREFUSED，docker compose ps 是空的」，問題通常幾分鐘就解決。這套「由外往內」的順序到了雲端一樣適用，只是多了防火牆、安全群組（雲端主機上「誰能連哪個 port」的規則）這一層：被防火牆擋住時常見的是等到逾時（ETIMEDOUT），而不是立刻被拒絕。資深工程師遇到連線問題會先問兩件事：「之前可以嗎？這中間改了什麼？」，答案往往直接指向 .env、port 或剛換過的密碼。

練習

先在 learn/nestjs/practice 執行 docker compose up -d --wait，再到 learn/ 執行一次 node check.mjs nestjs 12，它會建立 work/12/。這一課的判分直接連你的容器：服務沒開時，每一題都會顯示怎麼啟動。三題的答案都寫在 work/12/answers.json。

練習 1：進到兩個容器裡。

  • 用 docker compose exec postgres psql -U learn -d learn 執行 SELECT system_identifier FROM pg_control_system();。這個數字是 PostgreSQL 初始化資料時產生的，每一台都不一樣（只有 down -v 之後才會變）。把它寫進 answers.json 的 systemIdentifier，用雙引號包成字串：這個數字超過 JavaScript number 能精確表示的範圍，不加引號，JSON.parse 讀出來會被四捨五入成另一個數字。
  • 用 docker compose exec redis redis-cli 在 DB 0 把 nest-12:hello 設成 coffee（不設期限）。

練習 2：證明資料存在 volume 裡。這一題不用改 answers.json，判分直接看資料庫。

  • 在 psql 建立資料庫 nest_12，用 \c 切過去，建立資料表 visits：id 是 serial 主鍵、note 是 text not null、created_at 是 timestamptz not null，預設 now()。
  • 新增一列 note 為 before restart（created_at 不要自己填，讓預設的 now() 記下寫入的時間）。
  • 離開 psql，執行 docker compose restart postgres，再進 psql 確認那一列還在。

判分用 pg_postmaster_start_time()（這次 PostgreSQL 啟動的時間）確認那一列是在重啟之前寫入的，所以順序不能反過來，也不能跳過重啟；手動填一個很早的 created_at 也會被擋下（判分會跟 nest_12 建立的時間比）。

練習 3：answers.json 的 databaseUrl 有三個錯：port 寫成容器裡的 5432、密碼錯、資料庫名稱拼錯。目標是以 learn 連到練習 2 的 nest_12（先做完練習 2）。

  • 在 work/12 執行 node check-db.mjs，它用 databaseUrl 連線一次，失敗時印出錯誤代碼和訊息，成功時印出 connected。
  • 照排查表的順序一次只修一個：port → 密碼 → 資料庫名稱。每修一個就執行一次，把依序看到的三個錯誤代碼（每次輸出的第一個字）寫進 errors，例如 ["…", "…", "…"]。
  • 最後 check-db.mjs 要印出 connected。

判分會用同樣的三個步驟實際連線一次，比對你記下的代碼。

練習 4：docker compose down 和 docker compose down -v 差在哪？

✓ b。-v 是 --volumes：刪掉 compose.yaml 裡宣告的 volume。只有 down 時容器被刪，但 learn-nestjs-pgdata 還在，下次 up 接回去資料都在（沒掛 volume 的 Redis 例外）。a 錯在以為 down 會刪資料；-v 也不是 verbose。c 描述的是 stop：down 本身就會刪容器。

練習 5：ports 寫 "5433:5432" 和 "127.0.0.1:5433:5432" 差在哪？

✓ c。沒寫位址時，Docker 會在所有網路介面上開這個 port，不是只有本機。開發用的資料庫密碼通常很弱（這裡是 learn），「反正只有我在用」不成立：同網路的任何人都能試。b 錯：前者從本機也連得到，只是範圍太大。

練習 6：npm run start:dev 出現 connect ECONNREFUSED 127.0.0.1:5433，第一步該做什麼？

✓ a。ECONNREFUSED 代表 127.0.0.1:5433 上沒有程式在等連線，連線根本沒到 PostgreSQL：最常見的原因是 Docker Desktop 沒開或容器沒啟動。b 錯：密碼錯的話已經連上了，會看到 28P01。c 錯：程式寫錯不會讓 port 上沒人接。

常見錯誤

  • Docker Desktop 沒開就執行 docker compose：看到 Cannot connect to the Docker daemon。先 open -a Docker，等 docker info 正常再執行。
  • 用 down -v「重新開始」：所有課程的開發資料庫一起消失。重跑服務用 restart，清一課的資料就在 psql 刪那個資料庫。
  • 連線字串用了容器裡的 port：5432 是容器裡面的，從 Mac 要連對應出來的 5433，否則得到 ECONNREFUSED，或者更糟：連到你電腦上另一台 PostgreSQL。
  • port 沒綁 127.0.0.1：同一個網路的人都能連你的資料庫。ports 一律寫 "127.0.0.1:本機port:容器port"。
  • image 用 latest：重新下載時換成新的大版本，舊資料讀不了、行為也變了。tag 寫到小版本，例如 postgres:18.6-alpine。
  • 以為改了 POSTGRES_PASSWORD 就改掉密碼：這些環境變數只在第一次建立資料時用；之後要用 ALTER USER 改。
  • PostgreSQL 18 的 volume 掛在 /var/lib/postgresql/data：照舊教學寫，資料不在你的 volume 裡，刪容器就不見。18 起掛 /var/lib/postgresql。
  • 表建在錯的資料庫：psql 一進來在 learn，忘了 \c 就建表。先看提示字元。
  • 在正式環境用 KEYS *：Redis 在掃描期間不處理其他請求。用 SCAN。

補充與查表

主線用不到、但遇到時要知道的細節。

  • 課程驗證的版本：本課程用 Docker 29.6.2、Compose v5.3.1 驗證。docker compose version 可以看你的版本。
  • PostgreSQL 18 的 volume 路徑：PostgreSQL 18 起的官方映像檔把資料放在 /var/lib/postgresql/18/docker（環境變數 PGDATA），所以 volume 要掛在 /var/lib/postgresql。網路上很多舊教學寫 /var/lib/postgresql/data，用在 18 的映像檔上，資料其實沒有寫進你的 volume，刪掉容器就不見了。
  • 主機寫 127.0.0.1 而不是 localhost：主機寫 localhost 也可以，但 macOS 可能先試 IPv6 的 ::1，課程的 port 只綁在 IPv4 的 127.0.0.1，所以課程一律寫 127.0.0.1。
  • 密碼裡有特殊字元：密碼裡有 @、:、/ 這類字元時，要先 URL 編碼（encodeURIComponent），不然會被當成連線字串的分隔符號。
  • Redis 的 KEYS *：列出所有 key，練習時可以用。正式環境不要用：Redis 一次只做一件事，KEYS 掃過幾百萬個 key 的那段時間，其他所有請求都在等。要找 key 用 SCAN，第 19 課會再講。
  • 容器怎麼運作：這門課只學「會用」：能啟動、能連線、能排查。容器怎麼做到隔離、映像檔的分層、容器之間的網路，在 DevOps 課第 7 課和第 10 課。

小結

  • 直接在 Mac 安裝資料庫會遇到版本對不齊、port 互相占用、很難重來；容器把程式和它需要的檔案打包、隔離，解決這三件事。
  • 映像檔是範本（名稱:tag，鎖到小版本），容器是跑起來的程式；容器刪掉時，資料只有放在 volume 裡的會留下。
  • Docker Desktop（daemon）要先開；在 learn/nestjs/practice 執行 docker compose up -d --wait，healthcheck 通過、兩個服務都 healthy 才算能連。
  • "127.0.0.1:5433:5432"：只讓本機連，Mac 上的 5433 轉到容器裡的 5432。從程式連要用 5433、6380。
  • restart、stop 不刪資料；down 刪容器（PostgreSQL 資料在 volume 裡保留，Redis 清空）；down -v 刪掉所有資料。
  • docker compose exec postgres psql -U learn -d learn（\l、\c、\dt、\d、\q）與 docker compose exec redis redis-cli（SELECT 切換 DB）。
  • 連線字串 postgresql://使用者:密碼@主機:port/資料庫 就是 DATABASE_URL；開發用 nest_<題號>，判分用 nest_<題號>_test。
  • 連不上時照連線的過程查：ECONNREFUSED（Docker、容器、port）→ 28P01（帳密）→ 3D000（資料庫名稱），一次修一個。
