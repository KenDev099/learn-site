主線：轉職全端／後端

目標是做出一個完整的後端作品、通過面試、進團隊做事。後面的課會一直用到前面教過的東西，照順序走，每一課新增的只有一兩個概念；跳著學才容易卡住。每門課裡標「選修」的課、課文裡標「（選讀）」的節，第一輪都先跳過。

下面的時間以每週約 10 小時估算，只是粗估。

  1. 地基（約 3～4 個月）：PostgreSQL 第 1～26 課 → JS、非同步與 TypeScript → Node.js 核心。先學 SQL，因為它最直觀、最快建立信心；TypeScript 與 Node 是後面所有課的語言。
  2. 第一次做出完整的東西（約 2～3 個月）：NestJS → 作品專案階段 A（小專案，從零走完需求到上線）。這是整條路的轉折點：前面學的東西在這裡第一次串起來。同時開始兩件事：每週 3～4 課演算法（面試必考），讀面試與職涯第 1～3 課，讓作品一開始就照履歷需要來做。
  3. 後端工程師的核心（約 3～4 個月）：認證與資安 → 部署與維運 → PostgreSQL 第 27～39 課（資深篇，這時已經有 API 和真實的查詢）→ 系統設計。從「會寫 API」走到「API 安全、上得了線、出事查得到原因」。急著做出能登入的 API：認證課第 1～11 課後先跳第 18～21 課，再回頭讀第 12～17 課。
  4. 主力作品（約 2～3 個月）：作品專案階段 B，用 NestJS、Prisma、PostgreSQL 做多租戶 SaaS 後台。做完階段 B1（第 6～10 課）就可以開始投履歷，邊投邊做完。
  5. 進團隊前（約 1～2 個月）：實戰：咖啡店產品交付（接手既有專案、Git 協作、修 bug、審 PR、事故演練）→ 面試與職涯第 4～10 課。

最容易卡住的地方

位置為什麼難卡住怎麼辦
TypeScript 第 7～12 課：event loop、Promise、競態第一次要在腦中模擬程式執行的順序每格範例都按執行，對照輸出順序
TypeScript 第 18～21 課：泛型、工具型別抽象會用、讀得懂就夠；第 22 課本來就是選修
NestJS 第 15 課：交易與並發要同時想兩個請求怎麼互相影響面試重點，值得慢慢來
認證第 8～13 課：JWT、OAuth名詞多、流程長先走上面的快速路線
PostgreSQL 第 30～33 課：MVCC、鎖資料庫內部機制第一輪抓結論，工作遇到再回來看細節
系統設計第 12～13 課：outbox、saga分散式的失敗情境做完作品專案階段 B 再讀一次會更有感
作品專案第 8～9 課：租戶隔離兩道防線要一起理解作品裡最有價值的部分，不要跳過

三個原則

  • 選修、選讀第一輪一律跳過：它們偏資深或特定職缺，錄取後再補來得及。
  • 用階段檢核當關卡：每個階段最後的選擇題答不出來，回頭看那幾課；答得出來就往前，不必每課都完全吃透。
  • 卡住超過一兩天就先往下：很多概念要到後面用到才會懂，作品專案就是讓前面的東西被用上的地方。

選修：錄取前後依需要補

  • 進團隊前建議讀：資深工程師的工作方法（需求、估工、溝通、接手舊系統）。
  • 職缺有寫再學：Kubernetes 實戰、資料儲存選型（Redis、MongoDB、搜尋）、API 風格（GraphQL、gRPC）、AWS 雲端服務、Supabase。
  • 履歷差異化，最值得優先挑：AI 應用開發（第 1～9 課就夠做出 LLM 功能）。
  • 前端支線（你本來就會 Vue，挑著讀）：前後端串接先讀 Vue 第 16、20 課，搭配認證第 4～6 課與交付實戰第 3 課；網頁基礎優先讀第 1、4、5、18～20、23 課；React 等目標職缺要求 React／Next.js 再學。

課程地圖上標「選修」的課偏向原理或進階，第一輪先跳過；標「可略讀」的是你每天在用的東西，掃過重點、做練習即可。
