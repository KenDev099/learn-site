跨過信任邊界的資料都不能相信。先認證出 principal、再授權；用對密碼學工具，密碼用慢雜湊讓攻擊者每一次猜測都變貴。[回 認證與資安 學習地圖](../index.html)

## A 一個請求的旅程 {span=2}
```flow LR
(瀏覽器 GET /orders/42) -> 認證: 跨過信任邊界
認證 -> 授權: 得到 principal
授權 -> *[(orders)]: 你能看 42 嗎
認證 --> [401]: 你是誰？失敗
授權 --> [403 或 404]: 不准
```
識別是宣稱身分、認證是證明身分、授權是決定能做什麼。認證的結果是 principal，之後的判斷只看它。從瀏覽器進來的、從第三方回來的資料，都要在你這一側重新驗證；前端的路由守衛和隱藏按鈕不是安全機制。

## B 401、403、404 怎麼選
| 狀態碼 | 意思 | 什麼時候 |
|---|---|---|
| 401 | 沒認證或認證失敗 | 沒帶 token、過期、簽章不對；必須帶 `WWW-Authenticate` |
| 403 | 知道你是誰，但不准 | 資源存在本來就不是祕密，例如店員按退款 |
| 404 | 找不到，或不願透露存不存在 | 別人的訂單回跟「不存在」一樣的 404，擋住列舉 |

先檢查登入，再查資料：不然沒登入的人看 404 和 401 的差異，也能知道資料存不存在。判斷：回 403 會不會洩漏不該知道的事？會就回 404。

## C 認證因素與資安原則
| 因素 | 例子 | 弱點 |
|---|---|---|
| 你知道的 | 密碼、PIN | 會被猜、被釣魚、被別站外洩 |
| 你擁有的 | 驗證器 App、安全金鑰、passkey | 會遺失，要有復原流程 |
| 你本人的特徵 | 指紋、臉 | 換不掉，不該送到伺服器 |

MFA 是至少兩種「不同類型」的因素；密碼加安全問題都是「知道的」，不算。

## D 五件常被混為一談的事 {span=2}
| 工具 | 要金鑰嗎 | 能還原嗎 | 保護什麼 | 咖啡店的例子 |
|---|---|---|---|---|
| 編碼 | 不用 | 任何人都能 | no 什麼都不保護 | 把位元組放進網址、JSON |
| 雜湊 | 不用 | 不能 | ok 完整性 | 檢查下載的檔案、存 token |
| HMAC | 雙方同一把 | 內容本來就看得到 | ok 完整性加來源 | 簽名的 cookie、webhook |
| 加密 | 要 | 有金鑰才能 | ok 機密性 | 資料庫裡的身分證字號 |
| 簽章 | 私鑰簽、公鑰驗 | 不需要還原 | ok 完整性加來源，驗的人簽不出來 | JWT 的 ES256、passkey |

base64 是編碼，不是加密。

## E 密碼學工具的用法
```kv cols=1
位元組: 字串先 TextEncoder 轉 UTF-8，再編碼成 hex 或 base64url；位元組參數寫 `Uint8Array<ArrayBuffer>`
SHA-256: 輸出 32 bytes；不能反推不代表猜不到，可能性少的輸入雜湊後仍可列舉
安全亂數: 秘密一律用 crypto.getRandomValues
熵: log2(字元數) × 長度；隨機位元組每 byte 8 bits
有金鑰的雜湊: 用 HMAC，不用 SHA-256(秘密 + 訊息)；HMAC 不隱藏內容
```
```callout warn 比對簽章與 token 用常數時間比較
`crypto.subtle.verify`、`timingSafeEqual` 或 XOR 累加；用 `===` 比對會洩漏比對到第幾個字元。
```

## F 密碼怎麼存
| 做法 | 結果 |
|---|---|
| 明文 | no 資料庫外洩就全部外洩 |
| 可還原的加密 | no 金鑰常和資料庫一起被拿走，伺服器也不需要還原 |
| SHA-256 | no 越快越好，正好幫攻擊者逐一猜 |
| 慢雜湊加 salt | ok 每一次猜測都變貴 |

salt 每人一個、隨機、跟雜湊存在一起、不用保密，讓彩虹表失效。pepper 存在資料庫以外，是額外的一層。

## G 慢雜湊：參數存進同一個字串 {span=2}
```flow LR
(email 與密碼) -> verifyPassword: 用存的參數重算，常數時間比較
verifyPassword -> {正確?}
{正確?} --> [401 回應跟查無帳號一樣]: 否
{正確?} -> {needsRehash?}: 是
{needsRehash?} -> [用新參數重新雜湊並 UPDATE]: 參數過時
[用新參數重新雜湊並 UPDATE] -> *發 session
{needsRehash?} -> *發 session: 否
```
- 格式：`pbkdf2_sha256$600000$<salt>$<雜湊>`；Argon2 用 PHC 字串 `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<hash>`。
- OWASP 首選 Argon2id（m=19 MiB、t=2、p=1）；PBKDF2-HMAC-SHA256 要 600,000 次；bcrypt 只吃 72 bytes。參數在自己的伺服器上量。
- 驗證一定讀存的參數：用現在的設定重算，調高次數那一刻舊雜湊全部對不上。只有登入成功那一刻有明文，可以順便升級。

## H 密碼政策與外洩檢查
```kv cols=1
長度: NIST SP 800-63B-4：只靠密碼至少 15 字元，搭配 MFA 至少 8
不要做: 不設組成規則、不定期強迫改
外洩清單: 註冊、改密碼時比對
長度怎麼算: 先做 NFC，以 code point 計長度
```
```sequence
participants: 咖啡店 API, HIBP
咖啡店 API -> 咖啡店 API: SHA-1(密碼)
咖啡店 API -> HIBP: GET /range/前 5 碼，加 Add-Padding
HIBP --> 咖啡店 API: 幾百行「後 35 碼:次數」
咖啡店 API -> 咖啡店 API: 在自己的伺服器上比對
note 咖啡店 API, HIBP: 密碼和完整雜湊都沒有離開你的伺服器
```
這裡的 SHA-1 只是查表的索引，存密碼一樣用慢雜湊。
