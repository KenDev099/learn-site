API 風格與整合：GraphQL、gRPC 與契約 學習地圖

REST 你已經會了（Node 課第 14 課、NestJS 課第 23 課）。但職場上常同時遇到另外兩種 API：前端（Vue、React、App）常用 GraphQL 一次拿齊一個畫面要的資料；後端服務之間常用 gRPC 互相呼叫。這門課用同一間咖啡店，從「什麼時候該選哪一種」開始，一步一步做出菜單與訂單歷史的 GraphQL API（schema、resolver、N+1 與 DataLoader、cursor 分頁、錯誤、欄位層級授權、深度與成本限制、persisted operations、快取、schema 演進、從 Vue 呼叫），再做一個庫存的 gRPC 服務（protobuf、程式碼產生、unary 與串流、deadline 與取消、狀態碼、不破壞相容的 proto 變更）。

後半段是資深工程師的工作：用契約測試（Pact）和 schema 檢查讓前後端、服務之間改 API 時不互相弄壞；判斷什麼時候需要 API gateway、什麼時候該做 BFF（backend-for-frontend）。期末專題把 GraphQL 端點、gRPC 庫存服務、deadline 預算和契約測試組成一條完整的咖啡店下單查詢路徑。

第 1 課在頁面裡練習；第 2 課起在你自己的電腦上練習（learn/api-styles/practice，Node 24 + node:test，第一次先 npm install），不需要 Docker：資料庫用在 Node 裡執行的 PGlite（跟 PostgreSQL 課同一個版本）。每課另有至少 3 題選擇題。
