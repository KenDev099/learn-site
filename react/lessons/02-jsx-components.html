階段 1：心智模型：從 Vue 到 React · 第 2 課

JSX 與元件：props、children、條件與列表

設計師交來咖啡店菜單頁的 HTML，你貼進 React 元件。畫面出來了，console 卻跳出 Invalid DOM property `class`；購物車是空的時候，角落多了一個「0」；店員在拿鐵的備註框打了「少冰」，下架美式咖啡之後，「少冰」跑到卡布奇諾那一列。三個都不是 React 的 bug，是把 Vue 範本的習慣帶進了 JSX。

這課的路線：
  1. 練習環境：裝好本機的 Vite＋React 專案，從這課起練習都在自己的電腦上用測試判分。
  2. JSX、元件與 props：標籤怎麼變成函式呼叫，為什麼要寫 className，Vue 的 props 和 emit 在 React 怎麼寫（開場問題的最小答案）。
  3. children：後台每個區塊共用的外框怎麼寫，對應 Vue 的 slot。
  4. 條件渲染：v-if 換成 if、三元與 &&，購物車空的時候角落為什麼多一個「0」。
  5. 列表、key 與 Fragment：v-for 換成 map，key 選錯時備註為什麼跑到別的商品，一次回傳兩列 <tr> 怎麼包。
這課會用到：
  • 第 1 課：元件是函式，state 進、畫面出；set 之後 React 重新呼叫它，比對結果再更新 DOM。
  • TS 課第 18 課的解構與預設值：function f({ name, vip = false }) 從物件參數取出欄位，沒傳的用預設值。
  • TS 課第 14 課的物件型別：type Props = { name: string; vip?: boolean } 描述物件有哪些欄位，? 表示可以不給。

JSX：寫在 JavaScript 裡的標籤

Vue 的 <template> 會被編譯成 render 函式（Vue 課第 7 課）。React 沒有範本，標籤直接寫在函式裡，這種語法叫 JSX（JavaScript XML），檔名 .tsx。練習環境的 tsconfig 是 "jsx": "react-jsx"，用 TypeScript 6.0.3 轉譯一段看看：

// 你寫的
<li className={vip ? 'customer vip' : 'customer'}>
  {customer.name}（{points} 點）
  {vip && <span className="tag">VIP</span>}
</li>

// 轉出來的（import 由編譯器自動加）
import { jsx as _jsx, jsxs as _jsxs } from 'react/jsx-runtime'
_jsxs('li', { className: vip ? 'customer vip' : 'customer', children: [
  customer.name, '（', points, ' 點）',
  vip && _jsx('span', { className: 'tag', children: 'VIP' }),
] })

看懂這段，JSX 的規則都說得通：

  • 屬性是物件的鍵，用 DOM 屬性名稱：className（class 是 JavaScript 保留字）、htmlFor、駝峰的 onClick。寫 class，React 19.3.1 仍會放上 DOM，但警告 Invalid DOM property `class`. Did you mean `className`?，TypeScript 也會報錯。
  • { } 裡放 JavaScript 運算式，等於 {{ }} 加 :prop。if、for 是陳述式放不進去，所以條件和列表用三元、&&、map。
  • 標籤中間的內容變成 children。
  • 函式只能回傳一個值，所以只能有一個根元素；並排的元素用 Fragment。
  • style 收物件：style={{ fontWeight: 'bold', marginTop: 8 }}，駝峰屬性，數字自動加 px。

結果是 { type: 'li', key: null, props: {…} } 這樣的普通物件，React 拿它跟上一次比對再改 DOM，跟 Vue 的虛擬 DOM 同一個想法。

開場的三個問題都是把 JSX 當成 HTML 範本：class 是屬性名稱沒換成 DOM 的 className；「0」是 && 左邊放了數字，React 把 0 當成值畫出來；備註跑掉是列表的 key 沒選對，React 把舊的輸入框配給了另一個商品。細節在後面的〈條件渲染〉與〈列表與 key〉。

Vue 範本JSX
{{ product.name }}{product.name}
:disabled="soldOut"disabled={soldOut}
:class="{ vip }"className={vip ? 'customer vip' : 'customer'}（沒有物件語法）
@click="select(c.id)"onClick={() => select(c.id)}
v-html="html"dangerouslySetInnerHTML={{ __html: html }}

跟 {{ }} 一樣，{ } 裡的字串會被跳脫：{'<img src=x onerror=alert(1)>'} 在畫面上就是那串文字，顧客留言直接放進去是安全的。插入原始 HTML 只能用名字故意取得很嚇人的 dangerouslySetInnerHTML，內容來自使用者就是 XSS 漏洞。

元件與 props：函式的參數

元件是回傳 JSX 的函式，名稱一定要大寫開頭：小寫的 <customerTag /> 會被當成 HTML 標籤，React 警告 The tag <customertag> is unrecognized in this browser。父元件寫在標籤上的屬性收進第一個參數 props。Vue 用 defineProps 宣告輸入、defineEmits 宣告輸出（Vue 課第 9 課）；React 兩個都是 props：輸入是值，輸出是父元件傳進來的函式。

import type { Customer } from '../../helpers/fake-api.ts'

type Props = {
  customer: Customer
  vip?: boolean                          // 可以不傳
  onSelect: (customerId: number) => void // Vue 的 emit('select', id)
}

export function CustomerTag({ customer, vip = false, onSelect }: Props) {
  return (
    <button type="button" className={vip ? 'customer vip' : 'customer'} onClick={() => onSelect(customer.id)}>
      {customer.name}
    </button>
  )
}
// 使用：<CustomerTag customer={c} vip onSelect={id => openOrders(id)} />（只寫 vip 等於 vip={true}）
  • 預設值寫在解構：vip = false 只在沒傳或傳 undefined 時生效，null、0 不會。React 19 移除了函式元件的 defaultProps，舊範例別照抄。
  • props 唯讀：每次 render 拿到新的一份。開發模式下 props 物件是凍結的，模組又是嚴格模式，寫 props.vip = true 直接丟 TypeError。會變的值是 state（第 3 課）。
  • 型別只靠 TypeScript：React 19 也移除了 propTypes 檢查，用 any 等於不檢查。

最常見的事件 bug 是少寫箭頭函式：

onClick={onSelect(customer.id)}        // ✗ render 時就呼叫，把回傳值 undefined 當 handler
onClick={onSelect}                     // ✗ 按下才呼叫，但收到的是事件物件，不是 id
onClick={() => onSelect(customer.id)}  // ✓ 傳函式，按下時才呼叫

Vue 的 @click="onSelect(c.id)" 會被編譯器包成函式；JSX 的 { } 是普通 JavaScript，寫了括號就是現在呼叫。

💡 實務上：props 型別就是元件的 API 文件
同一個商品卡片會被前台、後台、外送頁面拿去用，別人看 Props 就知道要傳什麼、會收到什麼回呼。Review 時看三件事：必填、可選分得對不對（忘了傳 onAdd 應該編譯時就報錯，而不是按了沒反應）；回呼參數是不是剛好夠用（給 id，不要把 DOM 事件物件丟出去）；有沒有 any。回呼命名用 onXxx，跟 onClick 一致，一看就知道是「通知父元件」。

children：React 的 slot

後台每個區塊的外框都一樣，只有標題、內容、右上角的按鈕不同。Vue 用 <slot />（Vue 課第 11 課）；React 沒有 slot 語法，標籤中間的內容就是叫 children 的 prop，具名 slot 則是普通的 prop：

import type { ReactNode } from 'react'

type Props = { title: string; children: ReactNode; actions?: ReactNode }

export function Card({ title, children, actions }: Props) {
  return (
    <section>
      <header><h2>{title}</h2>{actions !== undefined && <div className="actions">{actions}</div>}</header>
      {children}
    </section>
  )
}

<Card title="今日訂單" actions={<button type="button">匯出</button>}>
  <p>共 12 筆</p>
</Card>

ReactNode 是「React 能畫的任何東西」：元素、字串、數字、null、undefined、布林值，以及它們的陣列。children 可能是文字、一個元素或 map 出來的一串，型別用 ReactNode，不要用只收單一元素的 ReactElement。

VueReact
<slot />{children}
<template #actions>型別是 ReactNode 的 prop：actions={<button>…</button>}
v-if="$slots.actions"{actions !== undefined && …}
後備內容 <slot>預設</slot>解構預設值
作用域 slot傳函式當 prop（render props，第 10 課）

「有沒有傳」是普通的判斷，不用 $slots。比對 undefined 最直接：寫 {actions && …} 的話，actions={0} 會畫出一個「0」（下一節）。

💡 實務上：外框元件只管外框
卡片、對話框、頁面版型會在專案裡用上百次。用 children 寫，外框不需要知道裡面放什麼。反過來用一堆 props 描述內容（items、showPrice、buttonText……），每多一種需求就多一個 prop，最後沒人敢動。設計時先分清楚：每個地方都一樣的（標題樣式、邊框、間距）寫死在元件裡，使用的人決定的（內容、按鈕）開成 children 或 ReactNode prop。

條件渲染：if、三元與 &&

JSX 沒有 v-if，用 JavaScript 本身：

export function OrderBadge({ pending, rush }: { pending: number; rush: boolean }) {
  if (pending === 0) return null                     // 提早 return：整個換掉（null 是什麼都不畫）
  return (
    <p>
      待處理 {pending} 筆
      {rush && <strong>（有急件）</strong>}           {/* &&：有才畫，等於只有 v-if */}
      {pending >= 10 ? <span>忙碌</span> : <span>正常</span>}   {/* 三元：v-if／v-else */}
    </p>
  )
}

{ } 裡的 null、undefined、true、false 都不會畫出來，所以 false && … 什麼都沒有。問題在數字：

{pending && <p>待處理 {pending} 筆</p>}   // pending 是 0 → 畫面出現「0」

a && b 在 a 是 falsy 時回傳 a 本身，0 && … 的結果是數字 0，而數字是 React 會畫的東西。實測 React 19.3.1：{0 && <p/>} 畫出 0，{NaN && <p/>} 畫出 NaN，{'' && <p/>} 什麼都沒有。Vue 的 v-if="pending" 只拿值判斷真假，所以從 Vue 來的人特別容易中。修法：左邊一定是布林值，pending > 0 && …、list.length > 0 && …，或用三元。

React 沒有 v-show。不畫就是從 DOM 移除；只想藏起來、保留 DOM，用 hidden 屬性或 CSS：<div hidden={!open}>。取捨跟 Vue 課第 7 課的 v-if／v-show 一樣，而且藏起來的內容開發者工具看得到，不能拿來藏沒有權限的資料。

💡 實務上：空狀態、載入中、錯誤都要畫
訂單列表、購物車實際上至少有四種畫面：載入中、出錯、沒有資料、有資料。新手常只寫最後一種，結果空購物車顯示空白表格和「合計 $0」，API 失敗時一片空白。這些分支用提早 return 寫最清楚，一個 if 一種畫面。Review 看到 {list.length && …} 直接請對方改成比較式；也可以開 eslint-plugin-react 的 react/jsx-no-leaked-render 規則，在編輯器裡就抓出來。

列表與 key：備註為什麼會跑掉

沒有 v-for，用陣列的 map。要篩選就先 filter 再 map，不會有 v-if 和 v-for 誰先執行的問題：

const shown = keyword ? customers.filter(c => c.name.includes(keyword)) : customers   // 新陣列，不改 props
if (shown.length === 0) return <p>找不到顧客</p>
return (
  <ul>
    {shown.map(c => (
      <li key={c.id}><CustomerTag customer={c} onSelect={onSelect} /></li>
    ))}
  </ul>
)

map 回傳的最外層元素要有 key，跟 v-for 的 :key 同一回事：React 用 key 判斷「新的這一個對應舊的哪一個」，對上了就重用那個 DOM 節點（和裡面打的字、元件的 state）。沒寫 key，React 警告 Each child in a list should have a unique "key" prop，並且照位置對應，等於用索引當 key。

  • 用資料本身的 id。索引只有在列表永遠不刪除中間、不插入、不排序時才安全。
  • 同一層要唯一：用名稱當 key，兩個同名但不同 id 的商品會撞號，React 警告 Encountered two children with the same key，行為不保證。
  • 不能每次 render 都不同：key={Math.random()} 讓每一列每次都重建，輸入框的字每次都不見。
  • key 不是 prop：元件裡讀 props.key 是 undefined，開發模式還會警告 `key` is not a prop。需要 id 就另外傳。
💡 實務上：key 的 bug 在刪除、排序之後才出現
跟 Vue 一樣，開發時看不出來，常是客服轉來「我改的是拿鐵，存到卡布奇諾」。Review 看到 .map( 先看 key 從哪來：是不是索引、是不是可能重複的名稱、是不是合併了兩支 API 的資料（id 可能撞號，要加前綴）。還沒存檔、後端還沒給 id 的品項，在建立的當下產生 id 存進資料（crypto.randomUUID()），不要在 render 時產生。

Fragment：一次回傳兩個元素

訂單明細每個品項要畫兩列 <tr>，map 的箭頭函式只能回傳一個值，習慣性用 <div> 包起來，React 就警告 In HTML, <div> cannot be a child of <tbody>：HTML 不允許，瀏覽器解析這種 HTML 時會把 <div> 移出表格。要的是「包起來但不產生 DOM 節點」，就是 Fragment，等於 Vue 的 <template v-for>：

import { Fragment } from 'react'

<dl>
  {items.map(item => (
    <Fragment key={item.productId}>
      <dt>{item.name} × {item.quantity}</dt>
      <dd>${item.price * item.quantity}</dd>
    </Fragment>
  ))}
</dl>

簡寫 <>…</> 在元件回傳兩個並排的元素時最常用，但它不能寫 key，在 map 裡要寫完整的 <Fragment key={…}>。字串用 && 判斷沒問題，空字串 '' 不會被畫出來；但只判斷 !== undefined 的話，空字串會通過，多出一個空的元素。

練習

在 learn/ 執行 node check.mjs react 02，改 react/practice/work/02/ 的檔案，每個起始檔最上面的註解有完整要求。測試傳入的商品和陣列都凍結過，元件改到它們（sort()、push()、改屬性）會丟 TypeError。每一題都要求 React 不印出任何警告。

練習 1：把設計師的 HTML 改成 ProductCard。props 用 TypeScript 宣告：product（Product）、soldOut?（boolean，預設 false）、onAdd（收到商品 id，必填），不能用 any。<h3> 顯示「品名 $價格」；<article> 的 class 平常是 card，售完是 card sold-out；按一次「加入」呼叫一次 onAdd(product.id)，render 時不能呼叫。售完時按鈕 disabled，並多一個 <span className="badge">售完</span>；沒售完時不能有這個 span。

練習 2：Panel 外框，props 是 title（string，必填）、children（ReactNode，必填）、footer?（ReactNode）。<section className="panel"> 裡依序是顯示 title 的 <h2>、裝 children 的 <div className="panel-body">，有傳 footer 才有 <footer>。children 可能是元素、文字加數字或 map 出來的一串；footer 不能跑進 panel-body。少了 title、title 給數字、沒有 children 都要是型別錯誤。

練習 3：CartSummary。count 是 0 時整個元件只有 <p>購物車是空的</p>；否則依序是 <p>共 N 件</p>、discount 大於 0 才有的 <p>折扣 -$N</p>、<p>合計 $N</p>，最後 total 滿 500（含）是 <p>免運</p>，不滿是 <p>再買 $差額 免運</p>。畫面上不能多出任何文字（包括「0」），不顯示的東西不能留在 DOM 裡。

練習 4：MenuList 把每個商品畫成一個 <li>（順序跟陣列一樣，結構照起始檔那一列），按「加入品名」呼叫 onAdd(商品 id)。有傳 category 只顯示那個分類；要顯示的是 0 個（空陣列或篩選後沒有）時只畫 <p>目前沒有商品</p>，沒有 <ul>。測試會在備註框打字後刪掉第一個商品、把順序反過來，字要跟著商品走，每個 <li> 要是原本的 DOM 節點；也會傳入兩個同名不同 id 的商品。

練習 5：OrderTable 每個品項一列 <tr>（品項、數量、小計 = price × quantity），note 有內容才多一列 <tr className="note"><td colSpan={3}>備註：…</td></tr>，沒有 note 或空字串都不能有。<tbody> 的直接子元素只能是 <tr>；每組的 key 用 productId，順序反過來時原本的 <tr> 要跟著品項移動。

練習 6：{orders.length && <OrderList orders={orders} />}，orders 是空陣列時畫面上有什麼？

✓ && 左邊是 falsy 時回傳左邊的值本身，這裡是數字 0。React 不畫 null、undefined、布林值，但數字照畫，所以不是 a，也不會丟錯（b）。右邊根本沒被求值（d）。改成 orders.length > 0 && …。

練習 7：{products.map(p => <ProductCard key={p.id} product={p} />)}，ProductCard 裡讀 props.key 會拿到什麼？

✓ key 只用來對應新舊元素，React 不會把它放進 props，開發模式還會警告 `key` is not a prop。要 id 就讀 product.id 或另外傳一個 prop。c 是 React 內部存 key 的方式（元素物件的 key 是字串），元件讀不到。

練習 8：Vue 的對話框有 <slot /> 和 <slot name="actions" />，改寫成 React 最常見的做法是？

✓ 具名 slot 在 React 就是普通的 prop，JSX 是值，可以像資料一樣傳。a 依賴子元素的位置和數量，children 只有一個時根本不是陣列。c 傳不了事件處理函式，又打開 XSS 的門。

常見錯誤

  • 照 HTML 寫 class、for：用 className、htmlFor。
  • onClick={onAdd(id)}：render 時就呼叫了。傳函式 () => onAdd(id)。
  • 改 props：唯讀，開發模式下丟 TypeError。排序用 toSorted()，會變的值放 state。
  • {count && …}：count 是 0 時畫出「0」。左邊用比較式或改三元。
  • key 用索引、名稱或 Math.random()：錯位、撞號或每次重建。用資料的 id。
  • 在 map 裡用 <> 或 <div> 包多個元素：簡寫寫不了 key，<div> 在表格裡不合法。用 <Fragment key>。
  • children 宣告成 ReactElement：文字、陣列傳不進來。用 ReactNode。

小結

  • JSX 轉成 jsx(type, props) 呼叫，結果是普通物件；屬性用 DOM 名稱，{ } 放運算式，字串會被跳脫。
  • 元件是大寫開頭的函式，props 是唯讀參數；輸出是 onXxx 回呼，預設值寫在解構，型別靠 TypeScript。
  • children 是預設 slot，具名 slot 是 ReactNode prop。
  • 條件用提早 return、三元、&&；&& 左邊要是布林值，不然 0 會被畫出來。
  • 列表先 filter 再 map，key 用穩定、唯一的 id，key 不會傳進元件。
  • 不想多一層 DOM 用 Fragment，map 裡寫 <Fragment key>。
