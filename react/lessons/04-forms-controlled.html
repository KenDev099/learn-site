階段 1：心智模型：從 Vue 到 React · 第 4 課

表單：受控元件與輸入處理

咖啡店的飲料客製表單從 Vue 改寫成 React。第一版上線後，客服收到三種回報：備註欄打不進字；把數量清空，輸入框卻自己跳出一個 0；用注音搜尋商品，打「ㄋㄚˊ」的過程中清單一直閃「找不到商品」，選字按的 Enter 還直接把第一筆加進購物車。這三個問題在 Vue 裡都沒遇過，因為 v-model 幫你處理掉了；React 沒有 v-model，表單的每一條線都要自己接。

這課的路線：
  1. 受控元件：React 沒有 v-model，value 加 onChange 怎麼接成一個圈，備註打不進字是少了哪一半（開場問題的最小答案）。
  2. 每種輸入讀什麼：select、radio、checkbox、數字各讀哪個屬性，清空數量為什麼跳出 0。
  3. label、送出與驗證：取餐資料這類表單要有的 label、錯誤訊息出現的時機，以及防止重複送出。
  4. 非受控與 FormData：欄位多、不需要每打一個字就反應時，讓瀏覽器保管值，送出時一次拿。
  5. 中文輸入法：注音組字中 onChange 照樣觸發，搜尋框和「按 Enter 送出」的輸入框怎麼寫才不出錯。
這課會用到：
  • 第 3 課的 state：useState 的值是這次 render 的快照，新值依賴舊值用 updater；更新要做出新物件；算得出來的值不放 state；換 key 會重建元件、重設 state。
  • 第 2 課的 JSX 與練習環境：屬性用 DOM 名稱（htmlFor、onChange），{ } 裡放運算式；練習用 node check.mjs react 編號 判分。

受控元件：value 加 onChange，就是手寫的 v-model

Vue 的 <input v-model="note">（Vue 課第 10 課）是語法糖，概念上展開成 :value 加 @input。React 沒有這個糖，你直接寫展開後的樣子：

const [note, setNote] = useState('')

<textarea value={note} onChange={e => setNote(e.target.value)} />

這種寫法叫受控元件（controlled component）：輸入框顯示什麼，完全由 React 的 state 決定。資料的流向是一個圈：

開場「備註打不進字」就是只寫了一半：

<textarea value={note} />   // ✗ 有 value、沒有 onChange

React 19.3.1 實測：使用者打字之後，輸入框還是原本的值，console 出現

You provided a `value` prop to a form field without an `onChange` handler. This will render a read-only field.
If the field should be mutable use `defaultValue`. Otherwise, set either `onChange` or `readOnly`.

訊息給了三條路：要能編輯就加 onChange；只想給初始值就用 defaultValue（下面的非受控）；真的要唯讀就加 readOnly。

開場另外兩個問題也是這個圈沒接好：數量欄把空字串轉成數字存進 state，Number(\'\') 是 0，又被 value 寫回輸入框；用注音打字時，組字中的每一次輸入都會觸發 onChange，拿去搜尋就會用「ㄋㄚ」篩選。細節在後面的〈每種輸入讀什麼〉與〈中文輸入法〉。

和 Vue 對照：

Vue v-modelReact 受控元件
寫法一個指令，編譯器展開自己寫 value＋onChange
事件文字框聽 input，checkbox／radio／select 聽 change一律 onChange；官方文件：每次按鍵都觸發，行為像瀏覽器的 input 事件（不是 DOM 的 change）
修飾符.trim、.number、.lazy沒有，在事件處理函式或 render 時自己轉

還有一條規則：受控元件的 value 不能是 undefined 或 null。React 把 value={undefined} 當成「沒有給 value」，也就是非受控；等 state 變成字串，又變成受控。實測會印出 A component is changing an uncontrolled input to be controlled.。從 API 拿到的資料可能是 null，初始值用空字串，或寫 value={customer.note ?? ''}。

onChange 裡要同步把 e.target.value 原樣寫進 state。官方文件列了兩種會讓游標跳到開頭的寫法：寫進去的不是 e.target.value（例如 setNote(e.target.value.toUpperCase())），以及非同步才更新（包在 setTimeout 裡）。要轉大寫、去空白，存原文、顯示或送出時再轉。

每種輸入讀什麼：select、radio、checkbox、數字

不同的輸入，控制它的屬性和讀值的方式不一樣（依 react.dev 的 <input>、<select>、<textarea> 文件）：

元素控制用的 proponChange 裡讀要注意
文字、<textarea>valuee.target.valuetextarea 不能用 children 放內容，要用 value 或 defaultValue
type="number"valuee.target.value（字串）清空時是 ''
<select>value（multiple 時是陣列）e.target.value（字串）不支援在 <option> 上寫 selected

三個最常見的型別錯誤：

// ✗ select 給你的是字串 "4"，products 的 id 是數字 4，find 找不到
onChange={e => set('productId', e.target.value)}
// ✓ 存進 state 前轉成數字
onChange={e => set('productId', Number(e.target.value))}

// ✗ checkbox 的 value 是 "on"，非空字串永遠是 truthy，取消勾選也是「外帶」
onChange={e => set('takeout', e.target.value)}
// ✓
onChange={e => set('takeout', e.target.checked)}

// ✗ 數量存成數字：清空時 Number('') 是 0，輸入框立刻被寫回 0，使用者刪不掉
onChange={e => set('quantity', Number(e.target.value))}
// ✓ state 存字串，計算時才轉；不合法時顯示提示
onChange={e => set('quantity', e.target.value)}

第三個就是開場的「清空跳出 0」，React 19.3.1 實測：清空之後 value 是 "0"。Vue 的 .number 轉不出數字時會保留原字串（Vue 課第 10 課），React 沒有這層保護。原則是：state 存使用者打的原文，衍生的數字、摘要、錯誤在 render 時算，這是第 3 課「算得出來的值不放 state」的延伸。

一個 state 物件管整張表單

欄位多的時候，可以把整張表單放在一個物件裡，用一個函式更新任一欄位。泛型 K 把「哪個欄位」和「值的型別」綁在一起，寫 set('takeout', e.target.value) 時 TypeScript 會報錯：

type Draft = { productId: number; quantity: string; sweetness: Sweetness; takeout: boolean; note: string }

const [draft, setDraft] = useState(initial)

function set<K extends keyof Draft>(key: K, value: Draft[K]) {
  setDraft(d => ({ ...d, [key]: value }))      // 複製一份再改，保留其他欄位
}

<input type="radio" name="sweetness" value="half"
  checked={draft.sweetness === 'half'}
  onChange={() => set('sweetness', 'half')} />

<button type="button" onClick={() => setDraft(initial)}>重設</button>
<p role="status">{summarize(draft, products)}</p>   // 摘要每次 render 算

兩個坑：setDraft({ [key]: value }) 會把其他欄位丟掉，物件 state 不會自動合併；draft[key] = value; setDraft(draft) 改了原物件又傳同一個參考，React 判定沒變（第 3 課）。「重設」能把畫面帶回初始值，前提是每個欄位都是受控的：只改 state、欄位卻用 defaultValue 的話，state 回去了，畫面上的字還留著。

💡 實務上：型別錯誤多半在「表單 → API」的邊界爆開
咖啡店後台的商品編輯頁，最常見的 bug 是送到 API 的價格是 "120"、商品 id 是 "4"：畫面一切正常，後端嚴格驗證就回 400，寬鬆的則存成字串，報表加總時才出事。資深工程師會讓表單 state 的型別和 API 的型別分開：state 存畫面上的樣子（字串），送出前用一個函式轉型並驗證。review 時特別看 select、checkbox、number 的 onChange 有沒有轉型。

label、送出與驗證

咖啡店的取餐資料表單只有姓名和手機兩格，但正式環境要顧的事不少。

label 要真的對到輸入框

旁邊放一個 <span>姓名</span> 看起來一樣，但報讀器不知道這兩個字屬於哪一格，點文字也不會聚焦。兩種寫法：把 input 包在 <label> 裡，或用 htmlFor 對到 input 的 id（JSX 裡 for 寫成 htmlFor）。元件可能在一頁出現兩次時，寫死的 id 會重複，React 官方的建議是用 useId() 產生：

const id = useId()
<label htmlFor={id + '-phone'}>手機</label>
<input id={id + '-phone'} type="tel" autoComplete="tel" value={form.phone} onChange={…} />

只加 aria-label="姓名" 能讓報讀器唸出名稱，但點文字不會聚焦。有看得到的文字就用 label。

送出：掛在 form 的 onSubmit，記得 preventDefault

async function handleSubmit(e: SubmitEvent<HTMLFormElement>) {
  e.preventDefault()          // 不然瀏覽器會把資料送到目前的網址並重新載入整頁
  …
}

<form onSubmit={handleSubmit} noValidate>
  …
  <button type="submit">送出</button>
</form>
  • 處理函式掛在 <form onSubmit>，不是按鈕的 onClick：在輸入框按 Enter 也會觸發表單送出，掛在 form 上兩種都接得到。Vue 的 @submit.prevent 在 React 就是自己呼叫 e.preventDefault()。
  • <form> 裡的 <button> 沒寫 type 時預設是 submit。「重設」「取消」這類按鈕要寫 type="button"，不然按了就送出。
  • 事件型別：@types/react 19.3 用 SubmitEvent<HTMLFormElement>；舊的 FormEvent 已標成 deprecated（型別檔的註解寫「FormEvent doesn't actually exist」），輸入框用 ChangeEvent<HTMLInputElement>。
  • noValidate 關掉瀏覽器內建的驗證泡泡，錯誤訊息全部由你的程式顯示，樣式和文字才一致。

錯誤是衍生值，「什麼時候顯示」才是 state

和 Vue 課第 18 課一樣，驗證寫成純函式，錯誤在 render 時由欄位的值算出來；要存的只有「使用者做過什麼」：

// 意見回饋表單：一格留言，至少 5 個字
const [message, setMessage] = useState('')
const [tried, setTried] = useState(false)        // 按過送出了沒：使用者做過的事，存 state
const error = message.trim().length < 5 ? '留言至少 5 個字' : null   // 衍生值：Vue 的 computed，在 React 就是 render 裡的一行

{tried && error && <p role="alert">{error}</p>}

常見的錯法是按送出時才 setError(validate(message))：錯誤變成另一份 state，使用者改對了，訊息還掛著，要再按一次送出才消失。

送出中、成功、失敗

非同步的送出有三個結果要處理，用一個狀態表示比三個布林清楚：'idle' | 'submitting' | 'failed'。

  • 開始：處理函式第一行檢查「是不是正在送出」，是就直接 return。按鈕的 disabled 只擋得住滑鼠點擊；程式觸發的 submit、狀態還沒更新前的連點，都要靠這一行。
  • 成功：清空欄位，同時把「按過送出」設回 false，不然空白的欄位會立刻報錯。
  • 失敗：await 包在 try／catch 裡，catch 時顯示錯誤、保留使用者輸入、讓按鈕恢復。下一次送出開始時，把狀態改成 submitting，上一次的失敗訊息就跟著消失。
💡 實務上：送出按鈕是重複訂單的第一道防線
線上點餐的「送出」被連點兩次，就可能變成兩筆訂單、刷兩次卡。前端要做到：送出中 disabled 並顯示「送出中…」、處理函式自己檢查狀態、失敗時保留輸入並給明確的重試訊息。但前端只能減少機率，網路重試、使用者重新整理再送一次都擋不住，所以會改資料的 API 還要有後端的防重複（Vue 課第 18 課的冪等鍵）。錯誤顯示的時機（送出後、或離開欄位後）是設計系統的規範，動手前先跟設計師對好，全站一致。

非受控：defaultValue、FormData 與 key

受控不是唯一的寫法。非受控元件（uncontrolled component）讓瀏覽器自己保管輸入框的值，React 只給初始值，要用的時候再去 DOM 拿：

// 商品編輯：只有按「儲存」時才需要欄位的值
function handleSubmit(e: SubmitEvent<HTMLFormElement>) {
  e.preventDefault()
  const data = new FormData(e.currentTarget)     // 送出那一刻，依每個欄位的 name 收集值
  const price = data.get('price')                // 一律是字串（或 null），要自己轉
  …
}

<form onSubmit={handleSubmit}>
  <label>價格 <input type="number" name="price" defaultValue={product.price} /></label>
  <label><input type="checkbox" name="onSale" defaultChecked={product.onSale} />上架</label>
</form>

FormData 的細節，happy-dom 21.0.4 實測和瀏覽器的規則一致：勾選的 checkbox 值是字串 "on"，沒勾選的完全不在 FormData 裡（get 回傳 null、has 是 false）；數字輸入框給的是 "3"。所以 data.get('onSale') === 'true' 永遠是 false，Object.fromEntries(data) 直接送出去，價格就是字串。

非受控有兩件事要知道：

  • defaultValue 只在掛載時生效：之後 props 換成另一個商品，輸入框不會跟著變。要重來，就用第 3 課的 key：給表單一個跟著「是哪一筆資料」變的 key，換資料時整個表單重建。key 不能每次都不同（例如 Math.random()），不然父元件任何一次重新 render 都會把使用者打到一半的內容清掉。
  • 還原用瀏覽器原生的 <button type="reset">：它把每個欄位設回 defaultValue／defaultChecked，不用寫程式。

怎麼選：

受控非受控
值在哪裡React stateDOM
打字時每個字都重新 render 元件不 render
適合邊打邊算（摘要、即時驗證、依輸入切換欄位）、程式要改欄位的值（重設、自動帶入）只在送出時才需要值的表單（搜尋條件、後台的編輯頁）

同一個欄位只能選一種，整個生命週期都不能換。React 19 的 <form action> 與 useActionState 是建立在非受控＋FormData 上的另一套送出方式，第 17 課再談。

💡 實務上：大型表單的效能問題，先問「這格需要受控嗎」
後台的會員資料、商品設定這類幾十個欄位的表單，全部受控又放在同一個大元件裡，每打一個字整張表單連同下拉選單、圖片預覽都重新 render，慢的電腦上會感覺到延遲。不要第一步就加 memo（第 19 課）：先看哪些欄位真的需要邊打邊反應，其他改成非受控、送出時用 FormData 讀，或拆成各自管 state 的小元件。導入表單函式庫前，先確認它走受控還是非受控的路線。

中文輸入法：組字中的 onChange

用注音、倉頡打字時，字還沒選定的過程叫組字（composition）。打「拿」時，W3C 的 UI Events 規格規定的事件順序如下（每次 input 之前還有 beforeinput 與 compositionupdate，這裡省略）：

compositionstart
input   輸入框「ㄋ」     isComposing: true
input   輸入框「ㄋㄚ」   isComposing: true
input   輸入框「ㄋㄚˊ」  isComposing: true
input   輸入框「拿」     isComposing: true   ← 選字後的最後一次 input，還在組字中
compositionend           data: '拿'

規格寫明組字期間的 input 事件 isComposing 是 true，compositionend 時 DOM 不再變動，所以後面不會再有 input。React 的 onChange 每一次 input 都會觸發；選字按的 Enter，keydown 也會先送到你的 onKeyDown。

Vue 的 v-model 在組字中不寫回變數（Vue 課第 10 課）。React 沒有這層處理：React 19.3.1 的 react-dom 只要輸入框的值變了就觸發 onChange，不看是不是在組字。所以「每次 onChange 就拿去搜尋」，注音使用者會看到清單用「ㄋ」「ㄋㄚ」篩選，閃出「找不到商品」。

直覺的修法是組字中直接 return，但這會打斷輸入：受控的輸入框不更新 state，React 會把 DOM 改回 state 的舊值，注音符號打不上去（本機用測試模擬過）。正確的做法是把兩件事分開，用兩個 state：

const [text, setText] = useState('')         // 輸入框顯示的字：組字中也要更新
const [keyword, setKeyword] = useState('')   // 拿去篩選的字：組完字才更新
const matched = products.filter(p => p.name.includes(keyword))

// 在 onChange 裡判斷這次輸入是不是組字中
const composing = (e.nativeEvent as InputEvent).isComposing
  • isComposing 是原生事件的屬性，從 e.nativeEvent 讀。React 的 ChangeEvent 型別裡 nativeEvent 是一般的 Event，所以要轉成 InputEvent；KeyboardEvent 的 nativeEvent 本來就有 isComposing。
  • 最後一次 input（選定「拿」）的 isComposing 還是 true，只靠 onChange 會漏掉，要在 onCompositionEnd 補一次。非組字的 onChange 與 compositionend 兩邊都更新關鍵字，就算實際環境的順序跟規格有出入，結果也一樣。
  • compositionend 的 e.data 只有這次組出來的字：輸入框已經有「紅」、再組出「茶」，data 是「茶」，e.currentTarget.value 才是「紅茶」。
  • 選字按的 Enter 也會送出 keydown。MDN 的建議寫法是 if (e.isComposing || e.keyCode === 229) return：組字的第一個或最後一個字，keydown 的 isComposing 可能是 false，但 keyCode 仍是 229。keyCode 已經 deprecated，這是少數還需要它的地方；在 React 裡 isComposing 一樣從 e.nativeEvent 讀。
💡 實務上：每個搜尋框、聊天輸入框都要用注音測一次
「按 Enter 送出」的輸入框（搜尋、留言、聊天）是組字問題的重災區：中文、日文、韓文使用者選字按的 Enter 被當成送出，訊息只送出一半的注音。資深工程師會把「用注音打字、選字按 Enter」寫進 QA 檢查清單，並把處理好組字的輸入框包成共用元件。要減少打 API 的次數是另一件事：用防抖或 第 21 課的 useDeferredValue，不是靠組字判斷。

練習

在 learn/ 執行 node check.mjs react 04，檔案在 react/practice/work/04/。測試用 Testing Library 的 userEvent 模擬真的點擊和打字；練習 4 用 fireEvent 依規格的順序送出組字事件（happy-dom 沒有輸入法）；練習 2 的 onSubmit 由測試決定什麼時候成功或失敗；測試傳入的 initial、member 是凍結的物件，改到就會出錯。

練習 1：DrinkForm 的五個欄位現在都用 defaultValue／defaultChecked，摘要寫死、「重設」沒作用。用一個 useState 存整份 Draft（初始值是 props 的 initial），把商品 select、數量、甜度 radio、外帶 checkbox、備註 textarea 全部改成受控。productId 在 state 裡是數字；quantity 在 state 裡保持字串，清空時輸入框要是空的。<p role="status"> 的摘要由 state 算出：拿鐵 × 2，半糖，外帶，共 $220（沒勾外帶寫「內用」），備註去掉頭尾空白後不是空的才在最後加 ，備註：少冰（輸入框裡保留原文）；數量不是 1～20 的整數（包含清空、0、21、2.5）時整句改成 數量要是 1～20 的整數。商品名稱與價格從 props 的 products 讀，測試會傳別的菜單。按「重設」所有欄位與摘要回到 initial。不能修改 initial 或 state 物件。

練習 2：PickupForm 的兩個欄位要有對應的 <label>（「姓名」「手機」，點文字能聚焦），欄位受控。驗證：姓名去掉頭尾空白後不能是空的（請輸入姓名）；手機要是 09 開頭的 10 碼數字（手機要是 09 開頭的 10 碼數字）。一進頁面不顯示錯誤，按過一次送出後每個錯誤是一個 <p role="alert">，之後每打一個字就跟著更新。處理函式掛在 form 的 onSubmit 並 preventDefault（按 Enter 也能送出）；有錯就不呼叫 onSubmit，沒錯就呼叫 onSubmit({ name: 去掉頭尾空白的姓名, phone })。等待 Promise 期間按鈕 disabled、文字是「送出中…」，這段時間再觸發 submit 也不能再呼叫。成功：清空欄位、回到沒按過送出的狀態。失敗：顯示 <p role="alert">送出失敗，請再試一次</p>、保留輸入、按鈕恢復；下一次送出開始時這個訊息消失。

練習 3：MemberEditor 的欄位寫了 value 卻沒有 onChange，打不進字。改成非受控：用 defaultValue／defaultChecked 帶入 member，不用 useState 存欄位（測試會數 commit 次數，打字、勾選時元件不能重新 render）。按「儲存」：preventDefault，用 new FormData(e.currentTarget) 讀出欄位，呼叫 onSave({ id: member.id, name: 去掉頭尾空白的姓名, points: 數字, newsletter: 布林 })。props 的 member 換成另一位會員（id 不同）時，欄位顯示新會員的資料、丟掉打到一半的內容；同一位會員重新 render 時，打到一半的內容不能被清掉。「還原」用 <button type="reset">，欄位回到 member 的資料，不能觸發儲存。

練習 4：ProductSearch 每次 onChange 都拿去篩選，注音組字中清單一直閃「找不到商品」，選字的 Enter 也被當成選第一筆。改成：輸入框受控，組字中的每個符號照常顯示；清單用「關鍵字」篩選（名稱包含關鍵字，空的顯示全部，沒有符合的顯示 <p>找不到商品</p>）；組字中關鍵字不更新，清單維持組字前的結果；compositionend 時關鍵字更新成輸入框當下的完整內容；不是輸入法的輸入（英文、貼上）每次都更新。在輸入框按 Enter 呼叫 onPick(清單的第一筆)，組字中的 Enter 不算，清單是空的也不呼叫。

練習 5：<input value={note} />，note 是 state，沒有寫 onChange。使用者在輸入框打字，會怎樣？

✓ 有 value 就是受控：React 每次都把 DOM 對齊 state，沒有 onChange 就沒人更新 state，輸入框等於唯讀。React 不會丟錯，而是在 console 印出「You provided a `value` prop to a form field without an `onChange` handler」。c 是非受控＋另外存 state 才會有的狀況。

練習 6：外帶 checkbox 寫成 checked={takeout} onChange={e => setTakeout(e.target.value)}（takeout 的型別寬鬆）。勾選再取消，會發生什麼？

✓ checkbox 沒有設定 value 屬性時，e.target.value 永遠是 "on"，跟有沒有勾無關；非空字串是 truthy，所以 checked 一直是真的。checkbox 和 radio 要讀 e.target.checked。b 是把 checked 誤以為會反映在 value 上。

練習 7：搜尋框寫 onChange={e => { setText(e.target.value); search(e.target.value) }}。使用者用注音打「拿」，search 會被呼叫幾次？

✓ React 的 onChange 對應瀏覽器的 input 事件，值變了就觸發，不分是否在組字。b 是 Vue v-model 的行為，React 沒有。要只用選定的字搜尋，把輸入框的字和關鍵字分成兩個 state，組字中（e.nativeEvent.isComposing）不更新關鍵字，在 onCompositionEnd 補上。

常見錯誤

  • 有 value 沒有 onChange：欄位變唯讀。要編輯就加 onChange；只想給初始值用 defaultValue；真的唯讀加 readOnly。
  • value 一開始是 undefined 或 null：先是非受控，有值之後變受控，React 警告。初始值用 '' 或 value={x ?? ''}。
  • 讀錯值或型別：select 給的是字串，存進 state 前 Number()；checkbox 的 e.target.value 永遠是 "on"，要讀 checked；數量存成 number，清空時會變成 0，state 要存字串。
  • onChange 裡改寫值或延後更新：trim()、toUpperCase() 或 setTimeout 會讓游標跳動、空白打不出來。原文同步存進 state，顯示或送出時再轉。
  • 物件 state 只寫一個欄位或直接改：setDraft({ [key]: value }) 丟掉其他欄位；draft[key] = value 不會 render。用 setDraft(d => ({ ...d, [key]: value }))。
  • 錯誤訊息存成 state：只在送出時更新，改對了還掛著。錯誤在 render 時由欄位的值算，state 只存「按過送出了沒」。
  • 送出寫在按鈕的 onClick、只靠 disabled 防重複：用 <form onSubmit> 並 e.preventDefault()，其他按鈕寫 type="button"；處理函式開頭自己檢查是否送出中，失敗要 catch。
  • 非受控欄位換資料卻沒換 key：defaultValue 只在掛載時生效。用 key={資料的 id}，不要用每次都不同的值。
  • 組字中跳過 setText 或每次 onChange 都搜尋：前者打斷注音，後者用注音符號搜尋。分成兩個 state，關鍵字在非組字的 onChange 與 compositionend 時更新；Enter 先檢查 isComposing。

小結

  • 受控元件就是手寫的 v-model：value（checkbox／radio 是 checked）加同步更新 state 的 onChange；React 的 onChange 每次按鍵都觸發，像原生的 input 事件。
  • e.target.value 一律是字串：select 要轉數字，checkbox 讀 checked，數字欄位在 state 存字串。state 存原文，摘要、錯誤、轉型後的值在 render 或送出時算。
  • 表單：label 用包住或 htmlFor＋useId；送出掛在 <form onSubmit> 並 preventDefault；錯誤是衍生值，「按過送出」才是 state；送出中自己擋重複，失敗保留輸入。
  • 非受控：defaultValue／defaultChecked 帶初始值，送出時用 FormData 讀（值都是字串，沒勾的 checkbox 不存在），換資料用 key 重建，還原用 type="reset"。
  • 中文組字：React 不會等組字結束。輸入框的字和拿去用的關鍵字分開存，在 compositionend 補上最後一次；Enter 先檢查 isComposing。

階段檢核：面試會問的觀念

這個階段一定要講得出來的 8 件事。先在心裡回答，再選。

練習 8：小費按鈕寫在元件裡，按了畫面一直是 0。為什麼？

function TipJar() {
  let tips = 0
  return <button onClick={() => { tips++ }}>小費 {tips} 元</button>
}

✓ 元件函式每次 render 都從頭執行，區域變數留不住，改它也不會通知 React。要記住、又要更新畫面的值放進 useState，用 set 函式「存新值＋觸發 render」。a 錯在根本沒有安排 render，不是晚一點才更新；React 不攔截任何寫入，只看你有沒有呼叫 set。（第 1 課）

練習 9：集點要先存到伺服器。網路很慢，客人在 save 回來前連按三下，三次都成功。畫面最後顯示幾點？

async function handleStamp() {
  await save()
  setStamps(stamps + 1)   // stamps 一開始是 0
}

✓ stamps 是按下當時那次 render 的快照，await 回來後還是 0，三次都是 setStamps(1)。新值依賴舊值就用 updater：setStamps(s => s + 1)。b 錯在批次只把更新合成一次 render，不會丟掉任何一次；三次都是「設成 1」才是問題，改成 updater 就是 3。（第 3 課）

練習 10：「加一杯」這樣寫，專案用 Vite 範本（有 StrictMode）。開發時拿鐵從 1 杯按一下，會看到什麼？

setLines(prev => prev.map(l => {
  if (l.productId === id) l.quantity += 1
  return l
}))

✓ StrictMode 在開發時把 updater 呼叫兩次，用來抓不純的寫法；這裡改了 prev 裡的舊物件，兩次就加了兩杯。改成符合的那一列回傳新物件：{ ...l, quantity: l.quantity + 1 }。c 錯在陣列是新的，裡面那一列卻是被直接改掉的舊物件；拿掉 StrictMode 會看到 2，但 bug 只是被藏起來。（第 1、3 課）

練習 11：點餐頁輸入備註時，DevTools 顯示沒用到備註的 Menu 每打一個字就 render 一次。同事說「整份菜單的 DOM 每個字都重建，要全部包 memo」。他錯在哪？

✓ 父元件 render，子元件預設全部跟著 render，但 render 是計算，commit 才改 DOM，結果一樣就不動。render 次數多不等於慢，先用 React DevTools 的 Profiler 量出慢在哪再決定優化。a 是 Vue 的直覺：Vue 看 props 決定要不要更新子元件，React 預設不看。（第 1 課）

練習 12：購物車把合計也存成 state。測試發現改數量後，合計顯示的總是上一次的金額。原因是？

function changeQty(id: number, qty: number) {
  setLines(prev => prev.map(l => (l.productId === id ? { ...l, quantity: qty } : l)))
  setTotal(sum(lines))
}

✓ set 不改手上的變數，lines 到下一次 render 才是新的。根本的修法不是調整 set 的寫法，而是刪掉 total 這個 state，在 render 時算 const total = sum(lines)：能算出來的就不存。a 錯在同一個事件裡的 set 會批次處理，只 render 一次。（第 1、3 課）

練習 13：購物車依序是美式、拿鐵、卡布奇諾，用 key={index} 渲染 CartRow，每列用自己的 state 存備註。在拿鐵那列打「少冰」，再刪掉美式。「少冰」會出現在哪？

✓ React 用 key 決定哪個元件對應哪筆資料，state 跟著元件走。key 是索引時，刪掉第一筆後，索引 1 的元件連同「少冰」留著，資料換成卡布奇諾。用資料的 id 當 key。a 錯在 React 不比對內容，只看 key，同一個 key 就當成同一個元件。（第 2、3 課）

練習 14：櫃檯頁首把 Vue 的 v-if="pending" 照搬成下面這行，pending 是待處理的訂單數。沒有待處理的訂單時，畫面上會出現什麼？

{pending && <span>待處理 {pending} 筆</span>}

✓ a && b 在 a 是 falsy 時回傳 a 本身；null、undefined、true、false 不畫，數字 0 會畫。左邊一定寫成布林值：pending > 0 && …，或改用三元。a 是 Vue 的直覺：v-if 只拿值判斷真假，JSX 的 && 是 JavaScript 運算式，回傳的值會被畫出來。（第 2 課）

練習 15：這個檔案還沒加型別。選了「拿鐵」（id 是數字 2）之後，product 一直是 undefined。原因是？

const [productId, setProductId] = useState(1)
const product = products.find(p => p.id === productId)
<select value={productId} onChange={e => setProductId(e.target.value)}>…</select>

✓ e.target.value 一律是字串，React 沒有 Vue 的 .number。存進 state 前轉型：setProductId(Number(e.target.value))；這類錯誤常到送 API 時才爆開。b 錯在下一次 render 時 find 確實拿到新值，只是它是字串；c 錯在有 onChange 就是正常的受控元件。（第 4 課）
