階段 3：元件設計與型別 · 第 10 課

組合：children、render props 與 compound components

咖啡店的 MenuList 要出現在三個地方：點餐頁有「加入」按鈕，吧台只要品名，後台還要備註欄。同事每多一種長相就加一個 prop：showButton、showNote……半年後沒人敢改。另一位同事做分頁元件，用 cloneElement 把「目前選中哪一個」塞給子元件，設計師在分頁按鈕外面包了一層 <span>，分頁就壞了。

React 沒有 slot 語法，組合元件靠的都是普通的 JavaScript：值、函式與 context。

這課的路線：
  1. 插槽與 render props：Vue 的 slot、作用域 slot 在 React 是 ReactNode prop 和回傳畫面的函式，MenuList 不用再一直加 showXxx（開場問題的最小答案）。
  2. compound components：Tabs、Tab、Panel 這種一組一起用的元件，怎麼用 context 共用「選中哪一個」，不靠 cloneElement。
  3. 受控與非受控：同一個數量選擇器，父元件要記就傳 value，不想記就給 defaultValue，對應 Vue 的 defineModel。
  4. props 透傳與怎麼選：沒宣告的 aria-label、className 怎麼交給根元素（Vue 的 $attrs），以及五種組合方式各用在哪。
這課會用到：
  • 第 2 課的 children 與 ReactNode：標籤中間的內容會變成叫 children 的 prop，ReactNode 是 React 能畫的任何東西（元素、字串、null…）。
  • 第 4 課的受控與非受控：給 value 加 onChange 是由 state 決定顯示什麼，給 defaultValue 只設初始值，之後由元素自己保管。

插槽就是 ReactNode 型別的 prop

第 2 課說過：標籤中間的內容會變成叫 children 的 prop，具名 slot 就是型別為 ReactNode 的普通 prop。購物車卡片要三個位置：標題、右上角的數量徽章、底部的「結帳」按鈕，中間是一整張清單：

import type { ReactNode } from 'react'

type CardProps = {
  title: ReactNode
  badge?: ReactNode
  footer?: ReactNode
  children: ReactNode
}

export function Card({ title, badge, footer, children }: CardProps) {
  return (
    <section className="card">
      <header>
        <h3>{title}</h3>
        {badge != null && <span className="badge">{badge}</span>}
      </header>
      <div className="body">{children}</div>
      {footer != null && <footer>{footer}</footer>}
    </section>
  )
}

<Card title={<>購物車 <em>外帶</em></>} badge={items.length} footer={<button onClick={pay}>結帳</button>}>
  <CartItems items={items} />
</Card>

三件事要注意：

  • 型別用 ReactNode，不要用 string。title 宣告成 string，就放不進 <em>；用 String(title) 或樣板字串硬轉，JSX 會變成 [object Object]。
  • 「有沒有傳」用 != null。!= null 同時排除 undefined 與 null，數量是 0 時仍會顯示徽章。寫成 {badge && …} 的話，0 是 falsy，徽章不見，還會在 <header> 裡直接印出一個「0」（第 2 課的陷阱）。
  • 沒傳就整個外框都不要。<footer> 有上邊框和內距，沒傳 footer 還留一個空的，卡片底下就多一條線。這跟 Vue 的 <footer v-if="$slots.footer"> 是同一件事，只是 React 不需要 $slots，直接判斷 prop。

跟 Vue 一樣，插槽內容在父元件的作用域裡建立：<button onClick={pay}> 是父元件 render 時做好的 JSX，pay 是父元件的變數，Card 只負責把它放到某個位置。

render props：把資料交回給插槽

MenuList 的問題卡在：每一列長什麼樣由使用的人決定，但「這一列是哪個商品」只有 MenuList 知道。ReactNode prop 是父元件事先做好的畫面，沒辦法每一列不一樣。Vue 用作用域 slot 解決（Vue 課第 11 課）；React 的做法是傳一個函式，由子元件在每一列呼叫它、把資料當參數傳進去，這叫 render prop（回傳畫面的函式 prop）：

export type ItemHelpers = { index: number; add: () => void }

type MenuListProps = {
  products: readonly Product[]
  onAdd: (productId: number) => void
  renderItem?: (product: Product, helpers: ItemHelpers) => ReactNode
}

const defaultItem = (product: Product): ReactNode => `${product.name} $${product.price}`

export function MenuList({ products, onAdd, renderItem = defaultItem }: MenuListProps) {
  return (
    <ul>
      {products.map((product, index) => (
        <li key={product.id}>{renderItem(product, { index, add: () => onAdd(product.id) })}</li>
      ))}
    </ul>
  )
}

<ul>、<li> 與 key 由 MenuList 負責，使用的人只管 <li> 裡面，排序後備註框才會跟著商品走（第 2 課），不必每個使用的人都記得 key。傳 add 而不是讓使用的人自己呼叫 onAdd(product.id)，是讓「加入」的規則（售完不能加）留在 MenuList，每種長相共用。

函式也可以放在 children：<Countdown>{seconds => `還剩 ${seconds} 秒`}</Countdown>，元件裡呼叫 children(seconds)，效果一樣。

render prop 裡不能呼叫 hook

render prop 是一個普通函式，在 MenuList render 的時候被呼叫，不是元件。在裡面寫 useState：

renderItem={product => {
  const [note, setNote] = useState('')   // ✗
  return <input value={note} onChange={e => setNote(e.target.value)} />
}}

這些 state 記在 MenuList 的 hook 格子上（第 9 課），商品數一變，hook 數量就變了。React 19.3.1 實測會丟出 Rendered more hooks than during the previous render.；eslint-plugin-react-hooks 7.1.1 也會報 React Hook "useState" cannot be called inside a callback。需要 state 時，把那一列寫成元件，render prop 只負責回傳它：renderItem={product => <NoteRow product={product} />}。

💡 實務上：先問「真的有第二種長相嗎」
表格的儲存格、下拉選單的選項、虛擬捲動列表的每一列，是 render prop 最常出現的地方：元件負責版面和捲動，不知道你要放什麼。自己寫共用元件時，只有一種長相就用 props，確定有第二種再開 render prop；開了之後參數就是公開介面，改名就要改所有使用的頁面。只有邏輯、沒有 DOM 的話，抽成自訂 hook（第 9 課）比包一層元件簡單。

compound components：用 context 共用 state

這節會用到還沒教的 context：讓上層元件把值交給底下任意深度的子元件，不用一層層傳 props，等於 Vue 的 provide／inject（Vue 課第 13 課）。這裡只用最基本的寫法，細節在第 11 課。

菜單頁要用分頁切換「咖啡／茶／點心」。我們希望使用的人只寫結構：

<Tabs defaultValue="coffee">
  <Tabs.List>
    <Tabs.Tab value="coffee">咖啡</Tabs.Tab>
    <Tabs.Tab value="tea">茶</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel value="coffee">…</Tabs.Panel>
  <Tabs.Panel value="tea">…</Tabs.Panel>
</Tabs>

這種「一組要一起用、共用一份 state 的元件」叫 compound components（複合元件），Vue 課第 13 課的 Tabs 與 Tab 就是。「目前選中哪一個」只能有一個擁有者：Tabs。問題是 Tab、Panel 是使用的人寫的 children，Tabs 沒辦法在 JSX 上替它們加 props。

反例：Children.map 加 cloneElement

舊文章常見的做法是走訪 children，用 cloneElement 複製每個子元素、多塞幾個 props：

// ✗ 只碰得到直接的子元素
{Children.map(children, child =>
  isValidElement<{ value: string }>(child)
    ? cloneElement(child, { selected: child.props.value === value, onSelect: setValue })
    : child,
)}

練習環境實測：把第二個 Tab 包進 <span>，被複製的是 span，Tab 拿不到 selected，按下去丟出 TypeError: onSelect is not a function。官方文件說明 Children 的走訪不會深入 React 元素，也看不到子元件 render 的結果，並把 Children、cloneElement 標成「少用，容易寫出脆弱的程式」，建議改用 render prop 或 context。

修正：Tabs 提供 context，Tab 與 Panel 去讀

context 用到三個 API：createContext(預設值)；React 19 起直接 render <TabsContext value={…}> 當提供者（舊寫法 <TabsContext.Provider> 官方說之後會棄用）；底下用 use(TabsContext)（或 useContext）讀到最近的提供者的值。

import { createContext, use, useState, type ReactNode } from 'react'

type TabsContextValue = { value: string; select: (value: string) => void }
const TabsContext = createContext<TabsContextValue | null>(null)

function useTabs(name: string) {
  const tabs = use(TabsContext)
  if (!tabs) throw new Error(`<Tabs.${name}> 要放在 <Tabs> 裡面`)
  return tabs
}

export function Tabs({ defaultValue, children }: { defaultValue: string; children: ReactNode }) {
  const [value, setValue] = useState(defaultValue)
  return <TabsContext value={{ value, select: setValue }}><div className="tabs">{children}</div></TabsContext>
}

function Panel({ value, children }: { value: string; children: ReactNode }) {
  const tabs = useTabs('Panel')
  if (tabs.value !== value) return null
  return <div role="tabpanel">{children}</div>
}

Tabs.Panel = Panel   // Tab、List 同理：掛在 Tabs 上，用的人只要 import Tabs
  • state 在 Tabs 的 useState 裡，每個 <Tabs> 各自提供 context，同一頁兩組分頁互不影響。放在模組層級的變數，兩組會共用，而且改了不會 render。
  • 沒選中的 Panel 回傳 null，裡面的元件不會被呼叫；用 hidden 或 CSS 藏起來，元件照樣執行、照樣抓資料。
  • 預設值給 null，讀到就丟錯：Tab 放在 Tabs 外面時，一 render 就看到原因，而不是默默沒反應。跟 Vue 課第 13 課在 useXxx() 裡檢查 inject 結果是同一個習慣。

Vue 課第 13 課的 Tab 要向 Tabs 登記自己，Tabs 再畫出按鈕；這裡讓使用的人自己寫 Tabs.List 與 Tabs.Tab，不用登記。ARIA 一樣是 tablist、tab 加 aria-selected、tabpanel；React 會把 aria-selected={false} 輸出成 "false"。

💡 實務上：設計系統的元件多半長這樣
UI 元件庫的 Tabs、Select、Accordion 常用這種「外層元件加一組子元件」的 API，成熟的元件庫也處理好了鍵盤操作與 ARIA。一般專案直接用元件庫；自己寫的時機通常是公司要做設計系統，這時把「只用鍵盤操作一輪」列進驗收。設計 API 時先想「使用的人會不會在中間包東西」：會的話一定用 context，不要用 cloneElement。review 時看到 Children.map、cloneElement，先問中間包一層 div 還能不能用。

受控與非受控：同一個元件兩種用法

購物車頁的數量由父元件記，因為小計要跟著算；商品卡片上的數量只是「先選好幾杯再按加入」，不想為它開一個 state。第 4 課的 <input> 就有兩種用法：給 value 是受控，給 defaultValue 是非受控。自己的元件也可以：

type QuantityStepperProps = {
  value?: number
  defaultValue?: number
  onChange?: (value: number) => void
}

export function QuantityStepper({ value, defaultValue = 1, onChange }: QuantityStepperProps) {
  const [inner, setInner] = useState(defaultValue)   // 只在掛載時讀 defaultValue
  const controlled = value !== undefined
  const current = controlled ? value : inner

  function change(next: number) {
    if (!controlled) setInner(next)   // 非受控：自己記
    onChange?.(next)                  // 兩種都通知；受控時由父元件決定要不要採用
  }
  // …按鈕呼叫 change(current + 1)、change(current - 1)
}
  • 受控時畫面只聽 value。父元件不更新（例如庫存不夠），畫面就不變；子元件自己也改 state 的話，父元件拒絕時兩邊對不上。
  • value !== undefined，不是 value ||：數量 0 是合法的受控值。
  • 不要用 effect 把 value 複製進 state，也不要用 effect 呼叫 onChange。前者晚一次 render、還會蓋掉使用者的操作；後者掛載時就通知、而且會重複通知（第 6 課）。通知寫在事件處理函式裡，每按一次剛好一次。
  • onChange 是選填，呼叫寫 onChange?.(next)。寫成 onChange!(next) 只是騙過 TypeScript，沒傳的時候按下去就丟 TypeError。
  • 不要中途切換模式。官方文件規定 <input> 不能中途在受控與非受控之間切換；自己的元件也照這個約定，否則切回非受控時 inner 還停在很久以前的值。

範圍限制（1～20）用 disabled 擋：到上限時「增加」disabled。React 19.3.1 的事件系統在 <button> 有 disabled prop 時不會呼叫它的 onClick（react-dom 的原始碼裡，滑鼠事件遇到 disabled 的 button、input、select、textarea 會跳過），所以處理函式不必再檢查一次；要防的是忘了加 disabled，或條件差一格：寫成 current > max，數量已經是 20 時「增加」還按得下去。

Vue 這邊，defineModel（Vue 課第 10 課）在父元件沒用 v-model 時會自動變成本地狀態，等於內建了這個模式。React 沒有這種巨集，上面這幾行就是它做的事。

props 透傳：...rest 與合併

團隊的 BaseButton 只收 children。有人寫 <BaseButton aria-label="移除可頌" className="wide" disabled onClick={remove}>×</BaseButton>，結果 aria-label、className、disabled、onClick 全部消失。Vue 會把沒宣告的屬性自動加到根元素（Vue 課第 9 課的透傳屬性），React 不會：props 就是函式參數，沒用到的就沒了。要透傳，自己用 rest 收起來再展開：

import type { ComponentProps } from 'react'

type BaseButtonProps = ComponentProps<'button'> & {
  variant?: 'primary' | 'ghost'
  loading?: boolean
}

export function BaseButton({ variant = 'primary', loading = false, className, disabled, ...rest }: BaseButtonProps) {
  return (
    <button
      type="button"                                                       // 預設值：寫在 rest 前面
      {...rest}                                                           // aria-*、data-*、onClick、ref…
      className={['btn', `btn-${variant}`, className].filter(Boolean).join(' ')}
      disabled={disabled || loading}                                      // 元件要保證的：寫在 rest 後面
      aria-busy={loading || undefined}
    />
  )
}

ComponentProps<'button'> 是「原生 <button> 能收的所有 props」，第 12 課細講。重點在順序和合併，都在練習環境實測過：

寫法結果原因
<button {...rest} type="button">，使用的人傳 type="submit"還是 button，表單送不出去JSX 屬性後面的蓋前面的；預設值要放 rest 前面
className={`btn ${className}`}，沒傳 className"btn undefined"樣板字串把 undefined 轉成字串；用 filter(Boolean) 濾掉
className 只留在 rest 裡、自己的寫在前面傳進來的蓋掉 btnReact 不合併 class；Vue 會，所以容易忘
variant 沒解構出來，留在 rest 裡DOM 上出現 variant="ghost"，沒有警告React 會把不認識的字串屬性照寫到 DOM
loading 留在 rest 裡警告 Received `true` for a non-boolean attribute `loading`布林值不能當 DOM 屬性

所以元件自己的 props 解構出來；要合併的（className、disabled）解構出來自己組；其餘的交給 rest。aria-busy={loading || undefined} 的 undefined 讓屬性整個不出現，不是 aria-busy="false"。ref 也在 rest 裡：React 19 的 ref 是普通的 prop（第 7 課），展開到 <button> 就接上了，不需要 forwardRef。

💡 實務上：只有「包住一個原生元素」的元件才全部透傳
Button、Input、Link 這類薄包裝要讓使用的人加 aria-*、data-*（埋點）、id，不透傳就一直有人來要「多開一個 prop」。但官方文件也提醒展開要節制，到處 {...props} 通常代表該拆元件、改傳 children。業務元件（OrderCard、CheckoutForm）的 props 要明確列出來，不要整包往下丟。

練習

在 learn/ 執行 node check.mjs react 10，改 react/practice/work/10/ 的檔案，每個起始檔最上面的註解有完整要求。測試傳入的商品陣列是凍結的。

練習 1：把 Card 的 props 改成 title、badge?、footer?、children，型別都是 ReactNode。title 放在 <h3>（傳 JSX 也要原樣出現）；children 放在 <div className="body">，裡面的按鈕要照常運作。badge 有傳才在 <header> 裡、<h3> 後面 render <span className="badge">；undefined、null 算沒傳，badge={0} 要顯示 0，<header> 裡不能多出任何文字。footer 有傳才 render <footer>，沒傳時整個 <footer> 都不能出現，footer 的內容也不能跑進 .body。

練習 2：替 MenuList 加上 renderItem?: (product, helpers) => ReactNode。有傳時每個 <li> 的內容就是它的回傳值，每個商品呼叫一次；helpers 是 { index, add }，index 從 0 開始，add() 呼叫 onAdd(這一列商品的 id)（只傳 id）。沒傳時每一列顯示「品名 $價格」，例如「拿鐵 $110」。<ul>、<li> 與 key（用 product.id）由 MenuList 負責，重新排序後備註框的內容要跟著商品走。products 是空陣列時不 render <ul>，改成 <p className="empty">，內容是 empty prop（ReactNode，可以是按鈕），沒傳顯示「目前沒有商品」；有商品時不能出現 .empty。不能修改 products。

練習 3：完成 Tabs、Tabs.List、Tabs.Tab、Tabs.Panel。Tabs 用 useState 記目前選中的 value（初始值是 defaultValue），用 context 交給底下。List 是 role="tablist"；Tab 是 <button type="button" role="tab">，選中的 aria-selected="true"、其他 "false"，按下就選中它；Panel 只在自己的 value 是目前的值時 render <div role="tabpanel">，否則回傳 null（裡面的元件不能被呼叫）。Tab 與 Panel 外面多包 <span>、<nav> 或別的元件也要能用；同一頁兩個 <Tabs> 互不影響。Tab 或 Panel 不在 <Tabs> 裡時丟出 Error，訊息要包含 <Tabs>。不能用 Children.map／cloneElement、模組層級的變數。

練習 4：讓 QuantityStepper 同時支援受控與非受控。有傳 value（包括 0）時畫面永遠顯示 value，按 +／− 只呼叫 onChange(新數量)，父元件沒更新就不變；父元件改了 value 畫面要跟著變。沒傳 value 時自己記數量，初始值是 defaultValue（預設 1），之後 defaultValue 改了也不理它；按鈕更新自己的數量並呼叫 onChange。onChange 可以不傳，不傳時按按鈕不能出錯；只在使用者按按鈕時呼叫，每按一次剛好一次，掛載時不呼叫。範圍是 min～max（預設 1～20）：到上限時「增加」disabled、到下限時「減少」disabled，按了不能呼叫 onChange。不能用 effect 同步 value 或呼叫 onChange。

練習 5：讓 BaseButton 把 variant、loading 以外的 props 全部交給 <button>（aria-*、data-*、id、title、onClick、ref），用 rest 展開，不要一個一個挑。class 一定有 btn 與 btn-<variant>（預設 primary），再加上傳進來的 className；沒傳時 class 只能是 btn btn-primary。type 預設 button，傳 type="submit" 要蓋得過去。variant、loading 不能出現在 DOM 上，React 不能印出任何警告。loading 時一定 disabled（傳 disabled={false} 也一樣）並有 aria-busy="true"；不是 loading 時 disabled 照使用的人傳的，而且沒有 aria-busy 屬性。

練習 6：Tabs 用 Children.map 加 cloneElement 把 selected、onSelect 塞給每個 Tab。設計師把其中一個 Tab 包進 <span className="group">，會怎樣？

✓ Children 的走訪不會深入 React 元素，cloneElement 只改得到直接的子元素，也就是 span。Tab 的 onSelect 是 undefined，按下去丟 TypeError（練習環境實測）；React 不會限制 children 的種類，所以不是 c。改用 context，Tab 不管隔幾層都讀得到。

練習 7：renderItem={product => { const [note, setNote] = useState(''); return … }}。商品從 1 個變成 2 個時會怎樣？

✓ render prop 是 MenuList render 時呼叫的普通函式，不是元件，useState 記在 MenuList 的 hook 格子上；商品數一變，hook 數量就變了，React 丟錯，lint 也會報「cannot be called inside a callback」。所以既不是每列各一份（a），也不是共用一份（b）。要每一列有自己的 state，寫成 renderItem={product => <NoteRow product={product} />}。

練習 8：BaseButton 寫成 <button {...rest} type="button">。結帳表單裡用 <BaseButton type="submit">送出訂單</BaseButton>，按下去會怎樣？

✓ JSX 屬性由左到右套用，後面的蓋前面的，寫在 rest 後面的 type="button" 蓋掉了 submit。預設值放在 {...rest} 前面，元件一定要保證的（例如 loading 時 disabled）才放後面。TypeScript 不檢查展開後的重複，所以不是 c。

常見錯誤

  • 插槽型別寫成 string，或把 JSX 轉成字串：放不進元素，或變成 [object Object]。型別用 ReactNode，直接 {title}。
  • 用 {badge && …} 判斷有沒有傳：0 被當成沒傳，還印出「0」。用 badge != null。
  • 在 render prop 裡呼叫 hook：hook 記在外層元件上，數量一變就出錯。需要 state 就回傳一個元件。
  • 用 Children.map／cloneElement 傳 state：中間包一層就壞。用 context。
  • 受控時子元件也自己改 state、用 effect 同步 value 或呼叫 onChange：兩份資料對不上、重複通知。用 value !== undefined 決定顯示哪一個，通知寫在事件處理函式裡。
  • 以為 React 會自動透傳屬性：沒用到的 props 就消失。用 ...rest 展開，預設值在前、保證的在後，className 自己合併，元件自己的 props 解構出來。

小結

  • React 的插槽就是 props：children 和型別為 ReactNode 的 prop，有沒有傳用 != null，沒傳就連外框都不 render。
  • render prop 是 Vue 作用域 slot 的對應物：元件把資料當參數交給函式，結構與 key 留在元件裡；它是普通函式，裡面不能呼叫 hook。
  • compound components 用 context 共用 state：外層 useState、提供 <Context value>，裡面用 use() 讀，讀不到就丟錯；不用 cloneElement。
  • 同時支援受控與非受控：value !== undefined 就聽 value，否則用 defaultValue 起始的自己的 state；兩種都在事件裡呼叫 onChange?.()。
  • React 不自動透傳：薄包裝用 ...rest，注意展開順序與 className 合併；ref 在 React 19 也是普通 prop。
