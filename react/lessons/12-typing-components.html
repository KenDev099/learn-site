階段 3：元件設計與型別 · 第 12 課

元件的型別：props、泛型元件與事件

咖啡店的共用 Button 元件寫成 function Button(props: any)。新來的同事寫了 <Button varient="ghost">，按鈕還是藍色；另一個人寫 <Button disabled>，按鈕照樣按得下去，因為 Button 根本沒把 disabled 交給 <button>。取餐叫號的元件每個 prop 都是可選的，畫面出現「可以取餐，取餐碼」，後面一片空白。測試全部通過，編輯器沒有畫任何紅線。

這課教你替 React 元件寫出準確的型別，讓錯誤的用法在編譯時就失敗，每一項都對照 Vue 課第 14 課的 defineProps、defineEmits 與 generic。

這課的路線：
  1. 誰在檢查型別、props 的型別：測試全過為什麼還藏著錯字，props 和 callback props 怎麼寫型別取代 any（開場問題的最小答案）。
  2. 包裝原生元素：共用 Button 怎麼收下 <button> 的所有屬性（disabled、aria-*），並確實交給它。
  3. 辨識聯合的 props：自取、外送這種互斥的情況，讓「外送卻沒有地址」寫不出來。
  4. 事件、state、ref 與泛型元件：抽出去的處理函式怎麼標事件型別，共用的選項按鈕、表格怎麼讓選項的型別一路傳到 onChange。
這課會用到：
  • 第 2 課的 props 與 ReactNode：props 就是元件函式的第一個參數，children 和具名 slot 的型別是 ReactNode。
  • 第 8 課的可辨識聯合：幾種情況各是一個物件型別，用同一個字面值欄位（例如 type）區分，TypeScript 依那個欄位縮小型別。

誰在檢查型別：tsc 看得懂 .tsx

Vue 課第 14 課說過：擦掉型別和檢查型別是兩件事。Vite 的文件寫明它只轉譯 .ts 檔、不做型別檢查，Vitest 用同一套轉換，真正檢查的是 tsc。實測：測試裡寫 const wrong: number = '110'，Vitest 5.0.5 照樣顯示 passed。

跟 Vue 不同：JSX 是 TypeScript 本身支援的語法，.tsx 不需要 vue-tsc，直接用 tsc。Vite 官方的 react-ts 範本寫成 "build": "tsc -b && vite build"，型別錯了就不打包。這課的範例用 TypeScript 6.0.3 和 7.0.2 的 tsc 各跑一次，錯誤相同；Vue 因為 vue-tsc 暫時只能停在 6。

💡 實務上：先確認 CI 真的有跑 tsc
接手 React 專案時，先看 package.json 和 CI 設定有沒有 tsc -b 或 tsc --noEmit、失敗會不會擋下合併。編輯器的紅線只出現在你打開的檔案；改了共用元件的 props，要靠 tsc 一次列出所有需要跟著改的地方。

props 的型別：對照 defineProps 與 defineEmits

React 元件就是函式，props 的型別就是第一個參數的型別。官方文件的寫法是用 type 或 interface 描述 props 物件，直接標在參數上：

import type { ReactNode } from 'react'
import type { Product } from './api.ts'

type ProductCardProps = {
  product: Product
  soldOut?: boolean                          // 可選：使用的人可以不傳
  onAdd: (id: number, qty: number) => void   // Vue 的 emit('add', id, qty)
  children?: ReactNode                       // Vue 的預設 slot
}

export function ProductCard({ product, soldOut = false, onAdd, children }: ProductCardProps) {
  // 預設值寫在解構：soldOut 在元件裡是 boolean，不是 boolean | undefined
  …
}

React 沒有 emit：父元件把函式當 prop 傳下去，子元件呼叫它（第 3 課）。所以「事件的參數型別」就是那個函式 prop 的參數型別。父元件寫 <ProductCard onAdd={(id: string) => …}>，tsc 報 Type '(id: string) => void' is not assignable to type '(id: number, qty: number) => void'。

拿別人的 props 型別：ComponentProps<typeof X>

包裝現成元件、或在測試裡準備它的 props 時，不必把型別再抄一份：ComponentProps<typeof ProductCard> 取出它的 props 型別，元件改了這裡跟著變（typeof 是 TS 課第 20 課的「從值拿型別」）。

包裝原生元素：ComponentProps<'button'>

回到開場的 Button。把需要的屬性一個一個列出來（disabled?、onClick?…）永遠列不完：form、title、onKeyDown、所有 aria-*，每多一個需求就得回來改 Button。

@types/react 已經把每個原生元素能收的屬性寫好了。ComponentProps<'button'> 就是「JSX 裡 <button> 能收的全部 props」，用 &（交集）加上自己的 props。以搜尋框為例：

import type { ComponentProps, ReactNode } from 'react'

type SearchInputProps = ComponentProps<'input'> & {
  label: string
  hint?: ReactNode
}

export function SearchInput({ label, hint, type = 'search', ...rest }: SearchInputProps) {
  return (
    <label>
      {label}
      <input type={type} {...rest} />
      {hint}
    </label>
  )
}

<SearchInput label="搜尋" placeholder="拿鐵" maxLength={20} onChange={e => console.log(e.target.value)} />  // ✓
<SearchInput label="搜尋" maxLength="20" />   // ✗ Type 'string' is not assignable to type 'number'
<SearchInput lable="搜尋" />                  // ✗ Property 'lable' does not exist … Did you mean 'label'?
  • ref 也在裡面：ComponentProps<'input'> 包含 ref，留在 rest 裡就接上了（第 10 課）。不想讓別人拿到 ref 時用 ComponentPropsWithoutRef，傳 ref 會報錯。
  • 不要用 HTMLAttributes<HTMLButtonElement>：它只有所有元素共用的屬性，{ disabled: true } 會報 'disabled' does not exist in type 'HTMLAttributes<HTMLButtonElement>'，也沒有 type、form、ref。
  • 想改掉原生 prop 的型別，先 Omit：ComponentProps<'input'> & { onChange: (value: string) => void } 的 onChange 會變成兩個函式型別的交集，傳 (v: string) => … 報錯：Type 'ChangeEvent<HTMLInputElement, HTMLInputElement>' is not assignable to type 'string'。寫成 Omit<ComponentProps<'input'>, 'onChange'> & { onChange: … }。
💡 實務上：設計系統的元件都是這樣包的
團隊的 Button、Input、Link 幾乎都是「原生屬性＋幾個自己的 props」：使用的人用原生的知識就會用，aria-* 也不會被吃掉。review 時先看型別是不是從 ComponentProps 來，再看第 10 課的展開順序與 className 合併。反過來，元件刻意不讓外面改的東西（例如 Dialog 的 role），用 Omit 從型別拿掉，比文件寫「請勿傳」可靠。

辨識聯合的 props：讓不可能的組合寫不出來

結帳頁要顯示取餐方式：自取要有時間，外送要有地址和運費。最直覺的型別是全部可選：

type DeliveryInfoProps = {
  mode: 'pickup' | 'delivery'
  pickupAt?: string
  address?: string
  fee?: number
}
// <DeliveryInfo mode="delivery" />                     ← 沒地址，通過檢查
// <DeliveryInfo mode="pickup" address="中山路 1 號" />  ← 自取卻有地址，也通過

合法的組合只有兩種。第 8 課用可辨識聯合（discriminated union）描述 action，props 一樣可以：每一種情況是一個物件型別，用一個字面值欄位（這裡是 mode）區分：

type DeliveryInfoProps =
  | { mode: 'pickup'; pickupAt: string }
  | { mode: 'delivery'; address: string; fee: number }

export function DeliveryInfo(props: DeliveryInfoProps) {
  switch (props.mode) {
    case 'pickup':
      return <p>{props.pickupAt} 到店自取</p>
    case 'delivery':
      return <p>外送到 {props.address}，運費 {props.fee} 元</p>
    default:
      return props satisfies never   // 之後多一種 mode 卻忘了處理，這一行會報錯
  }
}

錯的用法都會報錯，訊息指出是哪一種情況：

<DeliveryInfo mode="delivery" address="中山路 1 號" />
// Property 'fee' is missing in type … but required in type '{ mode: "delivery"; address: string; fee: number; }'
<DeliveryInfo mode="pickup" pickupAt="14:30" address="中山路 1 號" />
// Property 'address' does not exist on type 'IntrinsicAttributes & { mode: "pickup"; pickupAt: string; }'

元件裡有一個限制：不能在參數直接解構只存在於某一種情況的屬性。寫 function DeliveryInfo({ mode, address }: DeliveryInfoProps) 會報 Property 'address' does not exist on type 'DeliveryInfoProps'：還沒判斷 mode 之前，address 可能不存在。先拿整個 props，用 props.mode 縮小（TS 課第 16 課），再讀各自的欄位。satisfies never 跟第 8 課 reducer 的 const _exhaustive: never = action 是同一件事。

💡 實務上：props 的形狀跟著資料的狀態走
訂單狀態、付款結果、API 的「載入中／成功／失敗」都適合辨識聯合，看到一個元件有一串可選的 props、裡面又寫滿 if (a && !b)，通常就是該換成聯合的訊號。代價是使用的人得先判斷再讀欄位；只有一兩個彼此無關的可選 prop（例如 soldOut?）時，不要硬拆成聯合。

事件、state 與 ref 的型別

事件：寫在行內會推論，抽出來要自己標

寫在 JSX 裡的處理函式，參數由位置推論：<input onChange={e => …}> 的 e 是 ChangeEvent<HTMLInputElement>，e.target.value 是 string。抽成具名函式後，function handleChange(e) {…} 會報 Parameter 'e' implicitly has an 'any' type。官方文件建議自己寫上事件型別，不確定就把滑鼠移到 onChange 上看提示。

寫在哪參數型別（從 'react' import）
<input onChange>ChangeEvent<HTMLInputElement>
<select onChange>ChangeEvent<HTMLSelectElement>
<form onSubmit>SubmitEvent<HTMLFormElement>（@types/react 19.3 把 FormEvent 標成 deprecated，第 4 課）
<button onClick>MouseEvent<HTMLButtonElement>
<input onKeyDown>KeyboardEvent<HTMLInputElement>
當成 prop 的型別ChangeEventHandler<HTMLInputElement> 這類 …EventHandler

型別參數是「掛處理函式的那個元素」，它決定 e.currentTarget 的型別。e.target 則是事件真正發生的元素，可能是按鈕裡的 <svg>，所以 MouseEvent 的 target 型別只是 EventTarget：e.target.form 報 Property 'form' does not exist on type 'EventTarget'，e.currentTarget.form 才通過。表單元素的 ChangeEvent 例外：@types/react 讓它的 target 跟 currentTarget 同型別。

型別寫對了，ChangeEvent<HTMLInputElement> 的處理函式接到 <select>、SubmitEvent 的接到 onClick 都會報錯；寫成 any，連 e.target.valeu 這種錯字也不會報。

useState：從初始值推論，初始值不夠時要寫型別參數

useState('1') 推論成 string、useState(false) 推論成 boolean，不用寫型別。問題出在初始值只是其中一種可能時：

const [error, setError] = useState(null)
setError('數量要是 1 到 20 的整數')
// ✗ Argument of type '"數量要是 1 到 20 的整數"' is not assignable to parameter of type 'SetStateAction<null>'

const [error, setError] = useState<string | null>(null)   // ✓ 沒有錯誤時是 null
const [picked, setPicked] = useState<Product | null>(null)
const [hint, setHint] = useState<string>()                // string | undefined：不給初始值就多一個 undefined

useRef：DOM ref 寫元素型別，初始值 null

useRef<HTMLInputElement>(null) 的型別是 RefObject<HTMLInputElement | null>：掛上去之前、卸載之後都是 null，所以 ref.current.focus() 報 'ref.current' is possibly 'null'，要寫 ref.current?.focus()。元素型別寫對了，把它放到 <textarea ref> 會報錯（HTMLInputElement 少了 cols、rows…）。不給初始值的 useRef<HTMLInputElement>() 在 @types/react 19 直接報 Expected 1 arguments（第 7 課）。

ref.current!.focus() 能讓錯誤消失，但 ! 和 as 都只是你對編譯器的保證：哪天 ref 沒接上，執行時才丟錯。

泛型元件：選項的型別一路流下去

菜單頁選商品、結帳頁選顧客、點餐頁選杯型，都用同一排「選項按鈕」。第一版為了什麼都能放，寫成 any：

type ChipListProps = { items: readonly any[]; getLabel: (item: any) => string; onPick: (item: any) => void }
<ChipList items={PRODUCTS} getLabel={p => p.title} onPick={…} />   // Product 沒有 title，卻不報錯

缺的是「元件不在乎選項是什麼，但要記住是什麼」，這就是 TS 課第 19 課的泛型。React 元件是函式，泛型元件就是泛型函式：

type ChipListProps<T> = {
  items: readonly T[]
  getKey: (item: T) => string | number
  getLabel: (item: T) => string
  onPick: (item: T) => void
}

export function ChipList<T>({ items, getKey, getLabel, onPick }: ChipListProps<T>) {
  return (
    <ul>
      {items.map(item => (
        <li key={getKey(item)}>
          <button type="button" onClick={() => onPick(item)}>{getLabel(item)}</button>
        </li>
      ))}
    </ul>
  )
}

使用的人不用指定 T，TypeScript 從 items 推論，再檢查其他 props：

<ChipList items={PRODUCTS} getKey={p => p.id} getLabel={p => `${p.name} $${p.price}`} onPick={p => …} />  // ✓
<ChipList items={CUSTOMERS} getKey={c => c.id} getLabel={c => c.title} onPick={…} />
// ✗ Property 'title' does not exist on type 'Customer'
<ChipList items={['S', 'M', 'L'] as const} getKey={s => s} getLabel={s => s} onPick={(s: 'XL') => …} />
// ✗ Type '"S"' is not assignable to type '"XL"'

幾個細節：

  • readonly T[]：PRODUCTS 是 readonly Product[]，as const 的陣列也唯讀，寫成 T[] 會報 The type 'readonly Product[]' is 'readonly' and cannot be assigned to the mutable type。元件不改陣列就宣告成唯讀，兩種陣列都收得下。
  • 不需要就不加 extends：Vue 課的 PickList 寫 T extends { id: number }，因為元件自己讀 item.id；這裡由 getKey、getLabel 讀選項，T 不需要限制，字串也能當選項。
  • 「沒選」要寫進型別：選中的值如果寫成 value: T，使用的人傳 value={null} 時，TypeScript 會把 T 推論成 Product | null，結果 getLabel={p => p.name} 反而報 'p' is possibly 'null'。寫成 value: T | null，T 才會只是 Product。
  • 推論不出來就手動指定：items={[]} 推論出 never，讀 p.name 就報錯。JSX 可以直接寫型別參數：<ChipList<Product> items={[]} … />。
  • 箭頭函式要寫 <T,>：.tsx 裡的 <T>(props) => … 會被當成 JSX 標籤（JSX element 'T' has no corresponding closing tag）。加逗號，或改用 function。
💡 實務上：泛型元件留給真的有多種資料的共用元件
後台的表格、下拉選單最常用：訂單表、商品表共用一個 DataTable，欄位的 render 函式拿到各自的列型別。動手前先確認已經有兩三個真實用法；只顯示商品的 ProductCard 就寫 Product，泛型只會讓錯誤訊息變長。寫好之後至少用兩種型別各試一次，再放一行 @ts-expect-error 確認錯的用法真的會報錯，否則 T 可能早就默默變成 any。

練習

在 learn/ 執行 node check.mjs react 12，要改的檔案在 react/practice/work/12/，每個檔案最上面的註解寫了要求。每題的第一個測試會在旁邊寫一個隱藏的使用檔，用 tsc（TypeScript 6.0.3）檢查：正確的用法要通過，標了 @ts-expect-error 的錯誤用法要報錯（第 8 課）。訊息出現 Unused '@ts-expect-error' directive（TS2578）代表那一行該報錯卻沒有，型別寫得太寬；其他錯誤代表正確的用法被擋下，型別太窄。型別測試一次要 1～2 秒。

練習 1：把 Button 的 props: any 改成 ComponentProps<'button'> 加上兩個自己的 prop：variant?: 'primary' | 'ghost'（預設 primary）、icon?: ReactNode（JSX、字串都能放，顯示在文字前面）。class 是 btn btn-<variant>，使用的人傳的 className 接在後面；沒傳 type 時是 "button"，傳了就用傳進來的；其餘的原生屬性（disabled、aria-label、data-*、onClick、ref…）全部展開到 <button>。完成後 variant="big"、varient、href、onClick="add()"、ref 指向 input 都要報錯，form、title、onKeyDown 這類原生屬性都能傳。不能用 any、unknown、索引簽章或型別斷言，也不能自己一個一個列出原生屬性。

練習 2：取餐叫號的 OrderStatus 每個 prop 都是可選的。把 props 改成用 status 區分的辨識聯合：preparing 一定要有 minutesLeft: number，顯示「製作中，約 5 分鐘」；ready 一定要有 pickupCode: string，顯示「可以取餐，取餐碼 A12」；cancelled 一定要有 reason: string 與 onReorder: () => void，顯示「已取消：售完」和「重新點餐」按鈕，按了呼叫 onReorder。文字放在 <p role="status"> 裡，只有 cancelled 有按鈕。缺資料、帶了別的狀態的資料、不存在的狀態（shipped）都要報錯。不能保留可選的 prop 再用 ! 或 as，不能用 any，status 不能寫成 string。

練習 3：useQuantityField(onSubmit) 管「數量」輸入框，裡面到處是 any，還藏了一個打錯字的 bug（打字之後輸入框的內容不見）。把每個 any 換成正確的型別：onSubmit 收一個 number、沒有回傳值；error 是錯誤訊息字串，沒有錯誤時是 null；inputRef 會放到 <input> 的 ref 上；handleChange 是 <input> 的 onChange 處理函式，handleSubmit 是 <form> 的 onSubmit 處理函式，參數要是 SubmitEvent<HTMLFormElement>。再修好 TypeScript 找到的錯誤。行為：一開始是 1；送出時數量不是 1～20 的整數就顯示「數量要是 1 到 20 的整數」、焦點回到輸入框、不呼叫 onSubmit，合法就呼叫 onSubmit(數字)；重新打字清掉錯誤；送出要 preventDefault。不能留下 any，不能用 as 或 !。

練習 4：把下拉選單 Select 改成泛型元件，型別參數 T 是一個選項的型別，從 options 推論。options 要收得下唯讀陣列（PRODUCTS、['S', 'M', 'L'] as const）；value 是選中的選項，null 時選中停用的「請選擇」；onChange 收到 options 裡的那個選項本身，不是 <select> 的字串；getKey 回傳 string 或 number，當 <option> 的 key 與 value；getLabel 回傳顯示文字。哪個選項被選中一律比 getKey：value 可能是內容相同、參考不同的另一個物件，兩個選項的文字也可能相同。商品、顧客、字串選項與 <Select<Product> options={[]}> 都要能用；讀不存在的屬性、value 傳字串、getLabel 回傳數字都要報錯。不能用 any、unknown、as，也不能限制 T 一定要有 id。

練習 5：const [error, setError] = useState(null)，之後在送出時呼叫 setError('數量錯誤')。會怎樣？

✓ useState 的型別從初始值推論，null 的型別就是 null，set 字串會報錯。型別在編譯時就決定，不會等到第一次 set（a 錯）。執行時 React 不檢查型別，什麼都存得進去（c 錯）。strict 模式下不會推論成 any（d 錯）。

練習 6：泛型元件的 props 寫成 { options: readonly T[]; value: T; getLabel: (o: T) => string }。使用的人寫 <Select options={PRODUCTS} value={null} getLabel={p => p.name} />，結果 p.name 報錯。原因是？

✓ T 出現在 options 和 value，兩邊都參與推論，得到 Product | null。修法是把「沒選」寫進型別：value: T | null，T 只剩 Product。泛型元件會從 props 推論 T（a 錯），手動指定只在推論不出來時才需要，例如空陣列。readonly T[] 收唯讀陣列沒問題（b 錯）。

練習 7：按鈕的處理函式寫成 function handleClick(e: MouseEvent<HTMLButtonElement>) { submit(e.target.form) }，tsc 報 Property 'form' does not exist on type 'EventTarget'。怎麼修最恰當？

✓ 型別參數 HTMLButtonElement 描述的是 currentTarget。target 是實際被點到的元素，按鈕裡有圖示時可能是那個 <svg>，所以型別只是 EventTarget。b 的斷言能讓錯誤消失，但點到圖示時拿到的真的是 svg，form 是 undefined；c 讓整個函式失去檢查。

常見錯誤

  • 以為 Vite 或 Vitest 會檢查型別：CI 要跑 tsc -b 或 tsc --noEmit。
  • 包裝原生元素時自己列屬性，或用 HTMLAttributes：永遠列不完，HTMLAttributes 也沒有 disabled、type、ref。用 ComponentProps<'button'> 加上自己的 props。
  • 每種狀態的資料都寫成可選的 prop：缺資料、帶錯資料都不報錯。改成辨識聯合，元件裡先判斷再讀，default 用 satisfies never。
  • 用 ! 或 as 讓 null、型別錯誤消失：編譯器不再幫你檢查，問題延到執行時。DOM ref 用 ?.，事件讀 currentTarget。
  • 泛型元件寫 T[]、加不必要的 extends、「沒選」不寫進型別：唯讀陣列、字串選項傳不進來，或 T 被推論成 X | null。用 readonly T[]、value: T | null，限制只放元件真的用到的。

小結

  • Vite、Vitest 只擦掉型別；.tsx 直接用 tsc 檢查（react-ts 範本的 tsc -b && vite build），不需要 vue-tsc 這類工具。
  • props 的型別就是函式參數的型別；Vue 的 emits 在 React 是 onXxx 函式 prop，slot 是 ReactNode prop。ComponentProps<typeof X> 取出別的元件的 props。
  • 包裝原生元素用 ComponentProps<'button'> & { … }，包含 React 19 的 ref；要換型別的原生 prop 先 Omit。
  • 每種狀態各帶不同資料時，props 寫成辨識聯合：錯的組合寫不出來，元件裡用 switch 縮小、satisfies never 窮舉。
  • 行內處理函式會推論事件型別，抽出來要自己標：ChangeEvent<HTMLInputElement>、SubmitEvent<HTMLFormElement>；讀 currentTarget。useState<T | null>(null)、useRef<HTMLInputElement>(null) 配 ?.。
  • 泛型元件就是泛型函式：T 從 props 推論，readonly T[]、value: T | null，不需要就不加 extends；推論不出來寫 <Select<Product>>，箭頭函式寫 <T,>。
