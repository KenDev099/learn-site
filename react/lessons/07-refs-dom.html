階段 2：Hooks 與副作用 · 第 7 課

useRef 與 DOM：不觸發 render 的值、ref 與焦點

咖啡店吧台的手沖計時器按「停止」停不下來；結帳頁手機沒填，父元件拿不到子元件裡的輸入框；點「編輯備註」後輸入框出現了，游標卻不在裡面。三個問題都和 React 的 ref 有關：有些值要跨 render 保留、改了卻不該重新 render；有些時候要直接拿到 DOM 節點，在對的時間點操作它。

這課的路線：
  1. useRef 與它的規則：計時器 id 這種要跨 render 保留、改了卻不該重新 render 的值放哪裡，為什麼 render 中不能讀寫 ref（開場問題的最小答案）。
  2. 保存最新的 callback：訂單看板每 5 秒刷新，父元件一直 render 時計時器怎麼不被重來。
  3. ref 指到 DOM、一整串節點：React 什麼時候把節點放進 ref，列表每一列怎麼各拿一個節點、捲到指定的訂單。
  4. ref 是 prop：父元件要聚焦子元件的輸入框時，怎麼只交出 focus 這類允許的動作。
  5. state 改了之後聚焦：顯示輸入框的同時把游標移進去，關閉後焦點回到哪裡，鍵盤使用者就靠它操作。
這課會用到：
  • 第 3 課的快照與 updater：set 只影響下一次 render，這次 render 的變數不會變；setSeconds(s => s + 1) 從最新的值算。
  • 第 5 課的 useEffect：在 commit 之後執行，依賴陣列決定何時重跑，回傳的清理函式在重跑前和卸載時呼叫；開發模式的 Strict Mode 會多跑一輪 setup → cleanup。

ref：跨 render 保留、改了不重新 render

先看停不下來的計時器：

function BrewTimer() {
  const [seconds, setSeconds] = useState(0)
  let timerId: ReturnType<typeof setInterval> | undefined   // ✗

  function start() {
    timerId = setInterval(() => setSeconds(s => s + 1), 1000)
  }
  function stop() {
    clearInterval(timerId)   // 這裡的 timerId 是 undefined
  }
  // …
}

第 1 課講過，重新 render 就是再呼叫一次元件函式。一秒後 setSeconds 觸發重新 render，let timerId 又是一個新的、沒有值的變數；「停止」的 stop 是最新那次 render 建立的，看到的是新變數。

需要一個每次 render 都拿到同一個的盒子：useRef。useRef(初始值) 回傳只有 current 屬性的普通物件，之後每次 render 回傳同一個物件。current 可以隨時讀寫，React 不追蹤它，改了不會重新 render。

const timerId = useRef<ReturnType<typeof setInterval> | null>(null)

function start() {
  timerId.current = setInterval(() => setSeconds(s => s + 1), 1000)   // 存進盒子
}
// stop() 從 timerId.current 拿 id 來清

連按兩次「開始」、停止後再開始、元件卸載時計時器還在跑，這些情況留給練習 1。

四種放值的地方比較：

放在哪跨 render 保留改了會重新 render每個元件各一份用在
元件裡的 let✗✗✓這次 render 裡的暫時計算
useState✓✓✓畫面要顯示的資料（秒數）
useRef✓✗✓畫面用不到的資料（計時器 id、DOM 節點）
元件外面的變數✓✗✗ 所有元件共用真正的全域常數

最後一列是陷阱：id 放在元件外面，畫面上兩個 BrewTimer 會共用同一個 id，第二個按「開始」被當成「已經在跑」。TypeScript 上，@types/react 19 的 useRef 一定要給初始值（useRef<number>() 會報 Expected 1 arguments），還沒有值就寫 useRef<T | null>(null)。

開場另外兩個問題也靠 ref：父元件要拿子元件裡的輸入框，是把 ref 當成 prop 傳下去；點「編輯備註」後游標不在輸入框，是 set state 的那一刻輸入框還不在 DOM 裡，要等 React 把它放進去再 focus。細節在後面的〈ref 是 prop〉與〈state 改了之後聚焦〉。

💡 實務上：名字一樣，Vue 的 ref 和 React 的 useRef 是相反的東西
Vue 的 ref() 是響應式的，對應 React 的 useState；useRef 刻意不響應。Vue 的 <script setup> 每個實例只執行一次，let timerId 本來就會保留；React 的元件函式每次都重跑，才需要 useRef。從 Vue 轉過來的人常拿 useRef 存要顯示的資料，畫面就不動了。review 時看到 JSX 裡有 xxxRef.current，先問「這該不該放 state」。

規則：render 過程中不讀寫 ref.current

既然 ref 能保存值，為什麼不把秒數也放進去？

const seconds = useRef(0)
// 計時器裡：seconds.current++
return <p role="timer">已沖煮 {seconds.current} 秒</p>   // ✗ 畫面永遠是 0

改 ref 不會重新 render，畫面停在 0，等別的 state 碰巧觸發 render 才突然跳一大段。官方文件的規則：不要在 render 過程中讀或寫 ref.current（元件函式本體和 JSX；事件處理函式和 effect 不算）。render 要用的資訊放 state。

寫也不行，例如在元件本體寫 latest.current = onTick 把最新的 props 存進 ref：React 可能呼叫元件函式卻不採用結果（Strict Mode 會故意多 render 一次，第 21 課的並行渲染會中斷重來），寫進去的可能是沒顯示過的 props。練習用 eslint-plugin-react-hooks 7.1.1 的 react-hooks/refs 規則檢查，兩段都會被擋下。例外是延遲初始化，第一次 render 建立一次、之後不改：

const rows = useRef<Map<number, HTMLLIElement> | null>(null)
if (rows.current === null) rows.current = new Map()   // ✓ 只在第一次執行

保存最新的 callback：計時器不重來

訂單看板每 5 秒呼叫一次 onTick 重新抓訂單。照第 5 課寫成 useEffect(() => { const id = setInterval(onTick, intervalMs); return () => clearInterval(id) }, [intervalMs, onTick])，問題就來了。

父元件每次 render 都傳新的箭頭函式，effect 每次都清掉計時器重來；父元件每 4 秒重新 render 一次，5 秒的計時器就永遠跑不完。把 onTick 從依賴陣列拿掉，計時不重來了，但呼叫的永遠是第一次 render 的函式，讀到當時的 props。

拆成兩件事：計時器只跟 intervalMs 有關；「時間到要做什麼」放在 ref 裡，每次 commit 後更新成最新的：

const latestOnTick = useRef(onTick)
useEffect(() => {
  latestOnTick.current = onTick          // 寫在 effect 裡：只有真的 commit 的那一版才會寫進來
})

useEffect(() => {
  const id = setInterval(() => latestOnTick.current(), intervalMs)   // 時間到才去盒子拿
  return () => clearInterval(id)
}, [intervalMs])

第一個 effect 每次 render 後都執行；第二個只在 intervalMs 改變時重來，時間到才讀 ref。第 5 課的 useEffectEvent（React 19.2 起穩定）做同一件事（const tick = useEffectEvent(() => onTick())，lint 知道它不用列進依賴），限制是只能在 effect 裡呼叫。練習寫 ref 版本，舊專案和函式庫裡到處都是它。

💡 實務上：看到 eslint-disable exhaustive-deps，多半是在找這個模式
接手的專案常見 effect 上關掉 react-hooks/exhaustive-deps，理由是「放進依賴會一直重跑」。代價是讀到舊的 props，例如切換門市後看板還在抓舊門市的訂單。資深工程師會先分清楚：哪些值改了應該重來（列進依賴），哪些只是到時候要用最新的（ref 或 useEffectEvent）。輪詢、WebSocket 訊息處理、分析事件回報都是這種情況。

ref 指到 DOM：React 什麼時候把節點放進去

把 ref 物件交給內建元素的 ref 屬性（<input ref={input} />），React 會把那個 DOM 節點放進 current。這對應 Vue 的 useTemplateRef('input') 配 ref="input"（Vue 課第 8 課），只是 React 直接傳物件，不用字串名稱。

React 的一次更新分兩階段：render 呼叫元件算出畫面；commit 套用到 DOM。官方文件寫明 ref 在 commit 時設定：更新 DOM 前把受影響的 ref.current 設成 null，更新後設成對應的節點；effect 在這之後才執行。

所以 DOM ref 在事件處理函式（使用者點下去時畫面早就 commit 好了）或 effect 裡讀。元素被條件渲染移除後 ref 變回 null，讀之前用 ?.，跟 Vue 的 template ref 被 v-if 移除後變回 null 一樣。

一整串節點：ref callback 與清理函式

訂單看板點通知要捲到那一張訂單，每一列都要一個 ref。但 Hook 只能在元件最上層呼叫，不能放在迴圈或 map 裡（React 靠呼叫順序認出每個 Hook）；一個 ref 掛在每一列上，最後只留下最後一列。

解法是 ref callback：ref 屬性也可以給一個函式。節點放進 DOM 時 React 呼叫它、傳入節點；React 19 起它可以回傳清理函式，節點離開時呼叫。下面是訂單看板「捲到某張訂單」的寫法，一個 ref 存一個 Map，每一列自己登記、自己移除：

const cards = useRef<Map<number, HTMLLIElement> | null>(null)
if (cards.current === null) cards.current = new Map()

function showOrder(id: number) {
  cards.current?.get(id)?.scrollIntoView({ block: 'nearest' })
}

{orders.map(o => (
  <li
    key={o.id}
    ref={node => {
      if (!node) return                              // 型別上 node 可能是 null
      cards.current?.set(o.id, node)                 // 掛上：登記
      return () => { cards.current?.delete(o.id) }   // 離開：移除
    }}
  >
    #{o.id} {o.customer}
  </li>
))}

Map 的鍵用 id，不用陣列索引：有一筆被移除或順序改變後，索引對應到的已經是別筆。要讓 <li> 能被 focus()，加上 tabIndex={-1}（可以用程式聚焦，但不進 Tab 順序）。也不要用 document.querySelector 找：同一個元件在頁面上出現兩次時，它永遠找到第一個。

ref callback 的細節（React 19.3.1 實際跑過）：

情況React 做什麼
掛上／移除呼叫 callback 傳入節點／呼叫清理函式
節點移除，沒有回傳清理函式用 null 再呼叫一次 callback（官方文件說之後會移除這個行為）
重新 render，傳的是新的函式（每次寫一個箭頭函式）先呼叫舊的清理函式，再用同一個節點呼叫新的 callback
Strict Mode（開發環境）第一次多跑一輪「掛上 → 清理 → 掛上」

第三列表示 callback 每次 render 後都會重跑（記錄到的順序是 set node | cleanup | set node | cleanup：掛上、重新 render、卸載），所以裡面只做登記、移除這種重跑也沒差的事。

TypeScript 會擋下 ref={node => (current = node)}：@types/react 19 規定 ref callback 只能回傳清理函式或不回傳，這裡回傳了賦值的結果，會報 Type 'null' is not assignable to type 'void | (() => VoidOrUndefinedOnly)'。加上大括號：ref={node => { current = node }}。

ref 是 prop：只交出允許的動作

菜單頁按 / 要把游標移到 <SearchBox> 裡的輸入框。React 19 起函式元件直接從 props 拿到 ref；官方文件寫明不再需要 forwardRef，之後會把它標為棄用（舊專案的 forwardRef((props, ref) => …) 意思一樣）。把 ref 轉交給 <input>，父元件就拿到整個 DOM 節點，連 value、style 都能改。useImperativeHandle 讓你決定父元件的 ref 拿到什麼：

export type SearchBoxHandle = { focus(): void; clear(): void }

export function SearchBox({ ref }: { ref?: Ref<SearchBoxHandle> }) {
  const input = useRef<HTMLInputElement>(null)   // 真正的節點留在裡面
  const [keyword, setKeyword] = useState('')
  useImperativeHandle(ref, () => ({
    focus() { input.current?.focus() },
    clear() { setKeyword('') },
  }), [])
  return <input ref={input} type="search" value={keyword} onChange={e => setKeyword(e.target.value)} />
}

// 父元件：const box = useRef<SearchBoxHandle>(null)，<SearchBox ref={box} />，box.current?.focus()

這就是 Vue 的 defineExpose({ focus })。useImperativeHandle 處理各種 ref：ref 物件設定 current、ref callback 呼叫它、卸載時給 null、沒傳就不做事；自己寫 ref.current = … 只顧得到 ref 物件。公開的方法就是介面，之後改不動：「彈窗開或關」是狀態，用 props；ref 留給 focus、捲動這類命令。

state 改了之後聚焦：flushSync 與 effect

回到備註編輯：setEditing(true) 的下一行寫 input.current?.focus()，什麼都沒發生。第 3 課講過 setState 只是排一次更新，這時輸入框還不在 DOM 裡，ref 是 null（上一張圖）。按「完成」時輸入框被移除，焦點掉回 <body>，用鍵盤的人要從頁面最上面重新 Tab。

第一種修法是 react-dom 的 flushSync：callback 裡的 state 更新會立刻 render、commit，回來時 DOM 和 ref 都是新的（官方文件「新增待辦後捲到最後一筆」的範例就是它）。結帳頁「輸入優惠碼」的寫法：

import { flushSync } from 'react-dom'

function openCoupon() {
  flushSync(() => setShowCoupon(true))
  couponInput.current?.focus()    // ✓ 輸入框已經在 DOM 裡
}

收起輸入框時反過來：flushSync 讓按鈕回到 DOM，再把焦點還給它。

React 19.3.1 實測：setShow(true) 的下一行讀 ref 是 null，包進 flushSync 後讀到 INPUT。它對應 Vue 的 await nextTick()（Vue 課第 6 課），但不是等，而是要求 React 現在就同步做完。官方文件把它列為最後手段：可能明顯拖慢效能，也可能讓 Suspense 重新顯示 fallback（第 13 課）。

第二種修法是 effect：useEffect(() => { if (editing) input.current?.focus() }, [editing])，commit 之後 ref 已經就位。但 effect 第一次 render 後也會執行，寫成「editing 是 false 就聚焦按鈕」會在載入時搶走焦點，要另外記住「使用者按了完成」。不要用 setTimeout 猜時間：測試用假計時器時它根本不會執行。

💡 實務上：焦點管理是彈窗與行內編輯的必考題
開彈窗把焦點移進去、關掉時還給原本的按鈕；行內編輯完成回到「編輯」按鈕；刪除一筆後焦點放到下一筆；捲到表單第一個錯誤欄位時也把焦點帶過去。客服回報「用鍵盤操作時畫面跳回頂端」，通常是有焦點的元素被移除了。寫完用 Tab 和 Enter 走一遍，看 document.activeElement 在哪。

練習

在 learn/ 執行 node check.mjs react 07（環境在第 2 課裝好）。練習 1、2 用假計時器，不會真的等。練習 1、2、3、5 會用 react-hooks/refs 等 lint 規則檢查你的檔案，不能用 eslint-disable 關掉。

練習 1：修好 BrewTimer。按「開始」後每秒加 1（「已沖煮 N 秒」）；按「停止」後不再增加、不留計時器，再按「開始」從原本的秒數繼續；計時中再按「開始」不能多開一個。按「開始」「停止」本身不能造成重新 render（測試用 Profiler 數 commit，每秒只能一次）。卸載時清掉計時器；同一頁兩個 BrewTimer 各自計時。不能在 render 過程中讀寫 ref.current。

練習 2：OrderPoller 每 intervalMs 毫秒呼叫一次 onTick。父元件每次 render 都傳新的 onTick：計時不能重來（測試每 400 毫秒傳一次新函式，4 秒內要呼叫 4 次），時間到時呼叫最新的那個。intervalMs 改變時用新間隔重新計時、只留一個計時器；卸載時清掉。依賴陣列要完整，ref 的更新寫在 effect 裡。

練習 3：MenuJump 按「跳到 X」時，對 X 那一列的 <li> 呼叫一次 scrollIntoView，並讓它取得焦點。products 換了（下架、上架、順序反過來）之後要跳到正確的列；同一頁兩個 MenuJump 各跳各的。不能在 map 裡呼叫 useRef、不能用 querySelector／getElementById、不能把節點存在元件外面。

練習 4：讓 PhoneField 接收 ref prop：父元件呼叫 ref.current.focus() 時輸入框取得焦點；ref.current 不能是 DOM 節點，只能有 focus 一個屬性。ref 物件和 ref callback 都要能用，卸載後要收到 null；不傳 ref 也能照常輸入。PhoneFieldHandle 與 ref?: Ref<PhoneFieldHandle> 的型別不能改（測試用 tsc 檢查）。

練習 5：修好 NoteEditor 的焦點。載入時不搶焦點（焦點在 <body>）。按「編輯備註」：輸入框出現、內容是目前的備註、已經取得焦點。按「完成」：呼叫 onSave(輸入的內容)、回到顯示模式，焦點回到「編輯備註」按鈕。兩次聚焦都要在點擊事件處理完時就完成（不能用 setTimeout）；只用鍵盤也要能連續編輯兩次。

練習 6：const count = useRef(0)，按鈕 onClick={() => { count.current++ }}，文字是 按了 {count.current} 次，沒有其他 state。連按 3 次後畫面顯示什麼？

✓ 改 ref 不會重新 render，畫面一直是第一次 render 的結果。count.current 確實是 3，但沒有人重新呼叫元件函式去讀它。要顯示的值放 state。d 錯在事件處理函式正是修改 ref 的地方。

練習 7：<li ref={node => { map.set(id, node); return () => { map.delete(id) } }}>，元件因為別的 state 重新 render，這一列還在。React 19 會怎麼處理這個 ref callback？

✓ 每次 render 的箭頭函式都是新的，React 視為換了 ref callback：先清理舊的，再呼叫新的。Map 短暫刪掉又加回來，結果還是對的，但 callback 裡不要做重跑會出事的事。a 只在傳入同一個函式（例如 useCallback 固定住）時成立。

練習 8：Vue 的 <script setup> 裡用 let timerId 一切正常，同樣寫法搬到 React 函式元件，stop 清不到計時器。主要原因是？

✓ 差別在元件函式跑幾次。Vue 的 setup 只跑一次，let 一直是同一個；React 每次 render 都重跑，stop 看到的是新的 let。useRef 補上「跨 render 同一個」的盒子。c 錯在 Vue 不會把普通變數變成響應式。

常見錯誤

  • 把要顯示的值放 ref：改了不會重新 render，畫面停在舊值。畫面用得到的放 state。
  • 在 render 過程中讀寫 ref.current：讀到舊值，或寫進沒被採用的那次 render。只在事件處理函式和 effect 裡碰它，延遲初始化除外。
  • 為了不讓 effect 重跑，拿掉依賴再關 lint：effect 讀到舊的 props。最新的函式放進 ref（在 effect 裡更新），或用 useEffectEvent。
  • 在 map 裡呼叫 useRef，或一個 ref 掛在每一列：前者違反 Hook 規則，後者只留下最後一列。用一個 ref 放 Map，ref callback 登記、清理函式移除，鍵用 id。
  • 把整個 DOM 節點交給父元件：父元件會繞過 props 改子元件。用 useImperativeHandle 只公開需要的動作。
  • setState 的下一行就操作新出現的元素：ref 還是 null。用 flushSync 或 effect，不要用 setTimeout 猜；元素消失時把焦點還給觸發它的按鈕。

小結

  • useRef 回傳每次 render 都相同的 { current }：跨 render 保留、改了不重新 render、每個元件各一份；對應 Vue setup 裡的普通變數，不是 Vue 的 ref()。
  • render 過程中不讀寫 ref.current（延遲初始化除外）；render 用得到的放 state。
  • effect 不該重跑、到時候又要用最新的 callback：ref 在 effect 裡更新，時間到才讀；或用 useEffectEvent。
  • React 在 commit 時設定 DOM ref，在事件處理函式或 effect 裡讀；一串節點用 ref callback 登記進 Map，React 19 的 ref callback 可以回傳清理函式。
  • React 19 的 ref 是普通 prop，不必 forwardRef；useImperativeHandle 只公開動作，等於 Vue 的 defineExpose。
  • state 改了要立刻操作新的 DOM：flushSync（對應 Vue 的 nextTick）或 effect，並把焦點放到對的地方。
