階段 2：Hooks 與副作用 · 第 5 課

useEffect：跟外部系統同步、清理與競態

咖啡店的分頁標題顯示購物車數量，客人加了第二杯，標題還是「(1)」；等候計時器在客人離開頁面後還在跑；商品詳情從拿鐵快速點到可頌，畫面卻停在拿鐵。原因都一樣：元件要跟 React 以外的東西保持一致，但「什麼時候重新同步」和「什麼時候停下來」沒寫對。

這課的路線：
  1. effect 是什麼：render 之後，讓分頁標題、計時器這類 React 管不到的東西跟 state 一致（開場問題的最小答案）。
  2. 依賴陣列與清理函式：什麼時候重新同步、什麼時候先復原，為什麼離開頁面計時器還在跑。
  3. 物件與函式依賴：為什麼 props 沒變，effect 卻每次 render 都重跑。
  4. 抓資料與競態：快速切換商品時，晚回來的舊回應怎麼擋，幾乎每個詳情頁都會遇到。
  5. 從 Vue 搬過來：watch、watchEffect、onUnmounted 各對到 React 的哪種寫法。
這課會用到：
  • 第 1 課的純函式與快照：元件本體不能改外面的東西；每次 render 的 props、state 是那一刻的快照，裡面的函式讀到的也是那一刻的值。
  • 第 3 課的 updater：setSeconds(s => s + 1) 從最新的值算下一個，不必讀這次 render 的 seconds。
  • TS 課第 11 課的 AbortController：把 signal 傳給 fetch，呼叫 abort() 就取消那個請求。

effect：render 之後，跟外部系統同步

第 1 課講過，元件函式要是純的（pure）：同樣的輸入、同樣的畫面，不改外面的東西。React 可能呼叫它好幾次、甚至算完不用，所以這樣寫是錯的：

export function CartTitle({ count, shopName }: { count: number; shopName: string }) {
  document.title = `(${count}) ${shopName}`   // ✗ 在 render 期間改外面的東西
  return <p>購物車有 {count} 項</p>
}

分頁標題、計時器、WebSocket、第三方地圖元件都是外部系統（external system），不歸 React 管。Effect 是「畫面更新完之後，讓外部系統跟現在的 props、state 一致」的程式，用 useEffect 宣告：

import { useEffect } from 'react'

export function CartTitle({ count, shopName }: { count: number; shopName: string }) {
  useEffect(() => {
    document.title = count > 0 ? `(${count}) ${shopName}` : shopName
  }, [count, shopName])

  return <p>購物車有 {count} 項</p>
}

第一個參數叫 setup 函式，第二個是依賴陣列（dependencies）。順序是 render（呼叫元件函式）→ commit（寫進 DOM）→ effect。依 react.dev 的 useEffect 參考，不是點擊觸發的更新，React 通常先讓瀏覽器畫出畫面再執行 effect；點擊觸發的可能在畫出前執行。要在畫面出現前量尺寸、定位 tooltip，改用會擋住畫面的 useLayoutEffect，能不用就不用。effect 只在瀏覽器執行，伺服器 render（第 22 課）時不會跑。

對照 Vue：這相當於 watch（Vue 課第 5 課）加 flush: 'post'。差別是 Vue 的 watch 預設建立時不執行（要 immediate），useEffect 第一次 commit 之後一定執行。

開場的三個 bug 對應接下來的三件事：標題停在「(1)」，是依賴陣列沒寫對，count 變了 effect 卻沒有重新同步；離開頁面計時器還在跑，是沒有用清理函式停掉它；畫面停在拿鐵，是拿鐵晚回來的回應蓋掉了可頌。細節在後面的〈依賴陣列〉〈清理函式〉與〈抓資料與競態〉。

依賴陣列：React 不追蹤，由你宣告

Vue 的 watchEffect 會自動記下讀了哪些響應式資料（Vue 課第 2 課）。React 沒有追蹤，props 和 state 只是普通的值，要由你用依賴陣列告訴它「這些值變了就重新同步」。

寫法什麼時候執行
useEffect(fn)（沒有陣列）每次 commit 之後都執行
useEffect(fn, [])只在第一次 commit 之後執行（開發模式多一輪，下面會講）
useEffect(fn, [a, b])第一次 commit 之後，以及 a 或 b 跟上次不同時

「不同」用 Object.is 逐一比較。effect 讀到的響應值（reactive value）都要列：props、state、元件函式本體裡宣告的變數和函式；元件外面的常數不用。漏列的話，effect 看到的是建立它那次 render 的快照（第 1 課）：

const [seconds, setSeconds] = useState(0)

useEffect(() => {
  const id = setInterval(() => setSeconds(seconds + 1), 1000)   // 這裡的 seconds 永遠是 0
  return () => clearInterval(id)
}, [])   // ✗ 讀了 seconds 卻沒列

計時器裡的 seconds 是第一次 render 的 0，每秒都在做 setSeconds(0 + 1)；在練習環境用假計時器推 5 秒，畫面停在「1」。把 seconds 列進依賴，數字會動，但每秒都清掉計時器再建一個。更好的修法是讓 effect 不讀 seconds：用第 3 課的 updater function setSeconds(s => s + 1)，計時器只建一次。

lint 規則 react-hooks/exhaustive-deps（eslint-plugin-react-hooks 7.1.1）會檢查漏列，上面那段它會報：

React Hook useEffect has a missing dependency: 'seconds'. Either include it or remove the
dependency array. You can also do a functional update 'setSeconds(s => ...)' ...
💡 實務上：不要用 eslint-disable 蓋掉 exhaustive-deps
接手的專案裡常看到 // eslint-disable-next-line react-hooks/exhaustive-deps，多半是想「只在掛載時執行一次」。之後有人在 effect 裡多讀一個 prop，lint 不會再提醒，快照過期的 bug 就藏在這裡。資深工程師把依賴當成由程式碼決定的事實：想讓依賴變少，就改程式碼（updater function、物件搬進 effect、Effect Event），讓 effect 不再讀那個值。

清理函式：每一次同步都要能復原

setup 可以回傳清理函式（cleanup），React 在依賴改變、重新執行之前，以及卸載時呼叫它：

useEffect(() => {
  if (!running) return                     // 這次不用計時：沒有東西要清
  const id = setInterval(() => setSeconds(s => s + 1), 1000)
  return () => clearInterval(id)          // 清掉「這一次」建立的計時器
}, [running])

在練習環境記錄一個依賴 count 的元件：掛載、同樣的 props 再 render、count 變 2、卸載：

render 1 | setup 1 | render 1 | render 2 | cleanup 1 | setup 2 | cleanup 2

依賴沒變的那次 render 沒有執行 effect；count 變了，先用舊的值清理，再用新的值執行；卸載時清理最後一次。訂閱 API 多半回傳「取消訂閱」的函式，直接回傳它：

useEffect(() => {
  const unsubscribe = hub.subscribe({ storeId, orderId }, setStatus)
  return unsubscribe                       // ✓ 回傳函式，React 之後再呼叫
  // return unsubscribe()                  // ✗ 當場就取消了，回傳的是 undefined
}, [hub, storeId, orderId])

return clearInterval(id) 也一樣是當場清掉。清理要「回傳一個函式」，不是「回傳呼叫的結果」。

對照 Vue：Vue 用 onWatcherCleanup(fn) 登記 watcher 重跑前的清理，元件卸載的清理寫在 onUnmounted。React 合成同一個清理函式，所以要用「同步」而不是「生命週期」來想 effect：讓外部系統跟這組值一致；值換了，先復原，再用新的值同步。

開發模式的 StrictMode：多跑一輪

第 3 課的 <StrictMode> 會多呼叫一次元件函式；對 effect，官方文件寫明它在開發模式下、第一次真正的 setup 之前，多執行一輪 setup → cleanup。同樣記錄一次：

render 1 | render 1 | setup 1 | cleanup 1 | setup 1 | cleanup 1

這是壓力測試：清理確實復原了 setup，使用者就看不出差別；沒寫清理的計時器會變成兩個、每秒加 2。正式環境不會多跑。該問「清理少了什麼」，不是用 useRef 擋掉第二次。

💡 實務上：清理沒寫，症狀在「切頁幾次之後」才出現
單頁應用切頁不會重新載入，沒清掉的計時器、WebSocket 訂閱、window 事件監聽會累積，切幾次頁就有好幾個計時器在打 API，常是客服回報「通知跳了三次」才發現。習慣是每寫一個 addEventListener、setInterval、subscribe，就同時寫好移除；review 時看到它們卻沒有 return 就要問。

物件與函式依賴：每次 render 都是新的

數字、字串值一樣就相等；但元件函式本體建立的物件、陣列、函式，每次 render 都是新的，永遠「不同」：

const target = { storeId, orderId }        // 每次 render 都建立新物件

useEffect(() => {
  return hub.subscribe(target, setStatus)
}, [hub, target])                           // ✗ target 每次都不同：每次 render 都取消再重新訂閱

實測 props 沒變、render 三次，effect 執行 3 次。lint 會報「The 'target' object makes the dependencies of useEffect Hook change on every render. Move it inside the useEffect callback.」照做：物件搬進 effect 裡建立，依賴只剩原始值。只在 effect 裡用的函式也宣告在 effect 裡面。

麻煩的是從 props 傳進來的函式，或「要讀、但不該觸發重新同步」的值。例如換門市時送一筆統計，帶上當下的購物車件數：列了 cartCount，每加一杯就多送一筆；用 eslint-disable 拿掉，又會讀到舊的件數。父元件每次 render 都傳新的 onRefresh，effect 依賴它的話，計時器每次都重來，也是同一個問題。

「進入門市時記錄件數」是一個事件：要讀最新的值，但值變了不代表要重做。React 19.2 起穩定的 useEffectEvent 就是為此設計的：

const onVisit = useEffectEvent((id: number) => {
  track('進入門市', { storeId: id, cartCount })   // 讀到的永遠是最新的 cartCount
})

useEffect(() => {
  onVisit(storeId)
}, [storeId])                                     // Effect Event 不列進依賴

官方文件對 Effect Event 的限制：不能放進依賴陣列（它刻意每次 render 都不同，lint 會報錯）；只能在 effect 裡呼叫，不能在 render 時呼叫或傳給子元件；不要拿它逃避列依賴。

對照 Vue：watch callback 裡讀 cart.count 本來就是最新的，沒放進來源就不會觸發。Vue 的響應式物件是活的，React 的值是快照，所以需要 useEffectEvent 表達「讀最新的，但不因為它重新同步」。

抓資料與競態：舊回應不能蓋掉新結果

商品詳情頁依 productId 抓資料，最直覺的寫法：

useEffect(() => {
  api.getProduct(productId).then(setProduct)   // ✗ 沒有清理
}, [productId, api])

客人從拿鐵（2 號）快速點到可頌（5 號），拿鐵的請求比較晚回來，把畫面蓋回拿鐵，這就是競態（race condition，TS 課第 12 課）：

修法用清理函式：每一次 effect 有自己的 ignore 旗標，被清理時設成 true，回應回來先檢查；同時用 AbortController 取消還沒回來的請求：

useEffect(() => {
  const controller = new AbortController()
  let ignore = false
  setProduct(null)                          // 換商品時回到「載入中」
  api.getProduct(productId, { signal: controller.signal })
    .then(p => { if (!ignore) setProduct(p) })
  return () => {
    ignore = true                           // 這次的回應過期了，之後不再改 state
    controller.abort()                      // 取消請求
  }
}, [productId, api])

錯誤處理也要先檢查 ignore：被取消的請求以 AbortError 失敗，沒有 ignore 就會顯示成錯誤；沒有 abort，畫面對了，但舊請求還占用連線。abort 只是前端不再等，伺服器可能已經處理了，會改資料的請求不能靠取消防重複。

effect 的函式不能是 async

useEffect(async () => { … }) 回傳的是 Promise，不是清理函式。TypeScript 會報錯；React 19.3.1 實測，開發模式印出「useEffect must not return anything besides a function…」，卸載時還丟出 TypeError: destroy is not a function。要用 await，就在 effect 裡宣告 async 函式再呼叫，清理照樣同步回傳：

useEffect(() => {
  let ignore = false
  async function load() {
    const p = await api.getProduct(productId)
    if (!ignore) setProduct(p)
  }
  load()
  return () => { ignore = true }
}, [productId, api])

對照 Vue：watch callback 可以 async，因為清理用 onWatcherCleanup 登記（要在第一個 await 之前）；React 的 callback 不能 async，清理同步回傳。

💡 實務上：正式專案很少手寫抓資料的 effect
商品詳情、訂單列表這類伺服器資料還要快取、重試、多個元件共用，手寫 effect 很快就又長又容易錯，開發模式也會看到請求送兩次。React 官方文件建議用框架的資料載入機制或有快取的函式庫；這門課在第 15 課用 TanStack Query，它處理的就是這課的競態與取消。手寫 effect 留給計時器、訂閱、第三方元件這類真正的外部系統。

練習

在 learn/ 執行 node check.mjs react 05（環境見第 2 課）。練習 2、3 有在 <StrictMode> 裡掛載的測試；每題都用 eslint-plugin-react-hooks 檢查，依賴有缺或用 eslint-disable 都算沒過。練習 2、4 用假計時器：vi.useFakeTimers() 之後計時器不會真的等，測試用 vi.advanceTimersByTime(1000) 把時間往前推。練習 5 的假 API 由測試決定請求回來的順序；signal 被 abort 時，它像 fetch 一樣以 AbortError 失敗。

練習 1：CartTitle 把購物車數量同步到 document.title：count 大於 0 是「(數量) 店名」（例如「(3) 咖啡店」），0 時只有店名。count 或 shopName 改變時跟著變；兩個都沒變時，重新 render 不能再寫標題。只能在 effect 裡寫，不能寫在元件函式本體；店名不能寫死。

練習 2：WaitTimer：running 是 true 時每 1000 毫秒加 1，在 <p role="timer"> 顯示「已等候 N 秒」；變成 false 時停止、數字留著，變回 true 時接著加；一開始是 false 就不建立計時器。running 變 false 或卸載時要 clearInterval。計時期間只能呼叫一次 setInterval（用 updater function），StrictMode 下一秒也只加 1。

練習 3：OrderStatus 用 hub.subscribe({ storeId, orderId }, listener) 訂閱，顯示「訂單 #12：製作中」；它回傳取消訂閱的函式。storeId 或 orderId 改變時先取消舊的再訂閱新的，舊訂單的推播不能再改到畫面；卸載時取消；三個 props 都沒變時重新 render 不能重新訂閱；StrictMode 下只留一個訂閱。不要改 order-hub.ts。

練習 4：AutoRefresh 每 everyMs 毫秒呼叫一次 onRefresh。父元件每秒重新 render、每次傳新的 onRefresh，計時器不能重來：第 30 秒仍要呼叫一次，而且是最新的 onRefresh。everyMs 改變時用新間隔重新計時、清掉舊的；卸載後不再呼叫。用 useEffectEvent，不要把它列進依賴，也不能拿掉依賴陣列。

練習 5：ProductDetail 在掛載時與 productId 改變時呼叫 api.getProduct(productId, { signal })。載入中（包括換商品後）顯示「載入中…」；成功在 <p className="name"> 顯示「拿鐵 $110」這樣的「品名 $價格」；失敗在 <p role="alert"> 顯示錯誤的 message，換商品時清掉。晚回來的舊回應不能蓋掉新結果；productId 改變或卸載時 abort 還沒回來的請求，被取消不能顯示成錯誤。effect 的函式不能是 async。

練習 6：一個元件的 effect 依賴 [count]，setup 印 setup N、清理函式印 cleanup N（N 是當時的 count）。count 從 1 變成 2，這次更新會印出什麼？

✓ 依賴改變時，React 先執行上一次的清理函式（在 count 是 1 的 render 建立，看到的是 1），再用新的值執行 setup。清理不只在卸載時呼叫，每次重新同步前都會呼叫，舊的計時器、訂閱才不會跟新的同時存在。

練習 7：開發時發現商品詳情頁打開時，Network 面板裡 getProduct 送了兩次。最好的處理是？

✓ StrictMode 在開發模式多跑一輪 setup → cleanup → setup，檢查清理有沒有寫對；清理正確時使用者看不出差別，正式環境只送一次。拿掉 StrictMode 或用 ref 擋住只是關掉檢查；空陣列擋不住那一輪，還會讓 productId 改變時不重新載入。

練習 8：const options = { storeId } 寫在元件函式本體，effect 寫 useEffect(() => connect(options), [options])。storeId 沒變、父元件重新 render，effect 會怎樣？

✓ 依賴用 Object.is 比較，不看內容。每次 render 都建立新的 options，所以每次都「不同」，effect 每次都清理再重新連線。把 options 搬進 effect，依賴只列 storeId。

常見錯誤

  • 在元件函式本體做副作用：render 要是純的。改標題、建計時器、發請求放進 useEffect。
  • 空陣列當 onMounted，再用 eslint-disable 蓋掉警告：effect 永遠讀到第一次 render 的值。改程式碼讓 effect 不讀它。
  • 計時器裡寫 setX(x + 1)：讀到過期快照，或每秒重建計時器。改用 setX(v => v + 1)。
  • 沒有清理，或寫成 return clearInterval(id)：前者卸載後還在跑，後者當場就清掉。回傳函式：return () => clearInterval(id)。
  • 依賴裡放 render 時建立的物件、函式或 Effect Event：每次都不同，effect 每次重跑。搬進 effect、只依賴原始值；Effect Event 不列。
  • 抓資料沒處理競態：清理時設 ignore 並 abort；被取消不要顯示成錯誤。
  • useEffect(async () => …)：清理函式拿不到，卸載時還會丟 TypeError。在 effect 裡宣告 async 函式再呼叫。

小結

  • effect 在 commit 之後跟外部系統同步；render 要保持純的。
  • React 不追蹤依賴：effect 讀到的響應值都要列，用 Object.is 比較；交給 exhaustive-deps 檢查。
  • 清理函式在依賴改變前（用舊的值）和卸載時呼叫，要完整復原 setup；StrictMode 會在開發時多跑一輪來檢查。
  • 物件、函式依賴每次 render 都是新的：搬進 effect，或用 useEffectEvent（React 19.2 起）。
  • 抓資料用 ignore 加 AbortController 處理競態；effect 的函式不能是 async。
  • 對照 Vue：useEffect ≈ watch＋flush: 'post'，但先執行一次、依賴手動列；清理函式 ≈ onWatcherCleanup＋onUnmounted。

下一課反過來看：很多 effect 其實不該存在。從 props 算出來的值、使用者點擊才要做的事、換了顧客時重設 state，都有不用 effect 的寫法。
