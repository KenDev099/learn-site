階段 3：元件設計與型別 · 第 13 課

Portal、Suspense 與 Error Boundary

咖啡店後台有三個回報：訂單列表的「刪除訂單」確認框被列表的捲動區塊裁掉一半；商品詳細頁每個元件都自己寫一套「載入中」，點太快還會顯示錯的商品；首頁的「推薦商品」API 回了奇怪的資料，元件在 render 時丟錯，整頁變成空白，連購物車都不見了。

這三件事在 React 各有一個內建的工具：Portal 把一段畫面放到別的 DOM 位置；Suspense 讓「等資料」交給外層統一顯示；Error Boundary（錯誤邊界）把壞掉的區塊換成替代畫面。

這課的路線：
  1. Portal 與對話框：確認框被捲動區塊裁掉時，把 DOM 搬到 body，同時顧好焦點、Esc 與 id，鍵盤和報讀器使用者才用得了。
  2. Suspense 與 Promise 從哪裡來：元件只寫資料好了的樣子，「載入中」交給外層；傳給 use 的 Promise 為什麼不能在 render 裡建立。
  3. Error Boundary：一個元件 render 時丟錯，怎麼只換掉那一塊，不讓整頁空白。
  4. 組合起來：ErrorBoundary 加 Suspense 加重試，商品詳細頁的載入中、失敗、重試一次寫好。
這課會用到：
  • 第 5 課練習 5 的 ProductDetail：在 effect 裡抓商品，自己管載入中與錯誤，用 ignore 旗標或 AbortController 擋掉晚回來的舊回應。
  • 第 11 課的 use：use(SomeContext) 讀最近的 Provider 給的值，跟其他 hook 不同，可以寫在 if 裡。

Portal：DOM 搬到 body，元件關係不變

確認框寫在每一列 <li> 裡，DOM 也就在列表裡。列表為了捲動加了 overflow: auto，超出的部分被裁掉；祖先有 transform 時 position: fixed 也不再相對視窗。Vue 課第 11 課講過，這些都由 DOM 位置決定。Vue 用 <Teleport to="body">，React 用 react-dom 的 createPortal：

import { createPortal } from 'react-dom'

function ConfirmDialog({ open, title, children }: Props) {
  if (!open) return null
  return createPortal(
    <div role="dialog" aria-modal="true">
      <h2>{title}</h2>
      {children}
    </div>,
    document.body,   // 第二個參數是 DOM 節點，不是選擇器字串
  )
}

官方文件的說法：Portal 只改變 DOM 節點實際放的位置，其他方面它仍是 render 它的元件的子節點。所以 props、state、Context 照常運作（React 19.3.1 實測：Portal 裡讀得到外層 <Context value="總店"> 的值），事件也照 React 樹冒泡，不是照 DOM 樹。

後果是：在對話框裡點「取消」，<li onClick> 也會被呼叫，這一列被選取了。官方文件給兩個解法：在 Portal 裡面 stopPropagation()，或把 Portal 移到 React 樹上不在 <li> 裡的位置。Vue 的 Teleport 沒有這個問題，因為 Vue 的事件是原生 DOM 事件，照 DOM 樹冒泡；React 的 onClick 是 React 自己沿元件樹分派的。反過來，你在 document 上用 addEventListener 註冊的原生監聽，看到的仍是 DOM 樹。

「彈窗被裁掉」「下拉選單被下一張卡片蓋住」是後台最常見的 UI bug。先在 DevTools 看祖先有沒有 overflow、transform、新的 z-index 堆疊脈絡，確定是被困住了才用 Portal，不要先把 z-index 越調越大。團隊通常只在共用的 Modal、Toast、Popover 元件裡用 Portal，層級定義一次。新專案也可以評估原生 <dialog> 的 showModal()（Vue 課第 11 課介紹過，它放進瀏覽器的頂層，不需要 Portal）。

對話框：焦點、Esc 與不重複的 id

Vue 課第 11 課的三件事在 React 一樣要做：開啟時焦點移進去、Esc 關閉、關閉後焦點回到開啟它的按鈕。React 的寫法用第 7 課的 ref 與 effect，標題的 id 用第 4 課的 useId（每個元件實例產生一個不重複的 id）：

const titleId = useId()                          // 第 4 課：同一頁兩個對話框也不會重複
const confirmRef = useRef<HTMLButtonElement>(null)

useEffect(() => {
  if (!open) return
  const previous = document.activeElement as HTMLElement | null   // 焦點還在「刪除訂單」上
  confirmRef.current?.focus()                                       // commit 之後，按鈕已經在 DOM 裡
  return () => previous?.focus()                                    // open 變 false 或卸載時還回去
}, [open])

這段把 Vue 的 watch(open, …, { flush: 'post' }) 拆成「同步」和「清理」：清理函式在 open 變回 false 時執行，剛好就是「關閉後還焦點」。依賴陣列只放 open 是關鍵：寫成沒有依賴陣列，父元件每次 render（例如使用者在對話框的輸入框打字）都會清理再重跑，焦點被搶回「確定」，打字打到一半就跑掉了。

Esc 寫在對話框元素的 onKeyDown（焦點在裡面時按鍵事件會冒泡上來），對話框關掉後元素消失，也就不會再收到。如果改成在 document 上註冊，一定要在清理函式裡移除，不然關掉之後按 Esc 還會呼叫 onClose。

完整的模態對話框還要焦點陷阱（Tab 到最後一個按鈕時繞回第一個）。邊界情況很多，正式專案用元件庫或原生 <dialog>；練習 1 先做好上面三件事。

Suspense：把「載入中」交給外層

回到第 5 課練習 5 的 ProductDetail：在 effect 裡抓資料，自己管 product、error、「載入中」，還要用 ignore 旗標或 AbortController 擋掉晚回來的舊回應。每個抓資料的元件都要重寫一次這套判斷。

Suspense 換一個分工：元件只寫「資料好了長什麼樣子」，還沒好就暫停（suspend），由最近的 <Suspense> 顯示 fallback。讓元件暫停的方式是第 11 課讀 context 用的 use，它也能讀 Promise：

import { Suspense, use } from 'react'

function ProductDetail({ productPromise }: { productPromise: Promise<Product> }) {
  const product = use(productPromise)   // 還沒好：暫停；好了：拿到值；失敗：丟錯
  return <p className="name">{product.name} ${product.price}</p>
}

<Suspense fallback={<p role="status">載入商品中…</p>}>
  <ProductDetail productPromise={productPromise} />
</Suspense>

官方文件對 use(promise) 的說明：Promise 還沒完成時元件暫停，最近的 Suspense 顯示 fallback；完成後換成用結果 render 的畫面；Promise 失敗時顯示最近的 Error Boundary 的 fallback（後面兩節）。use 可以寫在 if 裡（第 11 課），但不能包在 try/catch 裡，React 19.3.1 會印出「use was called from inside a try/catch block」，而且 Promise 還沒完成時 catch 就先執行了，畫面直接顯示錯誤。

哪些東西會讓 Suspense 顯示 fallback？官方文件列出的是：用 use 讀 Promise、lazy 載入的元件、支援 Suspense 的框架與資料函式庫。在 effect 或事件處理函式裡抓資料，Suspense 偵測不到。也不能把元件寫成 async function：19.3.1 會報「is an async Client Component. Only Server Components can be async at the moment」。

lazy 用來把某個元件的程式碼拆成另一個檔案，第一次 render 到它才下載：

const ReportChart = lazy(() => import('./ReportChart.tsx'))   // 寫在模組最上層，那個檔案要 export default

<Suspense fallback={<p>載入圖表中…</p>}><ReportChart /></Suspense>

官方文件提醒 lazy 要寫在元件外面；寫在元件裡，每次 render 都是新的元件型別，state 會一直被重設。

fallback 的位置決定使用者看到什麼。Suspense 包住整個面板，等一個商品時標題和按鈕都被換掉；只包住 ProductDetail，就只有詳細資料的位置在等。巢狀的 Suspense 可以排出載入順序：外層等商品名稱，內層等評論，各自顯示自己的 fallback。

Promise 從哪裡來：不能在 render 裡建立

最直覺的寫法是在元件裡直接 use(api.getProduct(id))。React 19.3.1 實測：每 10 毫秒會完成的 Promise，等了 300 毫秒，畫面還停在 fallback，API 被呼叫了 3 次。原因是官方文件寫的這條：還沒掛載就暫停的元件，React 不保留它的任何 state，Promise 完成後從頭重試 render，又建立一個新的 Promise，又暫停。

所以在那個會暫停的元件裡用 useMemo 或 useState 記住 Promise 也沒用（實測一樣呼叫 3 次）。官方文件要求傳給 use 的 Promise 要被快取，最好在 render 之前建立：事件處理函式、路由的 loader、Server Component。練習 2 在點擊時建立，存進不會暫停的父元件的 state：

const [productPromise, setProductPromise] = useState<Promise<Product> | null>(null)

<button onClick={() => setProductPromise(api.getProduct(p.id))}>{p.name}</button>
{productPromise && (
  <Suspense fallback={<p role="status">載入商品中…</p>}>
    <ProductDetail productPromise={productPromise} />
  </Suspense>
)}

第 5 課的競態在這裡自然消失：state 裡永遠是「最後一次點擊的 Promise」，舊的 Promise 晚回來也沒有人讀它，不需要 ignore 旗標。

換商品時，ProductDetail 已經顯示過內容又暫停了。React 19.3.1 的做法是把舊內容加上 style="display: none !important" 藏起來、顯示 fallback，舊內容的 state 保留著，資料回來再顯示。所以測試裡「看不到」不等於「不在 DOM 裡」，要檢查是否可見。

要在掛載時就開始抓（練習 4 的菜單），可以用 useState(() => api.getMenu())：初始化函式只在第一次 render 執行，而這個元件自己不會暫停（Suspense 在它裡面），state 會保留。代價是開發環境的 StrictMode 會呼叫初始化函式兩次（19.3.1 實測發出 2 個請求，只用其中一個）。

💡 實務上：use 很少直接接 fetch，通常接快取
正式專案很少自己管 Promise 的快取：TanStack Query（第 15 課）有 Suspense 版本的查詢，React Router 的 loader（第 18 課）在進頁面前就開始抓，Next.js 由 Server Component 建立 Promise 傳下來（第 22 課）。這課自己管 Promise，是為了看懂它們底下在做什麼。code review 看到 use(fetch(…)) 或 use(api.xxx()) 直接寫在元件裡，就是這節的 bug。

Error Boundary：攔下 render 時的錯誤

官方文件：render 時丟出錯誤、又沒有人攔，React 會把整個 UI 從畫面上移除。推薦商品一個欄位是 null，整頁空白。Error Boundary 是攔截子孫元件錯誤、改顯示替代畫面的元件，這個詞就是從 React 來的；Vue 課第 21 課用 onErrorCaptured 加 slot 做出同樣的東西。

React 目前沒有對應的 Hook，官方文件寫明錯誤邊界只能用 class 元件寫（或用 react-error-boundary 套件）。class 元件是 React 舊的寫法：繼承 Component，props 在 this.props，state 在 this.state，用 this.setState() 更新，render() 方法回傳畫面。整個專案通常只寫這一個 class：

import { Component, type ErrorInfo, type ReactNode } from 'react'

type Props = { children: ReactNode; fallback: ReactNode; onError?: (error: unknown, stack: string) => void }
type State = { error: Error | null }

export class ErrorBoundary extends Component<Props, State> {
  state: State = { error: null }

  static getDerivedStateFromError(error: unknown): State {   // render 階段：純函式，只算新的 state
    return { error: error instanceof Error ? error : new Error(String(error)) }
  }

  componentDidCatch(error: unknown, info: ErrorInfo) {        // commit 之後：回報這類副作用放這裡
    this.props.onError?.(error, info.componentStack ?? '')
  }

  render() {
    return this.state.error ? this.props.fallback : this.props.children
  }
}

兩個方法的分工跟第 7 課的 render／commit 一樣：getDerivedStateFromError 在 render 階段被呼叫，官方文件要求它是純函式；React 19.3.1 實測一個錯誤呼叫了它 2 次、componentDidCatch 1 次，回報寫錯地方就會送出重複的錯誤。throw '逾時' 也合法，所以參數是 unknown；給畫面用之前包成 Error，回報時送原本的值。

💡 實務上：錯誤邊界的粒度跟 PM 一起決定
常見的切法是每個路由頁面一個，再加上可以單獨壞掉的區塊（推薦商品、評論、地圖）。結帳金額壞了不該只顯示「區塊暫時無法顯示」讓客人照樣結帳，那種錯誤要往上傳到整頁。第 8 課的 reducer 選擇「不合法的轉換回傳原 state、不丟錯」，就是因為 reducer 丟錯等於 render 時丟錯。review 新頁面時問兩句：它壞掉時客人看到什麼？這個錯誤有沒有被回報？

組合起來：ErrorBoundary ＋ Suspense ＋ 重試

同一個 Promise 有三種結果，交給兩個邊界：等待中由 Suspense 處理，失敗由 Error Boundary 處理，成功由元件自己 render。

重試是最容易寫錯的地方。fallback 拿到 reset()，按下去讓邊界清掉錯誤、重新畫 children，但 children 讀的還是同一個已經失敗的 Promise，立刻又失敗。失敗的 Promise 不會變成功，重試要同時換一個新的請求：

const [menuPromise, setMenuPromise] = useState(() => api.getMenu())

<ErrorBoundary fallback={({ error, reset }) => (
  <>
    <p role="alert">菜單載入失敗：{error.message}</p>
    <button onClick={() => { setMenuPromise(api.getMenu()); reset() }}>重試</button>
  </>
)}>
  <Suspense fallback={<p role="status">載入菜單中…</p>}>
    <MenuList menuPromise={menuPromise} />
  </Suspense>
</ErrorBoundary>

兩個 setState 在同一個事件裡批次處理，下一次 render 就是「新的 Promise、沒有錯誤」，MenuList 暫停，畫面回到載入中。

另一種重設是外部條件變了，例如切換門市後錯誤畫面要消失。用第 6 課的 key：<ErrorBoundary key={storeId}>，門市一換，React 丟掉舊的邊界（連同它的錯誤 state）建立新的。官方文件也用同一招重設 Suspense：<Suspense key={user.id}> 讓換人時顯示 fallback，而不是先留著上一個人的資料。

💡 實務上：測試 Suspense 要 await act
用 Testing Library 測會暫停的元件，觸發暫停的操作要包在 await act(async () => { … }) 裡。React 19.3.1 實測：直接 await user.click(…) 讓元件暫停，React 會警告「A component suspended inside an act scope, but the act call was not awaited」，之後 Promise 完成了畫面也停在 fallback；改成 await act(async () => { await user.click(…) }) 就正常。練習 2、4 的測試都這樣寫，第 23 課會再整理元件測試的寫法。

練習

在 learn/ 執行 node check.mjs react 13（環境在第 2 課裝好）。練習 2、4 用手動控制的假 API，測試決定每個請求什麼時候成功或失敗，不會真的等。練習 4 會用到你在練習 3 寫的 ErrorBoundary，先做練習 3。

練習 1：修好 ConfirmDialog。open 為 false 時回傳 null；為 true 時用 createPortal 畫到 document.body，元素有 role="dialog"、aria-modal="true"、aria-labelledby 指向顯示 title 的 <h2>（用 useId，同一頁兩個對話框不能重複）。開啟後焦點在「確定」；用取消、確定或 Esc 關閉後，焦點回到開啟它的按鈕。焦點在對話框裡按 Esc 呼叫 onClose，沒開時按 Esc 不呼叫。「取消」呼叫 onClose、「確定」呼叫 onConfirm。在對話框裡點擊不能觸發外層 <li> 的 onClick；在對話框的輸入框打字時焦點不能被搶走。

練習 2：把 ProductPanel 改成用 Suspense。ProductDetail 改收 productPromise，用 use() 讀出商品，在 <p className="name"> 顯示「品名 $價格」，自己不管載入中。ProductPanel 在點商品按鈕時呼叫 api.getProduct(id) 一次，把 Promise 存進 state（重新 render 不能再呼叫，也不能在 render 或 useMemo 裡呼叫）。還沒選時顯示「請選擇商品」。用 <Suspense fallback={<p role="status">載入商品中…</p>}> 只包住 ProductDetail，載入時標題「商品資訊」和按鈕要看得到。連點兩個商品，不管哪個先回來，最後顯示的都是最後點的。

練習 3：完成 class 元件 ErrorBoundary。子孫在 render 時丟錯，就改畫 fallback({ error, reset })，邊界外面照常顯示。丟出來的不是 Error（例如字串「逾時」）時，給 fallback 的 error 要包成 Error，message 是 String(值)。每個錯誤呼叫 onError(原本丟出的值, componentStack) 剛好一次，沒傳 onError 也不能壞。reset() 清掉錯誤重新畫 children，又出錯就再顯示 fallback（onError 再呼叫一次）。兩個邊界各自記錄自己的錯誤。Props、FallbackProps 型別不要改。

練習 4：修好 MenuSection。掛載時呼叫 api.getMenu() 剛好一次，外層重新 render 不能再呼叫。載入中顯示 <p role="status">載入菜單中…</p>，成功後 MenuList 用 use() 每個商品畫一個 <li>「品名 $價格」。失敗時用練習 3 的 ErrorBoundary 只包住菜單的部分，顯示 <p role="alert">菜單載入失敗：message</p> 和「重試」按鈕；標題「菜單」和旁邊的購物車照常顯示。按「重試」重新呼叫一次 API、回到載入中；又失敗就再顯示錯誤，可以一直重試。不能用 try/catch 包 use()。

練習 5：<li onClick={() => select(order.id)}> 裡面 render 了一個用 createPortal(…, document.body) 畫出的對話框。使用者點對話框裡的「取消」按鈕，select 會被呼叫嗎？

✓ 官方文件寫明 Portal 的事件照 React 樹冒泡。要避免就在對話框裡 stopPropagation()，或把 Portal 移到不在 li 裡的位置。a 是 Vue Teleport 的行為：Vue 用原生 DOM 事件，照 DOM 樹冒泡。這跟 StrictMode 無關（c）。

練習 6：結帳按鈕 onClick={() => { throw new Error('庫存不足') }} 放在一個 ErrorBoundary 裡面。按下去會怎樣？

✓ 錯誤邊界只攔 render、effect 這類 React 在畫畫面時發生的錯誤；事件處理函式的錯誤不經過它（官方文件，19.3.1 實測 fallback 沒出現）。要給使用者看，就在處理函式裡 try/catch，把錯誤存進 state。b 錯在畫面沒有在 render 時壞掉，React 不會卸載任何東西。

練習 7：function Menu() { const menu = use(fetch('/api/menu').then(r => r.json())); … }，外面有 Suspense。會發生什麼事？

✓ 還沒掛載就暫停的元件，React 不保留它的 state，Promise 完成後從頭重試，又建立一個新的 Promise。use 不會幫你快取（b 錯）；use 收任何 Promise，型別沒問題（c 錯）；d 一樣不行，useMemo 也是這個元件的 state。Promise 要在 render 之前建立（事件、loader），或存在不會暫停的父元件、快取裡。

常見錯誤

  • Portal 裡的點擊觸發了外層的 onClick：React 事件照元件樹冒泡。在 Portal 裡 stopPropagation，或把 Portal 移出那個元素。
  • 對話框聚焦的 effect 沒有依賴陣列：父元件每次 render 都把焦點搶回去。依賴只放 open，清理函式負責還焦點。
  • 在 render 裡建立要給 use 的 Promise（包括在會暫停的元件裡用 useMemo、useState）：每次重試都是新的請求。在事件、loader 建立，或存在不會暫停的父元件。
  • Suspense 包太大：等一筆資料，整個面板都換成 fallback。只包住真的在等的部分，巢狀排出順序。
  • 用 try/catch 包 use，或在 effect 裡抓資料還期待 Suspense：前者還沒完成就進 catch，後者 Suspense 偵測不到。失敗交給 Error Boundary。
  • 在 getDerivedStateFromError 裡回報錯誤：它是 render 階段的純函式，會被呼叫不只一次。回報放 componentDidCatch。
  • 重試只 reset 邊界：children 讀的還是已經失敗的 Promise。同時換一個新的 Promise。

小結

  • createPortal(jsx, domNode) 只改 DOM 位置：Context、state 照元件樹，事件也照元件樹冒泡（Vue Teleport 照 DOM 樹）。
  • 對話框：useId 給標題 id，effect 依賴 [open] 聚焦、清理函式還焦點，onKeyDown 處理 Esc。
  • use(promise) 讓元件暫停，最近的 <Suspense> 顯示 fallback；Promise 要快取、在 render 之前建立，state 裡放「最新的 Promise」就沒有競態。
  • Error Boundary 是 class 元件：getDerivedStateFromError 算 state（純函式），componentDidCatch 回報；攔不到事件處理函式與非同步 callback 的錯誤。
  • use 的三種結果：等待給 Suspense、失敗給 Error Boundary、成功自己畫；重試要換新的 Promise 再 reset，外部條件改變用 key 重設。
  • Vue 對照：Teleport ↔ createPortal、Suspense（Vue 仍是實驗性）↔ Suspense＋use、onErrorCaptured ↔ Error Boundary、errorHandler ↔ createRoot 的 onCaughtError／onUncaughtError。

階段檢核：面試會問的觀念

這個階段一定要講得出來的 8 件事。先在心裡回答，再選。

練習 8：購物車傳 value={qty} 給這個數量元件；庫存只剩 3 杯，父元件的 onChange 收到 4 時不更新 qty。客人在 3 杯時按「＋」，會怎樣？

function QuantityStepper({ value, onChange }: Props) {
  const [inner, setInner] = useState(value)
  useEffect(() => { setInner(value) }, [value])
  function change(next: number) {
    setInner(next)
    onChange?.(next)
  }
  return <button onClick={() => change(inner + 1)}>{inner} 杯 ＋</button>
}

✓ 父元件拒絕時 value 沒變，effect 不會執行，inner 停在 4，變成兩份對不上的資料。受控時畫面只聽 value：value !== undefined ? value : inner，inner 只給非受控用，不用 effect 把 value 複製進 state。a 錯在 effect 只在依賴改變時執行，3 到 3 沒有改變。（第 10 課）

練習 9：門市的 Provider 寫成下面這樣，切換按鈕直接改屬性。按下之後，讀 StoreContext 的元件會怎樣？

const store = { name: '總店' }
function StoreProvider({ children }: { children: ReactNode }) {
  return <StoreContext value={store}>{children}</StoreContext>
}
// 某個後代元件
const s = use(StoreContext)
<button onClick={() => { s.name = '中山店' }}>切換</button>

✓ React 的 context value 跟 props 一樣是這次 render 的快照，參考沒換，React 不知道要通知誰。要換值就把門市放在 Provider 元件的 state，後代透過它提供的函式修改；放在模組層級的變數，並排的 Provider 還會共用一份。a 是 Vue 的直覺：Vue 交出的是 ref，改 .value 會被追蹤。（第 11 課）

練習 10：CartProvider 提供 useMemo(() => ({ lines, dispatch }), [lines])，菜單上 200 顆「加入」按鈕都用 memo 包著，只從 useCart() 拿 dispatch。每加一杯，200 顆按鈕全部重新 render。怎麼修？

✓ lines 一變 value 就換新，所有讀這個 context 的元件都 render，memo 只比較 props，擋不住 context。依變化頻率拆開，dispatch 的參考不會變，只讀它的按鈕就不動。c 能讓按鈕不 render，但購物車摘要讀到的 lines 永遠是第一次的空陣列。（第 11 課）

練習 11：同事把 ProductCard 的 price 改成必填的物件，漏改了三個使用它的頁面。本機開發與 Vitest 都沒報錯，上線後那三頁壞掉。先查什麼？

✓ Vite、Vitest 只轉譯，型別錯了照樣跑；真正檢查的是 tsc，react-ts 範本的 build 是 tsc -b && vite build，CI 要跑它，失敗要擋下合併。改了共用元件的 props，tsc 會一次列出所有要跟著改的地方。b 錯在 JSX 是 TypeScript 本身支援的語法，.tsx 直接用 tsc，這點跟 Vue 不同。（第 12 課）

練習 12：結帳頁的取餐資訊元件型別如下，元件裡寫 {mode === 'delivery' && <p>外送到 {address}，運費 {fee} 元</p>}。有人寫了最下面那一行，結果是？

type DeliveryInfoProps = {
  mode: 'pickup' | 'delivery'
  pickupAt?: string
  address?: string
  fee?: number
}
<DeliveryInfo mode="delivery" address="中山路 1 號" />

✓ 每個欄位各自可選，TypeScript 不知道 mode 和其他欄位的關係，缺 fee 也合法；React 遇到 undefined 什麼都不畫。改成辨識聯合 { mode: 'pickup'; pickupAt: string } | { mode: 'delivery'; address: string; fee: number }，錯的組合就寫不出來，元件裡用 props.mode 縮小再讀。a 錯在型別之間沒有這種關聯，要你自己用聯合寫出來。（第 12 課）

練習 13：飲品選單用 createPortal(<ul>…</ul>, document.body) 畫出下拉面板，「點外面就關閉」寫成下面這樣（rootRef 掛在選單按鈕外層的 div）。點面板裡的「燕麥奶」會怎樣？

useEffect(() => {
  function onDown(e: MouseEvent) {
    if (!rootRef.current?.contains(e.target as Node)) setOpen(false)
  }
  document.addEventListener('mousedown', onDown)
  return () => document.removeEventListener('mousedown', onDown)
}, [])

✓ Portal 只讓 React 的 state、context、合成事件照元件樹走；contains 和 document 上的原生監聽看的是 DOM 樹，面板在 body 底下，不在 rootRef 裡。修法是面板也掛一個 ref，兩個都不包含才關閉。a 把 React 樹和 DOM 樹混在一起：照元件樹冒泡的只有 onClick 這類 React 事件。（第 13 課）

練習 14：菜單 API 掛了，畫面顯示錯誤與「重試」。API 恢復後客人按重試，會怎樣？

const [menuPromise] = useState(() => api.getMenu())

<ErrorBoundary fallback={({ reset }) => <button onClick={reset}>重試</button>}>
  <Suspense fallback={<p>載入菜單中…</p>}>
    <MenuList menuPromise={menuPromise} />
  </Suspense>
</ErrorBoundary>

✓ 失敗的 Promise 不會變成功，reset 只清掉邊界的錯誤 state，children 讀到同一個 Promise 又失敗。重試要同時換新的請求：setMenuPromise(api.getMenu()); reset()，兩個更新一起處理，畫面回到載入中。c 錯在請求是父元件建立的，MenuList 重新掛載也只是再讀一次同一個 Promise。（第 13 課）

練習 15：評論區包在 <ErrorBoundary fallback={<p>評論暫時無法顯示</p>}> 裡，元件這樣抓資料。API 回傳失敗時，客人看到什麼？

useEffect(() => {
  api.getReviews().then(r => {
    if (!r.ok) throw new Error('評論載入失敗')
    setReviews(r.items)
  })
}, [])

✓ 錯誤邊界只攔 render、effect 本身與 use 讀到的失敗；這個錯誤丟在 Promise 的 callback 裡，effect 早就執行完了，跟丟在 setTimeout 裡一樣攔不到。修法是 .catch 後把錯誤存進 state 顯示，或改用 use 加 Suspense，讓失敗交給錯誤邊界。a 錯在「effect 攔得到」指的是 effect 函式執行時直接丟出的錯誤。（第 13 課）
