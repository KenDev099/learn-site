階段 2：Hooks 與副作用 · 第 9 課

自訂 hook：抽出有狀態的邏輯

咖啡店的菜單頁和訂單頁各自複製了一份「停止輸入 300ms 才查詢」的計時器，結帳按鈕和頁首各自寫了一份 addEventListener('online')。修好了菜單頁計時器沒清掉的問題，訂單頁忘了改。另一位同事把購物車數量抽成共用函式，數量卻放在模組最外層的變數，兩個頁面的數字互相影響，畫面也不會更新。

這課教你把「有狀態、有副作用的邏輯」抽成自訂 hook（custom hook），並對照 Vue 的 composable。

這課的路線：
  1. 自訂 hook 是什麼、Hook 的規則：把重複的計時器、監聽搬進 use 開頭的函式，它共用的是邏輯不是 state，為什麼只能在最上層呼叫（開場問題的最小答案）。
  2. 回傳值、有 effect 的 hook：回傳 tuple 還是物件，參數變了 effect 怎麼跟著重新同步，例如搜尋框的防抖。
  3. 訂閱外部資料、抓資料的 hook：視窗寬度、連線狀態怎麼讀才不漏掉變化，商品詳細頁的載入、錯誤與過期回應怎麼包成一個 hook。
  4. 測試自訂 hook：給很多頁面共用的 hook，用 renderHook 單獨測。
這課會用到：
  • 第 3 課的快照與 updater：這次 render 的 state 不會變，setQuantity(q => q + 1) 從最新的值算。
  • 第 5 課的 useEffect：依賴陣列列出 effect 讀到的 props、state，清理函式在重跑前和卸載時呼叫，用來停計時器、移除監聽、擋掉晚回來的舊回應。

自訂 hook 是什麼

Hook 是名稱以 use 開頭、只能在 render 期間呼叫的函式，useState、useEffect 都是。自訂 hook 就是你自己寫、裡面呼叫了其他 hook 的函式。官方規定名稱要是 use 加大寫字母開頭，例如 useQuantity；React 的 lint 規則和 React Compiler（第 20 課）都靠這個名稱認出它是 hook。反過來，裡面沒有呼叫任何 hook 的函式（格式化價格、算總金額）寫成普通函式，不要加 use。

購物車每一列都有「數量 1～20」的加減按鈕。把元件裡的 state 和兩個函式原封不動搬出去：

function useQuantity(initial = 1) {
  const [quantity, setQuantity] = useState(initial)
  const inc = () => setQuantity(q => Math.min(q + 1, 20))
  const dec = () => setQuantity(q => Math.max(q - 1, 1))
  return { quantity, inc, dec }
}

// 每一列：const { quantity, inc, dec } = useQuantity()

拿鐵、可頌兩列都呼叫 useQuantity()，拿鐵按兩次 +，結果是拿鐵 3、可頌 1（React 19.3.1 實測）。官方文件的說法：自訂 hook 共用的是有狀態的邏輯，不是 state 本身，每次呼叫都完全獨立，裡面的 useState 屬於呼叫它的元件。要兩個元件共用同一份資料，把 state 提升到父元件，或用 Context（第 11 課）、Zustand（第 14 課）。開場那位同事把 let count = 0 放在模組最外層：所有呼叫共用一個變數，改它也不會觸發 render。

💡 實務上：先有第二個使用者，再抽 hook
常見的時機是第二個頁面要用同一段邏輯（搜尋防抖、連線狀態），或元件裡的 state 和 effect 多到看不出它在畫什麼。只在一個元件用、又很短的邏輯，抽出來只是多一個檔案要跳。抽出來之後 hook 就是團隊共用的介面：名稱說出用途、回傳的函式穩定、清理完整、有自己的測試。review 時可以問：這個 hook 能不能只用參數和回傳值說明清楚？說不清楚通常是一次做太多事。

跟 Vue composable 的差別

用途一樣，執行模型不同。Vue 的 setup 只執行一次，composable 建立的 ref 一直活著；React 的元件函式每次 render 都重新執行，自訂 hook 也跟著每次執行：

Vue composableReact 自訂 hook
執行幾次setup 時一次每次 render 都執行
狀態閉包裡的 refuseState，React 照呼叫順序存放
回傳ref 組成的物件，解構後仍會更新這次 render 的值（快照），下次 render 回傳新的
參數會變MaybeRefOrGetter，在 watch 的 getter 裡 toValue參數就是這次 render 的最新值，用到的放進依賴陣列
清理onScopeDispose、watch 的清理函式effect 回傳的清理函式
呼叫限制setup 裡同步呼叫每次 render 都在最上層、以同樣順序呼叫

Vue 的「解構 reactive 失去響應」「toValue 只讀一次」在 React 不存在，因為每次 render 都重新拿值。代價是：呼叫順序必須固定，回傳的函式和物件每次都是新的。

Hook 的規則：只在最上層呼叫

useState(false) 沒有傳任何名字，React 怎麼知道這次回傳哪一個 state？官方文件的解釋：每個元件有一串 hook 的格子，render 開始時指標歸零，每呼叫一次 hook 就拿下一格。所以每次 render 都要以同樣順序呼叫同樣的 hook。

官方列出的禁止寫法：條件裡、迴圈裡、early return 之後、事件處理函式裡、傳給 useMemo／useEffect 的函式裡、try/catch 裡。實際跑一個違規的元件：

function ProductNote({ product }: { product: Product | null }) {
  const [liked, setLiked] = useState(false)
  if (!product) return null
  const [open, setOpen] = useState(false)   // ✗ early return 之後
  // …
}
// 有商品 → null：     Rendered fewer hooks than expected. This may be caused by an accidental early return statement.
// null → 有商品：     Rendered more hooks than during the previous render.

這兩個錯誤在 React 19.3.1 會直接讓 render 失敗。但 React 不保證每次都抓得到：如果 early return 之前一個 hook 都沒有，從「沒有 hook」變成「有 hook」時 React 會當成第一次掛載，不會丟錯，只是 state 默默重設（練習 5 的起始程式就是這樣）。能可靠擋下的是 lint：eslint-plugin-react-hooks 7.1.1 的 rules-of-hooks，對上面的寫法會報 React Hook "useState" is called conditionally，寫在迴圈裡會報 may be executed more than once。

規則對自訂 hook 一樣適用：裡面的 hook 要在最上層，呼叫它的地方也要在最上層。修正方式：

  • 條件：hook 照常呼叫，條件放在用結果的地方；early return 移到所有 hook 之後。
  • 迴圈：每一項需要自己的 state 時，把一項抽成元件，在它的最上層呼叫 hook，列表用 key={item.id}（第 2 課）。這也是官方的建議。
  • 事件處理函式：hook 在最上層呼叫，事件裡只用它回傳的值或函式。

Vue 也有「在 setup 裡同步呼叫」的規則，但 setup 只跑一次，寫在 if 裡頂多是之後不會補呼叫；React 每次 render 都要對上順序，規則更嚴格。

💡 實務上：react-hooks 的 lint 放進 CI，不要用註解關掉
Hook 規則和依賴陣列的錯誤，常常要等資料長度改變、某個 props 換掉才出事，客服回報的是「展開狀態跑到別的商品上」或「偶爾整頁白掉」。專案通常把 rules-of-hooks 和 exhaustive-deps 設成 error，在 CI 擋下。review 看到 eslint-disable-next-line react-hooks/… 就該問原因；多數時候正確的修法是抽元件、補依賴或用 useEffectEvent。

回傳值：tuple、物件與參考穩定

兩三個值時常回傳 tuple（固定長度、每個位置型別固定的陣列），像 useState 那樣讓呼叫端自己命名：const [open, toggleOpen] = useToggle()；值多時回傳物件 { products, loading, error, reload }，靠名稱取。

回傳陣列時要加 as const。TypeScript 6.0.3 把 [on, toggle, setOn] 推成 (boolean | Dispatch<SetStateAction<boolean>>)[]（實測），解構出來每個都是聯合型別，on 不能直接當 boolean 用、toggle() 也呼叫不了。as const 讓它變成唯讀的 tuple，每個位置保留自己的型別。

第二件事是參考穩定：hook 每次 render 都重新執行，裡面的 const inc = () => … 每次都是新的函式，回傳的物件也每次都是新的。實測 useQuantity 重新 render 後：物件不同、inc 不同、quantity 相同（數字比的是值）。如果呼叫端把 inc 放進 effect 的依賴陣列，effect 每次 render 都會重跑。

useCallback(fn, deps) 讓函式在依賴沒變時保持同一個參考：

function useQuantity(initial = 1) {
  const [quantity, setQuantity] = useState(initial)
  // updater function 不需要讀 quantity，所以依賴陣列是空的，inc 永遠是同一個函式
  const inc = useCallback(() => setQuantity(q => Math.min(q + 1, 20)), [])
  const dec = useCallback(() => setQuantity(q => Math.max(q - 1, 1)), [])
  return { quantity, inc, dec }
}

實測：呼叫端寫 useEffect(…, [q])（整個回傳物件）時，三次 render 執行 3 次；寫 useEffect(…, [q.inc]) 只執行 1 次。所以呼叫端依賴個別的函式，不要依賴整個物件。如果寫 setQuantity(quantity + 1)，依賴陣列就得放 quantity，數量一變函式又變了，所以搭配第 3 課的 updater function。useCallback 在效能上的用法留到第 19 課；這裡的理由是：給別人用的 hook，回傳的函式應該穩定，你不知道呼叫端會不會把它放進依賴陣列。

有 effect 的 hook：參數就是依賴

叫號螢幕要顯示「現在時間」，每隔一段時間更新。抽成 hook：

function useNow(intervalMs: number) {
  const [now, setNow] = useState(() => Date.now())
  useEffect(() => {
    const timer = setInterval(() => setNow(Date.now()), intervalMs)
    return () => clearInterval(timer)   // intervalMs 變了、或元件卸載：清掉舊的計時器
  }, [intervalMs])
  return now
}

hook 的參數每次 render 都可能不同，在 hook 裡它們就是第 5 課說的響應值，effect 用到就要列進依賴陣列；lint 的 exhaustive-deps 在自訂 hook 裡一樣會檢查。練習 2 的防抖（debounce，值停止變化一段時間才採用）是同樣的結構，只是計時器要在 value 每次改變時重來；用泛型 <T> 讓傳數字回傳數字、傳字串回傳字串（TS 課第 19 課）。

參數是函式時要小心。輪詢 hook 收一個 onTick，呼叫端通常直接寫 inline 函式，每次 render 都是新的。把 onTick 列進依賴陣列，父元件每 render 一次計時器就重來；改用 useEffectEvent，effect 讀得到最新的 onTick，但它不是依賴：

function usePolling(onTick: () => void, intervalMs: number) {
  const tick = useEffectEvent(onTick)
  useEffect(() => {
    const timer = setInterval(() => tick(), intervalMs)
    return () => clearInterval(timer)
  }, [intervalMs])
}

用假計時器實測，間隔 30 秒、父元件每 20 秒 render 一次：依賴 onTick 的版本 60 秒內建立了 3 次計時器，onTick 一次都沒被呼叫；這個版本只建立 1 次，呼叫到的都是最新的 onTick。官方文件也建議：自訂 hook 收到的事件處理函式，用 useEffectEvent 包起來。

官方文件也提醒：不要寫 useMount(fn) 這種包裝 useEffect 本身的「生命週期 hook」，lint 只檢查直接寫出來的 useEffect，看不到呼叫端漏掉的依賴。自訂 hook 以用途命名：useNow、useOnlineStatus。

訂閱 React 以外的資料：useSyncExternalStore

瀏覽器的視窗寬度、連線狀態（navigator.onLine）不在 React 裡。用 useState 加 useEffect 自己同步有兩個問題：初始值得自己猜；元件 render 完到 effect 開始監聽之間的改變會漏掉。

useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?) 是 React 內建、專門讀外部資料的 hook：

// 宣告在 hook 外面：每次 render 都是同一個函式，React 不會重新訂閱
function subscribe(onChange: () => void) {
  window.addEventListener('resize', onChange)
  return () => window.removeEventListener('resize', onChange)
}

export function useWindowWidth() {
  return useSyncExternalStore(
    subscribe,
    () => window.innerWidth,   // getSnapshot：現在的值
    () => 1024,                // getServerSnapshot：伺服器端渲染時用的值
  )
}
  • subscribe：收到 React 給的 onChange，資料變了就呼叫它，回傳取消訂閱的函式。官方文件說明：每次 render 傳不同的 subscribe，React 就會重新訂閱，所以放在元件外面。
  • getSnapshot：回傳目前的值。React 用 Object.is 比較，不同才重新 render。資料沒變時必須回傳同一個值；每次回傳新物件（{ width: window.innerWidth }）會一直重新 render，官方文件說會出現 The result of getSnapshot should be cached 錯誤。
  • getServerSnapshot：伺服器上沒有 window，也不知道使用者的螢幕，提供一個固定的值，伺服器端渲染（第 22 課）才不會出錯。

訂閱之後 React 會再讀一次 getSnapshot，所以 render 到訂閱之間的變化不會漏掉。練習 3 用同樣的方法讀 navigator.onLine。對照 Vue 課第 12 課的 useOnline：Vue 用 ref 加事件監聽就夠了，因為 ref 本身會通知畫面；React 的外部資料要透過這個 hook 接進來。Zustand 5.0.16 的 hook 底層也是呼叫 useSyncExternalStore。

抓資料的 hook：載入、錯誤與過期的回應

把第 5 課的商品詳細頁抽成 hook，順便解決一個問題：在 effect 裡 setLoading(true) 會晚一次 render，換商品的那一瞬間畫面是「新的 id、舊的商品、沒有在載入」。第 6 課說過，能算出來的就不要存成 state。做法是把結果和「它屬於哪一次請求」一起存，render 時比對：

type Result = { id: number; product: Product | null; error: Error | null }

function useProduct(api: ProductApi, id: number) {
  const [result, setResult] = useState<Result | null>(null)

  useEffect(() => {
    const controller = new AbortController()
    const { signal } = controller
    api.getProduct(id, { signal }).then(
      product => { if (!signal.aborted) setResult({ id, product, error: null }) },
      (error: Error) => { if (!signal.aborted) setResult({ id, product: null, error }) },
    )
    return () => controller.abort()
  }, [api, id])

  // 衍生值：結果屬於目前的 id 才算數，否則就是載入中
  const current = result?.id === id ? result : null
  return { product: current?.product ?? null, error: current?.error ?? null, loading: current === null }
}
  • id 一換，同一次 render 裡 result.id !== id，loading 立刻是 true。
  • 清理函式 abort 之後 signal.aborted 就是 true：API 沒理會 signal、舊回應照樣成功，也會被丟掉；被取消的 AbortError 也不會變成錯誤訊息。
  • 「重新載入」可以多一個計數器 state，算進「這是哪一次請求」：計數器加 1，比對不符，就回到載入中，effect 也重跑。
💡 實務上：抓資料的 hook 通常交給函式庫
正式專案還要快取（回到上一頁不要重抓）、失敗重試、多個元件共用同一個請求，手寫會越長越大，所以多半用 TanStack Query（第 15 課），它的 useQuery 就是做完這些事的自訂 hook。自己寫一次的價值是：看到同事在 effect 裡 fetch、沒有 abort、用 setLoading(true) 時，你知道會出什麼事。

測試自訂 hook：renderHook

hook 只能在元件裡呼叫。Testing Library 16.3.3 的 renderHook 建一個測試用元件，在裡面呼叫你的 hook：

import { act, renderHook } from '@testing-library/react'

test('最多 20', () => {
  const { result } = renderHook(() => useQuantity(19))
  act(() => result.current.inc())
  act(() => result.current.inc())
  expect(result.current.quantity).toBe(20)
})
  • result.current 是最近一次 render 的回傳值。先解構 const { quantity } = result.current 再操作，拿到的是舊快照（實測：操作後解構出來的還是 1，result.current.quantity 是 2）。
  • 會改 state 的操作包在 act() 裡，React 才會在結束前處理完更新；實測沒包 act，inc() 之後讀到的仍是 1。
  • rerender(newProps) 用新參數重新 render（搭配 initialProps），unmount() 用來檢查清理。

Testing Library 的文件也提醒：只在一個元件裡用的 hook，透過那個元件測試比較好；renderHook 適合要給很多地方重用的 hook。

練習

在 learn/ 執行 node check.mjs react 09。練習 1～4 用 renderHook 測試；練習 2 用假計時器推進時間；練習 4 的假 API 由測試決定每個請求何時、以什麼結果回來，abort 時像 fetch 一樣以 AbortError 失敗。有幾題會跑 tsc 或 react-hooks 的 lint，各要 1～2 秒。

練習 1：寫 useToggle(initial = false)，回傳 [on, toggle, setOn]。initial 是初始值，每一次呼叫各有自己的 state（同一個元件呼叫兩次、兩張卡片各自呼叫，都互不影響；不能用模組層級的變數）。toggle() 把值反過來，同一個事件裡連續呼叫兩次要回到原值；setOn(value) 直接指定。toggle 的參考要穩定：重新 render、值改變之後都是同一個函式，而且第一次拿到的 toggle 也能切換。回傳值的型別是 tuple：on 是 boolean、setOn 只收 boolean，不能用 any。

練習 2：寫 useDebouncedValue<T>(value: T, delayMs: number): T。第一次 render 直接回傳 value；value 改變後滿 delayMs 毫秒才回傳新值，期間 value 又變就重新計時，中間的值不能出現。delayMs 由參數決定；跟 value 無關的重新 render 不能讓計時重來；元件卸載後不能留下計時器。傳 number 回傳 number、傳 string 回傳 string。react-hooks 的 lint 規則要通過，不能用 eslint-disable。

練習 3：把 useOnlineStatus() 從 useState＋useEffect 改成 useSyncExternalStore。第一次 render 就是目前的 navigator.onLine；online／offline 事件發生時更新；render 完到開始訂閱之間斷線也不能漏掉；卸載時移除 online、offline 兩個監聽；重新 render 不會重新訂閱；伺服器端渲染（renderToString）時當作有連線，回傳 true。

練習 4：完成 useMenu(api, keyword)，回傳 { products, loading, error, reload }。掛載時與 keyword 改變時呼叫 api.search(keyword, { signal })，signal 來自這次 effect 自己的 AbortController。loading：目前 keyword 的結果還沒回來時是 true，keyword 一換，同一次畫面就要是 true（寫成衍生值，不要在 effect 裡 setLoading）。error：失敗時是那個 Error，換 keyword、reload 之後清掉；被取消的請求不算錯誤。keyword 改變或卸載時 abort 上一個請求；API 不理會 signal 時，過期的回應也不能蓋掉新的結果。reload() 用同一個 keyword 重新查，參考要穩定。react-hooks 的 lint 要通過，不能用 eslint-disable。

練習 5：FavoriteList 把 useExpanded() 寫在 early return 之後、又寫在 map 迴圈裡。修正它：products 從 null 變成清單、收藏變多或變少都不能出錯；每一列各自展開；移除或在前面插入商品後，展開狀態仍跟著原本的商品；畫面結構（li 的 aria-label、「說明」按鈕的 aria-expanded、展開後的「品名 $價格」）不變。react-hooks 的 rules-of-hooks 要通過，不能用 eslint-disable。

練習 6：結帳按鈕和頁首都呼叫 useOnlineStatus()，裡面用 useState 存連線狀態。這兩個元件共用同一個 state 嗎？

✓ 自訂 hook 共用的是邏輯，不是 state，兩份 state 值剛好一樣，是因為同步的是同一個外部資料。要共用一份就提升到父元件，或用 Context、Zustand。寫在哪個檔案不影響這件事。

練習 7：元件第一行是 const [liked, setLiked] = useState(false)，接著 if (!product) return null，之後才 const [open, setOpen] = useState(false)。product 從 null 變成有值時會怎樣？

✓ React 靠呼叫順序對應 hook。上一次 render 只呼叫了一個 hook，這次呼叫兩個，React 發現數量不同就丟錯，render 失敗。lint 的 rules-of-hooks 會在 early return 之後的 hook 報錯。修法是把所有 hook 移到 early return 之前。b 是「數量相同但順序錯」時才會發生的錯位；d 錯在規則要求每一個 hook 都在 early return 之前。

練習 8：useMenu 回傳的 reload 寫成 const reload = () => setVersion(v => v + 1)。呼叫端寫了 useEffect(() => { … reload() … }, [reload])，會怎樣？

✓ 依賴陣列用 Object.is 比較，內容一樣的兩個函式仍是不同的參考，TypeScript 也不會攔。用 useCallback(() => setVersion(v => v + 1), [])：updater function 不需要讀 version，依賴陣列是空的，reload 永遠是同一個函式。

常見錯誤

  • 以為自訂 hook 會共用 state，或把 state 放在模組最外層：每次呼叫一份；模組變數改了也不會 render。要共用就提升 state 或用 Context、Zustand。
  • 在條件、迴圈、early return 之後、事件處理函式裡呼叫 hook：順序對不上，React 丟錯或 state 錯位。hook 放最上層，迴圈裡的 state 抽成元件。
  • 沒有呼叫 hook 的函式也取名 use…：lint 和 Compiler 會把它當成 hook 套規則。普通函式就用普通名字。
  • 回傳的函式每次都是新的：呼叫端放進依賴陣列就每次重跑。用 useCallback 加 updater function。
  • hook 裡的 effect 少依賴參數：參數改了 effect 不重跑，或拿到舊值。參數都是響應值，照 lint 列進依賴陣列；函式參數用 useEffectEvent。
  • useState＋useEffect 同步外部資料：初始值靠猜，訂閱前的變化會漏掉。用 useSyncExternalStore，subscribe 宣告在元件外。
  • 寫 useMount 這類生命週期 hook：lint 看不到裡面漏掉的依賴。以用途命名，直接寫 useEffect。

小結

  • 自訂 hook 是以 use 開頭、呼叫了其他 hook 的函式；共用邏輯，不共用 state。
  • 跟 Vue composable 只執行一次不同，自訂 hook 每次 render 都執行，所以呼叫順序要固定、回傳的函式要穩定。
  • Hook 只在元件或自訂 hook 的最上層、early return 之前呼叫；迴圈裡需要 state 就抽元件。用 lint 擋，不要靠 React 的錯誤訊息。
  • tuple 回傳加 as const；給別人用的函式包 useCallback，搭配 updater function。
  • hook 的參數是響應值，effect 用到就列進依賴；收到的事件處理函式用 useEffectEvent。
  • 外部資料用 useSyncExternalStore；抓資料的 hook 用 abort 與「結果屬於哪一次請求」處理競態和 loading。
  • 用 renderHook 和 act 測試要重用的 hook，讀 result.current，不要先解構。

階段檢核：面試會問的觀念

這個階段一定要講得出來的 7 件事。先在心裡回答，再選。

練習 9：門市看板每 30 秒回報一次目前的商品與門市，同事嫌 lint 吵，用 eslint-disable 把依賴寫成 [productId]。店員切換門市之後，回報的是哪個門市？

useEffect(() => {
  const id = setInterval(() => report(productId, storeId), 30000)
  return () => clearInterval(id)
}, [productId]) // eslint-disable-line react-hooks/exhaustive-deps

✓ React 不追蹤 effect 讀了什麼，只用 Object.is 比較你列的依賴；storeId 沒列，effect 不重跑，計時器裡的閉包一直是舊的快照。修法是把 storeId 列進依賴，換門市就清掉舊計時器重來。a 是 Vue watchEffect 的想法，React 的依賴要自己宣告。（第 5 課）

練習 10：商品詳情頁這樣抓資料。客人快速從拿鐵點到可頌，哪裡會出事？

useEffect(() => {
  getProduct(productId).then(p => setProduct(p))
}, [productId])

✓ 兩個請求都會 setProduct，誰最後回來誰贏，跟點的順序無關。修法在清理函式：每次 effect 有自己的 ignore 旗標，清理時設成 true，回應回來先檢查；再用 AbortController 取消舊請求，AbortError 不顯示成錯誤。c 錯在 React 不會等 effect 裡的 Promise，各個請求是同時在跑的。（第 5 課）

練習 11：習慣用 watch 的同事把購物車合計寫成 const [total, setTotal] = useState(0) 加 useEffect(() => setTotal(sum(lines)), [lines])。code review 時該怎麼改？

✓ 能從 state 算出來的就不是 state：寫 const total = sum(lines)。effect 在 commit 之後才 setTotal，畫面先顯示舊合計、再多 render 一次，set-state-in-effect 也會擋；真的慢才包 useMemo。a 錯在 React 沒有 computed，對應 computed 的是 render 裡的普通 const。（第 6 課）

練習 12：後台的 <OrderEditor order={order} /> 切到另一張訂單時，備註欄還留著上一張訂單的內容。最合適的修法是？

✓ 元件在同一個位置，React 就沿用它的 state；key 換了就當成另一個元件，所有 state 連非受控欄位一起重設，只 commit 一輪。a 會先閃過上一張的備註，新加的欄位和非受控欄位也容易漏掉。c 讓父元件每次 render 都清空正在輸入的內容。（第 6 課）

練習 13：按「編輯」才會出現輸入框，要順便把焦點放進去。在 Vue 會寫 await nextTick() 再 focus，React 寫成這樣會怎樣？

function startEdit() {
  setEditing(true)
  inputRef.current.focus()
}

✓ setState 只是要求下一次 render，事件處理函式跑完才 render、commit，ref 這時才指向輸入框。改成 flushSync(() => setEditing(true)) 再 focus（對應 nextTick，但是要求 React 現在就做完），或在 effect 裡聚焦；不要用 setTimeout 猜。b 錯在 setState 不會改到這次的快照，也不會立刻更新 DOM。（第 7 課）

練習 14：櫃檯看板用 WebSocket 收訂單進度，收到什麼就 dispatch 什麼。客人剛取消訂單，晚到的「開始製作」才送來，畫面從「已取消」跳回「製作中」。該怎麼修？

✓ reducer 同時拿到現在的狀態和發生了什麼，由它決定這件事算不算數；不合法的轉換回傳原本的 state，畫面就不會倒退。a 錯在 reducer 在 render 時執行，在那裡丟錯畫面會壞掉，要 Error Boundary 才接得住。b 的 onmessage 停在訂閱那次 render，讀到的永遠是舊的 status。（第 8 課）

練習 15：同事把 Vue 的 composable 照搬成 hook，打字改了 keyword，菜單卻一直是第一次的結果。該怎麼修？

function useMenu(keyword: string) {
  const [items, setItems] = useState<Product[]>([])
  useEffect(() => {
    search(keyword).then(setItems)
  }, [])
  return items
}

✓ hook 跟元件一樣每次 render 都執行，keyword 每次都是新的值，但 effect 只在依賴改變時重跑；hook 的參數就是響應值，用到就列進依賴（再加上第 5 課的競態處理）。a 是 Vue「傳 ref 進來」的想法，但 useRef 改了不會 render，也不會讓 effect 重跑。c 會 setItems → render → 又搜尋，停不下來。（第 9 課）
