每一題都走七步：重述、手算、暴力解、找重複、改進、查邊界、說複雜度。暴力解一定對，是改進版的對照答案。[回 演算法 學習地圖](../index.html)

## A 每一題都走七步 {span=2}
```flow LR
(① 重述題目) -> [② 手算] -> [③ 暴力解] -> [④ 找重複的工作] -> [⑤ 改進] -> [⑥ 檢查邊界情況] -> *⑦ 說出複雜度
```
- 手算用 3～5 個元素的小例子畫逐步表格；程式錯時，印出同樣的表格對照。邊界情況出錯時，回到第 2 步用那組輸入手算。
- 暴力解試遍所有可能，一定對：確認你懂題目，也是改進版的對照答案。
- 禮券題（兩杯飲料剛好 160 元）：內迴圈一直在找「價格是 `160 − prices[i]` 的那杯」，這就是重複的工作；第 5 課用 Map 改進。
- 累計杯數：第 i 天 = 第 i − 1 天的累計 + 當天，前一步的結果拿來用，O(n²) 變 O(n)。

## B 動手前要確定的四件事
```kv cols=1
輸入: 型別與內容，例如 `readonly number[]`
輸出: 值還是索引，例如金額還是第幾筆
限制條件: 題目保證的範圍，決定寫法夠不夠快、要不要處理負數
找不到時: 這門課一律回傳 `null`，除非題目另外說明
```
最後寫成函式簽章：`function maxOrder(totals: readonly number[]): number | null`。LeetCode 題目看三塊：函式簽章、Example、Constraints。

## C 範例過了不代表對
| 邊界情況 | 找最大差額 | 禮券兩杯（160 元） |
|---|---|---|
| 空的 | `[]` → `null` | `[]` → `null` |
| 一個元素 | `[7]` → `7` | `[80]` → `null` |
| 重複的值 | `[5, 9, 9]` → `9` | `[80, 80, 70, 90]` → `[0, 1]` |
| 負數 | `[-30, -10, -50]` → `-10` | 確認限制條件 |
| 全部一樣 | `[5, 5, 5]` → `5` | `[80, 80, 80]` → `[0, 1]` |
| 答案在頭尾 | `[9, 1, 2]`、`[1, 2, 9]` → `9` | `[70, 90, 80]` → `[0, 1]` |
| 找不到 | 有元素就有最大值 | `[80, 110]` → `null` |

```callout warn 初始值寫 0
全部是負數時回傳 0，陣列裡根本沒有 0。用第一個元素或 `-Infinity`，空陣列另外處理。
```

## D 從迴圈次數到 Big-O {span=2}
| 迴圈 | 最內層執行次數 | 寫成 |
|---|---|---|
| 單迴圈 | n | O(n) |
| 雙迴圈，j 從 0 | n × n | O(n²) |
| 雙迴圈，j 從 i + 1 | n(n − 1) / 2 | O(n²) |
| `i *= 2` | 大約 log₂ n | O(log n) |

- 去掉常數、只留成長最快的項；一前一後相加，套在裡面相乘；不同的輸入用不同的變數，例如 O(n × m)。
- 沒特別說明時，Big-O 指最壞情況。
- 由快到慢：O(1)、O(log n)、O(n)、O(n log n)、O(n²)、O(2ⁿ)。
- 空間複雜度看額外用的記憶體；用 O(n) 的空間換掉一層迴圈是最常見的改進。

## E 從限制推回需要的複雜度
| n 的上限 | 可以接受的複雜度 |
|---|---|
| ≤ 20 | O(2ⁿ) 都可以 |
| ≤ 10⁴ | warn O(n²) 勉強 |
| 10⁵～10⁶ | O(n log n) 或 O(n) |
| 更大，例如 10⁹ | O(log n) 或 O(1) |

粗估 JavaScript 每秒大約 10⁷～10⁸ 個簡單步驟，只是數量級。這門課判分逾時或計時不過，代表複雜度不夠，換演算法才會過。

## F 內建方法也是迴圈
| 操作 | 成本 |
|---|---|
| `arr[i]`、`arr[i] = x`、`arr.length` | O(1) |
| `push`、`pop` | 攤銷 O(1) |
| `includes`、`indexOf`、`find`、`slice`、展開 | O(n) |
| `shift`、`unshift`、`splice` | O(n)，後面的元素都要搬 |
| `Map`／`Set` 的 `get`、`has`、`set`、`add` | 平均 O(1) |
| `sort` | O(n log n) |

```callout warn 越界不報錯
讀越界得到 `undefined`，寫越界讓陣列變長；TypeScript 預設也不提醒。三種迴圈：`i < n` 往後、從 `n − 1` 到 0 往前、`i < Math.floor(n / 2)` 配對兩端。
```

## G 回傳新陣列還是原地修改
| 做法 | 額外空間 | 代價 |
|---|---|---|
| 回傳新陣列 | O(n) | ok 沒有副作用 |
| 原地修改 | O(1) | warn 會改到呼叫端的資料 |

題目沒說就問：「可以修改傳進來的陣列嗎？」不能改的參數宣告成 `readonly number[]`，需要時先複製或用 `toSorted`。`stock = stock.filter(…)` 只改了區域變數，原地修改要寫 `stock[i] = …`。

## H 讀寫指標：把售完的品項移到最後 {span=2}
```flow LR
[read 走過每一格] -> {這格不是 0?}
{這格不是 0?} -> [寫到 write，write 前進一格]: 是
{這格不是 0?} -> [跳過]: 是 0
[寫到 write，write 前進一格] -> [走完後 write 之後補 0]
```
| 寫法 | 時間 | 額外空間 |
|---|---|---|
| 邊走邊 `splice` | no O(n²)，連續的 0 會漏 | O(1) |
| `filter` 再補 0 | O(n) | warn O(n) |
| 讀寫指標 | ok O(n) | ok O(1) |

`write` 永遠不會超過 `read`，寫進去的一定是讀過的格子。例：`[0, 1, 0, 3, 12]` → `[1, 3, 12, 0, 0]`。
