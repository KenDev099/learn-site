## A 優先佇列為什麼用 heap
| 做法 | 放進去 | 拿出最小的 |
|---|---|---|
| 不排序的陣列，拿的時候掃一遍 | O(1) | no O(n) |
| 每次放進去都 `sort` | no O(n log n) | O(1) |
| 保持排序，二分找位置再 `splice` | no O(n) | O(1) |
| heap | ok O(log n) | ok O(log n)，peek O(1) |

heap 只知道誰最小，不知道第二小以後的完整順序。JavaScript 沒有內建 heap；面試時自己寫，或先問能不能假設有一個 MinHeap 類別。

## B 用陣列存的完全二元樹：heap {span=2}
```kv cols=2
左子節點: `2i + 1`
右子節點: `2i + 2`
父節點: `(i − 1) >> 1`
順序: 父節點不大於子節點；只有根一定最小，陣列不是排序好的
push: 放到最後，比父節點小就往上換
pop: 記下根，最後一個移到根，跟較小的子節點往下換
```
| 步驟 | 陣列 | 做了什麼 |
|---|---|---|
| 開始 | `[5, 12, 8, 20, 15, 9, 30]` | 記下 5，pop 出最後的 30 |
| 補洞 | `[30, 12, 8, 20, 15, 9]` | 30 放到根 |
| i = 0 | `[8, 12, 30, 20, 15, 9]` | 子節點 12、8，跟較小的 8 交換 |
| i = 2 | `[8, 12, 9, 20, 15, 30]` | 只有索引 5 的 9，交換 |

表格是這課的示範資料：從 min-heap pop 一次。傳入 `less(a, b)`，同一個類別可以是 min-heap、max-heap，也能比較物件。空的時候 pop 回傳 `undefined`。

## C 前 k 大與前 k 常見
| 做法 | 時間 | 什麼時候用 |
|---|---|---|
| 複製、排序、取第 k 個 | O(n log n) | ok 資料都在手上、n 不大 |
| 大小為 k 的 min-heap | O(n log k)，空間 O(k) | ok 資料一直進來 |
| 前 k 常見：Map 計數 + 排序 | O(n + m log m) | 並列靠 Map 插入順序 + 穩定排序 |
| 前 k 常見：Map 計數 + 大小為 k 的 heap | O(n + m log k) | 並列規則寫進比較函式 |

找最大的 k 個用 min-heap：新值比 `peek()` 大才換掉頂端。並列規則要先定義。

## D 圖：相鄰串列與 visited {span=2}
```flow LR
0 -> 1
1 -> 2
2 -> 0
1 -> 3
4
```
這課的示範：道路清單 `[[0, 1], [1, 2], [2, 0], [1, 3]]`。這是無向圖，道路兩個方向都走得通，圖上箭頭的方向沒有意義。0～3 互相走得到，4 自己一塊；0、1、2 繞成一圈，沒有 visited 就走不完。
- 先建相鄰串列，無向圖兩個方向都加；用 `Array.from({ length: n }, () => [])`，不用 `fill([])`。
- visited 在放進堆疊或佇列時就標記，每個頂點只處理一次。
- 圖 O(V + E)，網格 O(rows × cols)。

## E 網格也是圖
- 每格是頂點，上下左右是邊；`DIRS` 位移陣列加上 `>= 0 && < rows` 的邊界檢查算出鄰居。
- 格子的 visited 用二維布林陣列、`r * cols + c` 或字串鍵；不能用陣列當 Set 的鍵。
- 塗色、數連通區塊用 DFS；外層掃每一格，每格只被標記一次，總共仍是 O(rows × cols)。
- 最少步數用 BFS，`dist` 表 `-1` 代表還沒走到，同時就是 visited。

```callout warn 大網格不要用遞迴
遞迴深度會超出呼叫堆疊。改用自己的堆疊或佇列：參數變成一筆資料，檢查通過就標記並 push。
```

## F 怎麼選：DFS、BFS 與更多
| 題目問的是 | 用什麼 |
|---|---|
| 走不走得到、有幾區、塗色 | DFS 或 BFS 都可以 |
| 最少幾步（每步代價一樣） | BFS：一層就是一步 |
| 每條路代價不同的最短時間 | Dijkstra（需要 heap），這門課不要求實作 |
| 所有可能的路線、所有組合 | 回溯 |
| 有先後關係的步驟要排順序 | 拓撲排序（第 26 課） |

DFS 只保證找得到，找到的路不一定最短。

## G 回溯：選擇、探索、撤銷 {span=2}
```flow LR
(dfs 狀態) -> {走到底了?}
{走到底了?} -> *記錄 複製 path: 是
{走到底了?} -> [選擇 path.push]: 否
[選擇 path.push] -> [探索 遞迴 dfs]
[探索 遞迴 dfs] -> [撤銷 path.pop]
```
- 選擇時改了什麼，撤銷時就還原什麼（`path`、`used` 都要）。
- 記錄寫 `result.push([...path])`：整個過程共用一個 `path`，只放參考的話最後全是 `[]`。
- 要所有方案用回溯；只要有幾種或最少／最多改用動態規劃；正式環境答案可能很多時，給上限或用產生器逐一產生。

## H 子集合、排列、湊金額
| 題目 | 下一層從哪裡挑 | 複雜度 |
|---|---|---|
| 子集合、組合（不在乎順序） | 從 `start` 往後挑 | 子集合 O(n × 2ⁿ) |
| 排列（在乎順序） | 從頭挑，用 `used` 跳過 | O(n × n!) |
| 可重複使用的湊金額 | 遞迴傳 `j`；不能重複傳 `j + 1` | 指數時間 |

複雜度看答案數量，所以 n 都很小。剪枝（排序後面額大於剩下金額就 `break`）不改變最壞情況，但能省下大量搜尋；前提是排序正確，要給 `(a, b) => a - b`。
