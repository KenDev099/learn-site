這五招都在丟掉不必再看的部分，或重用算過的結果。每次移動指標、縮小範圍前，要能說出被丟掉的那部分為什麼沒有答案。[回 演算法 學習地圖](../index.html)

## A 對撞指標：每一步丟掉一個不可能的元素 {span=2}
```flow LR
(left 在頭、right 在尾) -> {left < right?}
{left < right?} -> [看 a 的 left 與 right 兩格]: 是
{left < right?} -> [結束]: 否
[看 a 的 left 與 right 兩格] -> *回傳: 找到
[看 a 的 left 與 right 兩格] -> [right--]: right 不可能是答案
[看 a 的 left 與 right 兩格] -> [left++]: left 不可能是答案
```
| 題目 | 丟掉一邊的理由 |
|---|---|
| 迴文 | 這一對比過了 |
| 已排序找兩數和 | 太大時 right 跟誰配都太大 |
| 最大展示區 | 矮的那片換不出更大的面積 |

O(n) 時間、O(1) 額外空間。找兩個不同的元素用 `left < right`，`<=` 會讓同一個元素用兩次。三數和：排序（給比較函式、先複製）→ 固定一個 → 雙指標，O(n²)，外層和內層都要跳過重複。

## B 排序：比較函式決定誰在前
| 寫法 | 結果 |
|---|---|
| `sort()` | no 依字串排序，`[1, 10, 100, 9]` |
| `(a, b) => a > b` | no 永遠不回傳負數，常常沒排好 |
| `(a, b) => a - b` | ok 由小到大 |
| `a.total - b.total \|\| a.time - b.time` | ok 多個欄位用 `\|\|` 串起來 |

負數 a 在前、正數 b 在前、0 相等。`sort` 原地修改並回傳同一個陣列，ES2023 的 `toSorted` 回傳新陣列。內建排序 O(n log n)，ES2019 起保證穩定。先排序常讓問題變簡單，代價是 O(n log n) 和原本索引的消失。

## C 合併：兩條已排序陣列與重疊的預約
```flow TB
(依開始時間排序) -> [拿下一筆預約]
[拿下一筆預約] -> {開始 ≤ 目前合併段的結束?}
{開始 ≤ 目前合併段的結束?} -> [合併，結束取較大的]: 是
{開始 ≤ 目前合併段的結束?} -> [目前這段定案，換它當新的一段]: 否
```
- 只跟最後一段比；相接算不算重疊要先問清楚，這課約定相接也合併。合併區間 O(n log n)。
- 合併兩個已排序陣列：兩個指標每次拿比較小的，O(m + n)；空位在後面時從後往前放大的，O(1) 額外空間。

## D 二分搜尋：左閉右開 [lo, hi) {span=2}
```flow LR
(lo = 0，hi = n) -> {lo < hi?}
{lo < hi?} -> [mid = Math.floor((lo + hi) / 2)]: 是
{lo < hi?} -> *回傳 lo: 否，範圍空了
[mid = Math.floor((lo + hi) / 2)] -> [lo = mid + 1]: mid 不是答案，答案在右邊
[mid = Math.floor((lo + hi) / 2)] -> [hi = mid]: mid 可能是答案或答案在左邊
```
每次丟掉不可能的一半，O(log n) 時間、O(1) 空間；100 萬筆約 20 次。前提是資料有序，或條件是單調的。範圍每圈至少縮小 1，不會無窮迴圈。`mid` 不要用 `>>`：位元運算先轉成 32 位元整數。

## E 同一個骨架能回答的問題
| 問題 | 條件 | 結果 |
|---|---|---|
| lower bound | `prices[mid] >= target` | 回傳 `lo`：第一個 ≥ 目標的位置，也是插入位置、小於目標的筆數 |
| 是非題 `false…true` | `isBad(mid)` | 第一個 `true`，可以對答案的範圍二分 |
| 旋轉過的陣列 | 先判斷哪一半有序 | 目標在有序那一半的頭尾之間就往那邊找 |

lower bound 可能回傳 `n`，代表插在最後面，讀 `prices[i]` 前先檢查 `i < n`。只查一次不值得先排序；要查的次數多時，排序一次才划算。

## F 滑動視窗：連續的一段 {span=2}
| 種類 | 怎麼移動 | 什麼時候更新答案 |
|---|---|---|
| 固定視窗 k | `sum += a[i] − a[i − k]` | 每移一格比一次；平均值先比總和，最後再除 |
| 可變視窗：最短達標 | `right` 擴張，`while` 收縮 `left` | 收縮前 |
| 可變視窗：最長合法 | `right` 擴張，`while` 收縮 `left` | 收縮後 |

長度 `right − left + 1`。for 裡有 while 仍是 O(n)：兩個指標都只往右。Set 守住視窗內有哪些值；Map 記最後出現的位置，讓 `left` 用 `Math.max` 一次跳到位。

```callout warn 可變視窗要求單調性
全部是正數才能用總和來縮。有負數時收縮會丟掉答案，改用前綴和。
```

## G 前綴和：先建表，每段 O(1)
```kv cols=1
建表: `prefix[0] = 0`，`prefix[i + 1] = prefix[i] + a[i]`，長度 n + 1
區間和: sum(l..r) = `prefix[r + 1] − prefix[l]`
取捨: 先付 O(n) 時間與空間，換每次查詢 O(1)；只查一次不會更快，資料常變動也不划算
平衡點: 只需要左邊的總和時，一個 `leftSum` 就夠；右邊 = total − leftSum − a[i]
總和等於 k: 數前面出現過幾次 p − k；頻率表一開始放 0 → 1，先查再存，有負數也成立，O(n)
```
這課的示範資料：`[3, -3, 3]`、k = 3，走到最後 p = 3，0 出現過 2 次，一次加 2。

## H 怎麼選技巧 {span=2}
| 重複的工作 | 用 | 代價 |
|---|---|---|
| 同一份資料反覆問某一段的總和 | 前綴和 | 建表 O(n)、空間 O(n) |
| 已排序，找位置、數落在範圍的有幾個 | 二分搜尋 | 每次 O(log n) |
| 連續段、非負數，求最長／最短／最大 | 滑動視窗 | O(n)、O(1) 空間 |
| 連續段的總和等於 k、有負數 | 前綴和 + 頻率表 | O(n)、空間 O(n) |
| 配對、看過沒有、出現幾次 | 雜湊表 | O(n)、空間 O(n) |
| 已排序，找兩個數的組合 | 雙指標 | O(n)、O(1) 空間 |

沒排序、要原本的索引用 Map；已排序用雙指標省下 O(n) 空間。
