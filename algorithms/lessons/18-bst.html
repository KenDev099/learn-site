階段 5：遞迴與樹 · 第 18 課

二元搜尋樹

咖啡店後台有一份依價格排好的品項表，店長常問三種問題：有沒有剛好 100 元的品項？100 元的新品上架，要怎麼排進表裡？第 3 便宜的是多少錢？用第 9 課的做法，把價格放在排好序的陣列裡、用二分搜尋查，查價是 O(log n)，很快；第 3 便宜也簡單，直接取 [2]，O(1)。卡住的是上架：100 元的新品要插進 90 和 110 之間，110 後面的元素全部往後搬一格，O(n)。品項一多、價格又常調整，每次上架都在搬資料。

這課的任務：做一個價格結構，查價跟二分搜尋一樣每次丟掉一半，上架時不用搬動既有的資料，換成樹之後也還能回答「第 k 便宜」。答案是二元搜尋樹（binary search tree，簡稱 BST）：把「排好序」這件事從陣列的位置，改成用樹的形狀來記。做的過程會碰到三個常見的坑：資料照順序進來時樹會退化、檢查樹的時候只比父子會被騙、邊界的初始值寫錯數字。

這課的路線：
  1. 不搬資料，怎麼還能每次丟掉一半？BST 的規則與查價（開場問題的最小答案）。
  2. 100 元的新品要放在哪裡？插入，以及中序走訪為什麼剛好由小到大。
  3. 上架的順序會讓查價變慢嗎？樹的形狀決定速度；正式環境為什麼用自動平衡的樹和資料庫索引。
  4. 拿到一棵樹，怎麼確認它真的是 BST？為什麼只比父子不夠，上下界要往下傳。
  5. 第 3 便宜是多少錢？用堆疊走中序，走到第 k 個就停。
  6. 題目沒說用哪個結構時，怎麼挑？回頭看第 12～18 課。
這課會用到：
  • 第 9 課的二分搜尋：在排好序的陣列裡每次看中間、丟掉不可能的一半，所以 O(log n)。
  • 第 16 課的二元樹：treeFrom 依層把陣列建成樹；中序走訪是先左子樹、再自己、再右子樹；高度是從根往下最長有幾層。

不搬動資料，怎麼還能每次丟掉一半？

先看二分搜尋為什麼能丟掉一半。它看中間那個值，如果目標比較大，就知道左半邊全部不可能。這個判斷靠的是「陣列排好序」：中間左邊的都比較小、右邊的都比較大。陣列用位置記住這個大小關係，所以插入時位置要跟著搬，這就是上架慢的原因。

換個記法：如果每個值自己記住「比我小的放在哪一邊、比我大的放在哪一邊」，大小關係就不再靠連續的位置，插入時也就不用搬動別人。這正是二元搜尋樹。它是一棵二元樹（第 16 課：每個節點最多有左、右兩個子節點），而且每個節點都滿足：

  • 左子樹裡的每一個值都比這個節點小。
  • 右子樹裡的每一個值都比這個節點大。

規則說的是「整個子樹」，不是只有直接的左右子節點。下圖 90 的左子樹裡有 70、60、80，這三個全部都要比 90 小，不是只有接在 90 左邊的 70。這一點到第 4 節檢查一棵樹是不是 BST 時，會決定程式寫得對不對。下面是把店裡的價格建成的 BST（這課的價格都不重複；重複值怎麼處理，第 4 節再談）：

查一個價格時，從根開始：相等就找到了；目標比較小就往左子樹找，因為右子樹全部比這個節點大，不可能有；目標比較大就往右。每走一步，就丟掉一整棵子樹。這跟二分搜尋「看中間、丟一半」是同一個想法，只是「中間」換成了「目前的節點」。

下面找三個價格：110 和 60 都在樹裡，100 不在。執行後看每次走過哪些節點，特別是找 100 最後停在哪裡：

找 100 時走到 110，100 比 110 小要往左，但 110 沒有左子節點，走到 null。BST 的規則保證：如果 100 存在，它只可能在這個位置，所以走到空位就可以直接說「沒有」，不用再看樹的其他地方。

查一次最多走過幾個節點？每一步往下一層，所以最多是樹的高度（第 16 課：從根往下最長有幾層），寫成 O(h)，h 是高度。找 110 時，比完 90 往右走，左邊 70、60、80 這一整棵子樹就不用看了。樹長得平均的時候，每棵子樹大約有一半的節點，走一步就丟掉約一半，h 約是 log₂ n，跟二分搜尋一樣快。這個「長得平均」不是自動成立的，第 3 節會看到它怎麼被破壞。查價用迴圈寫就好，不需要遞迴，也不需要額外空間，所以是 O(h) 時間、O(1) 空間。

查價解決了。而找 100 時停下來的那個空位，剛好就是下一個問題的答案：100 元的新品上架，要放在哪裡？

100 元的新品上架，要放在哪裡？

上一節找 100 時停在 110 的左邊，那裡是空的；BST 的規則又說 100 只能在那裡。所以插入就是：照查價的規則往下走，走到 null 的空位，把新節點放上去。新節點一定是葉節點（第 16 課：沒有子節點的節點），原本的節點一個都不用動。這就是陣列做不到的地方：陣列要把 110、120、135 往後搬，樹只要讓 110 的 left 指向新節點。

遞迴寫法很短，但有一個關鍵：函式回傳這棵子樹插入之後的根，呼叫的人要把回傳值接回去：

function insert(root, val) {
  if (root === null) return 新節點          // 走到空位：這棵（空）子樹的新根就是新節點
  if (val < root.val) root.left = insert(root.left, val)    // 把左子樹插完後的新根接回 left
  else root.right = insert(root.right, val)
  return root                               // 不是空樹時，根不變
}

為什麼要「接回去」？新節點是在最底下那次呼叫建立的，那一層拿到的只是 null，它不知道父節點是誰，沒辦法自己去改父節點的 left。它只能把新節點回傳給上一層，上一層寫 root.left = …，新節點才真的接上樹。上面每一層也都會重新指定一次 left 或 right，但除了最底下那一層，指定的都是原本的子節點，等於沒改。如果漏寫 root.left =，新節點建出來了，卻沒有任何節點指著它，樹看起來完全沒變。也可以用迴圈寫：一路走到空位的上一個節點，直接設定它的 left 或 right，第 3 節的範例就是迴圈寫法。

下面先把七個價格依序插入建出整棵樹，再插入 100。執行後看兩件事：中序走訪印出的順序，以及 100 接在哪個節點底下：

100 接在 110 的左邊，跟上一節查價停下來的位置一樣。中序走訪印出來是由小到大，這不是巧合：中序是「先左子樹、再自己、再右子樹」，左子樹全部比自己小、右子樹全部比自己大，所以每一個節點周圍都是「小、中、大」的順序，整棵樹走下來就排好了。這代表 BST 本身就是一份排好序的價目表：不用另外排序，中序走一遍就得到由小到大的清單。第 4 節檢查一棵樹、第 5 節找第 k 便宜，都會用到這個性質。

下架品項（刪除節點）比插入麻煩，因為被刪的節點可能還有子節點要安置，做法見課末「補充與查表」。

到這裡，查價和上架都只沿著一條路往下走，都是 O(h)。上一節說 h 約是 log₂ n 的前提是「樹長得平均」，但插入時只是照規則找空位放下去，沒有人在管形狀。那上架的順序會不會讓樹長歪？

上架的順序，會讓查價變慢嗎？

會。O(h) 裡的 h 由樹的形狀決定，而普通 BST 的形狀完全由插入順序決定：每個新值只是找空位放下去，樹不會回頭調整已經放好的節點。同樣的規則，可能長成兩種極端：

  • 平衡（balanced）：每個節點左右子樹的高度差不多。每往下一層，節點數大約翻倍，所以 n 個節點的高度約 log₂ n。1,000 個節點約 10 層，100 萬個約 20 層。
  • 歪斜（skewed）：每個節點都只有一邊有子節點，整棵樹就是一條線，看起來跟第 13 課的鏈結串列一樣，高度是 n。

最糟的情況很常見：資料進來時本來就排好序，例如依上架時間遞增的品項編號。下面把 1～1,000 用兩種順序插入同一種 BST，一種照 1、2、3 遞增，一種先打散。執行後比較兩棵樹的高度，和理想的 log₂ 1000：

遞增插入時，每個新值都比前面全部大，永遠接在最右邊，高度就是 1,000：找 1,000 要比較 1,000 次，跟從頭掃陣列一樣，BST 的好處全部消失。打散的順序得到二十幾層，比理想的 10 層高一些，但還是 O(log n) 的等級。

正式環境不能賭資料剛好亂序進來，所以用的都是自動平衡的樹：每次插入、刪除之後，檢查左右兩邊的高度差，太歪就調整幾個節點的上下關係（這種調整叫旋轉），把高度維持在 O(log n)。常見的有 AVL 樹、紅黑樹（Java 的 TreeMap 就是紅黑樹）。資料庫的索引則用 B-tree（PostgreSQL 課第 20 課）：資料放在磁碟上，每讀一個節點就是一次讀取磁碟，所以 B-tree 讓一個節點存很多個值、有很多個分支，樹更矮，一次讀一整頁磁碟就能排除一大片。面試通常不會要你寫出平衡的方法，知道這些名字、說得出「普通 BST 最壞是 O(n)，所以要用自動平衡的版本」就夠了。

把這課的任務放回來比較：排好序的陣列輸在上架，平衡的 BST 查價和上架都快，歪斜的 BST 什麼都慢：

操作排好序的陣列平衡的 BST歪斜的 BST
找一個值O(log n)（二分搜尋）O(log n)O(n)

那後台的價目表實際上該用什麼？JavaScript 沒有內建的平衡樹，所以要看需求：只問「有沒有」「依 id 找」，用 Map／Set（第 4 課，平均 O(1)，但它只記得插入順序，不會依大小排序，也做不了「找 100～150 元之間」這種範圍查詢）；資料不常變、要範圍查詢，用排好序的陣列加二分搜尋；資料很多、又要排序與範圍查詢，交給資料庫的索引。自己寫 BST 主要出現在面試，以及需要理解索引怎麼運作的時候。

💡 實務上：測資要有「排好序進來」的那一種
最壞情況常常就是最常見的情況：訂單編號、自動遞增的 id、建立時間，資料進來的順序本來就是遞增的。自己寫的資料結構如果只用隨機資料測，看起來很快，上線後資料依時間進來，就退化成上面那條斜線。資深的人看到手寫的樹或查找結構，會先問「正式環境的資料是什麼順序進來的」，並補一個用已排序資料、量級接近正式資料的測試。真的需要排序加範圍查詢，優先交給資料庫索引或維護良好的套件，平衡它們已經處理好了。

查價、上架、形狀的風險都清楚了。但到目前為止有一個前提一直沒有檢查：這棵樹真的符合 BST 的規則嗎？查價敢丟掉一整棵子樹，靠的就是規則成立。如果樹是從 JSON、資料庫或別人的程式拿來的，只要有一個節點放錯位置，查價就會默默回傳「沒有」，不會報錯。下一節處理這件事。

拿到一棵樹，怎麼確認它真的是 BST？

要檢查的就是上一節那個前提：每個節點都在規則允許的位置。這也是面試很常考的題目（對應 LeetCode 98），而第一個想到的寫法通常是錯的：檢查每個節點是不是比左子節點大、比右子節點小。看這棵樹：

每一對父子單獨看都沒問題，可是 80 在 90 的右子樹裡，第 1 節的規則要求右子樹的每一個值都比 90 大。實際查 80 時，會從 90 往左走，永遠找不到它，這就是上一節說的「默默回傳沒有」。所以一個節點的限制不只來自父節點，而是來自它所有的祖先。

既然限制來自所有祖先，就要讓每個節點知道「祖先們加起來，允許我落在哪個範圍」。這個範圍用兩個數表示：下界 low（值必須大於它）和上界 high（值必須小於它），合起來叫上下界（bounds），寫成 (low, high)，不含兩端。規則只有三條：

  • 根沒有祖先，範圍是 (-Infinity, Infinity)，什麼值都可以。
  • 往左走時，子樹的每個值都要比目前節點小，所以上界收緊成目前節點的值，下界照樣往下傳。
  • 往右走時，子樹的每個值都要比目前節點大，所以下界收緊成目前節點的值，上界照樣往下傳。

用上圖走一次：根 90 的範圍是 (-Infinity, Infinity)；往右到 120，範圍變成 (90, Infinity)；再往左到 80，上界收緊成 120，範圍是 (90, 120)。80 不在裡面，抓到了。下面把只比父子的寫法和帶上下界的寫法放在一起跑。執行後先看兩個寫法的結論，再看每個節點被要求的範圍：

這裡比較用嚴格的 <，是因為這課約定不允許重複值，值等於界線就不合格。重複值怎麼處理，每個題目規定不一樣：不允許、放左邊、或放右邊。面試時先問清楚再寫，它決定比較要用 < 還是 <=。

上下界的初始值一定要用 -Infinity 和 Infinity。常見的錯誤是寫 0（價格調整的差額、溫度都可能是負數），或寫 Number.MIN_VALUE，以為它是最小的數。執行後看 0 和 -5 跟 Number.MIN_VALUE 比較的結果：

Number.MIN_VALUE 是「最接近 0 的正數」，約 5e-324，不是最小的數。拿它當下界，值是 0 或負數的節點全部被判不合格，一棵合法的樹就被說成壞掉。要表示「沒有下界」，用 -Infinity 最不容易出錯（精確值和其他寫法見課末）。

還有另一種檢查法，用的是第 2 節的性質：BST 的中序走訪由小到大，所以反過來，中序走訪必須嚴格遞增。走訪時記住上一個值，只要目前的值 <= 上一個，就不是 BST。上圖的中序是 70、90、80、120、135，90 之後出現 80，下降了，一樣抓得到，而且不用另外傳上下界。兩種做法都是 O(n) 時間、O(h) 的遞迴堆疊。要注意是「嚴格」遞增：[2, 2, 2] 的中序是 2、2、2，沒有下降，卻有重複值，不允許重複時它不是 BST。

💡 實務上：找最小值、最大值時，初始值不要寫 0
同樣的坑在一般業務程式裡很常見：算購物車裡最便宜的品項寫 let min = 0，結果永遠回傳 0；反過來找最大值時，退款差額這種可能是負數的值，用 0 當起點也會錯。起點用 Infinity／-Infinity，或直接拿第一個元素。另外要先決定空陣列回傳什麼：空陣列寫 Math.min(...prices) 會回傳 Infinity，畫面上就會出現「Infinity 元」，通常應該回傳 null，讓畫面顯示「—」。Code review 看到 0、-1、999999 這種拿來當邊界的魔術數字，都值得問一句「資料可能超出這個範圍嗎？」

中序走訪由小到大這個性質，剛剛拿來檢查樹。任務還剩最後一個問題，答案也在它身上：第 3 便宜的品項是多少錢？

第 3 便宜的品項是多少錢？

陣列直接取 [k - 1] 就有答案，因為第幾小就放在第幾格。改用樹之後，大小順序記在樹的形狀裡，不再對應任何位置，沒辦法直接跳到第 k 個，只能照順序走過去，所以要重新想怎麼走、走多遠。這是 BST 為了「上架不用搬資料」付出的代價。中序走訪是由小到大，所以第 k 個走到的就是第 k 便宜（對應 LeetCode 230）。最直接的做法是用第 16 課的遞迴中序，把值全部收進陣列，再取 [k - 1]，O(n) 時間、O(n) 空間。但店長只要前 3 名，價目表卻可能有幾千個品項；走到第 3 個就該停下來，後面的不用碰。

遞迴的中序不好中途停：答案在很深的一層找到後，要一層一層把「找到了」傳回去。改用第 12 課的堆疊（只從頂端放入、拿出，後放的先拿）自己記住「還沒處理的祖先」，把中序寫成迴圈，就能在任何時候 return。做法分三步，重複到結束：

  1. 從目前的節點一路往左走，把經過的節點都放進堆疊。最左下的節點就是目前最小的。
  2. 取出堆疊頂端的節點。它的左子樹已經處理完了（或根本沒有），所以它就是下一個最小的值，計數加一；到第 k 個就回傳。
  3. 比它大一點的值在它的右子樹，轉到右子節點，回到第 1 步；右邊是空的，就繼續取堆疊裡的下一個祖先。

下面在同一棵價格樹找第 3 小。執行後看每次取出的值，以及當時堆疊裡還剩哪些節點：

找第 3 小只取出了 3 個節點就停，沒有碰到 110、120、135。時間是 O(h + k)：先往下走一條左邊的路，再取出 k 個。堆疊裡最多同時放一條路上的節點，最多 h 個，所以空間是 O(h)。

注意 k 從 1 開始：「第 1 小」是最小的那個。每取出一個就先 count++，再比較 count === k；順序寫反就會多走一個。

💡 實務上：「前幾筆」交給資料庫，「找到就停」到處用得到
咖啡店後台的「最便宜的 3 個品項」「最新的 20 筆訂單」，實務上會寫 ORDER BY price LIMIT 3、ORDER BY ordered_at DESC LIMIT 20；排序的欄位有索引時，資料庫可以沿著排好序的索引讀到需要的筆數就停，跟這裡的中序走訪是同一個想法。在前端或 Node 裡處理陣列也一樣：只要第一個符合條件的，用 find、some，不要寫 filter(…)[0] 把整個陣列走完。反過來，分頁用很大的 OFFSET 時，資料庫還是要先走過被跳過的那些筆，後台列表翻到很後面的頁數會變慢，這是常見的效能問題。

價目表的三個問題都有答案了：查價、上架、第 k 便宜。這個任務一開始就說了「依價格排序、要查、要插」，所以選 BST 很直接。但練習和面試的題目不會先告訴你要用哪個結構，最後一節就來練這件事。

題目沒說用哪個結構時，怎麼挑？

第 12～18 課學了堆疊、佇列、鏈結串列、快慢指標、遞迴、DFS、BFS、BST。題目不會說用哪一個，還是照第 1 課的步驟：先寫暴力解，看它重複做了什麼，再對照下表找特徵：

題目的特徵用代價
最近的那一個、成對抵消、可以撤銷（括號、相鄰的重複、復原）堆疊（第 12 課）O(n)、空間 O(n)
依先來後到處理、一層一層、最少幾步佇列、BFS（第 12、17 課）空間是最寬那一層
要先知道左右子樹的答案才能算自己DFS 後序（第 16 課）空間是高度
樹本身有大小順序：找值、插入、範圍、第 k 小BST：沿一條路往下、中序走訪（本課）O(h)，歪斜時 O(n)
串列上插入、刪除、反轉，要重用原本的節點鏈結串列的指標操作（第 13 課）O(n)、O(1) 空間
串列的中間、有沒有環、倒數第 k 個快慢指標（第 14 課）O(n)、O(1) 空間

同一題常常不只一種對的做法，例如「每一層的總和」用 BFS 最直觀，用 DFS 帶著深度也能做。面試時說出你選哪一個、為什麼、代價是什麼，比只寫出程式更重要。練習 5～7 就是這種沒有提示的題目。

補充與查表

  • 刪除節點（下架品項，對應 LeetCode 450）：比插入麻煩，分三種情況。葉節點直接刪；只有一個子節點時，讓子節點頂替它的位置；有兩個子節點時，用右子樹裡最小的節點（中序的下一個）取代它，再去右子樹刪掉那個節點。面試偶爾考，知道這三種情況就能推出來。
  • Number.MIN_VALUE 的精確值：主流引擎都是 2⁻¹⁰⁷⁴（約 5e-324），是最接近 0 的正數。最負的有限數是 -Number.MAX_VALUE，但當「沒有下界」用時，-Infinity 最不容易出錯。

練習

每題的起始程式都貼好了節點型別和建樹、建串列的工具（treeFrom 用第 16 課的層序陣列）。隱藏測試用固定案例和大量隨機案例比對參考解；判分逾時或出現「花了 … ms」，代表複雜度不夠。練習 1～4 的價格都不重複。練習 5～7 是混合複習：題目不說用哪個技巧，範圍是第 12～18 課。

練習 1：經典題。寫 findPrice(root, price)：root 是依價格建的 BST，回傳值等於 price 的那個節點（不是值，也不是新建的節點）；找不到回傳 null。要 O(高度)：測試會用 200 個以上節點的樹，計算你讀取 left／right 的次數，走訪整棵樹會超過。不能修改樹。對應 LeetCode 700. Search in a Binary Search Tree。

練習 2：經典題。寫 insertPrice(root, price)：把一個樹裡還沒有的價格插入 BST，回傳插入後的根；空樹時回傳新節點。新節點要放在搜尋停下來的那個空位，原本的節點都要保留（同一個物件），不能重建整棵樹。可以用遞迴或迴圈。對應 LeetCode 701. Insert into a Binary Search Tree。

練習 3：經典題。寫 isValidPriceTree(root)：判斷一棵樹是不是 BST；不允許重複值，空樹算是。值可能是負數或 0（這棵樹存的是價格調整的差額）。只比較直接的子節點會被深處的違規騙過；測試裡有 [90, 70, 120, null, null, 80, 135] 這種樹。對應 LeetCode 98. Validate Binary Search Tree。

練習 4：經典題。寫 kthCheapest(root, k)：root 是依價格建的 BST，回傳第 k 便宜的價格（k 從 1 開始，1 ≤ k ≤ 節點數）。建議用迴圈加堆疊的中序走訪，走到第 k 個就停。不能修改樹。對應 LeetCode 230. Kth Smallest Element in a BST。

練習 5（混合複習）：寫 busiestLevel(root)：一棵二元樹（不是 BST），每個節點的值是某個時段的杯數變化（可能是負數）。回傳「這一層所有節點的值加總」最大的那一層的層號：根是第 1 層；有好幾層並列最大時，回傳層號最小的；空樹回傳 0。測試期間不能用 shift()。（對應 LeetCode 1161. Maximum Level Sum of a Binary Tree）

練習 6（混合複習）：寫 dedupeSortedTickets(head)：取餐單串列已經依號碼由小到大排好，同一個號碼可能連續出現好幾次（重複列印）。刪掉重複的，每個號碼只留一個，回傳 head。要重用原本的節點，不能建立新節點。（對應 LeetCode 83. Remove Duplicates from Sorted List）

練習 7（混合複習）：寫 cancelAdjacent(codes)：出餐單是一串大寫字母代碼，相鄰兩個一樣的字母代表「點了又取消」，要一起刪掉；刪掉之後新變成相鄰的一樣字母也要刪，直到沒有可以刪的為止，回傳剩下的字串。'CADDAB'：刪 DD 得到 'CAAB'，再刪 AA 得到 'CB'。'AAA' 只刪一對，剩 'A'。測試會用長度 20,000 的字串計時。（對應 LeetCode 1047. Remove All Adjacent Duplicates In String）

練習 8：同事寫的 isBST 只檢查「每個節點都大於左子節點、小於右子節點」，並說「每一對父子都對，整棵樹就對」。哪個說法正確？

✓ 例如 [90, 70, 120, null, null, 80, 135]：80 < 120 這一對沒問題，但 80 在 90 的右子樹裡，必須大於 90。搜尋 80 時會從 90 往左走，永遠找不到。所以每個節點要帶著祖先給的範圍 (low, high)。a 錯：只比父子會漏掉這種違規。c 錯：左子節點本來就該比父節點小，而且一樣只看了一層。

練習 9：把每天新上架的品項依編號 1、2、3、…、10,000 的順序插入一棵普通的 BST，之後查一個編號。下列哪個說法正確？

✓ 搜尋是 O(高度)。普通 BST 不會自己調整形狀，插入順序決定高度：排好序的資料是最糟的情況。需要保證 O(log n) 要用自動平衡的樹（AVL、紅黑樹），資料庫的索引用 B-tree。a 錯：只有平衡時才是 O(log n)。b 錯：自動平衡是 AVL、紅黑樹這些變形才有的，一般的 BST 沒有。

練習 10：驗證 BST 時，有人把根的上下界寫成 (Number.MIN_VALUE, Number.MAX_VALUE)，理由是「MIN_VALUE 是 JavaScript 最小的數」。這樣寫會怎樣？

✓ Number.MIN_VALUE 是「最小的正數」，0 > Number.MIN_VALUE 是 false，所以 0 和所有負數都會被判出界。用 -Infinity 與 Infinity 當初始範圍最安全。b 錯：最負的有限數是 -Number.MAX_VALUE。c 錯：跟樹的大小無關，只要出現 0 或負數就錯。

常見錯誤

  • 驗證時只比較直接的子節點：深處的節點可能違反祖先的限制。往下傳上下界 (low, high)，或檢查中序走訪嚴格遞增。
  • 用 Number.MIN_VALUE 或 0 當最小值：Number.MIN_VALUE 是正數（約 5e-324）。初始範圍用 -Infinity、Infinity。
  • 沒問重複值怎麼處理：不允許、放左邊或放右邊，結果都不一樣。先問清楚，再決定比較用 < 還是 <=。
  • 以為 BST 一定是 O(log n)：插入順序決定形狀，排好序的資料會讓它歪成一條線。要保證效能，用自動平衡的樹或資料庫索引。
  • 遞迴插入沒接回回傳值：只寫 insert(root.left, val)，新節點建出來卻沒有人指著它。要寫 root.left = insert(root.left, val)，空樹時回傳新節點。
  • 在 BST 裡找值卻走訪整棵樹：DFS 每個節點都看是 O(n)，浪費了 BST 的順序。比較之後只往一邊走，O(h)。
  • 找第 k 小用前序走訪，或收集後用預設的 sort()：只有中序是由小到大；預設排序是字串順序（第 8 課），10 會排在 9 前面。
  • k 差一：「第 1 小」是最小的那個。先 count++ 再比 count === k。

小結

  • BST 把「排好序」從陣列的位置改成樹的形狀來記：每個節點的整個左子樹都比它小、整個右子樹都比它大。所以上架不用搬動既有資料。
  • 查價：小往左、大往右，走到 null 就是不存在；用迴圈寫，O(h) 時間、O(1) 空間。
  • 上架：照查價的路走到空位放上新節點；遞迴寫法回傳子樹的新根，呼叫的人要接回 left／right。中序走訪的結果由小到大。
  • 效能看高度：平衡時 h ≈ log n，歪斜時 h = n。普通 BST 不會自己平衡，排好序進來的資料是最壞情況；正式環境用 AVL、紅黑樹或 B-tree。JavaScript 沒有內建的平衡樹。
  • 檢查一棵樹是不是 BST：上下界從 (-Infinity, Infinity) 開始往下傳，往左收緊上界、往右收緊下界；或檢查中序嚴格遞增。重複值的規則要先問。
  • 第 k 便宜：用堆疊的迴圈中序走訪，取出第 k 個就停，O(h + k)。
  • 混合題先看特徵：最近的、可抵消 → 堆疊；逐層、最少步數 → 佇列／BFS；子樹的答案 → DFS；有大小順序的樹 → BST；串列的指標操作 → 鏈結串列。

階段檢核：面試會問的觀念

這個階段一定要講得出來的 8 件事。先在心裡回答，再選。

練習 11：二元樹每個節點的值是一個時段的杯數變化（可能是負數），要找出「以某個節點為根的子樹，所有值加總」最大是多少。該怎麼走？

✓ 要先知道左右子樹的總和才能算出自己的，這就是後序：回傳 val + l + r 給上一層，同時用閉包更新 best，一次走訪 O(n)。a 錯在同一層的節點分屬不同子樹，一個子樹又跨好幾層，層的總和不是子樹的總和。b 進入節點時子節點還沒算，累加出來的是根到這裡的路徑總和。（第 16、17 課）

練習 12：分類樹裡有一條很深的鏈，也有很淺的分支。要找出離根最近、標記為「停售」的分類（一樣近時回傳哪一個都可以），該用哪個做法？

✓ BFS 一層走完才走下一層，第一次碰到時更淺的層已經全部看過，所以它就是最近的，可以馬上停。b 錯在前序只保證自己在子節點之前，不保證在別的分支的淺層節點之前：DFS 先鑽進那條深鏈，找到的停售分類可能在第 50 層，另一邊第 2 層就有。c 一樣錯，答案取決於走訪順序，跟樹深不深無關。（第 17 課）

練習 13：同事說這段已經加了記憶化。它的時間和空間複雜度是？

function ways(n: number): number {
  const memo = new Map<number, number>()
  if (n < 2) return n
  const saved = memo.get(n)
  if (saved !== undefined) return saved
  const result = ways(n - 1) + ways(n - 2)
  memo.set(n, result)
  return result
}

✓ Map 宣告在函式裡面，每次呼叫都是新的空 Map，存進去的結果沒有別的呼叫查得到，等於沒有記憶化，還是照定義的指數時間。空間看遞迴最深幾層，是 O(n)。把 Map 移到函式外面讓所有呼叫共用，才會變成 a。（第 15 課）

練習 14：用這段算樹的直徑（最長路徑的邊數），n 個節點、高度 h。最壞情況的時間和額外空間是？

function maxDepth(node: TreeNode | null): number {
  return node === null ? 0 : 1 + Math.max(maxDepth(node.left), maxDepth(node.right))
}
function diameter(node: TreeNode | null): number {
  if (node === null) return 0
  const through = maxDepth(node.left) + maxDepth(node.right)
  return Math.max(through, diameter(node.left), diameter(node.right))
}

✓ 每個節點都呼叫 maxDepth 把整個子樹重走一遍，總共 O(n × h)；一條長鏈底下掛一大棵樹時是 O(n²)。空間看同時疊在堆疊上的最深層數，diameter 加上 maxDepth 最多兩倍高度，還是 O(h)。修法是在算高度的同一次後序走訪裡順便更新 best，O(n)。c 只在平衡的樹成立，最壞情況不是。（第 16 課）

練習 15：普通 BST 依 1、2、3、…、n 的順序插入，再用這段遞迴找 n。時間和額外空間是？

function find(node: TreeNode | null, x: number): TreeNode | null {
  if (node === null || node.val === x) return node
  return x < node.val ? find(node.left, x) : find(node.right, x)
}

✓ 遞增插入時每個新節點都接在右邊，樹歪成高度 n 的一條線，搜尋是 O(h) = O(n)。這是遞迴寫法，每往下一層就多一個堆疊框，空間也是 O(n)。改成迴圈可以把空間降到 O(1)，時間要靠平衡的樹才回到 O(log n)。c 漏算了遞迴的呼叫堆疊。（第 15、18 課）

練習 16：這段要回傳根到最近的葉節點經過幾個節點。哪一種輸入會算錯？

function minDepth(node: TreeNode | null): number {
  if (node === null) return 0
  return 1 + Math.min(minDepth(node.left), minDepth(node.right))
}

✓ 根的左邊是 null，回傳 0，min 取到 0，答案變成 1；但根有子節點、不是葉，正確答案是 2。只有一邊子樹時要只看有的那一邊；或用 BFS，遇到第一個左右都是 null 的節點就回傳。d 沒問題：兩邊都有子樹時取 min 是對的。（第 17 課）

練習 17：題目規定不允許重複值，這段用中序走訪驗證 BST。哪一種輸入會判錯？

function isValid(root: TreeNode | null): boolean {
  let prev = -Infinity
  const walk = (node: TreeNode | null): boolean => {
    if (node === null) return true
    if (!walk(node.left) || node.val < prev) return false
    prev = node.val
    return walk(node.right)
  }
  return walk(root)
}

✓ d 的中序是 70、90、90、120，90 < 90 是 false，所以被當成合法；不允許重複時要嚴格遞增，判斷寫 node.val <= prev。重複值怎麼算要先問清楚，它決定比較用哪個符號。b 會被抓到：中序 70、90、80 出現下降，中序法不用另外傳上下界。a 沒問題，prev 從 -Infinity 開始。（第 18 課）

練習 18：你用遞迴 DFS 寫完「算出巢狀留言的總則數」，面試官補充：回覆是使用者自己一層層回出來的，可能深到 10 萬層。下一步怎麼回應？

✓ 遞迴每深一層佔一個堆疊框，深度由使用者決定時可能丟 RangeError。改用迴圈加自己的陣列當堆疊，陣列放在一般記憶體，不受呼叫堆疊的上限限制；也可以補一句「寫入時就限制回覆層數」。b 錯在 V8 沒有實作尾呼叫最佳化，尾遞迴照樣溢位。c 減少的是重複計算，不是深度；d 回傳的數字是錯的。（第 15、16 課）
