階段 4：線性結構 · 第 14 課

快慢指標

第 13 課用鏈結串列存門市的排隊名單：每位客人是一個節點，next 指向排在他後面的人，head 是隊伍最前面那位。第 13 課的 val 放的是訂單金額或取餐時間，這一課改放他的取餐號碼。這一課店長要在這條名單上加三個功能：

  • 辦活動：排在正中間的那位，送一杯美式咖啡。
  • 防當機：插隊功能曾經寫錯，名單繞成一圈，叫號程式走不完、整台卡住。以後每次叫號前，先檢查名單有沒有繞成圈。
  • 取消排隊：客人說「我是倒數第 2 個，不等了」，要把他從名單拿掉。

這三件事在陣列上都只要一行：中間是 arr[Math.floor(n / 2)]，倒數第 2 個是 arr[n - 2]。串列沒有索引，也不知道自己有多長，直覺的做法是先走一遍數出長度，再走一遍去找。第二個功能更麻煩：名單繞成圈時根本沒有盡頭，while (cur !== null) 會一直跑下去，連「先數長度」那一遍都數不完。這一課用兩個指標同時走同一條名單，讓它們用不同的速度、或保持固定的距離，只走一遍、只多用兩個變數（O(1) 額外空間）就做完這三件事；最後再找出名單是從哪一位開始繞圈，好把它修好。

這課的路線：
  1. 第一題，誰站在中間：先看「數完人數再走一半」的暴力解，再用一個走 1 步、一個走 2 步的快慢指標只走一遍（開場問題的最小答案）。
  2. 第二題，名單有沒有繞成圈：環是什麼、為什麼會卡住整台伺服器；先用 Set 記住走過的人來偵測，代價是 O(n) 空間。
  3. 只用兩個變數判斷環：快的為什麼一定會從後面追上慢的、不會剛好跳過，以及實務上怎麼在寫入時就擋下環。
  4. 第三題，倒數第 k 位要離開：讓一個指標先走 k 步，兩個指標像一把固定長度的尺一起往後推，再靠 dummy 處理刪掉第一位的情況。
  5. 進階，環從哪一位開始、寫完怎麼檢查：把前面兩種走法合起來找出環的起點，再用一張邊界表確認迴圈條件，並決定什麼時候寧可用 Set。
這課會用到：
  • 第 13 課的鏈結串列：節點有 val 和 next，用另一個變數從 head 一路 cur = cur.next 走訪；dummy 是放在 head 前面的假節點，讓第一個節點也有前一個。
  • 第 2 課的空間複雜度：程式額外用的記憶體怎麼隨 n 成長；只用幾個變數是 O(1)，把每個節點都存起來是 O(n)。

第一題：不知道有幾個人，怎麼找到站在中間的那位？

串列題差一個位置就是錯的答案，所以先把「中間」的規則講好：

  • 5 個人時，中間是第 3 個（從 0 數是索引 2）。
  • 6 個人時有兩個中間（索引 2 和 3），本課約定回傳第二個，也就是索引 3。一般公式：索引 Math.floor(n / 2)。
  • 沒有人排隊（head 是 null）回傳 null。
  • 要回傳節點，不是值：拿到節點，呼叫的人才能從這裡繼續往後走，或把串列從中間切開。

在串列上「找人」要靠指標。第 7 課的雙指標是兩個存索引的變數；串列沒有索引，這裡的指標就是一個指向某個節點的變數。let slow = head 讓 slow 指著第一位，slow = slow.next 讓它往後移一位。指標只是變數，移動它不會改到名單；只有指定某個節點的 .next 才會改名單，這是第 13 課講過的區別。

本課的範例都用第 13 課的節點型別，加兩個小工具：listFrom 從陣列建出串列，listToArray 把串列轉回陣列方便印出來。練習的起始程式也已經貼好，不用自己寫。下面這格建出 5 位客人的名單，執行後看兩行：名單轉回陣列的樣子，以及從 head 往後讀兩位得到的號碼。

暴力解：先數人數，再走一半

串列不知道自己多長，最直接的做法就是先走一遍數出 n，再從頭走 Math.floor(n / 2) 步。執行後看每一行印出的人數、走的步數和找到的號碼：

程式裡的 cur!.next 多了一個 !，這是 TypeScript 的非空斷言。cur 的型別是 ListNode | null，TypeScript 不准你直接讀可能是 null 的東西的 .next。我們知道走不到一半就碰到 null 是不可能的，但 TypeScript 推不出這件事，! 就是告訴它「這裡不是 null」。它只影響型別檢查，執行時不會幫你檢查，所以只能用在你確定的地方；猜錯了，執行時照樣丟錯。

這個解法是對的：O(n) 時間、O(1) 空間，總共走了大約 1.5n 步（數人數 n 步、再走一半 n / 2 步）。它的弱點不在速度，而在它依賴「先數得完」：要走兩遍，而且第一遍必須走到 null 才知道 n。面試官通常會接著問：「只走一遍做得到嗎？」

快慢指標：fast 到底時，slow 剛好在中間

想像兩個人同時從隊伍開頭往後走，一個每次走 2 步、一個每次走 1 步。不管走了幾輪，快的走過的距離永遠是慢的兩倍；所以快的走到隊伍末端時，慢的剛好走了一半的路，正好站在中間。這兩個變數叫 fast 和 slow，這種「從同一個地方出發、一個走 1 步、一個走 2 步」的走法叫快慢指標（fast & slow pointers）。寫成程式：

let slow = head
let fast = head
while (fast !== null && fast.next !== null) {
  slow = slow!.next        // 走 1 步
  fast = fast.next.next    // 走 2 步
}
return slow

迴圈條件是這題最容易寫錯的地方，所以先把 5 個人和 6 個人的情況逐步印出來。執行後看每一輪 slow、fast 在誰身上，以及最後一列 fast 停下來的原因：

奇數個時，fast 停在最後一個節點（fast.next 是 null）；偶數個時，fast 跳過最後一個、變成 null。兩種都要停，所以迴圈條件有兩個：

  • fast !== null：偶數個時 fast 會變成 null，這時再讀 fast.next 會丟 TypeError: Cannot read properties of null。
  • fast.next !== null：fast 要走 2 步，第 1 步 fast.next 必須存在，才能讀 fast.next.next。

兩個條件的順序也不能反。&& 左邊是 false 時右邊不會執行，所以 fast !== null 寫在前面，fast 是 null 時就不會去讀 fast.next。TypeScript 的嚴格模式會幫你抓這個錯：只寫 while (fast.next !== null) 會出現「fast 可能是 null」的型別錯誤。這時不要用剛才的 ! 寫成 fast!.next 把它壓下去：這裡 fast 真的會是 null，壓掉只是把編譯錯誤換成執行時的 TypeError。（偶數個時想取第一個中間，條件要改寫，見課末「補充與查表」。）

最後算一下走了幾步。fast 走完整條，大約 n 步；slow 走 n / 2 步，總共還是大約 1.5n 次 .next，跟暴力解差不多。所以快慢指標在這一題省的不是時間，而是不用先知道長度，一個迴圈就寫完。這個差別在第二個功能上就變得關鍵：名單繞成圈時，「先數長度」那一遍永遠數不完，暴力解直接失效，快慢指標卻照樣能用。

第二題：名單繞成一圈時，怎麼發現？

名單為什麼會繞成圈？第 13 課示範過插隊的兩行程式：先 node.next = cur.next，再 cur.next = node。順序寫反，新節點的 next 會指向自己。更一般的情況是某個節點的 next 指回排在它前面的人，名單從那裡開始一直繞。這種「沿著 next 一直走，會回到已經走過的節點」的結構叫環（cycle）。下圖是本課接下來一直用的例子：九位客人，為了圖好讀，號碼寫成 1 到 9，第 9 位的 next 指回第 4 位。

有環的名單沒有最後一位，任何「走到 null 為止」的迴圈都停不下來。這在後端比在前端嚴重：Node 用一個執行緒處理所有請求，一個停不下來的同步迴圈會卡住整個伺服器，CPU 被吃滿，其他人的請求也都沒有回應。下面的範例加了 15 步的上限，不然會一直跑下去（練習裡碰到這種情況，引擎跑滿 3 秒會判錯）。執行後看兩件事：走 15 步印出的號碼從哪裡開始重複，以及 JSON.stringify 丟出的錯誤名稱：

號碼走到 9 之後又回到 4，之後就是 4 到 9 一直重複。JSON.stringify 碰到繞回自己的物件會丟 TypeError，你在前端可能看過這個錯誤訊息裡的「circular structure」，說的就是環。所以叫號前的檢查要回答的問題是：沿著 next 走，會不會回到走過的節點？

直覺的做法：用 Set 記住走過的人

這個問題最直接的回答是把走過的人都記下來。沿路把每個節點放進 Set（第 4 課），碰到已經在 Set 裡的節點，就表示繞回來了。執行後比較兩行：同一條名單在 9 指回 4 之前和之後的結果：

Set 裡放的是節點物件，比對的是參考（TypeScript 課第 2 課：物件變數存的是位置，兩個變數指向同一個物件才相等），不是 val。兩位不同的客人可能剛好有一樣的值，值一樣不代表是同一個節點。

這個做法 O(n) 時間，但要記住每個走過的節點，額外空間 O(n)：名單有幾個人，Set 就長到多大。面試官的追問通常是：「只用 O(1) 的額外空間做得到嗎？」

只用兩個變數：快的為什麼一定追得上慢的？

做得到，而且用的就是第一題的快慢指標。第一題裡，fast 會走到 null 停下來；在有環的名單上它走不到 null，只會在圈裡一直繞。這個差別正好拿來判斷。想像操場上的跑道，兩個人一起出發，一個跑得快、一個跑得慢：

  • 如果跑道是一條直線（沒有環），快的先跑到終點（fast 碰到 null），兩人不會再碰面。
  • 如果跑道是一圈（有環），快的會繞回來，從後面追上慢的。兩人在同一個節點，就證明有環。

程式就是第一題的迴圈，多一行檢查。注意這行檢查放在兩個指標都走完之後：一開始兩個都在 head，本來就相等，先比的話每條名單都會被判成有環。

let slow = head
let fast = head
while (fast !== null && fast.next !== null) {
  slow = slow!.next
  fast = fast.next.next
  if (slow === fast) return true   // 先走，再比；一開始兩個都在 head
}
return false

常見的疑問：快的一次跳 2 步，會不會剛好跳過慢的，永遠追不上？不會。兩個都進到環裡之後，看「fast 還要往前走幾步才追到 slow」這個距離：每一輪 slow 往前 1 步（距離 +1），fast 往前 2 步（距離 −2），合起來每一輪剛好縮小 1。距離是整數，每次少 1，一定會經過 0，不可能從 1 直接變成 −1。用圖裡的名單印出來看，執行後看「距離」那一欄怎麼變：

第 3 輪 slow 進到環裡時，距離是 3，之後 2、1、0，第 6 輪相遇。距離一定小於環的長度，所以 slow 進環之後不到一圈就會被追上：O(n) 時間。整個過程只用了兩個變數：O(1) 額外空間。叫號前的檢查就這樣做完了，名單再長也不會多用記憶體。

這個方法叫 Floyd 判圈法（Floyd's cycle detection），也常被叫做「龜兔賽跑」。它的用途不只串列，見課末「補充與查表」。

比較要用 slow === fast（同一個節點），不能用 slow.val === fast.val。沒有環的串列 5 → 5 → 5，第一輪 slow 和 fast 就是兩個值都是 5 的不同節點，比值會誤判成有環。
💡 實務上：環多半是資料寫錯，最好在寫入時就擋下來
叫號名單的環來自我們自己寫錯的程式；後端更常見的環來自使用者能編輯的資料。推薦人、分類的上層分類、員工的主管、留言回覆的上一則，都是「沿著一個欄位往上走」的資料，跟串列一樣每筆只有一個「下一個」，後台一開放編輯就可能被設成繞圈：王小明的推薦人是陳美華、陳美華的推薦人又是王小明。等到讀的時候才發現，通常已經是某個頁面卡住或報表算不出來。比較好的做法是儲存前檢查：把王小明的推薦人改成陳美華之前，先從陳美華沿著推薦人往上走，走得回王小明就拒絕這次修改，回傳看得懂的錯誤訊息。資深工程師會先問：這個欄位有哪些入口能改（後台、匯入、API），每個入口都有檢查嗎？讀取端的步數上限是最後一道防線，碰到時要記 log 讓人來修資料，不要默默截斷當作沒事。

第三題：倒數第 k 位要離開，怎麼只走一遍找到他？

叫號前的檢查有了：發現有環就先停下來不叫號，怎麼找出是哪一位寫錯留到進階一節。先回到第三個功能：客人說「我是倒數第 2 個，不等了」，要把倒數第 2 個節點從名單拿掉。暴力解跟第一題一樣走兩遍：先數出 n，倒數第 k 個就是正數第 n − k 個（從 0 數），再走過去刪除。要只走一遍，還是用兩個指標，但這次兩個指標的關係不一樣：前兩題是速度不同，這一題要的是速度相同、距離固定。

還有一件事要先想清楚：刪除要停在哪裡。第 13 課講過，刪掉一個節點改的是它前一個節點的 next（cur.next = cur.next.next）。所以要找的不是倒數第 k 位本人，而是排在他前面的那一位。

間距指標：讓 fast 先走 k 步

想像拿一把長度固定的尺貼著名單往後推：尺的前端碰到最後一位時，尺的後端剛好落在倒數某個位置。用兩個指標當尺的兩端，讓 fast 先走 k 步、之後兩個每次都走 1 步，距離就一直保持 k。這種走法叫間距指標（gap pointers）：

  1. 建一個 dummy 節點接在 head 前面（第 13 課），slow 和 fast 都從 dummy 出發。
  2. fast 先走 k 步，兩個指標的距離變成 k。
  3. 兩個一起每次走 1 步，直到 fast 停在最後一個節點（fast.next === null）。
  4. 這時 slow 在倒數第 k + 1 個，也就是要刪除的節點的前一個，正好是剛才說要停的位置：slow.next = slow.next.next。
  5. 回傳 dummy.next。

為什麼 slow 剛好停在前一個？最後一個節點是倒數第 1 個，slow 落後它 k 步，就是倒數第 k + 1 個。用 6 位客人、k = 2 跑一次，再跑一次 k 等於人數（要刪的是第一位）的情況。為了輸出好讀，號碼寫成 1 到 6，dummy 的值設成 0、印成 dummy。執行後看每一列 slow 停在誰身上，以及最後刪掉的號碼：

第二個例子 k 等於長度，要刪的是第一個節點，slow 停在 dummy 上，dummy.next = dummy.next.next 就把第一個拿掉了，不用另外寫 if。這就是 dummy 的用處：「要刪的節點一定有前一個」。如果不用 dummy、兩個都從 head 出發，k 等於長度時 fast 會走出串列變成 null，下一行讀 fast.next 就丟錯。也因為第一個節點可能被刪，最後要回傳 dummy.next，不是原本的 head。

程式裡的 slow.next! 是第一題講過的非空斷言，這裡用得安全：slow 永遠落後 fast，fast 還有節點時 slow.next 一定存在，只是 TypeScript 推不出這個關係。

先走 k 步還是 k − 1 步、迴圈停在 fast === null 還是 fast.next === null，差一步就刪錯節點。不要背，拿 3 個節點、k = 1 和 k = 3 手算一次：k = 1 要刪最後一個，slow 應該停在倒數第 2 個；k = 3 要刪第一個，slow 應該停在 dummy。
💡 實務上：取消要用訂單編號，不要用「倒數第幾位」
真正的排隊名單是資料庫裡還沒取餐的訂單，要看最近幾筆是 ORDER BY ordered_at DESC LIMIT 5（依下單時間由新到舊取 5 筆），不會自己走串列。「倒數第 2 位」這種位置也很危險：客人開口的這幾秒又進來一筆新訂單，倒數第 2 位就換人了，結果取消到別人的單。所以畫面列出等待中的訂單讓店員點選，送到後端的是那筆訂單的 id。這一題在工作上真正留下來的是習慣：差一步就出錯的位置邏輯，把 k = 1、k = 長度這種邊界寫成單元測試，比在腦中推理可靠。

進階：名單是從哪一位開始繞圈的？

回到第二題。叫號前的檢查發現名單有環之後，要把名單修好，光知道「有環」不夠，還要知道環從哪一位開始。環的起點是「被指回去的那位」，也就是第二題圖裡的 4。找到起點後，從它沿著圈往後走，next 指回起點的那位（圖裡的 9）就是寫錯的節點，把它的 next 改回正確的人或 null，環就斷了。

用 Set 找起點很直接：走訪時第一個「已經看過」的節點就是起點，代價一樣是 O(n) 空間。只用 O(1) 空間的做法，要把前面兩種走法合起來：先用快慢指標找到相遇點，再像第三題那樣讓兩個指標用相同的速度一起走。

  1. 照第二題的做法，讓 slow 和 fast 跑到相遇。
  2. 拿一個新的指標 p 從 head 出發；slow 留在相遇點。
  3. p 和 slow 都改成一次走 1 步，兩個碰到的節點就是環的起點。

為什麼碰到的地方剛好是起點？用第二題的例子算：直線部分有 a = 3 個節點，環有 c = 6 個節點，相遇時 slow 走了 s = 6 步、fast 走了 2s = 12 步。

  • fast 比 slow 多走的 s 步，全部是在環裡繞圈，所以 s 是環長 c 的倍數（這個例子 s = 6 = c）。
  • 相遇點就是「從 head 走 s 步」的位置。
  • p 從 head 走 a 步，剛好到環的起點。slow 從相遇點走 a 步，等於從 head 走了 s + a 步，也就是先到環的起點（a 步），再繞 s 步。s 是整圈數，繞完回到原地，所以也在環的起點。
  • 前 a − 1 步 p 還在直線部分、slow 在環裡，不可能碰到，所以第一次碰到的地方就是起點。

寫完怎麼確認沒寫錯？什麼時候寧可用 Set？

快慢指標的程式很短，錯誤都出在邊界：名單是空的、只有一位、自己指自己。範例名單抓不到這些情況，寫完拿下面這幾種串列各手算一次：

情況要確認的事
空串列（head 是 null）迴圈一次都不跑；中間回傳 null、沒有環、沒有起點
一個節點、沒有環fast.next 是 null，馬上停；中間就是它自己
一個節點、自己指自己fast.next 是它自己，走 1 輪就相遇；起點是它自己
兩個節點中間是第二個；刪倒數第 2 個時要刪的是第一個（靠 dummy）
環從第一個節點開始（尾巴接回 head）a = 0：第二階段 p 和 slow 一開始就相等，直接回傳 head
值重複比較節點用 ===，不要比 val

這一課的四個做法都是 O(n) 時間、O(1) 額外空間。那 Set 版是不是就沒用了？跟 Set 版並排比較：

Set 記錄走過的節點快慢指標
時間O(n)O(n)
額外空間O(n)O(1)
好讀程度一看就懂要知道為什麼會相遇
能做到的事還能知道走過哪些節點、第一個重複的是誰只知道有沒有環、起點在哪

實際工作上怎麼選：面試題通常明說要 O(1) 空間，就用快慢指標。在一般的後端程式裡，資料量不大、又需要把繞圈的那幾筆印進錯誤訊息時，Set 的程式比較好讀、也比較好除錯，O(n) 的記憶體通常不是問題。不管用哪一種，沿著「下一個」一路走的資料（推薦鏈、分類的上層分類、資料表裡的 parent_id）只要可能被寫錯，就要有防繞圈的檢查或步數上限，不能假設資料一定是乾淨的。

補充與查表

兩種走法對照

本課的兩個指標有兩種走法，查表用，不用背：

走法怎麼走本課用來
快慢指標（fast & slow pointers）從同一個地方出發，slow 每次走 1 步、fast 每次走 2 步找中間節點、判斷有沒有環、找環的起點
間距指標（gap pointers）fast 先走 k 步，之後兩個每次都走 1 步，距離一直保持 k找倒數第 k 個節點

偶數個時取第一個中間

想要偶數時回傳第一個中間（例如要把串列切成前後兩半，前半多一個），把條件改成 while (fast.next !== null && fast.next.next !== null)，並先處理空串列。兩種約定都很常見，寫之前先跟面試官確認是哪一個。

Floyd 判圈法不只用在串列

只要「下一步完全由目前的值決定」，例如反覆做某個計算的數列，都能用同一招判斷會不會繞圈：把「走一步」換成「算一次」，slow 算一次、fast 算兩次，相等就表示繞回來了。

練習

練習 1、2、4 傳進去的節點都被凍結（Object.freeze），不能修改，也不能在節點上加 visited 這類記號。練習 2、4 要求 O(1) 額外空間：測試期間 Set、Map、WeakSet、WeakMap、JSON.stringify 都不能用，而且有 10 萬個節點的計時測試。有環時迴圈停不下來的寫法，會跑滿 3 秒被判錯。練習 2、6 把情境換成 💡 實務上提過的會員推薦鏈：每位會員只記一個推薦人，跟排隊名單一樣是串列，資料寫錯就會繞成圈。

練習 1：寫 middleCustomer(head)：回傳排隊串列的中間節點（節點本身，不是值）；偶數個時回傳第二個中間節點；空串列回傳 null。請用快慢指標走一遍（課文要求，判分只看結果）。對應 LeetCode 876. Middle of the Linked List。

練習 2：寫 hasLoop(head)：判斷推薦鏈（串列）有沒有環，O(1) 額外空間。測試期間 Set、Map、WeakSet、WeakMap、JSON.stringify 不能用（它們都要記住走過的節點）；節點被凍結，不能加記號；有一條 10 萬個節點的計時測試。起始程式附了 cycleFrom(vals, pos)：建出串列，再讓最後一個節點指回索引 pos 的節點（pos 是 -1 表示沒有環）。對應 LeetCode 141. Linked List Cycle。

練習 3：寫 removeKthFromEnd(head, k)：刪除倒數第 k 個節點（1 ≤ k ≤ 長度），回傳新的 head。要原地修改：保留下來的節點必須是原本的物件，不能建新的串列。請用 dummy 加間距指標走一遍（課文要求，判分只看結果）。對應 LeetCode 19. Remove Nth Node From End of List。

練習 4（進階）：寫 loopStart(head)：有環時回傳環的第一個節點（節點本身），沒有環回傳 null；O(1) 額外空間，限制跟練習 2 一樣。對應 LeetCode 142. Linked List Cycle II。

練習 5：判斷環的時候，fast 一次走 2 步、slow 一次走 1 步。有人擔心 fast 會剛好跳過 slow，在環裡一直繞卻永遠碰不到。實際上會怎樣？

✓ 每一輪 slow 往前 1 步讓距離 +1，fast 往前 2 步讓距離 −2，合起來 −1。距離是整數、每次只少 1，從 1 只能變成 0，不會變成 −1。a 錯：多加這個檢查只是提早一步發現，不加也一定會相遇。c 錯：跟環長是奇數或偶數無關；改成走 3 步時距離每輪少 2，反而可能從 1 跳到 −1 而錯過；例如環長 2、距離 1 時，距離永遠是 1，兩個永遠碰不到。

練習 6：同事用 Set 記錄走過的節點來判斷推薦鏈有沒有環，code review 時另一位同事說「Set 的 has 是 O(1)，所以這個做法沒有任何代價」。哪個說法正確？

✓ n 個節點各查一次、各加一次，時間 O(n)；但 Set 會長到 n 個元素，額外空間 O(n)。這不代表 Set 版不能用：資料不大、需要知道繞圈的是哪幾筆時，它比較好讀也比較好除錯。a 錯：空間不一樣，面試題要求 O(1) 空間時就不符合。b 錯：Set 的查詢平均是 O(1)，n 次合起來是 O(n)；O(n²) 是用陣列 includes 記錄的寫法。

練習 7：判斷有沒有環時，把 if (slow === fast) 改成 if (slow.val === fast.val) 會怎樣？

✓ 「同一個節點時值相同」是對的，但反過來不成立：不同節點也可以有相同的值。5 → 5 → 5 第一輪 slow 是第二個節點、fast 是第三個，值都是 5，就誤判了。=== 比較物件時比的是參考，只有真的是同一個節點才相等（TypeScript 課第 2 課）。b 錯：它只考慮了一個方向。c 錯：有環時真的相遇那一刻值也相同，問題是在相遇之前就可能誤判。

常見錯誤

  • 迴圈條件只檢查 fast.next：fast 本身是 null 時讀 fast.next 就丟 TypeError。寫成 fast !== null && fast.next !== null，順序不能反；也不要用 ! 把 TypeScript 的提醒壓掉。
  • 比較值而不是節點：不同節點可以有相同的值。判斷「是不是同一個節點」一律用 === 比參考。
  • 一開始就比 slow === fast：兩個都從 head 出發，一開始本來就相等，會把每條串列都判成有環。先走，再比。
  • 沒用 dummy：刪倒數第 k 個時，要刪的可能是第一個節點，它沒有前一個節點；用 dummy 統一處理，最後回傳 dummy.next。
  • 間距差一步：fast 先走 k 步、停在 fast.next === null，slow 才會停在要刪的前一個。拿 k = 1 和 k = 長度手算確認。
  • 把相遇點當成環的起點：相遇點只證明有環；還要一個從 head、一個從相遇點，都一次走 1 步，碰到的才是起點。
  • 有環的串列用一般的走訪：while (cur !== null) 永遠不會停，JSON.stringify 也會丟錯。可能被寫錯的「下一個」資料，要有防繞圈的檢查或步數上限。

小結

  • 串列沒有索引、不知道長度，「先數再找」要走兩遍，遇到環還數不完；兩個指標同時走，一遍就能回答位置問題。
  • 快慢指標：slow 走 1 步、fast 走 2 步。fast 到底時 slow 在中間（偶數個時是第二個中間）。
  • 迴圈條件 while (fast !== null && fast.next !== null)：先確認 fast，再確認 fast.next，才能走 2 步。
  • 判斷環：有環時 fast 每一輪追近 1 步，一定會在同一個節點相遇；先走再比，O(n) 時間、O(1) 空間。Set 版也是 O(n) 時間，但要 O(n) 空間。
  • 間距指標：從 dummy 出發，fast 先走 k 步，一起走到 fast.next === null，slow 就在倒數第 k 個的前一個。
  • 環的起點：相遇後一個回 head，兩個都走 1 步，碰到的地方就是起點；找到起點才知道要改哪個節點的 next。
  • 比較節點用 ===；沿著「下一個」走的真實資料，在寫入時擋下環，讀取端留步數上限當最後防線。

階段檢核：面試會問的觀念

這個階段一定要講得出來的 7 件事。先在心裡回答，再選。

練習 8：names 有 n 個人，這段程式依序叫號。時間與額外空間複雜度是？

function callAll(names) {
  const queue = [...names]
  const called = []
  while (queue.length > 0) {
    called.push(queue.shift())
  }
  return called
}

✓ shift 拿走開頭之後，剩下的元素要逐一往前搬一格，單次 O(n)，叫完 n 人是 O(n²)；陣列是原地修改，空間只有 O(n)。改用 head 索引，每次出隊 O(1)。a 錯在把 shift 當成跟 pop 一樣，pop 拿尾端才不用搬。（第 12 課）

練習 9：這個括號檢查在哪一個輸入會回傳錯的答案？

const pairs: Record<string, string> = { ')': '(', ']': '[', '}': '{' }
function isBalanced(s: string): boolean {
  const stack: string[] = []
  for (const ch of s) {
    if (ch === '(' || ch === '[' || ch === '{') stack.push(ch)
    else if (ch in pairs && stack.pop() !== pairs[ch]) return false
  }
  return true
}

✓ (( 兩個都 push 進去，沒有右括號來比對，最後直接回傳 true。讀完還有左括號就是沒被關上，最後要回傳 stack.length === 0。a 會正確回傳 false：空堆疊 pop 得到 undefined，跟 '(' 不相等。（第 12 課）

練習 10：兩個堆疊做的佇列，同事把 dequeue 寫成這樣。哪一組操作會拿錯人？

dequeue() {
  while (this.inbox.length > 0) this.outbox.push(this.inbox.pop())
  return this.outbox.pop()
}

✓ 第一次 dequeue 後 outbox 還剩 2，接著 3 被倒到 2 的上面，第二次 dequeue 拿到 3，應該是 2。只有 outbox 空了才倒：if (this.outbox.length === 0) 再搬。a 錯在它是「全部放進去再全部拿出來」，這種測法抓不到這個錯，要測進出交錯的順序。（第 12 課）

練習 11：面試做 LRU，不准依賴 Map 的順序。你提出「Map 存 id → 節點，加上雙向鏈結串列」，面試官問：為什麼不用單向的？

✓ 拿掉一個節點要改它前一個的 next，雙向串列每個節點都有 prev，O(1) 就拿到；單向要從頭找，get、put 就不是 O(1) 了。c 錯在找節點靠的是 Map，id → 節點本來就是 O(1)，跟單向雙向無關。（第 13 課）

練習 12：這個遞迴版的反轉串列，n 個節點時的時間與額外空間複雜度是？

function reverse(head) {
  if (head === null || head.next === null) return head
  const newHead = reverse(head.next)
  head.next.next = head
  head.next = null
  return newHead
}

✓ 每個節點只處理一次，O(n) 時間；但遞迴每深一層就在呼叫堆疊上多一層，n 個節點就是 O(n) 空間，串列太長會超出呼叫堆疊。改用迴圈（prev、cur、先存 next）是 O(1) 空間。a 錯在漏算了呼叫堆疊：沒有 new 節點，不代表沒用額外記憶體。（第 13 課）

練習 13：刪除倒數第 k 個節點（1 ≤ k ≤ 長度），沒有用 dummy。哪一個輸入會出錯？

function removeKthFromEnd(head, k) {
  let fast = head
  let slow = head
  for (let i = 0; i < k; i++) fast = fast.next
  while (fast.next !== null) { fast = fast.next; slow = slow.next }
  slow.next = slow.next.next
  return head
}

✓ k 等於長度時 fast 先走 k 步就走出串列變成 null，讀 fast.next 丟 TypeError；而且第一個節點沒有前一個，slow 也沒地方停。從 dummy 出發，slow 會停在 dummy，最後回傳 dummy.next。a 錯在 k = 1 時 slow 剛好停在倒數第 2 個，刪得正確。（第 13、14 課）

練習 14：面試時你用快慢指標寫完 hasCycle，題目給的兩個範例（有環、沒環）手算都對，面試官說「還有一點時間」。下一步最該做什麼？

✓ 快慢指標的程式很短，錯誤都出在邊界：fast 是 null 時讀 fast.next 會丟錯，一開始就比 slow === fast 會把每條都判成有環，範例抓不到這些。c 錯在快慢指標有環時一定相遇、沒環時 fast 一定走到底，不會停不下來；加上限反而會把很長的正常串列判錯。（第 1、14 課）
