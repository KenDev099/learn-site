階段 7：最佳化 · 第 23 課

一維動態規劃：狀態、轉移、初始值

店長在排下週的促銷：每天促銷都有一個預估營收，但連續兩天都促銷，常客會疲乏、反而不來，所以規定不能連續兩天。哪幾天促銷，總營收最高？

難的地方在每個選擇都會牽動旁邊：選了週三，週二和週四就不能選。第 22 課的貪婪「先挑營收最高的那天」會選錯；第 21 課的回溯可以把每一種排法都列出來比，但 30 天就有 2,178,309 種排法，排一整年跑不完。這課從這題出發，教動態規劃：把「列出全部排法」換成「每個小問題只算一次」，讓同一題從指數時間降到 O(n)。學完你能照固定的四個問題設計一題動態規劃、寫成 O(n) 的迴圈，也能判斷一題該不該用它。

這課的路線：
  1. 直覺的排法為什麼會錯、試遍所有排法為什麼太慢：用「最後一天做不做」寫出遞迴，發現同一個小問題被重算上萬次，存起來只算一次，就是動態規劃（開場問題的最小答案）。
  2. 四個問題怎麼答才不會錯：換一題能用手全部列出來的補牛奶，逐格檢查狀態、轉移、初始值、答案。
  3. 回到促銷、再改問最少：把遞迴改成由下往上的迴圈、壓縮成兩個變數；題目改成最低花費時，哪幾個答案要跟著改。
  4. 沒人說是 DP 時怎麼認出來：題目的訊號、從暴力解一路改到迴圈的四步，以及狀態有兩種常見說法。
  5. 混合複習：第 19～23 課的 heap、BFS、回溯、貪婪、DP，題目沒說時怎麼挑。
這課會用到：
  • 第 15 課的 Fibonacci 三個版本：照定義遞迴（重複算、指數時間）、用 Map 記憶化（每個 n 只算一次）、由下往上的迴圈（只留兩個變數）。
  • 第 21 課的回溯：每一步分成「選」和「不選」兩條路，把所有方案都走一遍。
  • 第 22 課的反例：一條「每步選最好」的規則，只要找到一組輸入讓它算錯，它就不能用。

直覺的排法為什麼會錯？

先把題目寫成程式看得懂的樣子：revenue[i] 是第 i 天（從 0 開始數）促銷的預估營收，相鄰兩天不能都促銷，求最大總營收。在找正確做法之前，先試兩個大多數人第一個會想到的規則，看它們錯在哪裡；知道錯在哪，才知道正確的做法必須多考慮什麼。

第一個直覺是「隔一天選一天」：比較「選第 0、2、4…天」和「選第 1、3、5…天」哪個總和大。用 [2, 1, 1, 2] 試：偶數天 2 + 1 = 3，奇數天 1 + 2 = 3，看起來答案是 3。但選第 0 天和第 3 天，2 + 2 = 4，這兩天也不相鄰。問題出在規則只說「不能相鄰」，沒說「一定要隔剛好一天」；中間空兩天以上也合法，只分奇偶就把這些排法漏掉了。

第二個直覺是第 22 課的貪婪：「每次挑營收最高的那天，把它兩邊的鄰居劃掉，再從剩下的挑最高的」。用 [2, 3, 2] 試：先挑 3，兩邊的 2 都被劃掉，總共 3；但選頭尾 2 + 2 = 4。挑 3 的那一刻看起來最好，代價是同時擋掉了兩天，而那兩天加起來比它多。這正是第 22 課說的危險訊號：這一步的選擇會影響後面能選什麼。這種題目只看眼前，就有反例。

兩個直覺錯的方式其實一樣：它們都在還沒看完全部的情況下，就替某幾天決定了「做」或「不做」。要保證找到最大值，每一天都得把「做」和「不做」兩種可能都留著，比過才算數。最直接能做到這件事的，是把所有排法都試一遍。但這要試多少次？

試遍所有排法為什麼慢？怎麼讓它快起來？

先把「試遍所有排法」寫成一個遞迴。關鍵是找一個問法，讓大問題可以用同一個問題的小版本回答。定義 best(i) = 只看前 i 天（第 0～i − 1 天）最多能賺多少。整週 7 天的答案就是 best(7)；best(5) 是同一個問題，只是天數短一點。

接著只看前 i 天的最後一天（第 i − 1 天），它只有兩種可能：

  • 不做：這天的營收拿不到，前面 i − 1 天怎麼排都可以，最多賺 best(i − 1)。
  • 做：拿到 revenue[i − 1]，但前一天（第 i − 2 天）就不能做，更前面的 i − 2 天怎麼排都可以，最多賺 best(i − 2) + revenue[i − 1]。

任何一種合法排法，最後一天不是做就是不做，所以這兩種情況涵蓋了全部排法；取兩者中大的，就是前 i 天的最大值。遞迴總要有停下來的地方：0 天什麼都賺不到，best(0) = 0；只有 1 天就做，best(1) = revenue[0]。這個遞迴每一層都把「做」和「不做」兩條路都走過，跟第 21 課的回溯一樣保證答案對。

它的問題在速度。best(i) 會呼叫 best(i − 1) 和 best(i − 2)；而 best(i − 1) 自己又會呼叫 best(i − 2)。同一個問題「前 i − 2 天最多賺多少」被問了兩次，往下每一層，重複被問的次數越滾越多（之後會看到大約每層乘 1.6），越小的問題被問越多次：24 天時，best(3) 會被呼叫 17,711 次。可是 best(3) 的答案永遠一樣，因為 revenue 沒有變；後面那 17,710 次全是白做。

修法就是第 15 課 Fibonacci 用過的記憶化：第一次算出 best(i) 就存進 Map，之後再被問到同一個 i，直接回傳存好的值。這樣每個 i 只真正算一次，總共只有 n + 1 個不同的 i，每個 i 做一次 max，所以是 O(n)。下面用 24 天的資料把兩個版本都跑一次，執行後比較兩行的呼叫次數；註解裡的「第 1 步、第 2 步」，後面〈怎麼把促銷題寫成不用遞迴的迴圈？〉會接著做第 3、4 步。

兩個版本的答案都是 76，暴力版呼叫了 150,049 次，記憶化只要 47 次。天數每多一天，暴力版的呼叫次數大約乘上 1.6 倍；記憶化只多 2 次。

剛剛做的事情有一個名字。先講兩個詞：

  • 子問題：同一個問題的小版本。best(5) 是 best(7) 的子問題，問的都是「前幾天最多賺多少」，只是天數比較少。
  • 子問題重疊：從大問題往下拆的時候，不同的路會問到同一個子問題，例如 best(7) 經過 best(6) 和直接呼叫，兩條路都會問到 best(5)。英文叫 overlapping subproblems。

把問題拆成子問題，而且子問題會重疊，所以每個子問題只算一次、把結果存起來重複使用，這個做法叫動態規劃（dynamic programming，常簡寫成 DP）。名字裡的「動態」「規劃」跟程式的意思沒什麼關係，不用從字面猜。重點在「重疊」：如果每個子問題本來就只會被問一次，存起來也不會省到任何時間，那就只是普通的遞迴。第 15 課的 Fibonacci 走的是同一條路：照定義遞迴很慢，加上 Map 每個 n 只算一次，最後改成從小往上的迴圈。

設計一題 DP，就是依序回答四個問題。拿剛剛的促銷題對照：

問題意思促銷題的答案
狀態（state）dp[i] 代表什麼，要能用一句話說清楚dp[i] = 只看前 i 天，最多能賺多少
轉移（transition）dp[i] 怎麼用比較小的格子算出來dp[i] = max(dp[i − 1], dp[i − 2] + revenue[i − 1])
初始值（base case）不用轉移、直接知道答案的格子dp[0] = 0、dp[1] = revenue[0]
答案題目要的是哪一格dp[n]，n 是天數

表裡的 dp[i] 就是 best(i)，只是換成「一格一格的表」的寫法，因為後面會真的把它存成陣列。四個問題要依序回答，前一個決定後一個：狀態沒說清楚，轉移就只能猜；轉移往回看兩格，初始值就要給兩格；狀態說的是「前 i 天」，答案就在「前 n 天」那一格。

開場的問題到這裡已經有答案：記憶化遞迴就是一個 O(n) 的正確解。但還剩兩件事沒解決。第一，遞迴的深度等於天數，best(n) 一路疊到 best(1)，天數一多就會像第 15 課那樣丟 RangeError。第二，四個答案這次是邊推邊湊出來的；換一題，初始值和答案在哪一格最容易寫錯，而促銷題很難用手把每種排法列出來核對。下一節先換一題能全部列出來的題目，練習把四個問題答對。

💡 實務上：記憶化就是你每天在用的快取
工作上很少有人寫出 dp 陣列，但「算過的結果存起來，輸入沒變就直接拿來用」到處都是：前端的 useMemo、Vue 的 computed，後端把熱門報表的查詢結果放進快取，都是同一個想法。差別在演算法題的輸入不會變，真實系統的資料會變：店長改了某天的預估營收、或品項改價之後，快取裡的舊結果就得作廢。所以加快取前先問兩件事：key 有沒有包含所有會影響結果的輸入（跟 DP 的狀態要說清楚是同一件事），以及資料變了由誰清掉舊值。重算本來就很便宜時不要加快取，多一份要維護的狀態反而容易出錯。

四個問題怎麼答才不會錯？先用一題能全部列出來的題目練

促銷題的答案是取最大值，想核對每一格，就得把每一種排法列出來加總比較，手算很快就不可行。換一題只要「數有幾種」的題目：每一格的答案都能直接把方案列出來數，程式算錯哪一格，一對就看得出來。它也正好會碰到初始值最常見的錯誤。

吧台的冰箱要補 n 箱牛奶，店員每趟搬 1 箱或 2 箱。剛好補到 n 箱，搬的順序有幾種？先手算小的：

1+2 和 2+1 算兩種，因為順序不同。接著依序回答四個問題：

  • 狀態：dp[i] = 剛好補到 i 箱的順序有幾種。
  • 轉移：看最後一趟。最後一趟搬 1 箱，前面要剛好補到 i − 1 箱，有 dp[i − 1] 種；最後一趟搬 2 箱，前面要剛好到 i − 2 箱，有 dp[i − 2] 種。兩種情況不重疊（最後一趟不同），也涵蓋了所有可能，所以 dp[i] = dp[i − 1] + dp[i − 2]。
  • 初始值：轉移往回看兩格，要給 dp[0] 和 dp[1]。dp[1] = 1。dp[0] 是「剛好補到 0 箱」：什麼都不搬，這是 1 種做法，不是 0 種。驗算：dp[2] = dp[1] + dp[0] = 1 + 1 = 2，跟手算的 1+1、2 一樣；如果 dp[0] = 0，dp[2] 會變成 1，後面每一格都跟著少算。
  • 答案：dp[n]。

轉移用的問法，跟促銷題「最後一天做不做」是同一招：依最後一步把所有方案分類。這招成立要兩個條件：每個方案只落在一類（不重疊，才不會重複算），所有方案都落在某一類（涵蓋全部，才不會漏）。滿足了，每一類的數量剛好是一個比較小的狀態，轉移就寫得出來。找不到轉移時，先問「最後一步有哪幾種可能」。

怎麼把促銷題寫成不用遞迴的迴圈？

記憶化遞迴會疊到 n 層，是因為它由上往下：從 best(n) 開始問，答案還不知道就往更小的問題問下去，每問一層就在呼叫堆疊上多佔一格，問到 best(1) 才開始一路回傳。但轉移有一個性質可以利用：dp[i] 只需要比它小的格子。那就反過來，從 dp[0]、dp[1] 開始，由小往大一格一格填，填到 dp[i] 時，它需要的 dp[i − 1]、dp[i − 2] 一定已經填好了。這種寫法叫由下往上（bottom-up），也常叫填表；它只是一個 for 迴圈，沒有遞迴，自然沒有堆疊深度的問題。

四個問題的答案沿用〈試遍所有排法為什麼慢？〉那張表，再逐項寫一次；最容易寫錯的是狀態用「前 i 天」，以及下面 dp 和 revenue 索引差一格：

  • 狀態：dp[i] = 只看前 i 天（第 0～i − 1 天），最多能賺多少。用「前 i 天」而不是「到第 i 天」，好處是 dp[0] 可以代表「0 天」，不用特別處理空陣列。
  • 轉移：看前 i 天的最後一天（第 i − 1 天）做不做促銷。不做：前 i − 1 天怎麼排都行，dp[i − 1]。做：第 i − 2 天就不能做，前 i − 2 天任意，再加上這天的營收，dp[i − 2] + revenue[i − 1]。取大的：dp[i] = max(dp[i − 1], dp[i − 2] + revenue[i − 1])。
  • 初始值：dp[0] = 0（沒有天數）；dp[1] = revenue[0]（只有一天就做）。
  • 答案：dp[n]，n 是天數。

注意 dp 的索引和 revenue 的索引差一格：dp[i] 的「最後一天」是 revenue[i − 1]。這是一維 DP 最容易寫錯的地方，寫之前先把狀態那一句寫在註解裡。用 [4, 1, 2, 9, 1] 手算：

到這裡，促銷題已經從指數時間的暴力解，一路改成 O(n) 時間、O(1) 空間的迴圈。補牛奶問「有幾種」、促銷問「最多」，如果題目改問「最少」，四個問題的答案哪裡要跟著改？

題目改問最少時，四個問題哪裡要跟著改？

換一題求最小值的題目，專門看「狀態那一句話怎麼決定初始值和答案的位置」。前兩題的答案都在 dp[n]，初始值也直接從「0 天、0 箱」推得出來；這一題的初始值和答案位置都要靠狀態那句話才推得出來，正好拿來驗證四個問題的順序。

倉庫的貨架有 n 層，cost[i] 是踩上第 i 層要付的費用（整理那層要花的時間）。可以從第 0 層或第 1 層開始，每次往上 1 層或 2 層，目標是走到頂端（超過最後一層）。最低總花費是多少？

例如 [12, 5, 20]：從第 1 層開始（付 5），一次跨 2 層就超過最後一層，總共 5。

  • 狀態：dp[i] = 站上第 i 層之前（還沒付 cost[i]）最少花了多少。頂端是第 n 層，沒有費用。
  • 轉移：最後一步從第 i − 1 層走上來（付了 cost[i − 1]），或從第 i − 2 層跨上來（付了 cost[i − 2]）。取小的：dp[i] = min(dp[i − 1] + cost[i − 1], dp[i − 2] + cost[i − 2])。
  • 初始值：可以從第 0 層或第 1 層開始，所以 dp[0] = 0、dp[1] = 0。
  • 答案：dp[n]，頂端。不是 dp[n − 1]，那只是站上最後一層之前，還沒付最後一層的錢、也還沒到頂。

兩個跟直覺不同的地方都來自狀態那一句「之前、還沒付」：因為還沒付，第 1 層當起點時 dp[1] 是 0，不是 cost[0]；也因為頂端不是任何一層，答案在多出來的 dp[n]。執行後看每一格的兩個候選值，最後一行應該是 5：

三題放在一起看，轉移的形狀幾乎一樣，都是「依最後一步分成兩類」，差在兩類的結果怎麼合起來：

題目問什麼合起來的方式為什麼
補牛奶有幾種相加兩類互不重疊，總數是兩類的數量加起來
不能連續兩天促銷最多max兩類裡挑比較好的那一種
最低花費的樓梯最少min同上，只是比的是誰小

初始值和答案在哪一格，則由狀態那一句話決定。這三題都事先告訴你「這是 DP」；面試和工作上的題目不會說，下一節講怎麼自己認出來。

沒人告訴你這是 DP 時，怎麼認出來？

回頭看促銷題是怎麼走到 DP 的：直覺規則有反例，試遍所有排法又太慢，慢的原因是同一個子問題被重算。把這段經過倒過來，就是認出 DP 的訊號：

  • 題目問最多、最少、有幾種方法，或「能不能做到」，而不是要你列出每一種方案。
  • 每一步的選擇會影響後面能選什麼（今天促銷，明天就不行），所以不能每一步只看眼前。
  • 寫出遞迴之後，同一組參數會被呼叫很多次。

不確定時，照促銷題走過的四步，每一步都是可以交出去的程式：

  1. 遞迴暴力解：寫一個函式 best(i)，意思就是狀態那一句話；函式本體就是轉移；終止條件就是初始值。先用小例子確認答案對。
  2. 記憶化：用 Map 或陣列存 best(i) 的結果。時間變成「狀態數 × 每個狀態的轉移成本」，這裡是 n × O(1) = O(n)。
  3. 由下往上：轉移只看比較小的 i，所以從小的 i 往上填表，不用遞迴，也不會有堆疊太深的 RangeError。
  4. 空間壓縮：轉移只看前幾格時，只留那幾格。

第 1、2 步是〈試遍所有排法為什麼慢？〉的 best 和 bestMemo，第 3、4 步是〈怎麼把促銷題寫成不用遞迴的迴圈？〉的 promoTable 和 bestPromo。面試時照這個順序講，先給出能動的暴力解，再說明「這裡同一個 i 被重複算，所以加記憶化」，比直接背出最後的四行更有說服力。

狀態怎麼選

四步裡最難的是第 1 步：best(i) 到底代表什麼。這課的三題都用「前 i 個」或「到第 i 個為止」，但遇到要求連續的題目，這種說法就不夠用。一維 DP 的狀態常見兩種說法，選哪一種看題目的限制：

狀態的說法適合答案在哪
「只看前 i 個」能得到的最佳值挑出一些元素、不要求連在一起（不連續促銷）dp[n]
「以第 i 個結尾」的最佳值要求一段連續的元素：能不能接上去只看前一個不一定是最後一格，要取所有格子裡最好的

看一個「以第 i 個結尾」的例子：sales[i] 是第 i 天的杯數，求「杯數一天比一天多」的最長連續天數。如果狀態用「前 i 天裡最長的上升段」，轉移時不知道最長那段是不是剛好接到昨天，今天接不接得上就判斷不了。所以改成 dp[i] = 以第 i 天結尾、一路上升的連續天數。轉移只看前一天：今天比昨天多，就接在昨天那段後面，dp[i] = dp[i − 1] + 1；不然這段斷了，從今天重新開始，dp[i] = 1。初始值 dp[0] = 1。最長的那段可能在中間就結束，所以答案是所有 dp[i] 裡最大的，不是最後一格。執行後看每一天的 dp，答案應該是 4：

判斷狀態夠不夠的方法：只知道 dp 前面幾格的值，能不能決定這一格？如果還需要知道「前一天有沒有促銷」這類額外資訊，就把它放進狀態（例如分成「今天做」和「今天不做」兩個陣列），或改用像「前 i 天」這樣已經把它包進去的定義。

💡 實務上：把 DP 放進正式程式前先確認的事
產品裡的 DP 多半藏在排班、促銷排程這類「挑一組最好的」建議功能裡，就像這課店長要的排程工具。上線前先看輸入大小受不受控制：記憶化遞迴的深度等於 n，資料一多就可能丟 RangeError: Maximum call stack size exceeded（第 15 課），正式程式用由下往上的迴圈。再問 PM 畫面要顯示什麼：通常是「哪幾天促銷」而不只是總營收，那就要保留表格或記下每格從哪裡來，才能倒推出方案。規則也常會加，例如店長追加「每週最多促銷 3 天」，狀態就得多記「這週已經用了幾天」；先跟 PM 把規則清單確認完再設計狀態，比寫完再改省事。n 很小時（例如只排一週），回溯列出全部方案更好讀也更好改，不一定要用 DP。

認得出 DP 之後，還有一個更實際的問題：第 19～23 課學了五種技巧，題目不會說用哪一種。

題目沒說用哪個工具時，怎麼挑？

第 19～23 課的技巧，面試題不會告訴你用哪一個。先看題目問什麼，再對照下表：

題目的樣子先想到
網格或圖上，每一步代價相同，問最少幾步、或從好幾個起點同時往外擴散要幾輪BFS（第 17、20 課），佇列用索引指標
要列出所有方案，n 很小回溯（第 21 課）
只要數量或最佳值，而且子問題會重疊動態規劃（這課、第 24 課）
每一步選眼前最好的，而且說得出為什麼不會錯（找不到反例）貪婪（第 22 課）
過程中一直要拿目前最小／最大的，或只要前 k 名heap（第 19 課）

表的第一列有一個第 20 課沒練過的變化：「好幾個起點同時往外擴散」叫多起點 BFS（multi-source BFS）。做法是開始前把所有起點都放進佇列，當成第 0 層，之後照第 20 課一層一層往外走，每走完一層就是過了一輪。只從其中一個起點出發會算錯：兩端同時往中間擴散，只從一端走會算出比較多輪。

同一題可能有兩種都對的做法；先用小例子手算，確認做法對，再看複雜度夠不夠。下面練習 4～6 的題目只描述情境，判斷用哪一個也是練習的一部分。

練習

練習 1～3 是這課的經典題；練習 4～6 是混合複習，範圍是第 19～23 課，也可能用到前面的技巧。沒有記憶化的遞迴會被 3 秒逾時判錯。

練習 1：經典題。寫 restockWays(n)：每趟搬 1 箱或 2 箱，剛好補到 n 箱有幾種順序（0 ≤ n ≤ 70）；n = 0 回傳 1。由下往上，O(n) 時間、O(1) 空間（用兩個變數；判分只看結果）。測試會從 n = 0 一路算到 70。對應 LeetCode 70. Climbing Stairs。

練習 2：經典題。寫 bestPromotion(revenue)：revenue[i] 是第 i 天促銷的預估營收（非負整數），相鄰兩天不能都促銷，回傳最大總營收；空陣列回傳 0。不能修改 revenue。用由下往上的迴圈：30,000 層的遞迴會超出呼叫堆疊。測試會和暴力解比對 500 組隨機資料，最後用 30,000 天計時：對每一天都往前掃一遍的 O(n²) 寫法不會通過。對應 LeetCode 198. House Robber。

練習 3：經典題。寫 cheapestClimb(cost)：cost[i] 是踩上第 i 層要付的費用，可以從第 0 或第 1 層開始，每次往上 1 層或 2 層，回傳走到頂端（超過最後一層）的最低總花費。cost 至少有 2 個元素，不能修改。對應 LeetCode 746. Min Cost Climbing Stairs。

練習 4（混合複習）：寫 bestStreak(changes)：changes[i] 是第 i 天營收和目標的差額（可能是負數），回傳「總和最大的一段連續天數」的總和，至少要選一天。changes 至少有 1 個元素，不能修改。測試會用 30,000 天計時。（對應 LeetCode 53. Maximum Subarray）

練習 5（混合複習）：冷藏櫃故障了。寫 minutesUntilAllSpoiled(fridge)：網格裡 2 是已經壞掉的牛奶、1 是好的、0 是空格。每過一分鐘，壞牛奶會讓上下左右相鄰的好牛奶也壞掉。回傳全部壞掉需要幾分鐘；有永遠不會壞的回傳 -1；一開始就沒有好牛奶回傳 0。不能修改 fridge；測試期間不能用 shift()。（對應 LeetCode 994. Rotting Oranges）

練習 6（混合複習）：寫 setMenus(n, k)：從編號 1～n 的品項選 k 個組成套餐，回傳所有不同的選法；每組裡的編號由小到大，組與組之間的順序不限。0 ≤ k ≤ n ≤ 12；k = 0 時只有一種選法：什麼都不選。（對應 LeetCode 77. Combinations）

練習 7：補牛奶那題，同事把初始值寫成 dp[0] = 0，理由是「補 0 箱不用搬，所以是 0 種」。會怎樣？

✓ b。dp[0] 的意思是「剛好補到 0 箱有幾種順序」：什麼都不搬，這是 1 種。它會被轉移用到：dp[2] = dp[1] + dp[0]，代表「最後搬 2 箱、前面什麼都沒搬」的那一種，設成 0 就漏掉了 2 這個順序，錯誤一路傳到後面每一格，所以 a、c 都不對。設初始值時，用最小的例子手算對照（n = 2 有 1+1、2 兩種）。

練習 8：不能連續兩天促銷，同事說：「隔一天選一天就好，把奇數天的總和和偶數天的總和比一比，取大的。」哪個說法正確？

✓ c。中間隔兩天也合法，奇偶分法漏掉了這種排法。選比較多天不代表比較多錢（a）：低營收的天占掉了旁邊高營收那天的位置。排序（b）會打亂哪幾天相鄰，題目就變了。像這種「直覺的規則」，先用小例子找反例；找得到就改用 DP，讓每一天都考慮「做」和「不做」兩種情況。

練習 9：動態規劃一定要開一個 dp 陣列嗎？

✓ a。DP 的核心是「每個子問題只算一次，算出來的結果拿去算更大的」，表格只是存結果的一種方式。轉移只看 dp[i − 1] 和 dp[i − 2] 時，更早的格子不會再讀，所以兩個變數就夠（b 錯）。時間一樣是 O(n)，每一步做的事情一樣多（c 錯）。保留陣列的理由是除錯時要印整張表，或之後要從表倒推出「是哪幾天」。

常見錯誤

  • 狀態說不清楚：直接寫轉移，寫到一半不知道 dp[i] 的 i 是「第 i 天」還是「前 i 天」，索引就差一格。先在註解寫一句「dp[i] = …」，再寫轉移。
  • 初始值錯：例如補牛奶的 dp[0] 寫成 0、最低花費只讓第 0 層當起點。用最小的例子（n = 0、1、2）手算，對照程式印出的前幾格。
  • 答案拿錯格：回傳 dp[n − 1] 還是 dp[n]，要看狀態的定義：「前 i 天」的答案在 dp[n]；「以第 i 個結尾」的答案要取所有格子的最大值。迴圈少跑一圈也會落到錯的那一格。
  • 用貪婪代替 DP：「隔天選」「先挑最大的」這類規則聽起來對，但每一步的選擇會影響後面時，常常有反例。先找反例，找到了就改用 DP。
  • 遞迴沒有記憶化：每一層分成兩個呼叫，指數時間，n = 45 就跑不完。看到同樣的參數被呼叫很多次，就加 Map，或改成由下往上。
  • 壓縮時更新順序錯：先寫 prev1 = cur 再寫 prev2 = prev1，prev2 拿到的是新值。先算出 cur，再依序 prev2 = prev1、prev1 = cur。

小結

  • 促銷這類「每一步的選擇會影響後面」的題目，直覺規則和貪婪常有反例；試遍所有排法是對的，但指數時間。
  • 慢的原因是子問題重疊：同一個 best(i) 被問上萬次。每個子問題只算一次並存起來，就是動態規劃，時間變成「狀態數 × 每個狀態的轉移成本」。
  • 設計時依序回答：狀態（dp[i] 是什麼，一句話）、轉移（問「最後一步有哪幾種可能」，分類要不重疊、涵蓋全部）、初始值（轉移往回看幾格就給幾格）、答案在哪一格。
  • 問「有幾種」用加法，問「最多」用 max，問「最少」用 min；「什麼都不做」也是一種方法，所以方法數的 dp[0] 常是 1。
  • 寫法的順序：遞迴暴力解 → 記憶化 → 由下往上 → 只用到前幾格時壓縮成幾個變數。由下往上沒有堆疊深度的問題；保留陣列才能倒推出方案。
  • 狀態有兩種常見說法：「前 i 個」的答案在 dp[n]；要求連續時用「以第 i 個結尾」，答案取所有格子的最大值。
  • 選工具：最少步數用 BFS、列出所有方案用回溯、只要數量或最佳值且子問題重疊用 DP、能說出理由的「每步選最好」用貪婪、一直要拿最小／最大用 heap。

補充與查表

方法數太大時

補牛奶的方法數長得跟 Fibonacci 一樣快：n = 70 是 308,061,521,170,129，還在 Number.MAX_SAFE_INTEGER 之內；n = 78 就超過了，數字不再精確（第 15 課的 Fibonacci 第 79 項）。所以題目常要求「回傳答案除以 1,000,000,007 的餘數」，每次相加後就取餘數；工作上要精確的大數就用 BigInt。

階段檢核：面試會問的觀念

這個階段一定要講得出來的 6 件事。先在心裡回答，再選。

練習 10：給每天的股價，可以多次買賣，但賣出的隔天不能買。求最大利潤，該用哪個做法？

✓ 冷卻期讓今天的選擇改變明天能做什麼，局部最佳接不成全域最佳，要用動態規劃，把「手上有沒有、是不是剛賣」放進狀態。a 的理由靠的是「賣了當天就能再買」，有冷卻就拆不了：[1, 2, 3, 0, 2] 正差加總是 4，實際最多 3。c 遇到 [1, 3, 5] 會在 3 就賣，只賺 2，正確是 4。（第 22、23 課）

練習 11：你用貪婪解了一題，題目給的三組範例都過了。面試官問：「你怎麼確定這是對的？」下一步最該做什麼？

✓ 範例都過不能證明貪婪對：找零面額 1、3、4 在 1～5 元都對，6 元才出錯。面試要講出理由，例如跳點題「能到的格子永遠是連續的一段」；講不出來，就用試過所有可能的暴力解跑很多組隨機小輸入比對。a 錯在自己想的例子常常跟範例一樣剛好對，少量手算找不到反例。（第 22 課）

練習 12：不能連續兩天促銷，這段記憶化遞迴的時間和空間複雜度是多少？

const memo = new Map()
function best(i) {
  if (i === 0) return 0
  if (i === 1) return revenue[0]
  if (memo.has(i)) return memo.get(i)
  const v = Math.max(best(i - 1), best(i - 2) + revenue[i - 1])
  memo.set(i, v)
  return v
}
best(revenue.length)

✓ 時間是「狀態數 × 每個狀態的轉移成本」：n 個狀態、每個只算一次、轉移 O(1)，所以 O(n)。空間有 Map 的 n 格，加上 best(n) 一路呼叫到 best(1) 的 n 層堆疊。b 錯在 O(1) 是改成由下往上、再壓縮成兩個變數之後才有的，記憶化遞迴兩樣都還在。（第 23 課）

練習 13：跳點題（hops[i] 是第 i 格最多能往前跳幾格），同事這樣寫。哪一組輸入會回傳錯的答案？

function canReach(hops) {
  let farthest = 0
  for (let i = 0; i < hops.length; i++) {
    farthest = Math.max(farthest, i + hops[i])
  }
  return farthest >= hops.length - 1
}

✓ [1, 0, 2] 卡在第 1 格，第 2 格到不了，迴圈卻拿它的 2 把 farthest 推到 4，回傳 true。修法是更新前先檢查 i > farthest，成立就回傳 false。a 是最多人懷疑的：只有一格時已經站在終點，回傳 true 本來就對。（第 22 課）

練習 14：求「杯數一天比一天多」的最長連續天數，同事這樣寫。哪一組輸入會算錯？

function longestRise(sales) {
  if (sales.length === 0) return 0
  let endHere = 1   // 以第 i 天結尾的上升天數
  for (let i = 1; i < sales.length; i++) {
    endHere = sales[i] > sales[i - 1] ? endHere + 1 : 1
  }
  return endHere
}

✓ 狀態是「以第 i 天結尾」，最長的那段可能在中間就斷了，答案要取所有格子裡最大的，不是最後一格。[10, 20, 30, 15] 最後一天重新開始，回傳 1，正確是 3。修法是多記一個 best，每一格都更新。c 錯在杯數一樣不算上升，答案本來就是 1。（第 23 課）

練習 15：你用記憶化遞迴解出不能連續兩天促銷，面試官接著說：「天數可能到十萬。」下一步該怎麼改？

✓ 記憶化遞迴的深度等於 n，天數一多會丟 RangeError: Maximum call stack size exceeded。由下往上從小的 i 開始填表，不用遞迴，時間一樣是 O(n)，壓縮後空間 O(1)。a 錯在換成陣列只是查表的方式不同，遞迴還是疊到 n 層。（第 15、23 課）
