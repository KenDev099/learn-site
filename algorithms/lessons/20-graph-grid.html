階段 6：進階結構與搜尋 · 第 20 課

圖與網格：visited、DFS、BFS

咖啡店的五家分店（本店、車站店、公園店、大學店、機場店）準備一起上線外送。上線前，營運部丟來三個問題，要後端寫程式回答。第一，分店之間有幾條道路，某家店缺貨時，本店的貨車開得到哪幾家分店去調貨？第二，外送員拿到一張街區地圖，牆和建築擋住某些格子，從店門口走到客人家最少要幾步，才能估外送時間？第三，地圖上可以外送的街區分成幾塊互不相連的區域，每一塊要各排一組外送員？

三個問題的資料長得不一樣：第一題是一份「哪兩家店之間有路」的清單，後兩題是一張格子地圖。但它們問的是同一件事：從某個點出發，沿著「相連」的關係往外走，走得到哪裡、最少要走幾步。描述「一群東西，加上它們之間的連線」的結構叫圖。第 16、17 課走樹用的 DFS、BFS，再加上一份記錄「哪些已經走過」的 visited，就能回答全部三題。這課從分店道路開始，一路做到外送地圖的最少步數。

這課的路線：
  1. 道路清單怎麼查「誰跟誰相連」：圖的基本名詞，以及先把清單轉成相鄰串列。
  2. 道路繞成一圈時怎麼不走不完：visited；走完一遍，也就回答了「本店的貨車開得到哪些分店」（開場第一題）。
  3. 外送地圖沒有道路清單，格子的鄰居怎麼算：網格也是圖，鄰居、邊界檢查，以及格子的 visited 怎麼存。
  4. 把相連的一整塊走完：先用座位區重新上色練 DFS，看大網格為什麼不能用遞迴；再數外送區有幾塊（開場第三題）。
  5. 從店門口到客人家最少幾步：BFS 為什麼保證最短、什麼時候標記、DFS 為什麼不行（開場第二題）；最後整理拿到新題目時怎麼選工具。
這課會用到：
  • 第 16 課的 DFS：先一路往下走到底再回頭；資料很深時改用自己的陣列當堆疊，不用遞迴。
  • 第 17 課的 BFS：用佇列一層一層往外走，取出前端用 head 索引，不用 shift。

道路清單怎麼查「誰跟誰相連」？

先把第一題的資料看清楚。營運部給的是一份道路清單 [[0, 1], [1, 2], [2, 0], [1, 3]]，分店用 0 到 4 編號：0 本店、1 車站店、2 公園店、3 大學店、4 機場店。每一筆是一條路的兩端，[0, 1] 代表本店和車站店之間有一條路。畫出來是這樣：

這種「一群點，加上連接其中某些點的線」就叫圖（graph）。點叫頂點（vertex，很多題目也叫 node），在這裡是分店；線叫邊（edge），在這裡是道路。和某個頂點之間直接有一條邊的頂點，叫它的鄰居（neighbor）：車站店的鄰居是本店、公園店和大學店。

分店之間的道路是雙向的，本店到得了車站店，車站店就到得了本店。邊沒有方向的圖叫無向圖（undirected graph）。如果邊有方向，例如單行道，或「先備料才能煮咖啡」這種只能由前往後的先後關係，就叫有向圖（directed graph），第 26 課的拓撲排序會用到。這課的圖都是無向圖。

圖上還有一個樹沒有的現象：從本店到車站店、再到公園店、再回到本店，沿著邊走、不走回頭路，就繞回了出發點。這叫環（cycle）。第 16、17 課的樹其實是一種特別的圖：有一個根、沒有環、每個節點只有一個父節點，所以一路往下走，永遠不會回到走過的地方。一般的圖沒有這些保證：可能有環；可能分成好幾塊互不相連，像機場店就沒有任何路；也沒有根，從哪裡出發由題目決定。環帶來的麻煩留到下一節，這一節先解決更基本的問題：怎麼查「某家店的鄰居有誰」。

直接拿道路清單來查很慢。想知道車站店的鄰居，要把整份清單從頭掃到尾，挑出含有 1 的那幾筆，花的時間跟道路條數成正比，記作 O(E)，E 是邊數。走訪時每走到一家店都要問一次「你的鄰居有誰」，V 家店就問 V 次（V 是頂點數），加起來是 O(V × E)。5 家店看不出差別；一萬家店、一萬條路時，就是上億次比對。

解法是先花一次工夫，把清單整理成每家店各自的鄰居名單，叫相鄰串列（adjacency list）。整理完，adj[1] 直接就是車站店的鄰居陣列，讀一次就拿到，不用再掃清單。下面把道路清單轉成相鄰串列，執行後看每家店的鄰居，再看最後一行 fill([]) 的結果：

這段程式有兩個地方容易寫錯。第一個是迴圈裡要加兩次。道路是雙向的，[0, 1] 代表 0 的鄰居有 1、1 的鄰居也有 0；只寫 adj[a].push(b)，從 1 出發就找不到 0，等於把雙向道路當成單行道。

第二個是建立空陣列的方式。new Array(n).fill([]) 看起來是放 n 個空陣列，其實 [] 只在呼叫 fill 之前建立了一次，n 個位置放的都是同一個陣列的參考。TypeScript 課第 2 課講過，陣列是物件，變數和陣列的格子裡存的是參考；所以往 wrong[0] 加東西，每個位置都跟著變，印出來就是最後一行那樣。Array.from({ length: n }, () => []) 會對每個位置各呼叫一次箭頭函式，每次都得到一個新陣列，彼此獨立。

建相鄰串列要走過每條邊一次、每條邊存兩份，時間和空間都是 O(V + E)。這筆成本只付一次，之後走訪時查鄰居直接讀 adj[v]。頂點是 0 到 n − 1 的整數時，用這裡的「陣列的陣列」；頂點是字串，例如用分店名稱或 id 當名字時，改用 Map<string, string[]>，鍵是頂點、值是鄰居陣列。存圖還有另一種方式叫相鄰矩陣，這門課的題目用不到，比較見課末。

有了相鄰串列，從本店出發一家一家往外找，看起來就能回答「貨車開得到哪些分店」。但 0、1、2 繞成一圈，照第 16 課走樹的方式直接走，會出事。

💡 實務上：圖通常存在資料庫裡，拿出來才建相鄰串列
工作中很少有人直接給你一張「圖」，它多半藏在資料表裡：分店之間的配送路線表、會員的「推薦人」欄位、商品的「搭配推薦」、分類的 parent_id。API 撈回來的就是這課的邊的清單，要在記憶體裡走訪，第一步一樣是建相鄰串列（頂點是 id 字串時用 Map）。要注意一次撈多少：幾百家分店全部拿出來沒問題，幾百萬個會員的社群關係就不該整份載入，改用資料庫查詢只撈需要的那一部分。真的要算路線、路況、距離的需求，例如外送預估時間，資深工程師會先問有沒有現成的地圖服務可以用，而不是自己寫。

道路繞成一圈：怎麼不走不完，又知道貨車開得到哪些分店？

先看照走樹的寫法直接走圖會怎樣。第 16 課最後一節用自己的陣列當堆疊做 DFS：把起點放進堆疊，然後重複「拿出一個頂點、把它的鄰居都放進去」，直到堆疊空了。樹沒有環，每個節點只會被它的父節點放進去一次，所以一定會停。

圖就不一樣了。從本店出發：拿出 0，放進 1、2；拿出 2，放進它的鄰居 1、0；拿出 0，又放進 1、2……本店的鄰居有公園店，公園店的鄰居又有本店，兩家店互相把對方放回堆疊，永遠拿不完。下面的 walkWithoutVisited 設了最多走 15 步的上限才停得下來。執行後先看第一行：同一批數字反覆出現，堆疊裡還剩一堆；再看後面三行加了 visited 的結果：

解法是記錄「哪些頂點已經處理過」，這份紀錄就是 visited。reachable 裡的 visited[w] 是 true，代表 w 已經被放進過堆疊：它不是已經處理完，就是已經排進待辦清單，不需要再排一次。關鍵在檢查的位置：在把鄰居放進堆疊之前檢查，標記過就跳過，沒標記過才標記並放入。起點是第一個放進去的，所以在進迴圈前就先標記。

這樣每個頂點最多被放進堆疊一次、拿出來一次，拿出來時把它的鄰居清單看一遍。每條邊在兩端的鄰居清單裡各出現一次，所以全部加起來最多看 2E 次。總時間是 O(V + E)；visited 和堆疊各最多 V 筆，額外空間是 O(V)。

開場第一題也在這裡回答了：從某家店出發走完一遍，被標記的頂點就是它走得到的全部分店。從 0 出發得到 0、1、2、3，本店的貨車開得到車站店、公園店、大學店；從 4 出發只有 4 自己，機場店沒有任何路接到其他店。要問「A 走不走得到 B」，就從 A 走一遍，看 B 有沒有被標記，練習 1 就是這一題。

最後一行是遞迴版：進入 dfs 時標記自己，再對每個還沒標記的鄰居呼叫自己。它的走訪順序跟堆疊版不一樣：堆疊是後放的先拿出來，所以堆疊版先走 0 的最後一個鄰居 2；遞迴版照鄰居清單的順序，先走 1。但兩者標記到的頂點一樣。連不連通、有幾塊這類問題只在乎「走得到哪些」，不在乎先後，所以用哪一種都可以；資料很大時遞迴會有深度的問題，第 4 節會實際看到。

💡 實務上：資料可能有環，就一定要有 visited
只要關係是使用者或營運人員設定的，就可能出現環：分類 A 的上層被設成 B、B 的上層又是 A；權限群組 A 包含 B、B 又包含 A；商品推薦互相指來指去。後端用遞迴展開「這個分類底下所有商品」「這個人實際有哪些權限」時沒有 visited，就會無窮迴圈，最後是請求逾時或伺服器記憶體被撐爆，而且通常是某天有人改了一筆設定才發生。資深工程師遇到「沿著關係一路找下去」的程式，會先問兩件事：這份資料保證沒有環嗎？最深會到幾層？保守的做法是一律加 visited，再加一個深度上限，超過就記 log 並回傳錯誤，比默默卡住好查得多。

外送地圖沒有道路清單：格子的鄰居怎麼算？

外送地圖通常用字串陣列表示：'.' 是可以走的路，'#' 是牆或建築。map[r][c] 是第 r 列、第 c 行的那一格。列（row）由上往下數，行（column）由左往右數，都從 0 開始，所以 map[0][0] 是左上角。

外送員每一步只能往上下左右走一格。把每一格當成一個頂點，一格和它上下左右的四格之間就有邊，地圖就是一張圖，上一節的 DFS 和 visited 都能直接用。差別只在找鄰居的方式：不用先建相鄰串列，因為鄰居可以算出來。把 (r, c) 加上四個方向的位移，得到四個候選格子，再排除跑出地圖外的和是牆的，剩下的就是鄰居。執行後看三個格子各有哪些鄰居，最後一行是邊界檢查寫錯時會讀到什麼：

neighbors 先做邊界檢查、再看是不是牆，順序不能反過來：列號超出範圍時 map[nr] 是 undefined，先讀 map[nr][nc] 就會丟 TypeError。合法的列號是 0 到 rows − 1，條件要寫成 nr >= 0 && nr < rows；範例寫的是它的反面，nr < 0 || nr >= rows 就跳過。寫成 nr <= rows 的話，nr 等於 rows 的格子也會通過，讀到 map[rows]，就是最後一行印出的 undefined，再取 [c] 就丟錯。

四個方向寫成 DIRS 陣列、用一個迴圈跑過，比手寫四段 if 不容易漏掉或抄錯。題目說「八個方向」，也就是斜對角也算相連時，只要在 DIRS 再加四筆斜向的位移。這課的題目都只算上下左右，斜對角不相連；讀題時先確認這一點，題目沒寫清楚就問。

網格的頂點數 V 是 rows × cols，每格最多 4 條邊，邊數 E 也跟格子數同一個量級，所以上一節的 O(V + E) 在網格上就是 O(rows × cols)。

頂點和鄰居都有了，剩下 visited。格子沒有 0 到 n − 1 的編號，它的名字是一對座標 (r, c)，這就帶來一個陷阱。

範例後三段是三種正確做法。r * cols + c 把座標換成唯一的整數：每列有 cols 格，第 r 列之前一共有 r * cols 格，再往右數 c 格，就是第 r * cols + c 格。`${r},${c}` 把座標換成字串，第 4 課用過，好讀，但每次都要組一個字串，比整數慢一些。第三種是直接開一個和網格一樣大的二維布林陣列，visited[r][c] 對應那一格。網格大小一開始就知道時，二維布林陣列最快也最好讀，這課的答案都用它。

也有人會想省掉 visited，直接把走過的格子改成 '#' 當記號。地圖是字串陣列時做不到。下面會提到嚴格模式（strict mode）：它是 JavaScript 比較嚴格的一套執行規則，ES 模組一律在嚴格模式下執行，這個頁面的練習程式也是當成模組執行的。在嚴格模式下，對字串的某一格賦值會直接丟 TypeError；非嚴格模式則是什麼事都沒發生，也不報錯：

字串是不可變的：map[r][c] = '#' 改不了字串，在嚴格模式還會丟 TypeError（TypeScript 會先報錯）。地圖是 string[] 時，「走過」只能記在另外的 visited 裡；題目給的是數字陣列而且允許修改時，才能直接把格子改掉當作標記。

圖、鄰居、visited 都準備好了，可以開始回答外送地圖的問題。數外送區之前要先會一件事：從一格出發，把跟它相連的一整塊走完。

把相連的一整塊走完：座位區重新上色怎麼寫？

「把一整塊走完」先用一個比外送地圖更小、結果一眼看得出來的例子練：店裡的座位圖。設計師把座位區畫成數字網格，數字代表顏色，例如 1 是木頭色、0 是白色。他點了某一格，想把跟它上下左右相連、而且同顏色的整塊都換成新顏色，就像繪圖軟體的油漆桶。這個操作叫 flood fill。用它來練有兩個原因：它只走一塊，塗完印出來就看得到哪些格子被走到；而且它示範了一種外送地圖做不到的省法，以及這種省法的陷阱。

做法是從點到的那一格開始 DFS：遇到出界、或顏色跟原本不同的格子就停；否則塗上新顏色，再往四個方向走。遞迴寫法跟第 16 課走樹一樣短。這裡不用另外開 visited：塗上新顏色的格子已經不是舊顏色，下次再走到時會被「顏色不同」擋下來，所以塗色本身就是標記。座位圖是數字陣列，可以直接改，上一節的字串地圖就不行。執行後先看印出來的網格，右下角那格是重點；再看最後一行拿掉第一個 if 的結果：

右下角的 1 跟中間那格只有斜對角相接，它的上下左右都是 0，不算相連，所以保持原色。

最後一行說明「用塗色代替 visited」的代價。這個方法成立的前提是：塗過的格子一定跟舊顏色不同。新舊顏色相同時，塗完的格子還是舊顏色，等於沒有標記；(0, 0) 走到 (0, 1)，(0, 1) 又走回 (0, 0)，兩格互相呼叫，直到呼叫堆疊爆掉、丟出 RangeError。所以 repaintRec 開頭先檢查新舊同色，同色就直接回傳。以後只要想用修改資料代替 visited，都要先確認改了之後一定跟原本不同。

座位圖只有 3 × 3，遞迴沒有問題。換成一張大一點的座位圖或外送地圖，遞迴就撐不住了。

網格大一點，遞迴為什麼會爆？

第 15 課講過，每呼叫一次函式，呼叫堆疊就多一個堆疊框，記住這一層做到哪；函式回傳時才拿掉。遞迴 DFS 一路往下走，路有多長，堆疊就疊多高。整張 200 × 200 都同色時，DFS 會沿著一個方向蛇行，把 4 萬格幾乎走成一條長路才開始回頭，遞迴深度最多到 4 萬層。

呼叫堆疊的大小有上限，規格沒有規定是多少，依瀏覽器、依每層存多少變數而定。在這個頁面執行程式的環境裡，一個什麼都不做的遞迴約 5,300 層就丟 RangeError；flood fill 每層存的東西更多，50 × 50（最深 2,500 層）就已經撐不住（實測紀錄見課末）。所以不能靠「應該還夠」，要換成不受這個上限影響的寫法：第 16 課最後一節的做法，自己用陣列當堆疊。執行後比較兩行：

改寫的步驟固定：遞迴的參數 (r, c) 變成堆疊裡的一筆資料；「呼叫 dfs」變成「檢查通過就標記並 push」；外面用 while 一直 pop 到空。標記放在 push 的時候，同一格就不會被放進堆疊兩次。時間 O(rows × cols)，堆疊最多存 rows × cols 筆，空間也是 O(rows × cols)，但它在一般記憶體裡，不受呼叫堆疊的上限影響。

什麼時候要改：面試時網格通常不大，先寫遞迴，再口頭補一句「網格很大時會超出呼叫堆疊，可以改成自己的堆疊」就夠了；題目寫明網格可以到幾百 × 幾百，或是正式環境處理使用者給的資料，就直接用自己的堆疊。這課的練習網格都到 200 × 200 以上，請用堆疊或佇列。

會把一整塊走完之後，數外送區只差一步：一張地圖上可能有好幾塊，要知道一共幾塊。

外送地圖上可以外送的街區分成幾區？

回到開場第三題。這張外送地圖用 '1' 表示可以外送的街區、'0' 表示不行，上下左右相連的 '1' 算同一區，每一區要排一組外送員。在圖裡，一群彼此都走得到、而且跟這群以外的頂點都走不通的頂點，叫連通區塊（connected component）；問有幾區，就是問有幾個連通區塊。開場的分店圖也一樣：0、1、2、3 是一塊，4 自己一塊，一共兩塊。

上一節的 flood fill 只走「點到的那一塊」。要數全部，就從左上角開始掃過每一格：遇到一個還沒走過的 '1'，代表發現了新的一區，區數加 1，然後從它出發，用 DFS 把整區走完、全部標記。之後掃到同一區的其他格子時，它們已經標記過，直接跳過，不會被算第二次。下面的 labelZones 把每格屬於第幾區記在 zone 表裡，zone 是 0 代表還沒走過，所以它同時就是 visited。執行後看每列右邊的區號，以及第二張棋盤格地圖的區數：

第二張地圖的五個 1 都只跟別的 1 斜對角相接，上下左右沒有相連，所以各自一區，共 5 區。

複雜度要小心估。外層兩個迴圈走過每一格，裡面又有一個 while，看起來是迴圈裡的迴圈，很容易估成 O((rows × cols)²)。但每一格只會被標記、放進堆疊一次：被某次 DFS 標記之後，外層迴圈再掃到它會跳過，之後的 DFS 也不會再放它。所以所有 DFS 加起來只處理 rows × cols 格，再加上外層迴圈掃一遍，還是 O(rows × cols)。估複雜度時，數「每個元素總共被處理幾次」，比數迴圈有幾層準確。

同一個寫法換成圖也成立：外層迴圈改成走過每個頂點，內層 DFS 改成走相鄰串列。「n 個帳號裡哪些其實是同一個人」「哪些分店的庫存可以互相調貨」，都是數連通區塊。

三個問題回答了兩個。最後一題問的不是「走不走得到」，而是「最少走幾步」，要換一種走法。

從店門口到客人家最少要幾步？

外送員從店門口出發，每步往上下左右走一格，要估外送時間，就要知道最少幾步到客人家。第 17 課的 BFS 正好適合：它用佇列一層一層往外走。第 0 層是起點；第 1 層是走 1 步到得了的格子；第 2 層是走 2 步到得了、而且前面沒到過的格子，依此類推。

為什麼 BFS 第一次走到某一格時，用的就是最少步數？因為佇列先進先出，第 k 層的格子全部處理完，才會輪到第 k + 1 層。如果某一格 3 步就到得了，它會在處理第 2 層時被放進佇列、成為第 3 層的一員；不可能等到第 5 層才第一次碰到它。這個保證有一個前提：每一步的代價都一樣，都是「一步」。

實作用第 12 課的 head 索引佇列，另外開一個 dist 表格記錄每格的步數。dist 是 -1 代表還沒走到，所以它同時就是 visited。新格子的步數，是把它放進佇列的那一格的步數加 1。執行後看右邊的步數表：

數字一樣的格子是同一層，可以看到從左上角一圈一圈往外擴。(2, 4) 四周是牆和地圖邊界，走不到，表裡印成 ?，它在 dist 裡的值仍是 -1（最後一行印出來的就是它）。題目要求走不到回傳 -1，就直接回傳 dist 裡的 -1，不要回傳 Infinity，那不是題目要的格式。每格最多進佇列一次，時間和空間都是 O(rows × cols)。

dist 的值是在放進佇列的那一刻寫進去的，不是取出來的時候。這個時機看起來是細節，寫錯會讓程式慢到跑不完。

為什麼要在放進佇列時就標記？

如果改成「取出時才標記」，一格在被取出之前，它的每個已經走過的鄰居都會把它再放進佇列一次。取出時如果又沒有檢查「我已經處理過了嗎」，每一份副本都會再把自己的鄰居放進去，副本越滾越多。下面在空地圖上比較三種寫法放進佇列的總次數，執行後看最後兩欄隨邊長怎麼長：

放入時標記，每格剛好進佇列一次。取出時標記但有檢查，結果還是對的，只是佇列裡多了一些重複的副本，大約是格子數的兩倍。取出時標記又沒檢查，數量隨邊長爆炸：10 × 10 的地圖就放了十八萬多次，300 × 300 的地圖根本跑不完。規則很簡單：BFS 在放進佇列的那一刻就標記。DFS 用自己的堆疊時也一樣，前面的 reachable、repaintStack、labelZones 都是這樣寫的。

BFS 寫對了。你可能會問：前面已經寫好 DFS，用它找路、順便數步數，不行嗎？

DFS 找到的路為什麼不一定最短？

DFS 會沿著一個方向一路走到底才回頭，它第一次碰到終點時走的那條路，只是「剛好先探索到的那條」。在一張空的 3 × 3 地圖上，從左上角走到它右邊那一格：

DFS 先往下走，繞了一大圈才到，5 步；真正的答案是 1 步。DFS 只保證「找得到」，要最短就用 BFS。開場第二題的答案就是這一節的 BFS：從店門口算一張 dist 表，客人家那格的數字就是最少步數。

💡 實務上：BFS 的「層」就是「幾步之內」
很多產品需求其實是在問層數：「朋友的朋友」推薦（第 2 層）、組織圖裡「某主管往下 3 層的所有人」、檢查網站時「從首頁點幾下到得了每一頁」。用 BFS 時把 dist 一起記著，到了指定層數就不再往外放，就不會把整張圖都走完。實際的圖可能很大，社群關係每往外一層，人數就會成倍放大，所以除了層數，也要限制最多處理幾個頂點或設逾時，並在需求階段就跟 PM 確認「幾層」「最多顯示幾筆」。這課的「最少步數」只適用每一步代價相同的情況；每條路花的時間不同時，要看下一節表格裡的 Dijkstra，或直接用現成的地圖服務。

拿到一道新的圖題目，怎麼判斷要用什麼？

三題做完，選工具的依據其實只有一個：題目問的是什麼。只問「走不走得到」「有幾區」，DFS、BFS 都可以；問「最少幾步」，用 BFS。下面把這課的情況，加上幾種還沒教、但題目長得很像的情況整理成一張表：

題目問的是用什麼原因
A 走不走得到 B、有幾區、塗色DFS 或 BFS 都可以只在乎走得到的集合，順序不重要；網格大時不要用遞迴
最少幾步（每步代價一樣）BFS一層就是一步，第一次走到就是最短
最短時間（每條路的時間不一樣）Dijkstra 演算法BFS 只數步數；走 3 條快速道路可能比走 1 條塞車的路快。Dijkstra 用第 19 課的 heap 每次取出「目前最近」的頂點，這門課不要求實作
所有可能的路線、所有組合回溯（下一課）要列出全部，不只一條

面試時，先說「這是一個圖」，再說頂點和邊是什麼，例如「每一格是頂點，上下左右是邊」，面試官就知道你接下來要用什麼工具。接著講複雜度：圖是 O(V + E) 時間、O(V) 額外空間（visited 和堆疊或佇列）；網格是 O(rows × cols)。

程式結果不對時，照這個順序檢查：visited 有沒有在放進去時就標記、邊界檢查是不是 <、無向圖有沒有加兩個方向、斜對角算不算相連。這四項就是這課一路上遇到的四個坑。

練習

每題的隱藏測試會用固定案例和幾百個隨機產生的圖或地圖比對參考解，有些題目最後還會用大資料量計時；「花了 … ms」的訊息代表複雜度不夠，「呼叫堆疊爆了」代表要改用自己的堆疊或佇列。傳進來的陣列都會被凍結，不能修改。

練習 1：n 家分店編號 0 到 n − 1，roads 是雙向道路的清單。先寫 buildAdjacency(n, roads) 回傳相鄰串列（每家店一個鄰居陣列，沒有路的店是 []，鄰居的順序不限），再用它寫 hasRoute(n, roads, from, to)：從 from 走不走得到 to。from 等於 to 時回傳 true。測試有 1 萬家店、5 萬家店連成一條長鏈的案例，不要用遞迴。（對應 LeetCode 1971. Find if Path Exists in Graph）

練習 2：寫 repaint(seats, r, c, color)：seats 是座位區的顏色編號，從 (r, c) 開始，把上下左右相連、跟它同顏色的格子都換成 color，回傳新的網格（不能修改 seats）。斜對角不算相連；網格最大 200 × 200，請用自己的堆疊或佇列。起始程式已經複製好網格，補上剩下的部分。（對應 LeetCode 733. Flood Fill）

練習 3：寫 countZones(map)：外送地圖中 '1' 是可以外送的街區、'0' 不行，上下左右相連的 '1' 算同一區，回傳一共有幾區（斜對角不相連）。地圖可能是空陣列；最大 300 × 300，請用自己的堆疊或佇列。（對應 LeetCode 200. Number of Islands）

練習 4：寫 fewestSteps(map, start, goal)：外送地圖 '.' 是路、'#' 是牆，每一步往上下左右走一格，回傳從 start 到 goal（都是 [列, 行]）最少幾步；走不到（包括終點是牆）回傳 -1；起點就是終點回傳 0。起點保證是路。地圖最大 300 × 300，測試最後會計時。

練習 5：外送員用 DFS 在地圖上找到一條從店門口到客人家的路，共 14 步。可以跟客人說「最快 14 步到」嗎？

✓ c。DFS 沿一個方向走到底，第一次碰到終點的路只是「先探索到的那條」，空的 3 × 3 地圖就能繞出 5 步、實際只要 1 步。visited 只避免重複走同一格，不會讓路變短（b 錯）；反過來從終點找也是 DFS，一樣不保證（d 錯）。BFS 一層就是一步，第一次走到就是最少步數。

練習 6：寫 BFS 時，visited 應該在什麼時候標記？

✓ b。一格在被取出前，每個已處理的鄰居都可能把它放進佇列，取出時才標記會出現很多副本；取出時再沒檢查，每個副本都會再展開，數量隨地圖大小爆炸（範例裡 10 × 10 就放了十八萬多次）。a 的「效率一樣」不成立。c 等到最後才標記，等於整個過程都沒有 visited，有環時停不下來。

練習 7：用 const seen = new Set<[number, number]>() 記錄走過的格子，seen.add([r, c]) 之後 seen.has([r, c]) 會是什麼？

✓ a。Set 用 SameValueZero 比較，物件和陣列看的是參考（TypeScript 課第 2 課），每次寫 [r, c] 都是新陣列，has 永遠是 false，visited 形同沒有（b 錯）。型別上完全合法，所以 TypeScript 不會擋（c 錯），這才危險。改用 r * cols + c、`${r},${c}` 或二維布林陣列。

練習 8：座位區是 200 × 200、全部同一個顏色。用遞迴 DFS 做 flood fill，在瀏覽器裡會怎樣？

✓ c。問題不在格子數，在深度：全部同色時 DFS 會蛇行走過每一格才回頭，呼叫堆疊上同時疊著 4 萬層，而這個頁面的 Worker 一個空遞迴約 5,300 層就爆了。4 萬格的工作量很小（a 錯），但堆疊爆掉是直接丟錯、不會「慢慢塗完」（b 錯）。BFS 本來就是用佇列寫的迴圈，深度問題的解法是把遞迴換成自己的堆疊或佇列，不是換一種遞迴（d 錯）。

常見錯誤

  • 沒有 visited：圖有環時永遠繞不出來。走圖一定要記錄處理過的頂點；走樹不用，是因為樹沒有環。
  • BFS 取出時才標記：同一格被重複放進佇列，取出時又沒檢查就會重複展開。放進佇列的那一刻就標記。
  • 用陣列當 Set 的鍵：has([r, c]) 永遠是 false，型別檢查也不會擋。用 r * cols + c、字串鍵或二維布林陣列。
  • 無向圖只加一個方向：adj[a].push(b) 之後也要 adj[b].push(a)，否則走不回來。
  • new Array(n).fill([])：所有位置共用同一個陣列。用 Array.from({ length: n }, () => [])。
  • 邊界檢查寫成 <= rows：讀到 map[rows] 是 undefined，接著丟 TypeError。最後一列的索引是 rows − 1。
  • 斜對角算不算沒確認：題目沒說清楚就問；這課的題目都只算上下左右。
  • 大網格用遞迴：200 × 200 全部相連時深度可到 4 萬層，超出呼叫堆疊。改成自己的堆疊或佇列。
  • 用修改資料代替 visited，卻沒考慮改了跟沒改一樣：flood fill 新舊同色時要直接回傳。
  • 用 DFS 求最少步數：DFS 不保證最短；每步代價一樣用 BFS，代價不同用 Dijkstra。

補充與查表

相鄰矩陣：另一種存圖的方式

除了相鄰串列，圖也可以存成相鄰矩陣（adjacency matrix）：n × n 的表格，m[a][b] 是 true 代表 a、b 之間有路。查「a、b 之間有沒有路」是 O(1)，但不管路有幾條都要 O(V²) 空間，走訪時找鄰居也要掃一整列。分店、使用者、網頁這類實際的圖，每個頂點通常只連到少數幾個，用相鄰串列；面試沒特別說時也預設用它。

遞迴深度的實測紀錄

「網格大一點，遞迴為什麼會爆」一節的數字，是 2026-11-01 在 Chrome 的 module Worker（這個頁面執行程式的地方）實測的：一個什麼都不做的遞迴約 5,300 層就丟 RangeError；flood fill 每層要存的變數更多，50 × 50（最深 2,500 層）就已經撐不住。上限依瀏覽器、依每層用多少空間而定，規格沒有規定，換一個瀏覽器或 Node 數字就不同，不要把它當成可以依賴的值。

小結

  • 開場三題都是圖：分店與道路是頂點與邊；外送地圖的每一格是頂點，上下左右是邊。
  • 題目給邊的清單時，先建相鄰串列（無向圖兩個方向都加，每個位置用 Array.from 各建一個陣列），之後找鄰居才不用掃整份清單。網格不用建，用 DIRS 位移陣列加上 >= 0 && < rows 的邊界檢查算出鄰居。
  • 圖可能有環，visited 讓每個頂點只處理一次，在放進堆疊或佇列時就標記；走完一遍被標記的頂點，就是走得到的全部（第一題）。格子的 visited 用二維布林陣列或數字、字串鍵，不能用陣列當 Set 的鍵。
  • DFS 用來把一整塊走完：flood fill 塗色、數連通區塊（第三題）。用修改資料代替 visited 時，要確定改了之後一定跟原本不同。
  • BFS 一層就是一步，每步代價一樣時第一次走到就是最少步數（第二題）；DFS 找到的路不一定最短。每步代價不同時要用 Dijkstra（需要第 19 課的 heap）。
  • 複雜度：圖 O(V + E)，網格 O(rows × cols)。大網格或深的圖不要用遞迴，改用自己的堆疊或佇列。

下一課的回溯也是 DFS，不過走的是「選擇」組成的樹：每一步做一個選擇、走下去，回來時撤銷，列出所有組合與排列。
