階段 6：進階結構與搜尋 · 第 21 課

回溯：選擇、探索、撤銷

咖啡店下週辦「新品週」，店長交給你三份要印出來的清單。第一份給收銀員：新品拿鐵可以加奶泡、糖漿、肉桂，每一種加或不加，要列出所有點法，收銀員才能一種一種對好價格。第二份給新人：三杯新品各試喝一次，要列出所有可能的試喝順序，讓新人輪流排。第三份是活動規則：點數券有 3、4、5 點三種，每種可以用好幾張，要列出所有剛好湊到 11 點、可以換一杯新品的用法。

第一份看起來最簡單，先試著用迴圈寫：外層一個 for 決定奶泡加不加，裡面一層決定糖漿，再裡面一層決定肉桂。三種配料寫三層，跑得出來。可是店長隔天說要多一種燕麥奶，你就得再套一層；配料如果是從後台讀出來的，寫程式的時候根本不知道有幾種，也就不知道要套幾層。這是第 15 課菜單管理碰過的同一個問題。另外兩份更麻煩：試喝順序每一格能選的飲料，會因為前面選過哪幾杯而變少；湊點數則連要用幾張券都不知道。

三份清單的共同點是「把所有可能列出來」。這課教的回溯，用遞迴一層做一個選擇，有條理地把所有可能走一遍。先用第一份清單把方法建起來，再看它碰到第二、第三份時各要改哪裡，最後看答案多到放不下時怎麼辦。

這課的路線：
  1. 配料清單要套幾層迴圈、只有一個 path 怎麼走遍每條分支：把選擇畫成決策樹，再用「選擇、探索、撤銷」走完它，記錄答案時一定要複製。做完這兩節，第一份清單就印得出來（開場問題的最小答案）。
  2. 換個問法「下一個挑誰」：同一份清單的第二種寫法，以及配料變多時，答案會多到什麼程度。
  3. 試喝順序：順序算數時，上一節的 start 為什麼不夠用，要改用 used。
  4. 點數券湊 11 點：同一種可以重複用、要剛好湊到時範本改哪裡，以及用剪枝少走冤枉路。
  5. 什麼時候該用回溯：題目的哪些條件是訊號，答案多到放不下時正式環境怎麼處理。
這課會用到：
  • 第 15 課的遞迴：先寫終止條件，再假設小一號的問題已經會算，只想這一層怎麼做。
  • 第 16 課的 DFS：先一路往下走到底，走不下去再退回上一個岔路，走另一條。

配料有幾種就要套幾層迴圈？先把選擇畫成一棵樹

先不寫程式，手算最小的版本。三種配料，一種一種問：「要不要奶泡？」「要不要糖漿？」「要不要肉桂？」每個問題有兩個答案，而且前一題不管怎麼答，下一題都照樣要問。把這個過程畫出來：

這種把每一步的選擇畫成分支的圖，叫決策樹（decision tree）。從最上面的根節點出發，每往下一層就回答一個問題；走到最下面、沒有子節點的葉節點時，所有問題都答完了，一路上的選擇合起來就是一種完整的點法。看這棵樹可以讀出三件事：

  • 深度等於要做幾次決定。3 種配料是 3 層，加了燕麥奶就變 4 層。迴圈寫法要多套一層的地方，在樹上只是多長一層。
  • 葉節點的數量就是答案的數量。每一層分成兩支，3 層是 2 × 2 × 2 = 8 個，所以第一份清單有 8 種點法。
  • 走的過程中要記住「到目前為止做了哪些選擇」。例如走到最左下角時，依序選了加奶泡、加糖漿、加肉桂，記成陣列 [奶泡, 糖漿, 肉桂]。這個一路累積的陣列，以下都叫 path（路徑），因為它記的就是從根走到目前位置的那條路。

現在問題變成：怎麼把每個葉節點都走到一次？第 16 課的 DFS 正好做這件事：先往左一路走到底，記下答案，退回上一個岔路改走另一邊，直到每條路都走過。DFS 用遞迴寫的時候，要走幾層由資料決定，不寫死在程式裡，「不知道要套幾層」的問題就沒有了。

差別在於，第 16 課的樹真的存在記憶體裡：每個節點是一個物件，用 left、right 指向子節點，DFS 沿著它們走。這棵決策樹沒有任何節點物件，它是程式邊走邊「想像」出來的：站在第 i 層，就代表正在決定第 i 種配料，往左是加、往右是不加，兩個子節點只存在於「接下來要怎麼呼叫自己」這件事裡。

這種一步一步做選擇，走到底（或走不通）就退回上一個岔路、改試別的選擇的搜尋方法，叫回溯（backtracking）。名字指的就是「退回去」那個動作。不過樹不存在，程式手上就只有一個 path 陣列：往左走時把奶泡放了進去，退回來改走右邊時，path 要怎麼變回沒有奶泡的樣子？

只有一個 path，怎麼走遍每一條分支？選擇、探索、撤銷

對著決策樹，把「站在第 i 層」要做的事一步一步寫下來。i 從 0 開始，代表正在決定第 i 種配料：

  1. 如果 i 已經等於配料數，代表所有配料都決定完了，走到了葉節點：把 path 記進結果，回頭。這是終止條件。
  2. 選擇：走左邊「加」，把第 i 種配料放進 path（path.push）。
  3. 探索：帶著這個選擇往下一層走，遞迴呼叫 dfs(i + 1)。這一呼叫會把左邊整棵子樹走完才回來。
  4. 撤銷：從下一層回來後，把剛剛放進去的拿出來（path.pop），讓 path 回到做選擇之前的樣子。
  5. 走右邊「不加」：path 不動，直接 dfs(i + 1)。

第 4 步的撤銷，是回溯跟一般遞迴最不一樣的地方。原因是整個過程只有一個 path 陣列，所有分支輪流用它。從「加奶泡」那一支走完回來、準備走「不加奶泡」時，path 裡還放著奶泡；不把它拿出來，「不加奶泡」那一支就會帶著奶泡往下走，印出來的點法全部多一份奶泡。撤銷讓 path 回到選擇之前的狀態，下一個分支才能從正確的起點開始。

也可以換個做法：每往下一層就複製一份新的 path 傳下去，各分支各用各的，就不用撤銷。結果一樣對，但每一層呼叫都要多建一個陣列。共用一個 path、走完就撤銷，同一時間只存「目前這一條路」，是回溯的標準寫法，後面每一題都這樣寫。

對照輸出看三件事：

  • 「記錄」出現的順序是 [奶泡, 糖漿]、[奶泡]、[糖漿]、[]，剛好是決策樹的葉節點由左到右。
  • 縮排就是遞迴的深度，也就是第 15 課看過的呼叫堆疊：每深一層，堆疊上多一框；撤銷發生在下一層 return 回來之後。

這段程式還有一個不起眼的地方：記錄時寫的是 result.push([...path])，不是 result.push(path)。少了那個展開運算子會怎樣？

記錄答案時為什麼一定要複製？

把展開拿掉，其他完全不變，執行後看 result 變成什麼：

四筆全是空陣列，而且第一筆和第四筆是同一個陣列。原因是 TypeScript 課第 2 課講的「陣列是參考」：變數裡存的不是陣列的內容，而是指向那個陣列的箭頭。result.push(path) 放進 result 的是這支箭頭，不是當下內容的副本，所以 result 裡的四筆都指向同一個 path。之後每一次 push、pop 都改到這同一個陣列；等所有撤銷做完，path 回到空的，四筆看起來就全是 []。

[...path] 會建立一個新陣列，把 path 當下的內容抄一份，像拍一張快照。之後 path 再怎麼 push、pop，都改不到這張快照。所以回溯的兩個動作是互相配合的：path 共用，走完要撤銷；記錄時拍快照，快照不受撤銷影響。少了任何一個，結果都會錯。

回溯的範本，之後每一題都照這個形狀寫： 
function dfs(狀態) {
  if (走到底了) { result.push([...path]); return }
  for (每一個可以做的選擇) {
    path.push(選擇)       // 選擇
    dfs(下一個狀態)        // 探索
    path.pop()            // 撤銷
  }
}
「加或不加」只是 for 迴圈只有兩個選項的特例。寫完先檢查兩件事：push 和 pop 是否成對、記錄時是否有複製。

到這裡，第一份清單已經印得出來：把配料陣列換成 ['奶泡', '糖漿', '肉桂']，同一段程式就列出 8 種點法；店長加了燕麥奶，陣列多一個元素，程式一行都不用改，樹自己多長一層。這就是開場問題的答案，練習 1 會讓你親手補完它。不過「加或不加」每層只有兩個選項，還看不出範本裡那個 for 迴圈的用處，而另外兩份清單每一層的選項都不只兩個。

💡 實務上：「存進去的是參考」不只出現在回溯
寫前端時很容易踩到同一個坑：在迴圈裡重複使用一個 draft 物件，改完內容就 push 進購物車，最後每一筆品項都長得一樣。React 也是：直接改原本的 state 陣列再 set 回去，參考沒變，畫面可能不會更新。習慣是「要保存當下的樣子就複製一份」，用展開運算子或 structuredClone；展開只複製一層，物件裡還有陣列或物件（例如品項裡的配料清單）時要用 structuredClone。Code review 時看到「放進結果的變數之後還會被改」，就該停下來確認有沒有複製。

換個問法：每一層改問「下一個挑誰」，同一份清單怎麼寫？

「加或不加」的樹，每一層問的是「第 i 種要不要」，只有兩個選項。另一種問法是每一層問「下一個要加哪一種」，選項就是所有還能挑的配料，這時範本裡的 for 迴圈才真正派上用場。後面的試喝順序和湊點數都是這種問法，所以先拿已經會的配料清單把它練熟：同樣 8 種點法，換一棵樹走出來。

這份清單在數學上叫子集合（subset）：從 n 個東西裡選任意幾個，可以一個都不選。點法不在乎配料加的順序，先加奶泡再加糖漿，和先加糖漿再加奶泡，是同一杯拿鐵。換成「下一個挑誰」之後，要小心的就是這件事：第一層挑奶泡、第二層挑糖漿，和第一層挑糖漿、第二層挑奶泡，會產生兩筆內容相同的答案。

解法是規定「只能往後挑」：配料照原本的順序排，挑了第 j 種之後，下一個只能從第 j + 1 種以後挑。用一個參數 start 記住「這一層從第幾種開始挑」：

  • 根節點的 path 是 []，它本身就是一個答案：一個都不加。
  • 從 start 往後每一個 j 都可以是下一個：放進 path，接著呼叫 dfs(j + 1) 從 j 後面挑，回來後撤銷。
  • 因為只往後挑，挑了糖漿之後不會回頭挑奶泡，[糖漿, 奶泡] 永遠不會出現，只會產生照原本順序排的 [奶泡, 糖漿]。

還有一個跟「加或不加」不同的地方：這棵樹上每個節點都是答案，不只葉節點。站在 [奶泡] 這個節點時，它已經是一種合法的點法（只加奶泡），往下走是在它後面再多加一種。所以一進函式就記錄，不用等走到底。執行後數一數是不是 8 種，再看沒有配料時回傳什麼：

兩種寫法得到的 8 種點法一樣，只是順序不同。「加或不加」的樹比較好畫，適合每個東西只有要、不要兩種狀態的題目；「start 往後挑」能推廣到每一層有很多選項的題目，第三份清單會再用到它。

最後一行 n = 0 的答案是 [[]]，不是 []。[[]] 代表「有一種點法，就是什麼都不加」；[] 代表「一種點法都沒有」。沒有配料時客人還是可以點一杯原味拿鐵，所以答案是前者。空的輸入有幾個答案要先想清楚，這是回溯題最常錯的邊界之一。

第一份清單現在有兩種寫法了。可是店長說配料以後可能加到十幾二十種，到時候清單還印得出來嗎？

配料變多時，清單會變多長？答案有多少，就至少要花多少

每多一種配料，每一種舊點法都可以再分成「加這種」和「不加這種」兩種，所以點法數量翻倍：n 種配料就是 2ⁿ 個子集合。每個子集合最長 n 個元素，記錄時複製要花 O(n)，所以時間是 O(n × 2ⁿ)。這沒辦法靠寫得更聰明壓下去：光是把答案寫出來，就要寫這麼多東西。額外空間（不算輸出）只有遞迴深度加上 path，O(n)。

所以列出全部子集合的題目，n 通常只有十幾到二十。看到題目的限制寫 n ≤ 10 或 n ≤ 20（第 2 課讀限制的方法），就是在暗示「指數時間可以」。回到新品週：20 種配料就有一百多萬種點法，就算程式跑得完，印成紙本也沒有收銀員看得完。這已經是需求的問題，不只是效能的問題，最後一節會回來談。

接下來是第二份清單：試喝順序。它也是從幾杯飲料裡挑，但順序算數，「只往後挑」這條規定就會出問題。

試喝順序：順序算數時，start 為什麼不夠用？

第二份清單要列出三杯新品各喝一次的所有順序。先喝拿鐵再喝美式，和先喝美式再喝拿鐵，對新人來說是兩種不同的安排，喝起來的對比不一樣。這種把 n 個東西全部排成一列、順序不同就算不同的方式，叫排列（permutation）。三杯新品在陣列裡依序是美式咖啡、拿鐵、伯爵紅茶，後面都用這個順序。

直接拿上一節的 start 寫法來用會怎樣？第一個位置挑了排在最後的伯爵紅茶之後，start 就跑到陣列尾端，後面沒有東西可以挑，[伯爵紅茶, 美式咖啡, 拿鐵] 這種順序永遠產生不出來。start 的用途本來就是「擋掉同樣內容換個順序的答案」，而排列要的正好就是那些換了順序的答案。

所以排列的每一層都要能挑任何一杯還沒喝過的，每次都從頭看。問題變成：怎麼知道哪幾杯已經放進 path 了？用 path.includes 檢查也可以，但每檢查一次就要從頭掃整個 path，是 O(n)；每一層的迴圈要對 n 杯各檢查一次，這個成本會一直疊上去。另外，如果飲料名稱可能重複（兩杯都叫拿鐵），用名稱比對還會分不出是哪一杯。常見做法是開一個跟飲料陣列一樣長的布林陣列 used，用位置 j 記錄，used[j] 是 true 代表第 j 杯已經在 path 裡，看一眼就知道，是 O(1)：

  • 選擇時同時改兩樣東西：path.push 放進第 j 杯，used[j] 設成 true。
  • 撤銷時兩樣都要還原：path.pop()，used[j] 設回 false。used 和 path 一樣是所有分支共用的，只還原 path、忘了 used，後面的分支會以為那杯還在 path 裡而跳過它，答案就少了。
  • 終止條件：path 長度等於 n，代表每一杯都排進去了。這棵樹只有葉節點是答案，半路上的 [拿鐵] 不是一種完整的試喝順序。

總共有幾種順序？第一個位置有 n 種選法，第二個位置剩 n − 1 種，最後一個位置只剩 1 種，總共 n × (n − 1) × … × 1 種，數學上寫成 n!，讀作 n 階乘，就是第 15 課 orders(n) 算的那個數。執行後先看 3 杯的 6 種順序，再看下面幾行 2ⁿ 和 n! 怎麼拉開：

3 杯有 6 種順序，第二份清單完成。後面那幾行說明了排列題的 n 為什麼比子集合題更小：n! 比 2ⁿ 長得快很多，10! 已經是 3,628,800，12! 將近 4.8 億。每個排列長 n、記錄時要複製，所以列出所有排列的時間是 O(n × n!)，題目的 n 通常不超過 8～10。

寫到這裡，兩種寫法的差別可以收成一個問題：順序算不算數。只在乎選了哪些、不在乎順序的情況，除了子集合，還有一個常用的名字叫組合（combination）：從一群東西裡選出幾個，不管排列順序。子集合就是所有大小的組合全部放在一起。

子集合和排列的寫法只差一個地方，記住這個對照就不會混：
  • 不在乎順序（子集合、組合）：下一層從 start 往後挑，[1, 2] 和 [2, 1] 只會產生一次。
  • 在乎順序（排列）：下一層從頭挑，用 used 跳過已經用過的。

第三份清單是點數券湊點數。用哪幾張券跟拿出來的順序無關，所以是組合，該用 start；但它有兩個前兩份沒有的條件：同一種券可以用好幾張，而且要剛好湊到 11 點。

點數券湊 11 點：可以重複用、又要剛好湊到，範本要改哪裡？

把活動規則寫成題目：點數券有幾種不同面額，每種可以用任意張，列出所有加起來剛好等於目標點數 amount 的用法；每一組由小到大寫，不能有重複的組。先用 [3, 4, 5]、amount = 11 手算：3 + 3 + 5 = 11、3 + 4 + 4 = 11，就這兩組。[3, 5, 3] 和 [3, 3, 5] 用的券一模一樣，只是拿出來的順序不同，算同一組，這就是上一節說的組合，沿用 start。

跟子集合比，範本有兩個地方要改：

  1. 同一種可以重複用：子集合挑了第 j 種，下一層從 j + 1 開始，第 j 種就不會再出現。這裡要允許再挑一次第 j 種，所以遞迴傳 j 而不是 j + 1。仍然只往後（含自己）挑：3 之後可以再挑 3、4、5，但 4 之後不會回頭挑 3，所以不會出現 [4, 3] 之類的倒序重複。
  2. 終止條件看剩下的點數：start 往後挑的子集合不需要終止條件：每個節點都記錄，start 走到陣列尾端，迴圈就自然結束。這裡同一種券可以一直重複挑，start 不會往後跑，迴圈不會自己停，也不知道要用幾張券。所以要帶著 remain（還差幾點）往下走：每放一張券就減掉它的面額；剛好 0 代表湊到了，記錄；變成負的代表超過了，這條路走不通，回頭。

這樣寫答案是對的，但會多走很多冤枉路。

超過了才回頭太慢：剪枝怎麼提早放棄整條分支？

「變成負的才回頭」的問題在於：明明放這張就會超過，還是要先放進去、呼叫一次 dfs，進了函式才發現。而且同一層後面的面額往往也會超過，每一張都要這樣白走一次。

如果先把面額由小到大排序，就能一次放棄一整串：迴圈從小面額往大面額看，一看到某個面額已經大於 remain，後面的只會更大，也一定超過，整個迴圈直接 break。這種「確定這條分支底下不會有答案，就不往下走」的做法叫剪枝（pruning），像把決策樹上註定失敗的整根樹枝剪掉，它底下的節點全都不用再走。

下面同一份寫法跑兩次，一次不剪枝、一次剪枝，數 dfs 被呼叫幾次。只是湊 11 點只有兩組答案，樹太小，剪不剪枝只差 25 次和 14 次呼叫，看不出差距。所以第一行先用 [3, 4, 5] 湊 11 點，確認是手算的那兩組；後面幾行假設活動擴大，改用 6 種面額 [3, 7, 5, 4, 9, 6] 湊 30 點，答案有 80 組，樹夠大，差距才看得出來。執行後先看第一行，再比較後面的呼叫次數：

30 點的例子，剪不剪枝答案一樣是 80 組，呼叫次數從 1,371 次降到 622 次，少了一半以上。剪枝不會讓最壞情況的 Big-O 變好看，但實際上常常省下大半的工作，這類題目的面試幾乎都會期待你加上它。

剪枝的代價是多了一個前提：面額必須真的排好序。這個前提不成立時，程式不會報錯，而是悄悄少了答案。

剪枝建立在「排序過」這個前提上，排序錯了就會漏答案，而且不會報錯。第 8 課講過：sort() 不給比較函式時用字串順序比較。面額 [10, 9] 用預設排序還是 [10, 9]（字串 "10" 排在 "9" 前面），湊 9 點時第一個看到 10 > 9 就 break，[9] 這個答案就不見了。一定要寫 (a, b) => a - b，而且先複製再排序，不要改到傳進來的陣列。

什麼時候該用回溯？答案多到放不下時怎麼辦？

三份清單做完，回頭看它們的共同點：題目要的是每一種可能都列出來，而且數量小到列得完。這兩個條件就是回溯的訊號；換掉其中一個，該用的工具就不一樣了：

題目的樣子做法
要列出所有組合、排列、方案；n 很小（大約 ≤ 20，排列 ≤ 10）回溯，複雜度跟答案數量成正比
只要其中一個可行方案，或只問「有沒有」回溯，找到第一個就一路回傳 true，不用走完
只問有幾種，或問最少／最多通常改用動態規劃（第 23、24 課），不列出每一種
n 是幾萬、幾十萬不是回溯，指數時間跑不完；回頭找雜湊表、雙指標、貪婪這類 O(n) 或 O(n log n) 的做法

第二列的「一路回傳 true」是這課還沒寫過的形狀。假設店長只問「湊得出 11 點嗎」，不需要列出每一組，找到一組就能回答。做法是讓 dfs 回傳 boolean：走到答案時 return true；for 迴圈裡寫 if (dfs(...)) return true，下一層一說找到了，這一層就立刻把 true 往上交，不撤銷、也不再試下一個選擇；整個迴圈都試完還沒找到，才 return false。true 會這樣一層一層傳回根節點，剩下的分支全部不走：

function canMake(start: number, remain: number): boolean {
  if (remain === 0) return true                // 找到一組，往上回報
  for (let j = start; j < sorted.length; j++) {
    if (sorted[j] > remain) break              // 剪枝
    if (canMake(j, remain - sorted[j])) return true   // 下一層找到了，立刻停
  }
  return false                                 // 這個節點底下全部試完都不行
}

這裡不用 path，所以也沒有東西要撤銷；如果還要知道找到的是哪一組，就把 path.push／path.pop() 加回來，並把 if (dfs(...)) return true 寫在 pop 之前：找到時直接返回、跳過撤銷，path 就停在那一組答案上。

第三列最容易被忽略。如果店長只問「湊 11 點一共有幾種用法」，用回溯一種一種走到再數，花的時間仍然跟答案數量成正比；答案一多，光是走就走不完。動態規劃不列出每一種，直接算數量，練習 7 會看到兩者差多少。題目要的東西從「列出」換成「數量」，演算法就整個換掉。

面試說複雜度時，回溯題的標準說法是「答案有幾個 × 每個答案的長度」：子集合 O(n × 2ⁿ)、排列 O(n × n!)。湊金額這種答案數量不好算的，說「指數時間，剪枝能減少實際搜尋量」就夠了，不用硬算出精確式子。

可是工作上的需求不一定附上「n ≤ 20」這種保證。菜單多一種配料，組合就翻倍，答案真的多到放不下時，程式要怎麼寫才不會出事？

正式環境：答案太多時，怎麼不要一次全部做出來？

回溯在工作上會出現在：產生所有配料組合來跑測試、排班、展開商品的所有規格（尺寸 × 溫度 × 甜度）。危險在於答案數量是指數成長，一次把全部放進陣列，可能把記憶體吃光。做法有兩種：一是給上限，超過就拒絕或分頁；二是改成 TypeScript 課第 10 課的產生器。

產生器函式（function*）執行到 yield 就暫停，把一個值交給呼叫端；呼叫端要下一個時，才從暫停的地方繼續。套到回溯上，就是每找到一個答案就 yield 一個快照，呼叫端要幾個拿幾個，不要了就停，後面的分支根本不會走到。遞迴的那一層用 yield*，把下一層產生的每一個答案原封不動轉交出去。

下面用 40 種配料示範：2⁴⁰ 超過一兆個子集合，全部做出來不可能。執行後看它是不是印完 4 行就馬上結束：

程式只做了 4 個答案的工作：break 之後產生器不會再被要求下一個值，剩下的分支一條都沒走。注意 yield [...path] 一樣是複製，跟記錄進 result 時的理由相同：path 之後還會被撤銷。

💡 實務上：先問清楚要「全部」、「幾種」還是「最好的一個」
PM 說「列出所有排班方案讓店長挑」，資深工程師會先問：真的要全部嗎？店長看得完幾個？多半真正要的是「符合規則的前幾個」或「最好的一個」：前者回溯找到夠多個就停；後者可以邊回溯邊記住目前最好的一個、搭配剪枝，或先想想能不能用之後幾課的貪婪、動態規劃。需求從「列出全部」改成「回傳數量」，演算法和效能可能完全不同，所以這個問題要在動工前問，而不是上線後才發現跑不完。規則多、規模大的排班或排課，正式產品常交給現成的排程或最佳化工具，不自己手寫搜尋。

練習 7：題目改成「用 1、2、5、10、20、50 點的點數券湊 1,000 點，有幾種湊法」，只要一個數字。最好的做法是？

✓ a。這題的答案是 103,119,386 種，超過一億。列出來（b）要花跟數量成正比的時間，還要一億多個陣列的記憶體；c 省了記憶體，但還是要一種一種走到，至少一億多步。只要數量時，用第 24 課的動態規劃（對應 LeetCode 518. Coin Change II），時間是 O(面額數 × 金額)，這題大約 6 × 1,000 = 6,000 步。回溯留給「要列出每一種」的題目。

常見錯誤

  • 記錄答案沒有複製：result.push(path) 讓所有答案指向同一個陣列，最後全部變成空的。寫 result.push([...path])。
  • 選擇與撤銷不成對：push 了沒有 pop，path 越來越長；排列題只還原 path、忘了把 used[j] 設回 false，後面的分支就少了選項。選擇時改了幾樣東西，撤銷時就要還原幾樣。
  • 組合題用排列的寫法：每一層都從頭挑，會產生 [3, 5] 和 [5, 3] 這種重複。不在乎順序就用 start 只往後挑。
  • 可重複使用時傳了 j + 1：每種面額只能用一次，[3, 3, 5] 這種答案就不見了。可以重複用傳 j，不能重複才傳 j + 1。
  • 剪枝前沒排序或用預設排序：sort() 是字串順序，[10, 9] 不會變，break 會提早停止而漏掉答案，而且不會報錯。寫 [...values].sort((a, b) => a - b)，先複製再排序。
  • 空輸入回傳 []：沒有配料時子集合是 [[]]，沒有飲料時排列也是 [[]]。先想清楚空的情況有幾個答案。
  • n 很大還用回溯：答案數量是指數成長，n = 30 的子集合就有十億個。先看限制；只要數量或最佳值時改用動態規劃。

小結

  • 「列出所有可能」時迴圈不知道要套幾層；回溯把每一步的選擇看成一棵決策樹，用 DFS 邊走邊產生它：每一層做一個選擇，走到底記錄答案，再退回來試別的。
  • 範本：選擇（path.push）→ 探索（遞迴）→ 撤銷（path.pop）。整個過程共用一個 path，選擇時改了什麼，撤銷時就還原什麼。
  • 記錄答案一定要 [...path] 拍快照，否則所有答案都指向同一個陣列，最後全變成空的。
  • 配料點法（子集合）、湊點數（組合）不在乎順序，用 start 往後挑；試喝順序（排列）在乎順序，從頭挑、用 used 跳過用過的；可以重複使用時遞迴傳 j，不能就傳 j + 1。
  • 複雜度看答案數量：子集合 O(n × 2ⁿ)、排列 O(n × n!)，所以 n 都很小。剪枝（排序後 break）不改變最壞情況，但能省下大量實際搜尋，前提是排序正確。
  • 要「所有」方案用回溯；只要「有幾種」或「最少／最多」改用動態規劃；正式環境答案可能很多時，給上限或用產生器逐一產生。

練習 8：n 個數字，這段找第 k 大的程式，時間與額外空間是多少？

function kthLargest(nums: readonly number[], k: number): number {
  const heap = new MinHeap<number>((a, b) => a < b)
  for (const x of nums) {
    if (heap.size < k) heap.push(x)
    else if (x > heap.peek()!) { heap.pop(); heap.push(x) }
  }
  return heap.peek()!
}

✓ heap 永遠不超過 k 個，每次 push、pop 是 O(log k)，n 個數字各最多做一次，總共 O(n log k)；只存 k 個，所以資料一直進來也不必全部存下來。a 錯在把 heap 的大小當成 n，那是 max-heap 把全部放進去的做法。k 遠小於 n 時才明顯比排序省。（第 19 課）

練習 9：同事的 MinHeap.pop 如下，siftDown 本身沒有問題（讀子節點前會檢查索引）。哪種情況會出錯？

pop(): T | undefined {
  if (this.items.length === 0) return undefined
  const top = this.items[0]
  const last = this.items.pop()!
  this.items[0] = last
  this.siftDown(0)
  return top
}

✓ 只剩一個時，items.pop() 之後陣列已經空了，再寫 items[0] = last 又把拿走的元素放回去：同一個值被拿出兩次，while (heap.size > 0) 的迴圈永遠停不下來。修法是 pop 完先檢查，空了就直接回傳 top。d 錯在 siftDown 有檢查索引，沒有子節點就停。（第 19 課）

練習 10：後台用這段程式展開「某個權限群組實際有哪些人」，上線幾個月都正常，某天這支 API 突然逾時。最可能是哪一種資料造成的？

// groups：群組名稱 → 成員（人或子群組）
function allMembers(name: string, groups: Map<string, string[]>, out = new Set<string>()): Set<string> {
  for (const m of groups.get(name) ?? []) {
    if (groups.has(m)) allMembers(m, groups, out)   // 成員是群組就展開
    else out.add(m)
  }
  return out
}

✓ 群組之間有環時，A 展開 B、B 又展開 A，遞迴停不下來，最後堆疊爆掉或請求逾時。要加 visited：展開過的群組記下來，遇到就跳過；保守再加深度上限。c 只是 D 被展開兩次、多做一點工，Set 會去重，結果仍然正確。（第 20 課）

練習 11：數外送區的主體如下，地圖是 rows × cols。同事說「兩層迴圈裡又呼叫 fill，最壞是 O((rows × cols)²)」。時間與額外空間應該是？

const seen = Array.from({ length: rows }, () => new Array<boolean>(cols).fill(false))
let zones = 0
for (let r = 0; r < rows; r++) {
  for (let c = 0; c < cols; c++) {
    if (map[r][c] !== '1' || seen[r][c]) continue
    zones++
    fill(r, c, seen)   // 用自己的堆疊，把相連的 '1' 都標記成 seen
  }
}

✓ fill 只走進還沒標記的格子，每格只會被標記、放進堆疊一次，再看 4 個鄰居；外層掃一遍也是 rows × cols，加起來 O(rows × cols)。a 錯在把每次 fill 都當成最壞情況：一次 fill 走得多，那些格子就都標記過了，後面的 fill 只會走得少。（第 20 課）

練習 12：你用 BFS 寫完外送地圖的最少步數，面試官改題：每條路花的時間不同（3～15 分鐘），求到客人家的最短時間。怎麼回答？

✓ BFS 的「一層就是一步、第一次走到就是最短」只在每步代價一樣時成立；代價不同時，步數少的路不一定時間短，走 3 條快速道路可能比 1 條塞車的路快。Dijkstra 每次從 heap 取出目前最近的頂點，這門課不要求實作，但要說得出為什麼換它。a 錯在把步數最少當成時間最短。（第 20 課）

練習 13：你用遞迴 DFS 寫完數外送區，範例都過了。面試官問：「地圖是 1000 × 1000 的話呢？」最好的回答是？

✓ 工作量不是問題，深度才是：全部相連時 DFS 蛇行走過每一格才回頭，呼叫堆疊上同時疊著的層數可以接近格子數，這課的 Worker 約 5,300 層就爆了。把遞迴換成自己的堆疊：參數變成一筆資料，檢查通過就標記並 push。b 錯在只看時間複雜度，堆疊爆掉是直接丟錯，不是變慢。（第 20 課）

練習 14：菜單有 n（≤ 10）種不同的飲料，要列出所有「挑 3 種組成套餐」的方式，同樣 3 種不論順序都算同一個套餐。回溯該怎麼挑？

✓ 不在乎順序是組合題：只往後挑，[拿鐵, 美式] 和 [美式, 拿鐵] 只會產生一次；每種只能挑一次，所以傳 j + 1。a 是排列的寫法，同一組 3 種會出現 3! = 6 次；c 傳 j 會讓同一種被挑好幾次。（第 21 課）

練習 15：這段湊金額加了剪枝，values 是互不相同的正整數，可以重複使用。下面哪個輸入會漏掉答案，而且不會報錯？

const sorted = [...values].sort()
function dfs(start: number, remain: number): void {
  if (remain === 0) { result.push([...path]); return }
  for (let j = start; j < sorted.length; j++) {
    if (sorted[j] > remain) break          // 剪枝
    path.push(sorted[j])
    dfs(j, remain - sorted[j])
    path.pop()
  }
}

✓ sort() 不給比較函式時比的是字串，[10, 4, 5] 排完 10 還在最前面，湊 9 點時第一個看到 10 > 9 就 break，[4, 5] 被剪掉，回傳 [] 也不報錯。改成 sort((a, b) => a - b)。a 錯在個位數的字串順序和數字順序一樣，排完是 [3, 4, 5]，結果正確。（第 21 課）
