階段 1：響應式原理：自己做一個 · 第 1 課

響應式是什麼：Proxy 與依賴追蹤

你每天寫 count.value++，畫面就跟著變。這個「改了資料，畫面自己更新」的能力叫響應式（reactivity）。這門課的前三課把它拆開，自己做一個迷你版。看懂之後，「資料改了畫面沒動」「為什麼要寫 .value」「為什麼解構之後就不更新」這類問題，你能從原理推出答案，不用靠背。

這一課從一個具體的 bug 開始：購物車清空了，結帳按鈕卻還寫「可以結帳」。我們要讓「改了購物車，所有用到它的地方自動更新」。要做到這件事，第一步是讓程式看得見購物車什麼時候被讀、什麼時候被改。這課只做這一步，做到最後，你能寫出一個函式，自動列出「小計這段畫面讀了 qty 和 price」；下一課再用這份清單讓畫面自動重跑。

這課的路線：
  1. 購物車的數字為什麼會對不起來、框架怎麼知道該重跑誰：手動同步為什麼一定會漏，以及自動化需要的「依賴追蹤」三步。
  2. JavaScript 能在哪裡插手讀和寫：攔截得到物件屬性、攔截不到區域變數，這也是 ref 要寫 .value 的原因。
  3. 把每個屬性都換成 getter／setter 夠不夠：Vue 2 的做法，以及它為什麼偵測不到新增屬性和陣列索引。
  4. 能不能攔截整個物件、包成 proxy 之後還有哪些攔不到：Proxy 與 Reflect 的寫法，以及「proxy 不是原物件」帶來的陷阱。
  5. 回到購物車：對照 Vue 3 官方文件的示意程式，並自動列出小計的依賴。
這課會用到：
  • TS 課第 1 課的 this：呼叫時點號前面是誰，this 就是誰。
  • TS 課第 3 課的 getter／setter：用 get／set 定義的屬性，讀寫時會執行你寫的函式。
  • TS 課第 19 課的泛型函式：function f<T extends object>(obj: T): T 傳進什麼物件型別，就回傳同一個型別。
這一課的範例和練習都是 TypeScript，在瀏覽器的 Worker 裡以 ES module（嚴格模式）執行，沒有載入 Vue。Vue 的程式碼只用 <pre> 展示。

購物車的數字為什麼會對不起來？

購物車頁面有三個地方顯示同一份資料：小計、右上角徽章的件數、結帳按鈕（購物車空的時候要停用）。不用框架時，你會這樣寫：每個顯示位置寫一個更新函式，改了數量之後，自己去呼叫每一個。執行後看第二行輸出的 checkout：

數量已經是 0，按鈕還寫「可以結帳」。程式沒有語法錯誤，每個函式單獨看也都對，錯在「改完 cart.qty 之後要呼叫哪些函式」這件事，完全靠寫程式的人記住。

這種寫法叫命令式（imperative）：你寫出每一步操作，「改數量、更新小計、更新徽章、更新按鈕」。它的問題不在今天，而在之後：下個月有人在購物車頁加了「免運還差多少」的提示，他要找出程式裡每一個改 cart.qty 的地方，在後面補上 updateShipping()。改數量的地方可能有五處（加減按鈕、刪除商品、清空、套用優惠），漏一處就是 bug，而且只有在那條路徑被走到時才會出現。資料和畫面之間的對應關係散落在每個「改資料」的地方，沒有一處寫得完整。

Vue 走的是另一條路，叫宣告式（declarative）：你只描述「畫面應該長什麼樣」，例如「按鈕的文字 = qty 大於 0 時是可以結帳」。寫成公式就是 畫面 = f(狀態)：畫面是狀態算出來的結果。狀態一改，由框架重新算出畫面並更新 DOM。這樣「免運提示」只要寫一次它怎麼從 cart 算出來，改數量的五個地方一行都不用動。

但「由框架重新算」說起來簡單：框架怎麼知道改了 cart.qty 之後要重算小計、徽章、按鈕，而改了別的資料時不用重算它們？它必須能自動知道兩件事：

  • 每段畫面（或計算）讀了哪些資料。
  • 某份資料什麼時候被改了。

能自動做到「資料改了，讀過它的計算和畫面自動重新執行」，就是響應式。下一節來看框架怎麼得到這兩項資訊。

💡 實務上：同一份資料顯示在多處，就交給響應式
咖啡店後台常見的例子：訂單狀態改成「已完成」，列表那一列、上方的「待處理 N 筆」計數、側邊欄徽章都要跟著變。用命令式手動同步，最常見的 bug 就是改了一處、漏了一處，而且通常是客服回報才發現。宣告式的做法是只改狀態，畫面全部由狀態算出來。不過有些事仍然是命令式的：讓輸入框取得焦點、捲動到某一列、呼叫圖表套件的 API，這些在 Vue 裡也是在狀態變了之後手動做。審查程式碼時，看到「改完資料又手動去改 DOM 或另一份重複的資料」，通常就是該改成從同一份狀態算出來的訊號。

框架怎麼知道該重跑誰？依賴追蹤的三步

上一節的購物車要自動更新，框架得知道「誰讀了哪些資料」和「資料什麼時候被改」。先替這兩件事裡的角色取名字，後面整門課都會用到。

第一個名詞是副作用（side effect）。一個函式除了回傳值以外，對外界造成的影響，例如改 DOM、印 log、發請求，都叫副作用。上面的 updateBadge 沒有回傳任何東西，它存在的意義就是改了 screen.badge，這是一個副作用。響應式系統要自動重跑的，就是這種函式：Vue 元件的渲染函式也是一個副作用，它的工作是把狀態畫到 DOM 上。

第二個名詞是依賴（dependency）。一段程式執行時讀到的資料，就是它的依賴。updateSubtotal 執行時讀了 cart.qty 和 cart.price，所以它依賴這兩個屬性；updateBadge 只讀了 cart.qty，所以改價格時它不用重跑。

有了這兩個名詞，就能說清楚框架要做的事：執行副作用時，自動記下它讀了哪些資料；之後只在這些資料改變時重跑它。這叫依賴追蹤（dependency tracking），分成三步：

  1. 先執行一次，執行期間每讀一個屬性就記下來：「updateSubtotal 讀了 cart.qty、cart.price」。
  2. 寫入時查表：有人寫 cart.qty = 0，查出讀過 cart.qty 的有 updateSubtotal、updateBadge、updateCheckout。
  3. 讓它們重新執行。重新執行時又會記一次依賴，所以依賴表永遠是最新的。

對照上一節的 bug：手動寫法漏掉的，正是第 2 步查表那件事。依賴追蹤把「改了 qty 要通知誰」從寫程式的人的記憶，變成執行時自動收集的一張表。誰讀過 qty，表上就有誰，不可能漏。

這三步裡，第 3 步「讓函式重新執行」只是呼叫函式，不難。難的是第 1 步和第 2 步：程式寫的是普通的 cart.qty * cart.price 和 cart.qty = 0，框架要能在「讀取」和「寫入」發生的那一刻插手，否則根本不知道發生了讀寫。這一課就專心解決「怎麼插手」；依賴表怎麼存、怎麼通知，留到第 2 課。那麼，JavaScript 給了我們哪些插手的機會？

JavaScript 能在哪裡插手讀和寫？

先試最直覺的寫法：把數量放在一個普通的變數裡。在一個函式或模組裡用 let、const 宣告的變數叫區域變數，讀它、改它都是語言本身直接完成的，中間沒有任何讓你插入程式的地方。執行後看 subtotal 是不是跟著 qty 變：

subtotal 還是 80。第一行讀了 qty、第三行改了 qty，這兩件事都沒有任何程式知道。JavaScript 在執行時沒有提供攔截區域變數讀寫的機制，所以不靠編譯器改寫程式碼的話，沒辦法把 let qty 變成響應式。

物件屬性就不一樣了。物件的屬性有兩種：一種是一般的資料屬性（data property），值直接存在物件上；另一種是存取器屬性（accessor property），用 get／set 定義，讀這個屬性時執行 get 函式、寫它時執行 set 函式。TS 課第 3 課的 getter／setter 就是存取器屬性。因為讀寫會執行你寫的函式，你就有了插手的位置。下面把數量包進一個物件的 value 屬性，執行後看讀、寫各印了什麼：

讀和寫都被看到了：qty.value * 80 觸發了 get，qty.value = 2 觸發了 set。只要把「印 log」換成「記下誰讀了」和「通知讀過的人」，就是上一節的依賴追蹤第 1、2 步。

這就是 Vue 的 ref 要把值包進 { value } 的原因：數字本身攔截不到，只好放進一個物件的屬性裡，讓讀寫經過 getter／setter。Vue 官方文件的〈Reactivity in Depth〉也這樣說明：JavaScript 攔截不到區域變數的讀寫，只能攔截物件屬性的存取。在不改寫原始碼的前提下，.value 是語言限制下的做法，不是 Vue 的設計偏好。第 3 課會自己做出 ref。

單一個數字可以這樣包。但購物車是一整個物件，有 qty、price、商品清單，還可能被加上折扣碼。最直接的想法是：把物件上每一個屬性都換成存取器屬性。這正是 Vue 2 的做法，下一節看它能走多遠。

把每個屬性都換成 getter／setter 夠不夠？Vue 2 的做法

上一節的 box 是在建立物件時就寫好 getter／setter。對一個已經存在的物件，JavaScript 提供 Object.defineProperty(obj, key, 描述)：它可以把物件上某個屬性重新定義成存取器屬性。Vue 2 要支援沒有 Proxy 的舊瀏覽器，所以只能用這個方法：建立元件時，走遍 data 裡每一個已經存在的屬性，逐一改成 getter／setter。

下面是同樣想法的簡化版，套在購物車上。程式第一行的 Reflect.get(obj, key) 先當成 obj[key] 看就好，它是什麼留到下一節講。執行後逐行對照註解，看哪些操作有印出 log、哪些沒有：

（型別 Cart 把 qty、coupon 寫成可選的 ?，範例才能新增、刪除它們；TypeScript 不允許 delete 必填的屬性。）

只有 cart.qty = 2 被攔到。原因要回到 defineProperty 的運作方式：它一次只改造一個已知的屬性。改造發生在建立的那一刻，那時 cart 上只有 qty 和 items，所以只有這兩個屬性變成存取器。之後的操作逐一看：

  • cart.coupon = 'NEW10'：coupon 是新加的屬性，它是一般的資料屬性，沒有 setter，寫入時沒人知道。
  • delete cart.qty：刪除屬性不是「寫入」，不會呼叫 setter。屬性連同它的 getter／setter 一起消失。
  • cart.items[1] = '可頌'：這行先讀 cart.items（有 getter，所以印了「讀 items」），拿到的是陣列本身；接著寫入的是陣列的索引 1，陣列的索引從來沒被改造過。

換成購物車的實際情境：使用者輸入折扣碼、從購物車移除某個欄位、把第二項商品換成可頌，三個操作畫面都不會動。這就是 Vue 2 官方文件 Change Detection Caveats 列出的限制：

  • 偵測不到新增屬性和刪除屬性，要改用 Vue.set(obj, key, value)／Vue.delete。這兩個函式會替新屬性補上 getter／setter，並主動通知畫面更新。
  • 偵測不到陣列的索引寫入（items[1] = 'x'）和改 length，要改用 splice 或 Vue.set。push、splice 這些方法能用，是因為 Vue 2 另外改寫了陣列的方法。
  • 建立時要走遍整個物件，資料越大，初始化越慢。

這些限制的根源是同一個：defineProperty 是「一個屬性一個屬性地改造」，攔得到的範圍在改造那一刻就定死了。要徹底解決，需要一種能攔截「對整個物件的任何操作」的機制，不管屬性是不是事先存在。

💡 實務上：接手 Vue 2 專案時先想到這張清單
Vue 2 已在 2023 年底停止維護，但不少公司的後台還在跑。在這類專案遇到「資料改了畫面沒動」，先檢查是不是新增屬性、刪除屬性、或用索引改陣列；程式碼裡的 this.$set（Vue.set 的元件內寫法）也是為了這個。查網路上的解法時，先確認回答針對的是 Vue 2 還是 Vue 3：Vue 2 的 $set 在 Vue 3 已經移除，不需要也不能用。專案升級到 Vue 3 時，這些 $set／$delete 都可以改回一般的賦值和 delete。

能不能攔截整個物件？Proxy 與 Reflect

上一節的結論是：要攔截「對整個物件的任何操作」。JavaScript 內建的 Proxy（代理物件）就是為此設計的。

Proxy 的運作方式：用 new Proxy(target, handler) 建立一個新物件，它包住原本的物件（叫 target）。之後對這個 proxy 做的每一種操作，讀屬性、寫屬性、刪除屬性、用 in 檢查、列出所有鍵，都會先交給 handler 這個物件處理。handler 上負責某一種操作的函式叫攔截器（trap）：get 負責讀、set 負責寫、deleteProperty 負責刪除、has 負責 in、ownKeys 負責列出鍵。沒寫的 trap 就照原本的行為直接作用在 target 上。

新增 coupon 印了 set，刪除印了 delete，in 印了 has，Object.keys 印了 ownKeys。最後一行印出的 cart 也看得到 qty 已經是 2：proxy 自己不存資料，所有操作最後都落在 target 上。

還有一個細節：範例印 key 時寫的是 String(key)。key 不一定是字串，也可能是 Symbol，例如把 proxy 放進模板字串 `${p}` 時，JavaScript 會先讀 p[Symbol.toPrimitive]。用模板字串 `${key}` 轉 Symbol 會丟 TypeError；String(key) 則會得到 'Symbol(…)'。練習 1 會用到這點。TypeScript 怎麼替 handler 推斷型別，查表用，見課末「補充與查表」。

這和 defineProperty 的差別在攔截的單位。defineProperty 攔的是「某個屬性」，要事先知道有哪些屬性；Proxy 攔的是「對這個物件的操作」，屬性存不存在都一樣會經過 trap。所以新增、刪除、陣列索引全都攔得到，建立時也不用走遍所有屬性。這就是 Vue 3 改用 Proxy 的原因。

每個 trap 最後都呼叫了一個 Reflect.xxx。Reflect 是 JavaScript 內建的一組函式，每一個都對應一種物件操作的預設行為，而且名稱和參數跟 trap 一一對應：Reflect.get(target, key, receiver) 就是「照原本的方式讀」，Reflect.set 就是「照原本的方式寫」，並回傳 true／false 表示成功與否。trap 接手了操作，就要負責把原本的操作完成，否則寫入根本不會發生。在 trap 裡做完自己的事，再用同名的 Reflect 函式完成原本的操作，是最不容易出錯的寫法。為什麼不直接寫 target[key] = value？接下來兩小節就是兩個不用 Reflect 會出錯的地方。

set 一定要回傳 true

第一個要靠 Reflect 避開的坑：set 和 deleteProperty trap 要回傳成功與否。回傳 false（或什麼都沒回傳，也就是 undefined）代表「這次寫入失敗」。失敗之後會怎樣，要看程式跑在哪種模式。嚴格模式（strict mode）是 JavaScript 一套比較嚴的執行規則，會把很多原本悄悄失敗的操作改成直接丟錯。非嚴格模式下，set trap 回報的失敗會被悄悄忽略，程式照常往下跑；嚴格模式下，寫入的那一行會丟 TypeError。ES module 一律是嚴格模式，Vite 專案的程式全都是 ES module，所以 Vue 專案裡寫的 Proxy 都受這條規則管。下面的 set 忘了 return，編輯器會在 set 底下畫紅線（ProxyHandler 規定 set 要回傳 boolean），但範例照樣能執行，執行後看印出的錯誤：

值其實已經寫進 target，但呼叫的那一行還是炸了。對使用者來說，這等於「購物車按了加一，數量變了，但後面的程式全部中斷」。TypeScript 能擋下「忘了 return」，擋不下「回傳了 false」（例如自己寫 return false 想拒絕寫入）；那種情況執行時一樣丟 TypeError。寫 return Reflect.set(…)，寫入成功與否原封不動交回去，就不會錯。

receiver：getter 裡的 this 要是 proxy

第二個坑跟 getter 有關，所以範例要換一個有 getter 的物件。購物車的小計是 price * qty 算出來的，實務上常寫成物件上的 getter，下面的訂單就是這樣：total 是 getter，它讀 this.price 和 this.qty。我們要的依賴是「讀 total 的畫面，依賴 price 和 qty」，所以 getter 裡的兩次讀取也必須被 get trap 看見。

get trap 的第三個參數、set trap 的第四個參數叫 receiver，代表這次操作原本的 this，通常就是 proxy 本身。它決定 target 上的 getter／setter 執行時，this 指向誰。範例用 spy 記錄每一次經過 get trap 的屬性名，執行後比較兩行印出的陣列長度：

沒傳 receiver 時只記到 total。target[key]、Reflect.get(target, key)（少了 receiver）都等於在原物件上呼叫 getter，TS 課第 1 課說過「點號前面是誰，this 就是誰」，這時點號前面是原物件，所以 this 是原物件，裡面的 this.price、this.qty 直接讀原物件，完全沒經過 proxy。傳了 receiver，getter 的 this 換成 proxy，this.price 又走進 trap，三個屬性都記到了。

對響應式來說，沒傳 receiver 代表「total 依賴 price 和 qty」沒被記下來。之後改價格，用到 total 的畫面不會更新，這正是我們想消滅的那種 bug。所以 get trap 一律寫 Reflect.get(target, key, receiver)。

到這裡，Proxy 補上了 Vue 2 的所有洞。但 Proxy 的運作方式是「另外建立一個新物件包住原物件」，這帶來一組 defineProperty 沒有的新問題：原物件還在，而且它和 proxy 不是同一個東西。

包成 proxy 之後，哪些操作還是攔不到？

上一節的範例都是對 proxy 操作。實際的程式裡，原物件的變數往往還留著，巢狀物件也很常見。購物車的巢狀資料 items 是陣列，陣列的情況留到練習；這裡換另一筆訂單，它跟上一節有 getter 的訂單不是同一個，多了一個巢狀的一般物件 customer，比較好觀察。set trap 每被呼叫一次就把 sets 加一。執行後對照每行註解，看 sets 有沒有增加：

三行輸出對應 Proxy 的三個特性，每一個都會在 Vue 裡變成一個陷阱：

  • proxy !== 原物件：new Proxy 建立的是另一個物件。Vue 的 reactive(obj) 回傳的也是新的 proxy，官方建議之後只用 proxy，別再碰原物件。
  • 改原物件不會觸發任何東西：order.total = 90 沒經過 trap，sets 還是 0。但 p.total 讀到 90，因為 proxy 讀的仍是 target。值變了，卻沒人被通知，對畫面來說就是「資料改了畫面沒動」。資料能被追蹤，完全是因為操作經過了 proxy。
  • Proxy 只包一層：讀 p.customer 拿到的是原本的巢狀物件，不是 proxy（就算寫了 get trap，Reflect.get 回傳的也是原本那個物件）。接著 .name = '陳美華' 是對那個巢狀物件的寫入，跟 p 的 set trap 無關，sets 還是 0。

還有第四個特性範例沒示範：Proxy 只能包物件。數字、字串這類原始值包不了，new Proxy(80, {}) 在 TypeScript 是型別錯誤（target 要是 object），在 JavaScript 執行時丟 TypeError。這是 ref 需要 { value } 的另一個原因：就算有 Proxy，單一個數字還是得先放進物件。

前兩個特性的解法是使用習慣（只用 proxy）。第三個「只包一層」則要改程式：購物車的商品清單、訂單的顧客資料都是巢狀的，必須讓巢狀物件也被攔截。

巢狀物件：讀取時才包，並且快取

做法是在 get trap 裡檢查讀到的值：如果是物件，就再包一層 proxy 回傳。這樣 p.customer 拿到的就是 proxy，.name = … 會經過 set trap。這種「用到才做」的策略叫 lazy：不像 Vue 2 一開始就走遍整個物件，沒讀到的部分完全不花成本。Vue 3.5 的 reactive 也是這樣做的。

但如果每次讀取都 new Proxy，同一個巢狀物件每次拿到的 proxy 都不同。要避免這件事，需要一張表記住「這個原物件已經包過了，它的 proxy 是哪一個」。這張表用 WeakMap：TS 課第 2 課教過，它的鍵必須是物件，鍵物件沒有其他人在用時，會連同對應的值一起被回收，所以快取不會讓舊資料一直佔著記憶體。範例比較兩種寫法，執行後看三行的 true／false：

沒有快取時，a.customer === a.customer 是 false。這會讓 includes、indexOf、=== 這類比較失敗，例如「這位顧客是不是目前選中的那位」永遠判斷為否；每次讀取也多建立一個物件。用 WeakMap 記住「原物件 → proxy」之後，同一個物件永遠拿到同一個 proxy，連對最外層物件再包一次也拿到同一個。Vue 內部也有一個同樣用途的 WeakMap（原始碼裡叫 reactiveMap），所以 reactive(obj) === reactive(obj)。

到這裡，攔截這一半的拼圖都齊了：讀寫、新增刪除、getter、巢狀物件都攔得到，而且身分一致。

💡 實務上：拿到 reactive 之後，原物件就別再用了
常見的坑：把 API 回傳的訂單物件傳進 reactive，卻在另一個函式裡繼續改原本那個物件，結果資料變了、畫面沒動。另一個常見情況是比較身分：拿原物件和 proxy 做 ===，結果是 false，像「這筆訂單是不是目前選中的那筆」這種判斷就會出錯。在 DevTools 的 console 印出 reactive 物件時會看到 Proxy(Object)，這是正常的，不是 bug。團隊裡的習慣通常是：資料一拿到就轉成響應式，之後所有讀寫都只經過 proxy，原物件的變數不再往外傳。

回到購物車：Vue 3 實際怎麼組起來？

回頭看開場的任務：要讓購物車改了之後，用到它的地方自動更新。這課學到的攔截手法，Vue 3 是怎麼組合的？Vue 官方文件〈Reactivity in Depth〉用下面這段 pseudo-code 說明。pseudo-code 是為了說明想法而寫、省略了細節、不能直接執行的程式。track 和 trigger 就是依賴追蹤的第 1、2 步，下一課會實作：

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key) {
      track(target, key)      // 記下：目前執行的函式讀了 target.key
      return target[key]
    },
    set(target, key, value) {
      target[key] = value
      trigger(target, key)    // 通知：讀過 target.key 的函式重新執行
    }
  })
}

function ref(value) {
  const refObject = {
    get value() {
      track(refObject, 'value')
      return value
    },
    set value(newValue) {
      value = newValue
      trigger(refObject, 'value')
    }
  }
  return refObject
}

兩個函式分別對應這課的兩條路：物件用 Proxy 的 get／set trap，單一值用 getter／setter 包成 { value }。這段為了好讀省略了很多事，而省略的正好是你這課學到的：真正的實作用 Reflect.get(target, key, receiver)、set 會回傳結果、值沒變就不觸發、巢狀物件讀取時才包並用 WeakMap 快取。把 Vue 2 和 Vue 3 放在一起對照：

Vue 2Vue 3
物件的攔截方式Object.defineProperty（getter／setter）reactive() 用 Proxy
單一值放在 data() 回傳的物件裡ref() 用 getter／setter 包成 { value }
新增、刪除屬性偵測不到，要 Vue.set／Vue.delete偵測得到
陣列索引、length偵測不到偵測得到
巢狀物件建立時就走遍整個物件讀取時才包（lazy）
改原物件原物件就是被改造過的那個，會觸發proxy 和原物件不同，改原物件不觸發

最後完成這課的任務：讓一段程式在執行期間讀 proxy，用 get trap 記下它讀了哪些屬性，就得到它的依賴清單。這就是依賴追蹤的第 1 步。範例把小計那段畫面交給 recordReads，執行後看印出的依賴清單，以及改 note（備註「少冰」）時需不需要重算：

練習

練習 1：寫 logAccess(obj, log)，回傳 obj 的 Proxy：

  • 每次讀屬性，先 log.push('get 屬性名') 再取值；每次寫屬性，log.push('set 屬性名')。屬性名用 String(key) 轉成字串，因為 key 可能是 Symbol。
  • 寫入要真的改到原物件，而且不能讓寫入的那一行丟錯。
  • 物件上的 getter（例如 total 會讀 this.price、this.qty）被讀時，裡面的讀取也要記錄到。

練習 2：寫 observe(obj, onChange)，回傳 obj 的 Proxy，在下列情況呼叫 onChange(key, oldValue, newValue)：

  • 屬性的值真的改變。設成相同的值不呼叫，NaN 改成 NaN 也不呼叫（想想 TS 課第 2 課的 Object.is）。
  • 新增屬性：一律呼叫，就算新值是 undefined（用 Object.hasOwn 判斷原本有沒有這個屬性）。
  • 刪除屬性：呼叫，newValue 是 undefined。刪除不存在的屬性不呼叫。
  • onChange 被呼叫時，物件上必須已經是新值（先寫入，再通知）。
  • 舊值用 Reflect.get(target, key) 讀（泛型的 target[key] 是型別錯誤）。

這正是 Vue 3.5 的 set、deleteProperty trap 決定「要不要通知」的規則。

練習 3：寫 readonlyView(obj)，回傳唯讀的 proxy，讓元件可以讀訂單、但改不了它：

  • 透過它寫入或刪除任何一層的屬性，都丟出 new Error(`唯讀：不能修改 ${String(key)}`)。所以 view.items.push('可頌')、view.customer.name = '…' 也要丟錯。
  • 巢狀物件與陣列在讀取時才包成唯讀，而且同一個巢狀物件每次讀到的是同一個 proxy（view.items === view.items）。
  • 原物件不能被改動：不能凍結它（TS 課第 2 課的 Object.freeze），也不能把 proxy 寫回原物件。原物件改了，view 要讀到新值。
  • 型別提示：快取可以寫成 new WeakMap<object, object>()，取出時照上面「巢狀物件」範例的 deepCached，用 as 轉回原本的型別。

Vue 有內建的 readonly()，規則類似，但寫入時是在開發模式印警告、不丟錯。

練習 4：為什麼 Vue 3 不能讓 let count = 0 直接變成響應式，而要寫 ref(0) 再用 .value？

✓ b。響應式靠的是「讀取、寫入時插手」，而 JavaScript 只提供攔截物件屬性的方法（getter／setter、Proxy）。a 錯在 Vue 沒有追蹤變數的魔法，範本（template）裡不用寫 .value，是 Vue 幫你自動取出（第 4 課會講什麼時候會、什麼時候不會）。c 錯在 Proxy 根本包不了數字，不是記憶體的取捨。

練習 5：const p = new Proxy(order, handler) 之後執行 order.total = 90（改的是原物件），handler 的 set 會被呼叫嗎？

✓ c。proxy 是另一個物件（p !== order），它只攔截對自己做的操作。改原物件繞過了 trap，但 proxy 讀的時候仍然讀 target，所以值是新的，只是沒人被通知。Vue 也一樣：改了 reactive 的原物件，畫面不會更新。b 錯在 trap 不會事後補呼叫。

練習 6：Vue 2 的元件裡，data 是 { cart: { qty: 1 } }。執行 this.cart.coupon = 'NEW10' 之後畫面沒有顯示折扣碼，原因是？

✓ a。defineProperty 一次只能改造一個已知的屬性，之後新增的屬性只是普通屬性，寫入時沒人知道。Vue 3 的 Proxy 攔截的是整個物件的操作，所以新增屬性也偵測得到。b 錯在 qty 是數字也照樣能響應；c 錯在根本沒有觸發更新，等多久都不會出現。

常見錯誤

  • set trap 忘了回傳 true：ES module 是嚴格模式，回傳 false 或 undefined 會讓寫入的那一行丟 TypeError，就算值已經寫進去也一樣。直接 return Reflect.set(target, key, value, receiver)。
  • trap 裡用 target[key] 取代 Reflect.get(target, key, receiver)：getter 的 this 變成原物件，裡面的讀取攔截不到，依賴就漏記了，改了 getter 讀的屬性，畫面不會更新。
  • 以為改原物件也會觸發 trap：只有經過 proxy 的操作才會被攔截。拿到 proxy 之後就只用 proxy。
  • 每次讀巢狀物件都 new Proxy：同一個物件得到不同的 proxy，===、includes 失敗，又多建立物件。用 WeakMap 快取「原物件 → proxy」。
  • 想用 Proxy 包數字或字串：new Proxy(80, {}) 直接丟 TypeError。原始值要放進物件的屬性，這就是 ref。
  • 用模板字串把 key 轉成字串：key 可能是 Symbol，`${key}` 會丟 TypeError，用 String(key)。

補充與查表

Proxy 在 TypeScript 裡的型別

在 TypeScript 裡，new Proxy(target, handler) 的 handler 型別是內建的 ProxyHandler<T>，所以 trap 的參數不用自己寫型別：target 是 T、key 是 string | symbol、receiver 是 any；回傳的 proxy 型別跟 target 一樣是 T。Reflect.get 回傳 any，因為 TypeScript 不知道你讀的是哪個屬性。另外，泛型的 target[key] 會報型別錯誤（string | symbol 不一定是 T 的鍵），這也是 trap 裡一律用 Reflect 的另一個好處。

小結

  • 響應式解決「改了資料，要記得更新每個用到它的地方」的問題：畫面 = f(狀態)，由框架負責重算。購物車清空後按鈕沒更新，就是手動同步漏了一處。
  • 依賴追蹤三步：執行時記下讀了什麼、寫入時查出誰讀過、讓它們重新執行。難的是前兩步，框架要能在讀寫的那一刻插手。
  • JavaScript 攔截不到區域變數，只能攔截物件屬性，所以 Vue 的 ref 要用 .value。
  • Vue 2 用 defineProperty 逐一改造已存在的屬性，偵測不到新增、刪除屬性與陣列索引；Vue 3 的 reactive 用 Proxy 攔截整個物件的操作，全都偵測得到。
  • trap 裡用 Reflect 完成原本的操作：set 要回傳 true，get 要傳 receiver 讓 getter 的 this 是 proxy。
  • proxy 不等於原物件，改原物件不觸發；巢狀物件讀取時才包，用 WeakMap 快取。
  • 讓函式在執行期間讀 proxy、用 get trap 記下讀了什麼，就得到它的依賴清單。
