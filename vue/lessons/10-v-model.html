階段 3：元件如何運作 · 第 10 課

v-model 與 defineModel

點餐頁的每一張品項卡上有一個數量輸入框元件 QuantityInput。上線第一天就收到三個回報：

  1. 客人在已經有 1 杯的品項上加點「2」，購物車變成「12」杯。
  2. 另一位客人打了 30，購物車真的記了 30 杯，店裡沒有人做得出來。
  3. 後台的顧客資料表單：PM 要求改到一半按「放棄修改」要回到原本的資料，但實際上改完姓名再按「放棄修改」，原本的姓名已經不見了。

這三件事都出在 v-model 怎麼寫。這課從原生 <input> 開始，一路把 QuantityInput 修好：讓父元件拿到的一定是 1 到 20 的數字，再讓同一張品項卡綁上甜度、冰塊和備註，最後處理顧客表單，判斷「放棄修改」這種需求為什麼不該用 v-model。

這課的路線：
  1. 為什麼數量變成「12」：原生 input 的 v-model 展開成什麼、寫回的值為什麼是字串；包成元件之後，v-model 變成一個 prop 加一個事件（開場問題的最小答案）。
  2. defineModel：同一件事少寫一半；初始值為什麼不能靠子元件的 default。
  3. set 轉換器：把數量限制在 1 到 20，所有輸入路徑都擋得住。
  4. 多個 model 與修飾符：同一張品項卡綁甜度、冰塊、備註。
  5. 顧客表單：model 是物件時為什麼「放棄修改」失效，以及什麼時候該改用草稿加事件、不用 v-model。
這課會用到：
  • 第 9 課的 props、emits 與單向資料流：子元件不改 props，用 emit 請擁有資料的元件改，改完新的值再往下傳。
  • 第 8 課的 Vue Test Utils：用 mount 掛上元件、setValue 模擬輸入，再檢查畫面和發出的事件。

數量為什麼變成「12」？原生 input 的 v-model 寫回了什麼

先不管元件，從一個最普通的輸入框看起。點餐頁要讓畫面上的輸入框和變數 qty 保持一致：變數是 2，框裡就顯示 2；客人在框裡改成 3，變數也要跟著變成 3。這種「資料改了畫面跟著變，畫面改了資料也跟著變」的關係叫雙向綁定（two-way binding）。

雙向綁定其實是兩件事：把變數的值放到輸入框上，以及監聽輸入事件、把框裡的新值寫回變數。每個輸入框都手寫這兩半很囉唆，所以 Vue 提供 v-model。它是一種語法糖（syntactic sugar）：寫起來短，編譯器會把它展開成較長的寫法，功能上沒有多出新東西。概念上展開成這樣：

<input v-model="keyword">

<!-- 概念上等於 -->
<input :value="keyword" @input="keyword = $event.target.value">

注意寫回去的是 $event.target.value。輸入框的 value 永遠是字串：客人打 2，寫回變數的是 '2'，不是 2。這就是「12 杯」的來源。購物車原本記著數字 1，拿到字串 '2' 後做 1 + '2'；JavaScript 的 + 只要有一邊是字串就做字串相接，結果是 '12'。畫面看起來沒問題，只有算錢、加總的時候才出錯，所以很容易一路漏到正式環境。

上面是「概念上」的展開。實際上 Vue 的編譯器產生的是一個內建指令 vModelText，再加一個 onUpdate:modelValue 函式負責寫回變數（在 Vue 3.5.44 編譯過確認）。指令多處理了幾件手寫版沒做的事，其中一件跟中文輸入直接有關。用注音或倉頡打字時，字還沒選定之前的狀態叫組字（composition）：框裡顯示「ㄋㄚˊ」，但客人還沒按下選字。內建指令在組字中不更新變數，選完字才更新；手寫 @input 的版本，打「ㄋㄚˊ」的每一個符號都會寫進變數。不同的表單元素（checkbox、radio、select）綁的屬性和聽的事件也不一樣，對照表放在課末〈補充與查表〉。

回到字串問題。v-model 有內建的修飾符（modifier）：寫在指令後面、用點接起來的小開關，用來改變指令的行為，例如 v-model.number。內建的有三個：

修飾符作用要注意
.trim寫回之前去掉頭尾空白中間的空白不動
.number用 parseFloat 轉成數字轉不出數字（例如 'abc'）時保留原字串，型別不保證是 number；type="number" 的 input 會自動套用
.lazy改在 change 事件才寫回不是「延遲幾毫秒」：文字框是失去焦點或按 Enter 時才觸發 change

.number 看起來正好解決「12 杯」，但第二欄是常見誤會：它只在轉得出數字時才轉。parseFloat('2杯') 是 2，parseFloat('') 是 NaN，所以留下空字串。客人把框清空的那一刻，購物車拿到的又是字串。它也不管範圍，30 杯照樣寫進去。資料要保證是數字、還要有範圍，得自己寫規則，這就是後面 set 轉換器要做的事，也是練習 2。

💡 實務上：點餐頁的每個輸入框，先選對事件再談其他
點餐頁上方的「搜尋品項」框要邊打邊查，用預設的 v-model（聽 input，組字中不更新，注音使用者不會一直觸發查詢）；要減少打 API 的次數，是在 watch 裡加防抖（第 5 課），不是加 .lazy。品項卡上的備註這類打完才需要的欄位，.lazy 可以少觸發很多次計算與驗證。自己手寫 :value＋@input 或包第三方輸入元件時，先用注音打幾個字試試，確認選字途中不會觸發查詢或驗證。另外記得：前端的 .number、.trim 只是讓體驗好一點，後端 API 一樣要驗證型別和範圍，30 杯的訂單最後要靠後端擋下來。

原生輸入框的行為清楚了。但點餐頁用的不是裸的 <input>，而是包成元件的 QuantityInput。v-model 寫在元件上時，值要怎麼跨過元件的邊界傳回父元件？

包成 QuantityInput 元件之後，v-model 展開成什麼？

v-model 也能寫在元件上。父元件寫起來跟原生輸入框一樣，但編譯器展開的東西不同：元件沒有 value 屬性，也沒有原生的 input 事件，所以展開成一個 prop 加一個自訂事件，名稱是固定的：

<QuantityInput v-model="qty" />

<!-- 展開成 -->
<QuantityInput
  :modelValue="qty"
  @update:modelValue="v => qty = v"
/>

modelValue 是元件 v-model 預設的 prop 名稱，update:modelValue 是預設的事件名稱。所以元件 v-model 不是什麼特別的「雙向連線」，就是第 9 課的單向資料流：資料往下傳給子元件，子元件用事件請父元件改，父元件改了再往下傳。qty 自始至終只有父元件那一份。

知道展開成什麼之後，子元件要做的事就很明確：接收 modelValue 顯示在輸入框上，客人輸入時送出 update:modelValue。父元件拿到的型別，完全取決於子元件 emit 出去的是什麼。「12 杯」的 QuantityInput 原本直接把 $event.target.value 送出去，所以父元件拿到字串。修正是在送出前轉成數字：

<script setup lang="ts">
const props = defineProps<{ modelValue: number }>()
const emit = defineEmits<{ 'update:modelValue': [value: number] }>()
</script>

<template>
  <input
    :value="props.modelValue"
    @input="emit('update:modelValue', Number(($event.target as HTMLInputElement).value))"
  >
</template>

這兩半的名稱要跟展開結果完全一致，拼錯一個字父元件就收不到。畫面上輸入框照樣能打字，因為原生 input 自己會顯示客人打的字，但父元件的 qty 沒變。從 Vue 2 升級的專案最常在這裡出錯，細節見課末〈補充與查表〉。

「12 杯」的答案已經出來了：子元件 emit 出去的是 $event.target.value，也就是字串，所以要在送出前轉成數字。「30 杯」要等 set 轉換器那一節處理；顧客表單的問題跟物件 model 有關，留到最後兩節。不過現在的 QuantityInput 還有兩個問題：每個 v-model 元件都要手寫一組 prop 和 emit，名稱容易拼錯；Number() 只是轉型，30 杯、0 杯、清空後的 0 照樣送出去。下一節先解決第一個。

每個元件都要手寫 prop 和 emit 嗎？用 defineModel

上一節的 prop 宣告、emit 宣告、名稱對齊，每個 v-model 元件都一模一樣，所以 Vue 提供 defineModel 一次做完。它跟第 9 課的 defineProps、defineEmits 一樣是巨集（macro）：只能寫在 <script setup> 裡、不需要 import，編譯時會被替換成真正的程式碼。defineModel 在 Vue 3.4 成為穩定功能。它幫你宣告 modelValue prop 和 update:modelValue 事件，回傳一個 ref：

<script setup lang="ts">
const qty = defineModel<number>({ required: true })
</script>

<template>
  <input v-model="qty">
</template>

這個 ref 讀和寫的行為不一樣，弄懂這點，後面的陷阱就都說得通：

  • 讀 qty.value：讀到的是 prop 的值。
  • 寫 qty.value = 3：送出 update:modelValue 事件，帶 3。子元件沒有改 prop，是請父元件改；父元件改了，prop 傳下來，qty.value 才變成 3。
  • required: true：父元件忘了綁 v-model 時，開發模式會警告。沒加的話型別是 number | undefined，元件裡每個地方都要處理 undefined。

名稱由 defineModel 產生，上一節「拼錯名稱父元件收不到」的問題就沒了。但有一個行為要知道：父元件沒有用 v-model 時（沒傳 prop，或只傳 prop 沒聽事件），defineModel 回傳的 ref 會變成元件自己的本地狀態，寫入時照樣送事件，但值存在子元件裡。值由父元件掌握的用法叫「受控」，值存在元件自己身上的叫「不受控」；這個行為讓同一個元件兩種用法都行。代價是父元件拼錯事件名稱時不會壞得很明顯：子元件自己能動，父元件的資料卻沒更新。測試要從父元件那一側檢查值，不能只看子元件畫面，這課的練習都是這樣檢查的。

接著是初始值。點餐頁新加入的品項，數量應該從 1 開始。有人會想直接在子元件寫 default: 1，官方文件正好用這個例子說明為什麼不行：

<!-- Child.vue -->
const model = defineModel({ default: 1 })

<!-- Parent.vue -->
const myRef = ref()                  // undefined
<Child v-model="myRef" />

子元件顯示 1，父元件的 myRef 還是 undefined（Vue 3.5.44 實測）。原因回到上面讀和寫的規則：default 是 prop 的預設值，只影響子元件「讀」到什麼；子元件沒有「寫」，就不會送事件，父元件也就不知道。放到點餐頁，結果是畫面上的數量是 1，送出訂單時用的卻是 undefined。正確的做法是讓資料的擁有者決定初始值：父元件寫 ref(1)，子元件用 required: true，讓沒給值的情況在開發時就被警告。

💡 實務上：團隊共用的表單元件幾乎都是 v-model 介面
專案裡的數量輸入、日期選擇、地址欄位，通常會包成共用元件放在 components/form/，讓每個頁面都能 v-model；元件庫也是同一套「prop＋update:xxx 事件」：Element Plus 的輸入框直接 v-model，Naive UI 的輸入框是 v-model:value、對話框是 v-model:show。新寫一個共用元件時（例如把 QuantityInput 開放給後台的庫存頁也用），資深工程師會先確認：必填的 model 有沒有 required、型別是不是父元件真正要存的型別（數量是 number 不是字串）、初始值是不是由父元件給、測試是不是從父元件那一側驗證。

QuantityInput 現在少了一半程式碼，名稱也不會拼錯，但開場的第二個問題還在：客人打 30，購物車照樣記 30 杯。範圍限制要放在哪裡？

數量要限制在 1 到 20：放進 set 轉換器

限制範圍最直覺的做法是在 @input 的處理函式裡判斷。問題是輸入的路徑不只一條：客人打字、按「+」「−」按鈕、之後有人加上鍵盤上下鍵，每條路徑都要記得呼叫同一段檢查，漏掉一條，30 杯就又進得去。比較穩的做法是把規則放在「寫入」這個唯一的出口：上一節說過，所有對 qty.value 的寫入都會變成送給父元件的事件，在這裡把關，任何路徑都逃不掉。

defineModel 的 轉換器（transformer）就是這個出口。它是 defineModel 的兩個選項：get 在讀取時轉換 prop 的值；set 在寫入時轉換，它的回傳值才是真正送給父元件的值。限制範圍、去掉多餘字元、統一格式，都放在 set 裡：

const qty = defineModel<number>({
  required: true,
  set(value: number | string) {
    const n = Math.trunc(Number(value))
    if (!Number.isFinite(n) || n < 1) return 1
    return Math.min(n, 20)
  },
})

逐行看它擋住了什麼：value 的型別寫成 number | string，因為範本裡 <input v-model="qty"> 寫回來的是字串（第一節的結論）；Number() 轉成數字、Math.trunc 去掉小數；轉不出數字（'abc' 得到 NaN）或小於 1 時給 1；大於 20 時給 20。父元件拿到的一律是 1 到 20 的整數，「12 杯」和「30 杯」都不會再發生。練習 2 就是寫出這段規則。

轉換後的值跟父元件目前的值一樣時，defineModel 可能直接跳過：不送事件，元件也不重新渲染。實測 Vue 3.5.44：父元件給的數量本來就是 20，客人打 30，set 回傳 20，父元件不變，輸入框卻停在「30」，接著打 21、40 也一樣。從 2 改成 30 就沒有這個問題（父元件真的變了、輸入框被重新設成 20）。原因是輸入框顯示的是客人打的字；Vue 只有在重新渲染、而且新的值不同時才會覆寫它。這次父元件的值還是 20，沒有變化，所以畫面上的 30 沒人去改。正式環境可以在 blur（離開輸入框）時，把輸入框的值設回 model 的值：<input v-model="qty" @blur="($event.target as HTMLInputElement).value = String(qty)">。送出訂單時也要用 model 的值，不要讀輸入框。

數量這一個值處理好了。但品項卡上不只有數量：同一杯飲料還要選甜度、冰塊，加一段備註。一個元件要怎麼同時對父元件開好幾個 v-model？

品項卡還要綁甜度、冰塊、備註：多個 model 與修飾符

把甜度、冰塊、備註做成一個 DrinkOptions 元件放在品項卡裡。三個值各自獨立：改甜度不該動到冰塊。defineModel 的第一個參數可以給 model 一個名稱，父元件就用 v-model:名稱 綁它，展開成 prop 名稱 和事件 update:名稱。沒給名稱的就是前面的 modelValue。

<!-- DrinkOptions.vue -->
const sugar = defineModel<'正常' | '少糖' | '無糖'>('sugar', { required: true })
const ice = defineModel<'正常' | '少冰' | '去冰'>('ice', { required: true })

<!-- 父元件 -->
<DrinkOptions v-model:sugar="sugar" v-model:ice="ice" />

每個具名 model 都是獨立的一組 prop 和事件，所以各自更新、互不影響，規則跟上一節完全一樣，包括 required 和 set。

備註多了一個需求：點餐頁的備註要印在杯貼上，最多 20 個字；後台的訂單備註沒有限制。同一個元件，不同頁面要不同行為，這時可以讓父元件用修飾符說明它要的版本。修飾符除了原生輸入框的 .trim、.number，也可以自己取名，寫在元件的 v-model 上。父元件寫 v-model:note.short，子元件會多收到一個 prop noteModifiers，值是 { short: true }（預設 model 的是 modelModifiers）。用 defineModel 時，把回傳值解構成兩個就拿得到，再配合上一節的 set 在寫入時套用：

// 第二個型別參數列出這個 model 接受的修飾符，modifiers.short 才有型別
const [note, modifiers] = defineModel<string, 'short'>('note', {
  required: true,
  set(value) {
    return modifiers.short ? value.slice(0, 20) : value
  },
})

內建的 .trim、.number 用在元件上時不用自己寫：Vue 在子元件送出 update:xxx 事件時，看到父元件給了這兩個修飾符，就自動把參數 trim 或轉數字（Vue 3.5.44 的 runtime-core emit() 原始碼，本機驗證過）。自訂的修飾符 Vue 不知道是什麼意思，才要在 set 裡處理。練習 3 會同時考這兩件事。

到這裡，品項卡上的值都是字串或數字這種單一的值。後台的顧客資料表單不一樣，它的 model 是一整個物件 { name, phone }，開場那個「放棄修改」失效的 bug 就出在這裡。

顧客表單的 model 是物件：為什麼「放棄修改」失效？

出問題的寫法看起來很自然，直接把 v-model 綁到物件的屬性上：

const customer = defineModel<{ name: string; phone: string }>({ required: true })

<input v-model="customer.name">     <!-- ✗ 展開成 customer.value.name = $event -->

回到 defineModel 的規則：只有「寫入 customer.value」才會送事件。這一行沒有寫入 customer.value，而是改了 customer.value 指向的那個物件的屬性，而那個物件就是父元件傳下來的同一個物件。第 9 課講過的問題全部出現：

  • 沒有送出 update:modelValue，父元件不知道資料被改，「表單已修改」的提示、復原、送出前的比對都失效。
  • 被改的是父元件的物件本身。「放棄修改」想回到原本的姓名，但原本的姓名已經被覆蓋，沒有東西可以回去。
  • 父元件的物件如果是凍結的（例如從快取拿來、或用 Object.freeze 防止被改），嚴格模式下直接丟 TypeError。

Vue 不會警告，因為 props 只有第一層是唯讀的，裡面的物件照樣改得動。

修正是 TS 課第 2 課的不可變更新：不動原本的物件，每次產生一個新物件，指定給 .value。指定給 .value 才是「寫入」，才會送出事件：

function update(key: 'name' | 'phone', event: Event) {
  customer.value = { ...customer.value, [key]: (event.target as HTMLInputElement).value }
}

<input :value="customer.name" @input="update('name', $event)">

欄位很多時，另一個做法是把表單拆成多個具名 model（v-model:name、v-model:phone），每個都是字串，就回到上一節的情況，不會有這個問題。練習 4 用的是不可變更新，測試會傳入凍結的物件。

這樣父元件的原物件不再被偷改。但仔細想「放棄修改」：每打一個字，父元件就收到一個新物件並換掉自己的資料。父元件的 customer 還是跟著每次輸入變了，按「放棄修改」時一樣沒有原本的資料可以回去。問題已經不在寫法，而在 v-model 本身的意思。

「放棄修改」要能回到原值：什麼時候不該用 v-model？

v-model 的意思是「這個值由子元件編輯，改了就立刻生效」。顧客表單的需求正好相反：改動要等按下「儲存」才生效，按「放棄修改」就當作沒發生。需求跟 v-model 的意思不符時，不是寫法要更小心，而是改用明確命名的 prop 和事件。下面幾種情況都是這樣：

情況為什麼不適合 v-model改用
刪除品項前要確認v-model 一改值就生效，沒有「確認之前不要動」的空間@remove-request，父元件確認後自己刪
值要先經過非同步驗證（例如優惠碼要問伺服器）set 轉換器是同步的；先寫進去再驗證，中間那段時間資料是錯的本地草稿＋@apply="code => …"，驗證通過才寫入
事件的意思比值重要（送出、加入購物車）父元件要知道「發生了什麼事」，不是「值變成什麼」@submit、@add，帶需要的資料

判斷方式：把 v-model="x" 換成「子元件隨時可能把 x 改成任何值」來讀，如果這句話讓你不安，就不要用 v-model。拿這課的例子試：品項卡的數量「隨時可能被改成任何值」沒關係，因為 set 已經把關；顧客資料「隨時可能被改」就不行，因為 PM 要求能取消。

所以顧客表單改成「草稿＋事件」。子元件不再用 defineModel，而是用一般的 prop 收到顧客資料，打開時複製一份自己的草稿，輸入框的 v-model 綁草稿。草稿是子元件自己的 ref，怎麼改都碰不到父元件的資料：

<!-- CustomerForm.vue -->
<script setup lang="ts">
import { ref } from 'vue'

type Customer = { name: string; phone: string }
const props = defineProps<{ customer: Customer }>()
const emit = defineEmits<{ save: [customer: Customer] }>()

// 複製一份草稿：之後的輸入都只改它
const draft = ref({ ...props.customer })

function save() {
  emit('save', { ...draft.value })
}
function discard() {
  draft.value = { ...props.customer }   // 回到父元件手上的原始資料
}
</script>

<template>
  <input v-model="draft.name">
  <input v-model="draft.phone">
  <button @click="save">儲存</button>
  <button @click="discard">放棄修改</button>
</template>

<!-- 父元件 -->
<CustomerForm :customer="customer" @save="onSave" />

async function onSave(next: Customer) {
  await api.updateCustomer(next)   // API 成功之後
  customer.value = next            // 才更新自己的資料
}

這裡的 draft.name 用 v-model 沒問題，因為 draft 是子元件自己的資料，改它本來就是子元件的事；上一節出問題，是因為被改的是父元件傳下來的物件。

為什麼這樣「放棄修改」就回得去？因為在按下「儲存」之前，父元件的 customer 完全沒被碰過：沒有被改屬性，也沒有被換成新物件。discard() 只要再從 props.customer 複製一次，草稿就回到原本的資料。按「儲存」時，父元件也是等 API 成功才更新，API 失敗的話畫面上的資料仍然是伺服器上那一份。

💡 實務上：v-model 留給「改了就生效」的值
對話框的開關（v-model:show）、篩選條件、分頁大小這類值，改了就應該立刻生效，用 v-model 剛好；需要確認、取消、等伺服器回應的編輯，用草稿＋事件。Code review 看到元件上的 v-model 時，問一句「這個值改了就立刻生效對嗎？」通常就能判斷用法對不對。

補充與查表

主線用不到、但寫其他表單元素、維護舊專案時會用到的細節。

各表單元素的 v-model 綁什麼、聽什麼

查表用，不用背。不同的表單元素，v-model 綁的屬性和聽的事件不一樣（依 Vue 3.5.44 的 runtime-dom 原始碼）：

元素綁的屬性聽的事件
<input>（文字類）、<textarea>valueinput（加 .lazy 改成 change）
<input type="checkbox">checked（綁陣列時是「陣列裡有沒有這個值」）change
<input type="radio">checked（和自己的 value 比較）change
<select>被選取的 <option>change

從 Vue 2 升級：元件 v-model 的名稱改了

Vue 2 的元件 v-model 用的是 value prop 和 input 事件；照舊習慣寫 emit('input', …) 或 emit('update:value', …)，Vue 3 的 v-model 一個都收不到，畫面看起來能打字，父元件的值卻沒變。舊專案從 Vue 2 升級時，先搜尋 emit('input' 和 value prop，這是升級後「畫面能打字但存不進去」最常見的原因。改用 defineModel 就不會拼錯。

版本備註

練習用的是 Vue 3.5.44。defineModel 在 Vue 3.4 成為穩定功能；這課提到的實測結果（default 不同步、set 回傳相同值時跳過更新、元件上的 .trim、.number 自動處理）都是在 3.5.44 確認的。

練習

本機練習在 vue/practice/work/10/。測試裡用一個範本字串定義父元件，像真正的頁面一樣用 v-model，再從父元件那一側檢查值。

練習 1：SizePicker.vue 現在用自己的 ref 保存杯型，父元件寫 v-model="size" 沒有作用。改用 defineModel，型別是 'S' | 'M' | 'L'、必填：點 L 之後父元件的 size 變成 'L'；父元件改值時，被選取的 radio 跟著變。

練習 2：QuantityInput.vue 讓父元件用 v-model 綁數量，用 defineModel 的 set 轉換器限制：輸入大於 20 時父元件得到 20；0、負數、不是數字或空字串時得到 1；小數無條件捨去。父元件拿到的一律是 number，而且每次輸入就更新，不能等失去焦點。

練習 3：DrinkOptions.vue 提供三個具名 model：v-model:sugar、v-model:ice、v-model:note，各自更新、互不影響。再支援自訂修飾符 .short：父元件寫 v-model:note.short 時，傳出去的備註最多 20 個字；沒寫就保留原樣。測試也會檢查父元件寫 v-model:note.trim 時會去除空白，這一點不用寫程式，想想為什麼。

練習 4：CustomerForm.vue 的 model 是 { name, phone }，起始版用 v-model="model.name" 直接改屬性。測試會傳入凍結的物件。改成每次輸入都指定一個新物件給 model：改到的欄位用新值，其他欄位保留，原物件不能被修改。

練習 5：<Child v-model="drink" /> 展開後是什麼？

✓ b：元件 v-model 只是一個 prop 加一個事件，資料還是單向流動，子元件要送 update:modelValue 才改得到父元件。a 錯：props 是唯讀的，沒有雙向連線。c 是 Vue 2 元件 v-model 的命名，Vue 3 不再使用；原生 input 上的 v-model 才是概念上的 :value＋@input。

練習 6：子元件寫 defineModel({ default: 1 })，父元件寫 v-model="x"，而 x 一開始是 undefined。掛載之後會怎樣？

✓ c：default 是 prop 的預設值，傳入 undefined 時子元件就用它，但不會送事件通知父元件，兩邊就不同步了（官方文件的例子，Vue 3.5.44 實測）。a 錯：defineModel 不會自己送初始事件。b 錯：prop 的值是 undefined 時同樣套用 default。修正方式是讓父元件給初始值，子元件設 required: true。

練習 7：<input v-model.lazy="note"> 的 .lazy 改變了什麼？

✓ a：.lazy 只是把聽的事件從 input 換成 change。b 錯：v-model 沒有內建防抖，要防抖得自己在 watch 或事件裡處理（第 5 課）。c 錯：值是在事件處理時同步寫回的，跟 nextTick 無關。

常見錯誤

  • 以為 .number 保證是數字：轉不出數字時保留原字串，清空輸入框時父元件拿到空字串，也不管範圍。需要範圍或型別保證時，在 set 轉換器裡自己轉。
  • 沿用 Vue 2 的 value／input 命名：Vue 3 的元件 v-model 用 modelValue／update:modelValue。用 defineModel 就不會拼錯。
  • 必填的 model 沒加 required：型別多了 undefined，父元件忘了綁也沒有警告；因為 defineModel 在沒有 v-model 時會變成本地狀態，畫面看起來還能動。
  • 用 defineModel 的 default 當初始值：子元件顯示預設值，父元件還是 undefined，送出的資料和畫面不一致。初始值放在父元件，子元件用 required: true。
  • 改 model 物件的屬性（v-model="model.name"、model.value.name = …）：不送事件、偷改父元件的物件、遇到凍結物件就丟錯。每次指定新物件，或拆成多個具名 model。
  • 把需要確認或驗證的操作做成 v-model：v-model 一改就生效。刪除、套用優惠碼、送出、可以「放棄修改」的表單，用草稿加明確的事件。

小結

  • 原生 input 上的 v-model 寫回的是字串，這是「12 杯」的來源。它編譯成內建指令：文字框聽 input（.lazy 改聽 change），組字中不更新；.number 轉不出數字時保留原字串。
  • 元件上的 v-model 是 modelValue prop 加 update:modelValue 事件；v-model:xxx 是 xxx 加 update:xxx。資料仍然單向流動，父元件拿到什麼型別由子元件 emit 決定。
  • defineModel（3.4 穩定）幫你宣告 prop 和事件，回傳 ref：讀是 prop，寫是 emit；父元件沒用 v-model 時變成本地狀態。初始值由父元件決定，不靠 default。
  • 範圍限制與格式轉換放在 set 轉換器，所有寫入都會經過；自訂修飾符用 const [model, modifiers] = defineModel(…) 讀；內建的 .trim、.number 由 Vue 在 emit 時自動處理。
  • model 是物件時指定新物件，不改屬性；改動要能取消、需要確認或非同步驗證、或事件本身有意義時，不用 v-model，用草稿加明確的事件。
