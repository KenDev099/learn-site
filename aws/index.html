AWS 雲端服務實戰 學習地圖

咖啡店的點餐系統要搬上雲端：API 要跑在不會因為一台機器壞掉就停擺的地方、收據 PDF 要放在便宜又不會遺失的儲存、尖峰時要自動加機器、每筆付款都要寄收據也不能寄兩次。AWS（Amazon Web Services）是目前最多公司使用的雲端平台，後端工作與面試都很常遇到它：「這個服務的權限怎麼給」「為什麼連不到資料庫」「帳單為什麼這麼高」這些問題，資深工程師都要能自己回答。

這是一門選修課，接在 部署與維運課第 18～20 課之後：那三課教的 VPC、EC2、RDS、S3、IAM、OIDC 與 OpenTofu 是「部署需要的最小 AWS」，這門課不重教，用到時一句回顧並連過去。這門課補上線之後真的會遇到的部分：帳號與 IAM 的延伸（SSO 設定檔、CloudTrail、跨帳號 role、permission boundary）、「為什麼連不到」的排查、Route 53／ACM／ALB／CloudFront、ECS Fargate、Lambda 與 API Gateway、S3、RDS、KMS 與機密管理，以及 SQS／SNS／EventBridge 與 S3 事件。每一課都先講咖啡店會遇到的情境，再講 AWS 的做法和取捨，也會標出面試常問的觀念。期末專題把作品專案課的多租戶 NestJS 後台部署上 AWS：先做架構取捨，再建出整套資源，最後修好幾個被埋進去的事故。

練習分兩種：純邏輯的題目（讀 ARN、算權限、模擬節流與告警）在頁面裡用 TypeScript 完成；需要 AWS API 的題目在你的電腦上做，連到本機的 AWS 模擬器 Moto（一個 Docker 容器），用 AWS CLI 與 AWS SDK for JavaScript v3 操作，不需要 AWS 帳號、不會產生任何費用。模擬器跟真的 AWS 有差異（例如預設不檢查權限），課文遇到時都會講清楚。每一課另附一節「在真的 AWS 帳號上做一次」，選做、不判分，寫明費用與清除資源的指令。先備：會 JavaScript／TypeScript 與 Node.js（Node.js 核心），用過 Docker（devops 課第 7 課），建議先讀完 devops 課第 18～20 課；需要 Docker Desktop 與 AWS CLI v2。
