AI 應用開發：LLM、RAG 與 Agent 學習地圖

2026 年的後端工程師常被要求「加一個 AI 功能」：客服聊天、菜單與 FAQ 搜尋、從顧客訊息擷取訂單、自動化處理。呼叫一次 API 只要五行程式；難的是讓它可靠、安全、便宜：模型的輸出每次不一樣、會格式錯誤、會被惡意文字操控、會在尖峰時段逾時，帳單也可能一夜暴增。這門課以 Anthropic Claude API 為主，從 token、context window 與不確定性這些實際會碰到的概念開始，依序學第一個 API 呼叫與串流、prompt 設計、結構化輸出與驗證、tool use 與 agent 迴圈、RAG（切塊、embedding、pgvector、混合搜尋、重排、引用來源），最後是上線前資深工程師要負責的部分：評估、資安、成本、可靠性與可觀測性。期末專題是一個咖啡店客服助理：能用 RAG 回答菜單問題、用工具查訂單、擋得住 prompt injection，附 eval 套件與成本報告。

練習分兩種。概念題在頁面裡的 TypeScript 練習區完成（token 預算、prompt 組裝、切塊、相似度計算）。其餘在自己的電腦上用 Node 24 跑 ai/practice：你寫的程式用真正的 @anthropic-ai/sdk，但測試替它換上一個假的 fetch，回放事先寫好的回應（包括串流事件、tool_use、錯誤、拒答），所以判分完全離線、每次結果一樣、不需要 API key，也不花錢。向量搜尋用 PGlite（在 Node 裡跑的 PostgreSQL 18.6）加 pgvector 0.8.7，不用裝 Docker。想看真實模型的回應時，可以設定自己的 ANTHROPIC_API_KEY 執行每課附的 live.ts，但那不影響判分。

這門課假設你學過 TypeScript、Node 與 PostgreSQL 課，也建議先看過認證、部署與系統設計課的相關章節；用到時都會寫出是哪一課並附上連結，不重教。課程裡的寫法以 Claude API 示範，但 messages、tool use、structured output、embedding、RAG、eval 這些模式在其他模型供應商幾乎一樣，換供應商時改的是 SDK 呼叫，不是架構。
