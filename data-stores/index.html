資料儲存選型：Redis、MongoDB 與搜尋 學習地圖

資深工程師的工作不只是把 SQL 寫對，而是替每一種資料挑對地方放：訂單要正確、購物車要快、菜單要搜得到、收據檔案要便宜又不丟。這門課先教你怎麼用「存取模式、一致性、規模、維運成本」四個問題做選型，並說清楚為什麼 PostgreSQL 仍然是預設答案；接著深入 Redis（不只快取：資料結構、限流、排行榜、Lua、Streams、記憶體與持久化、Cluster）、MongoDB（文件建模、索引、aggregation、交易與何時不該用）、搜尋引擎（Elasticsearch：倒排索引、中文分詞、相關性、與資料庫同步）、物件儲存（S3 的 presigned URL 與生命週期）、分析型資料庫（DuckDB／ClickHouse）與 DynamoDB 的 single-table 設計。

每一課都用同一間咖啡店：PostgreSQL 課的 customers、products、orders、order_items 仍是正式資料的來源，這門課替它加上 Redis 的購物車與限流、Elasticsearch 的菜單搜尋、MongoDB 的門市活動頁內容、物件儲存的電子收據、DuckDB 的營運報表。期末專題把這些拼成一套，並處理它們之間的一致性：資料庫寫成功但搜尋沒更新、檔案上傳了但訂單沒建立，該怎麼辦。

練習大多在你的 Mac 上用 Docker Compose 跑真的 Redis、MongoDB、Elasticsearch 與 S3 相容儲存（Garage），測試用 node:test；Redis Cluster 的 hash slot 與 DynamoDB 的 key 設計在頁面裡寫 TypeScript 判分，不必安裝。所有容器都有記憶體上限，一次只開需要的服務，16 GB 的筆電跑得動。
