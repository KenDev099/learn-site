階段 3：現代 CSS 與視覺品質 · 第 16 課

主題與設計變數：custom properties、色彩、間距與深色模式

咖啡店要換品牌色：咖啡棕從 #6e401e 調成偏紅一點的棕色。打開 CSS 搜尋 #6e401e，找到 120 處，有的寫成 #6E401E、有的寫成 rgb(110, 64, 30)，還有幾個是「看起來差不多」的 #6d3f1f，搜不到。同一週，老闆又說手機上晚上看太亮，想要深色模式，那等於把整份樣式的顏色再寫一遍。設計師看完也補了一句：「卡片的留白不整齊，有的 13px、有的 15px，這次一起統一。」

這張改版單上的三件事卡在同一個地方：顏色、間距這些設計決策沒有名字，散落在每一條規則裡。這一課從頭到尾都在處理這張改版單：先讓品牌色只寫一次，再把變數分層，讓深色模式只多寫一組；接著做出深色要用的色階、讓 hover 色跟著主色走，完成深色模式；最後把間距也收成刻度，並讓團隊半年後還守得住。

這課的路線：
  1. 換品牌色為什麼要改 120 處，custom properties 怎麼讓顏色只寫一次：宣告、讀取、繼承，以及寫錯時為什麼不會報錯。
  2. 變數只有一層時，深色模式為什麼卡住：把變數分成「原始色」與「用途」兩層。
  3. 深色要用的色階怎麼做、hover 色怎麼跟著主色走：oklch()、color-mix() 與每一階的文字對比。
  4. 深色模式：跟著系統切換，也讓使用者手動選，表單控制項和捲軸一起變深色。
  5. 卡片留白怎麼統一：間距與字級刻度；最後讓團隊半年後還守得住這些變數。
這課會用到：
  • 第 6 課的權重與繼承：同一個屬性有多條規則時權重高的贏；會繼承的屬性，子元素沒寫就沿用父元素的值。
  • 第 5 課的對比要求：一般文字和背景的對比至少 4.5:1。
  • 第 11 課的 media query：@media (條件) { … } 裡的規則只在條件成立時生效。

換品牌色，為什麼要改 120 個地方？

先看咖啡店樣式的一小段，就知道那 120 處是怎麼來的。同一個棕色出現四次，hover 色是另一個手調出來的色碼，它跟主色之間的關係只存在當初寫的人腦中：

.top        { background: #6e401e; }
.card h2    { color: #6e401e; }
.price      { color: #6e401e; }
.btn        { background: #6e401e; color: #fff; }
.btn:hover  { background: #502d13; }   /* 為什麼是這個值？沒人記得 */

這種寫法在第一版不會出事，出事是在要改的時候。改版單上的事，各自會在這裡卡住：

  • 換品牌色改不乾淨：搜尋取代比對的是字串，但同一個顏色有 #6e401e、#6E401E、rgb(110, 64, 30) 好幾種寫法，搜一種漏一種。反過來，某張圖表的線剛好也是這個棕色，但它不是品牌色，一起被換掉就改錯了。字串相同，不代表用途相同。
  • 深色模式要整份重寫：深色模式的樣式要寫在 @media (prefers-color-scheme: dark) 裡（系統設成深色時才生效的 media query，後面會細講），每一條有顏色的規則都得再寫一次。120 處棕色，加上文字色、背景色、邊框色，兩份要一起維護，之後每改一個顏色都要記得改兩次。
  • 沒人知道顏色的用途：#836450 是「次要文字」還是「邊框」？看色碼看不出來。不知道用途就不敢改，只好再加一個新色碼，問題越滾越大。

三件事的根源相同：程式裡只有「值」，沒有「這個值代表哪個決定」。解法是幫每個決策取名字，例如價格的顏色寫成 .price { color: var(--color-accent); }：名字說明用途（強調色），值只寫在一個地方。換品牌色時改那一個地方，所有用到這個名字的規則一起變。

這種替設計決策取的名字，叫做設計變數（design token）。顏色、間距、字級、圓角這些整個網站要一致使用的值，都可以是設計變數。設計系統的完整做法（命名規則、從 Figma 匯出、版本管理）在第 26 課；這一課先學會 CSS 本身提供的工具，也就是下一節的 custom properties。

怎麼讓品牌色只寫一次？custom properties

CSS 用來替值取名字的工具叫自訂屬性（custom property），常被叫做 CSS 變數。它就是一個名字以兩個減號 -- 開頭的 CSS 屬性：宣告方式跟 color、margin 一樣寫在規則裡，名字自己取；要用的時候，在別的屬性的值裡寫 var(--名字)，瀏覽器算樣式時會把它換成那個值。

:root {
  --color-accent: #6e401e;   /* 宣告：名字自己取，-- 開頭 */
  --space-4: 1rem;
}

.price {
  color: var(--color-accent); /* 讀取 */
  margin-top: var(--space-4);
}

全站共用的變數宣告在 :root。:root 是選中整份文件根元素 <html> 的偽類，選到的元素跟寫 html 一樣，但權重是 (0,1,0)，比 html 的 (0,0,1) 高。為什麼要宣告在最外層的 <html>？因為 custom properties 會繼承。

宣告在 :root，整頁都讀得到：繼承

第 6 課講過，會繼承的屬性，子元素沒寫時沿用父元素的值。custom properties 全部都會繼承（第 6 課的表格裡有它）。所以宣告在 <html> 上，底下每個元素都繼承到同一個值，任何規則寫 var(--color-accent) 都讀得到。換品牌色時只改 :root 裡那一行，整頁一起變，120 處的問題就解決了。

繼承還帶來另一個能力：局部覆寫。在某個元素上重新宣告同一個變數，只有它和它的子孫拿到新值，其他地方不受影響。咖啡店的頁尾是深色區塊，裡面也放了卡片；不用替頁尾的卡片另寫一套顏色，只要在頁尾改變數：

:root  { --color-surface: #ffffff; --color-text: #35251b; }
.card  { background: var(--color-surface); color: var(--color-text); }

/* 頁尾是深色區塊：只改變數，裡面的 .card 不用另外寫規則 */
.footer {
  --color-surface: #35251b;
  --color-text: #f0e6de;
}

.card 的規則一個字都沒改。頁尾裡的卡片往上找，最近的宣告在 .footer，讀到深色的值；頁面其他地方的卡片最近的宣告在 :root，照舊是淺色。這是變數和搜尋取代最大的不同：同一條規則，在不同區塊可以拿到不同的值。

元件自己的參數與預設值

設計師要統一的卡片留白還有一個麻煩：同一張卡片放在窄的側欄裡，內距要小一點。用剛學的局部覆寫，可以讓卡片開一個「可以從外面調整的參數」。下面的 --space-4、--space-5 是間距刻度（16px、24px），後面整理卡片留白時會完整定義：

.card {
  padding: var(--card-pad, var(--space-5));   /* 沒人設定 --card-pad 時用 --space-5 */
}
.sidebar .card { --card-pad: var(--space-4); }

var() 逗號後面的部分是預設值（fallback）：var(--card-pad, var(--space-5)) 的意思是「有人設定 --card-pad 就用它，沒有的話用 --space-5」。一般的卡片沒有宣告 --card-pad，所以用預設值；側欄裡的卡片被 .sidebar .card 宣告了 --card-pad，就改用 --space-4。卡片的規則不需要知道自己會被放在哪裡。預設值裡有逗號、或要串好幾層預設值時有一個常見的誤寫，整理在課末的「補充與查表」。

寫錯時為什麼不會報錯？

把品牌色收成變數之後，新的風險是打錯字，而且這類錯誤不會出現在 Console。要理解原因，先看一般屬性寫錯值時發生什麼事：瀏覽器在讀入 CSS（解析）的時候就看得出 color: 16px 不是顏色，直接丟掉這條宣告，改用同一個規則裡前一條有效的宣告。「寫兩條，後面那條不支援就用前面那條」的備援寫法，就是靠這個行為成立的。

custom properties 不一樣。瀏覽器解析 color: var(--space-4) 時，還不知道 --space-4 會是什麼（它可能被任何祖先元素覆寫），只能先收下這條宣告。要等到替每個元素算樣式、把值代入的時候，才發現代入後是 color: 16px，不合法。這時前一條宣告早就被這一條蓋過了，退不回去。這種狀況叫計算值時期無效（invalid at computed-value time），結果是這個屬性變成 unset：會繼承的屬性（例如 color）用父元素的值，不會繼承的（例如 background）用初始值。

:root { --space-4: 16px; }

.badge {
  color: #b42318;
  color: var(--space-4);   /* 代入後是 color: 16px → 無效 */
}
/* 結果：color 用繼承來的值（例如 body 的文字色），不是 #b42318 */

變數名稱拼錯也是同一件事。var(--colour-accent) 找不到這個變數，又沒寫預設值，屬性一樣變成 unset：畫面上價格的棕色「消失」、變成內文色，但 Console 沒有任何錯誤，因為對 CSS 來說這不是語法錯誤。名稱還區分大小寫，--Brand 和 --brand 是兩個不同的變數。

所以這類問題要在 DevTools 的樣式面板裡查，不是看 Console。Styles 面板裡，未定義的變數名稱會被標示出來，滑鼠移到上面會顯示它的值，沒有定義時也會提示；Computed 分頁看這個屬性最後算出來的值。看到「明明寫了顏色，畫面卻是繼承來的顏色」，先懷疑變數名稱。

到這裡，換品牌色只要改 :root 的一行。但改版單上還有深色模式，下一節會看到，只有一層變數時，深色模式會卡住。

深色模式時，一層變數為什麼不夠？兩層變數

上一節的 --color-accent 直接存色碼 #6e401e，按鈕、標題、價格都寫 var(--color-accent)。換品牌色沒問題，改這一行就好。接著做深色模式：在深色背景上，按鈕底色和標題文字都要換成比較亮的棕，不然看不清楚（後面會算給你看）。這時只有一層變數，會遇到兩條路，兩條都走不順。

第一條：照外觀取名。如果當初把品牌棕取名叫 --brown，深色模式時把 --brown 的值改成亮棕，同一個名字在淺色和深色模式指的就是兩個不同的顏色，名字說謊了。更麻煩的是，不是每個用到 --brown 的地方在深色時都要變亮。名字描述的是外觀，深色模式要改的卻是「某個用途該用哪個顏色」，兩者對不上。

第二條：像 --color-accent 這樣照用途取名，但值直接寫色碼。名字不會說謊了，可是深色模式的 media query 裡要再寫一次 #c9a58a 這類色碼。好幾個用途變數共用同一個棕色時（強調色、邊框、次要文字可能都取自同一組棕），同一個色碼又重複散落在淺色、深色兩份清單的好幾行裡，回到一開始「改一個顏色要找好幾處」的問題。

兩條路卡住的原因相同：「這是什麼顏色」和「這個顏色拿來做什麼」擠在同一個變數裡。所以把變數分成兩層，一層講外觀，一層講用途：

層例子名字描述什麼誰可以用
palette（原始值、primitive）--brown-700: oklch(0.42 0.08 55)外觀：什麼顏色、第幾階只有語意變數
語意變數（semantic token）--color-accent: var(--brown-700)用途：主要強調色、次要文字、邊框、危險所有元件

palette 是調色盤：所有可以用的原始顏色都放在這裡，名字只說它長什麼樣，哪個色系、第幾階（數字越大越深）。語意變數的名字說的是用途。元件只能用語意變數，語意變數再指向 palette 裡的某一階。兩層的關係如下圖：

換主題時，改的是中間那一層指向哪一階：淺色時 --color-accent 指向 --brown-700，深色時改指向 --brown-300。元件規則寫的一直是 var(--color-accent)，一行都不用動。品牌改版也一樣，調整 palette 的值，或讓語意變數改指向別的色階。這就是改版單上「換品牌色」和「深色模式」都只改一個地方的原因。

咖啡店的語意變數可以從這幾個開始。夠用再加，不要一開始就定義 50 個：每多一個語意變數，深色模式和品牌改版時就多一個要決定的值。

語意變數用途淺色指向
--color-bg頁面背景--cream-50
--color-surface卡片、輸入框等浮在背景上的面--white
--color-text內文--brown-900
--color-text-muted次要文字（說明、時間）--brown-500
--color-accent品牌強調：主要按鈕、連結、價格--brown-700
--color-accent-hover強調色的 hover 狀態由 accent 算出
--color-on-accent放在強調色上的文字--white
--color-border分隔線、卡片邊框--brown-200

命名的原則是名字講用途，不講外觀。--color-danger 好過 --color-red，因為哪天危險色改成橘色，名字還是對的。--color-on-accent 這種「放在某個顏色上面的文字色」要跟底色成對定義：深色模式把 --color-accent 換成亮棕時，上面的白字就看不清楚了，成對放在一起，才不會忘記它也要跟著換。

💡 實務上：接手舊專案時，語意變數是一步一步長出來的
接手一個色碼散落各處的後台，不需要一次全部改完：先把出現最多次的幾個顏色（主色、內文、邊框）換成語意變數，之後每次碰到某個元件再順手改掉它的色碼。專案如果用了 UI 套件（例如 Naive UI、Vuetify），它的主題設定也是同一個想法：你改的是 primary、error 這類語意名稱，所以先看套件提供哪些可以設定，不要另外再包一層自己的。只用一次的顏色（某張活動 banner 的漸層）不必升級成變數，寫在元件裡就好。取名卡住時，通常代表這個顏色的用途還沒想清楚，先跟設計師確認它是什麼。

語意層已經知道深色時要指向「比較亮的那一階棕」，但 palette 裡還沒有這些色階。下一節處理：色階怎麼做，以及怎麼知道哪一階可以放在深色背景上當文字。

深色要用的色階怎麼做？oklch() 與文字對比

palette 需要同一個色系的好幾階，從很淺（50）到很深（950）：淺色模式用深的那幾階當文字，深色模式反過來用淺的。每一階放在背景上當文字時，都要滿足第 5 課的對比要求，至少 4.5:1。

用 hex 或 HSL 手調色階，常見的狀況是各階的亮度跳動不平均、某一階突然偏黃，而且看數字猜不出哪一階對比夠。原因是 hex 和 HSL 的數字都不直接對應「人眼覺得多亮」。oklch() 是另一種寫顏色的方式，設計目標就是讓數字對應人眼的感受。它用三個數字描述顏色：

  • L（lightness）：感知亮度，0 是黑、1 是白（也可以寫 0%～100%）。
  • C（chroma）：彩度，0 是灰色，數字越大越鮮豔，實務上很少超過 0.4（寫百分比時 100% 等於 0.4）。
  • H（hue）：色相角度，0～360。跟 HSL 的角度不同，oklch 的 0 度是偏粉的紅，棕色在 50～60 度附近。

重點在 L 是人眼感受到的亮度。固定 H、大致固定 C、只改 L，就得到一組色相不偏、亮度均勻的色階。對比也是用亮度算的，所以 L 跟對比的關係很穩定：知道 L，大致就知道它在白底或深底上夠不夠；同一個 L 換個色相，對比也不會差太多。HSL 的 L 做不到這點：hsl(60 100% 50%) 的黃色和 hsl(240 100% 50%) 的藍色 L 都是 50%，實際亮度差了十幾倍。

下面的程式把咖啡店的棕色（色相 55、彩度 0.05）從 L 0.9 一路改到 0.28，換算成螢幕上的顏色，再算它在白底和深色底上的對比，公式跟第 5 課相同；最後兩行是 HSL 黃色與藍色的對照。執行後看每一行最後的兩個判定：哪幾階在白底能當文字，哪幾階在深底能當文字。

從結果可以讀出一條挑色階的規則：白底上的文字色大約要 L ≤ 0.55，深底（L 0.22 左右）上的文字色大約要 L ≥ 0.65；中間的 0.6 兩邊都不夠（實際仍以計算為準，背景換了就要重算）。這也回答了上一節的問題：淺色模式的 --color-accent 用 L 0.42 的 --brown-700，深色模式必須改指向 L 0.65 以上的那一階。挑色階時先用這個範圍篩，再實際算對比。

做色階時還有一件事：色階的兩端要降低彩度。螢幕（sRGB）能顯示的顏色範圍有限，L 接近 0 或 1 時，高彩度的顏色根本顯示不出來，瀏覽器會換成最接近的可顯示顏色，這個動作叫 gamut mapping，換過之後色相可能跑掉。所以咖啡店最淺的 --cream-50 彩度只有 0.008，是帶一點暖色的米白。

最後，每次調色都要重算對比。oklch 讓對比「好預測」，不代表「一定過」，背景換了也要重算。DevTools 的顏色選擇器會直接顯示目前文字色對背景的對比，以及 AA／AAA 的分界線，調色時邊看邊調最快。

💡 實務上：品牌色常常過不了對比，要分「大面積」和「文字」兩種用途
行銷給的品牌色多半是為 Logo 和大面積色塊挑的，偏亮的橘、黃、淺綠拿去當白底上的文字或按鈕文字，很容易不到 4.5:1。常見的解法是保留品牌色給 Logo、插圖、大塊背景，文字和連結改用同色系深一兩階的顏色，這正是兩層變數好用的地方：--color-accent 指向深的那階就好。咖啡店這次換成偏紅的棕，也要先用上面的方法確認新主色在白底上還過得了 4.5:1。這件事要帶著 DevTools 算出來的對比數字去跟設計師談，而不是自己偷偷把顏色調深。

色階有了，但樣式裡還有一個寫死的顏色：按鈕 hover 的 #502d13。品牌色一換，它就跟新的主色對不上了。

hover 色能不能跟著品牌色自動變？color-mix()

#502d13 是當初有人把棕色手動調暗得到的。品牌色換了以後沒人記得要跟著換，畫面上就會出現新的主色配舊的 hover 色。比較好的做法是不要記一個新的色碼，而是記下它和主色的關係：hover 色就是主色再暗一點。color-mix() 把這種關係寫成 CSS，它把兩個顏色依比例混合：

--color-accent-hover: color-mix(in oklch, var(--color-accent), black 20%);
/*                              ↑ 在哪個色彩空間混   ↑ 顏色 1      ↑ 顏色 2 佔 20%，顏色 1 自動是 80% */

三個部分依序是：

  • 色彩空間：in oklch 指定在哪個色彩空間混合，實務上一律寫出來，讀的人一眼看得出在哪個空間混（可以省略的規則見課末）。在 oklch／oklab 裡混出來的顏色亮度變化均勻，在 srgb 裡混常常中間變灰。
  • 比例：只寫一個百分比時，另一個補到 100%；兩個都不寫各 50%。
  • 混什麼：混黑色是加深、混白色是變淺、混 transparent 是變透明，例如 color-mix(in oklch, var(--color-accent), transparent 85%) 做淡淡的底色。

好處是狀態色跟著主色走：品牌色改了，hover 色自動跟著改，不會有人忘記更新 #502d13。設計稿已經把 hover 色定好時照設計稿；color-mix() 適合設計稿沒寫到的狀態，例如 focus 底色、停用狀態。color-mix() 與 oklch() 都可以直接用，支援度見課末。

hover 色現在跟著 --color-accent 走了。但「跟著走」有一個前提，局部改主色時就會露餡。

局部覆寫主色時，hover 為什麼沒跟著變？

衍生色有一個常見的陷阱，要換個情境才看得到。咖啡店的頁面上還有一塊促銷區塊，想用紅色當強調色（palette 裡另有一組 --red-* 色階，--red-700 是其中深的那階），於是在 .promo 上覆寫 --color-accent，結果按鈕底色變紅了，hover 卻還是暗棕色：

:root {
  --color-accent: var(--brown-700);
  --color-accent-hover: color-mix(in oklch, var(--color-accent), black 20%);
}
.promo { --color-accent: var(--red-700); }
/* .promo 裡的 hover 色仍然是棕色混黑：--color-accent-hover 裡的 var() 在 :root 就代換好了 */

原因是：一個變數的值裡用到別的變數時，代入發生在宣告它的元素上。--color-accent-hover 宣告在 :root，裡面的 var(--color-accent) 就在 :root 代換成當時的值（棕色）。子孫繼承到的是代換完的 color-mix(in oklch, 〈棕色〉, black 20%)，已經不含 var(--color-accent)。所以 .promo 後來改了 --color-accent，也影響不到它。

要讓局部覆寫連帶影響衍生色，有兩種修法：在 .promo 把衍生色也重新宣告一次；或乾脆在元件規則裡現算，.btn:hover { background: color-mix(in oklch, var(--color-accent), black 20%); }，這樣代入發生在按鈕自己身上，讀到的是最近的 --color-accent。這是資深工程師常被問的「為什麼我改了主色，hover 沒跟著變」。

顏色的工具到這裡都齊了：語意變數、色階、從主色算出的狀態色。接下來把它們組起來，完成改版單上的深色模式。

系統設成深色時，頁面怎麼跟著變？

深色模式要處理兩種顏色：瀏覽器自己畫的東西（預設背景、表單控制項、捲軸），和你在 CSS 裡指定的顏色。前者靠一行 color-scheme，後者靠切換語意變數。先處理前者，因為它最常被忘記。

第一步：color-scheme 讓瀏覽器自己畫的東西變深色

:root { color-scheme: light dark; }

color-scheme 告訴瀏覽器「這個頁面淺色、深色都支援」。系統是深色時，瀏覽器會把它自己負責畫的東西換成深色：頁面的預設背景與文字色、表單控制項（輸入框、下拉選單、核取方塊）、捲軸。你自己寫的 color: #35251b 不會變。這個屬性會繼承，所以設在 :root 整頁都生效；也可以只在某個區塊設 color-scheme: dark。

少了它會怎樣：頁面背景自己做成深色了，但沒設 color-scheme，瀏覽器以為頁面只支援淺色，結果深色頁面上出現白色的輸入框和亮色捲軸。另外在 <head> 的 CSS 之前加 <meta name="color-scheme" content="light dark">，瀏覽器在 CSS 下載完之前就知道要用深色底，可以避免深色使用者開頁時先閃一下白。

第二步：系統偏好深色時，語意變數改指向深色的色階

prefers-color-scheme 是作業系統（或瀏覽器）設定的淺／深色偏好，可以當成第 11 課 media query 的條件。有了兩層變數，深色模式只要在這個條件下改語意層：

@media (prefers-color-scheme: dark) {
  :root {
    --color-bg: var(--brown-950);
    --color-surface: var(--brown-900);
    --color-text: var(--brown-100);
    --color-text-muted: var(--brown-400);
    --color-accent: var(--brown-300);
    --color-on-accent: var(--brown-950);
    --color-border: var(--brown-800);
  }
}

元件規則一行都不用動，這就是前面分兩層換來的。挑深色的指向時，有幾個原則：

  • 背景不要用純黑：--brown-950 帶一點棕。大面積純黑配白字，對比太刺眼。
  • 強調色換成比較亮的那一階：原本的 --brown-700 在深底上對比只有 2:1 左右，做色階那一節（oklch）算出的規則是深底上的文字要 L ≥ 0.65。強調色變亮之後，放在上面的 --color-on-accent 也要改成深色，這就是它要成對定義的原因。
  • 次要文字一定要重算：它是最常不過 4.5:1 的。
  • 陰影在深色底上幾乎看不見：改用淺一點的 surface 色區分層次。

另一種寫法：light-dark() 把兩個值寫在同一行

第二步的寫法要維護兩份清單：:root 裡一份淺色、media query 裡一份深色，新增一個語意變數時兩邊都要記得加。light-dark() 把兩個值寫在同一行：

:root {
  color-scheme: light dark;
  --color-bg: light-dark(var(--cream-50), var(--brown-950));
  --color-text: light-dark(var(--brown-900), var(--brown-100));
}

light-dark(淺色值, 深色值) 依元素目前使用的 color scheme 回傳其中一個。它需要 color-scheme 是 light dark 才會跟著系統切換（head 裡的 <meta name="color-scheme" content="light dark"> 也算）；兩者都沒有時永遠回傳第一個值。好處是淺色與深色寫在同一行，不會漏改，也不用維護兩份清單。要支援比較舊的瀏覽器，就用第二步的寫法，支援度見課末。

light-dark() 在 custom property 裡不會先被算掉，而是等代入到 color、background 時，依那個元素的 color-scheme 決定。規則跟前面 hover 色那個陷阱相同：var() 在宣告的元素上就代換，light-dark()、color-mix() 這些函式則原樣留著，等真正用在 color、background 上時才計算。所以 light-dark() 能依使用它的元素的 color-scheme 選值。所以在某個區塊設 color-scheme: dark，那個區塊裡的語意變數就自動變成深色版本，局部深色區塊（例如咖啡店的深色頁尾）不用另外寫變數。

到這裡頁面會跟著系統走。但有些人系統是深色，卻希望這個網站用淺色，下一節讓使用者自己選。

使用者想自己選主題時，怎麼讓選擇勝過系統？

常見的做法是提供切換按鈕，把選擇存在 localStorage，由 JavaScript 在 <html> 加上 data-theme：

<head>
  <meta name="color-scheme" content="light dark">
  <script>
    // 放在 head、CSS 之前同步執行：畫面出現前就套用使用者的選擇，不會先閃一下另一個主題
    const theme = localStorage.getItem('theme')
    if (theme === 'light' || theme === 'dark') document.documentElement.dataset.theme = theme
  </script>
  <link rel="stylesheet" href="/css/site.css">
</head>

切換按鈕做的事就是 localStorage.setItem('theme', 'dark') 加上 document.documentElement.dataset.theme = 'dark'；「跟隨系統」就是兩個都刪掉。JavaScript 只負責記住選擇、標在 <html> 上，顏色怎麼變仍然交給 CSS。CSS 這邊只有一條規則：使用者的選擇要勝過系統偏好。

用 light-dark() 時：只要改 color-scheme

:root { color-scheme: light dark; }                  /* 預設：跟隨系統 */
:root[data-theme="light"] { color-scheme: light; }   /* (0,2,0)：勝過 :root */
:root[data-theme="dark"]  { color-scheme: dark; }

:root[data-theme="light"] 是偽類加屬性選擇器，權重 (0,2,0)，高過 :root 的 (0,1,0)，所以有標 data-theme 時，它的 color-scheme 一定贏。color-scheme 一變成單一的 light 或 dark，所有 light-dark() 都照它回傳，瀏覽器畫的輸入框和捲軸也跟著它，不再看系統偏好。

用 media query 時：小心權重相同

用第二步的 media query 覆寫變數時要多想一步，因為 @media 本身不增加權重。假設寫成這樣：使用者選淺色的規則是 [data-theme="light"] { … }，權重 (0,1,0)；後面又有 @media (prefers-color-scheme: dark) { :root { … } }，裡面的 :root 也是 (0,1,0)。系統是深色、使用者選了淺色時，兩條都成立、權重相同，後出現的 media query 勝出，使用者選的淺色就失效了。

有兩種修法：

  • 讓深色的 media 規則在使用者選淺色時不成立：選擇器寫成 :root:not([data-theme="light"])，只在使用者沒選淺色時生效，兩條規則就不會同時成立。
  • 提高 data-theme 規則的權重：寫成 :root[data-theme="…"]，權重 (0,2,0) 高過 media 裡的 :root，前後順序就不影響。這時 [data-theme="light"] 要把淺色的語意變數全部再寫一次，才蓋得掉 media 裡的深色值。

不確定是哪一邊贏時，用第 6 課的方法看 DevTools 裡哪一條被劃線。不管用哪種寫法，下面四種情況都要測：

系統偏好data-theme應該顯示
淺色（沒有）淺色
深色（沒有）深色
淺色dark深色
深色light淺色，color-scheme 也要是 light，不然輸入框是深色的

不用改系統設定也能切換：DevTools 的 Rendering 面板（⋮ → More tools → Rendering）有「Emulate CSS media feature prefers-color-scheme」；練習 2 的測試也是這樣模擬的。

不要用 filter: invert(1) 做深色模式：它把整頁的像素反轉，照片變成負片、品牌棕變成藍色、陰影變成光暈。要把圖片再反轉回來又會牽扯一堆例外。深色模式的正確做法是換語意變數。
💡 實務上：接下深色模式前，先問清楚範圍
深色模式不是一次性的工作：之後每個新頁面、新元件都要在兩個主題各設計、各驗收一次，PM 排時程時要算進去。先確認範圍：只跟隨系統，還是要有切換按鈕？有會員登入的話，偏好要不要存在帳號裡、換裝置也一樣？最容易漏的是你控制不到的東西：寫死白底的商品圖或 Logo、圖表套件的配色、金流或地圖的 iframe、寄出去的 Email 樣式，這些要列成清單逐一決定怎麼處理。如果樣式還沒整理成語意變數，先做那一步，深色模式的工作量會差很多。

改版單上的顏色部分完成了，還剩設計師那一句：卡片留白不整齊。

卡片留白有 13、14、15px，怎麼統一？間距與字級刻度

間距的問題跟顏色一樣，值沒有名字：一頁裡出現 13px、14px、15px、0.9rem，每個都「差不多」，整體看起來不整齊，設計師說「留白大一點」時也沒辦法統一調整。做法跟顏色相同，先替值取名字；差別是間距要的不是「用途」，而是一組固定的刻度（scale），元件只能從刻度裡挑：

:root {
  --space-1: 0.25rem;  /*  4px */
  --space-2: 0.5rem;   /*  8px */
  --space-3: 0.75rem;  /* 12px */
  --space-4: 1rem;     /* 16px */
  --space-5: 1.5rem;   /* 24px */
  --space-6: 2rem;     /* 32px */
}

.card { padding: var(--space-5); gap: var(--space-3); }

13px、14px、15px 這種值收到刻度上，都會對齊成 12px 或 16px 其中一階；之後要整體放大留白，討論的是「卡片內距從 --space-4 換成 --space-5」，而不是一個一個改像素。定刻度時有幾個原則：

  • 以 4 或 8 為基準：小的地方 4 的倍數、大的地方 8 的倍數，步距越往上越大。相鄰兩階差太少（例如 14 和 16）的話，設計師和工程師都分不出要用哪個，刻度就失去意義。
  • 用 rem 定義：rem 是根元素的字級（預設 16px）。使用者在瀏覽器設定裡把字級調大時，用 rem 的間距會一起放大，文字和留白的比例不會被擠壞（第 13 課有完整說明）。
  • 0 和 auto 不算：margin: 0 auto 是版面用法，不是間距值。
  • 需要負值或組合時用 calc：calc(-1 * var(--space-2))、calc(var(--space-5) + var(--space-1))。後者如果常常出現，代表刻度少了一階。

同一張卡片放在不同寬度的地方，常常需要不同的間距。這時不要另外發明一個值，改成「換一階」：

.card { padding: var(--space-5); }

/* 卡片所在的欄寬小於 20rem（側欄、手機）時，內距縮一階 */
@container (max-width: 20rem) {
  .card { padding: var(--space-4); }
}

這裡用 container query 而不是 media query（第 12 課）：container query 看的是卡片所在那一欄的寬度，media query 看的是整個視窗的寬度。同一張卡片在桌機的側欄裡也很窄，看視窗寬度會判斷錯。

字級也照同樣的方式做成刻度，例如 --font-size-sm: 0.875rem、--font-size-md: 1rem、--font-size-lg: 1.25rem、--font-size-xl: 1.75rem。想讓大標題隨螢幕寬度平滑變大，可以用 clamp() 做流動刻度：--font-size-xl: clamp(1.5rem, 1.2rem + 1.5vw, 2.25rem)，最小、最大值要用 rem，使用者放大字級時才有效。clamp() 的算法在第 13 課，中文字級與行高在第 15 課。

💡 實務上：設計稿上的 13px，先問它對應哪一階
切版時最常遇到設計稿標著 13px、18px、22px 這種刻度上沒有的值，多半是設計師手動拉的，不是刻意的決定。這時不要照抄，先對齊最接近的一階，有疑慮再問設計師「這裡是 space-3 還是 space-4？」；如果某個值反覆出現，就是刻度該討論要不要加一階的訊號。比較成熟的團隊會讓 Figma 裡的間距、顏色也用同一組名稱，交接時講的是 --space-4 而不是像素，雙方對得起來，改版也比較快。

到這裡改版單上的三件事都有了做法。剩下的問題不在技術：這些變數半年後還有沒有人遵守？

半年後還守得住嗎？讓團隊遵守設計變數

變數定好不難，難的是半年後還有人遵守。只要有一個人在元件裡寫回 #6e401e，下次換品牌色就又漏一處，深色模式也會出現一塊沒變色的區域。常見的做法：

  • 用 lint 擋下寫死的值：Stylelint 的 color-no-hex、color-named: "never" 擋下色碼與顏色名稱，只在定義 palette 的檔案用註解關掉。程式碼審查時看到新的色碼，問的第一個問題是「這是哪個語意？」
  • 新增語意變數要有理由：先問現有的能不能用。每多一個變數，深色模式、品牌改版就多一個要決定的值。
  • 一次驗收所有主題：淺色過了不代表深色過了。對比檢查要在兩個主題都跑（第 27 課會把它自動化）。
  • 變數就是元件的公開介面：--card-pad 這類元件變數一旦被別的團隊拿去覆寫，改名就是破壞性變更。設計系統怎麼管理版本與文件在第 26 課。

守得住的話，下一張改版單（換季活動色、多一個高對比主題）要改的仍然只有 palette 與語意層。

練習

練習 1：咖啡店的樣式把顏色寫死在每一條規則裡（色票在 CSS 最上面的註解）。改成兩層變數：在 :root 定義 palette（色票裡的 6 個顏色，用 oklch()），再定義 8 個語意變數 --color-bg、--color-surface、--color-text、--color-text-muted、--color-accent、--color-accent-hover、--color-on-accent、--color-border，每個指向一個 palette 變數；--color-accent-hover 用 color-mix() 從 --color-accent 算出來。元件規則（:root 以外）的顏色只能用 var(--color-…)。改完之後畫面要跟原本一樣（測試逐一比對 11 個顏色與 hover 色）。

練習 2：會員設定頁目前只有淺色。加上深色模式：系統偏好深色時自動切換；使用者在 <html> 加上 data-theme="light" 或 data-theme="dark" 時，照使用者的選擇，不管系統偏好；下拉選單、輸入框與捲軸也要跟著變深色；深色時所有文字對比仍然 ≥ 4.5:1（palette 已經準備了深色用的色階，先用上面的範例算一下對比再挑）。主題規則只能改語意變數（--color-*）與 color-scheme，元件規則不要動。測試會模擬四種情況：系統淺／深色，各自再加上使用者選了相反的主題。

練習 3：在 :root 建立間距刻度 --space-1 到 --space-6：4、8、12、16、24、32px，用 rem 寫（1rem = 16px）。把規則裡 14 個零散的 padding、margin、gap 值換成最接近的刻度變數（例如 13px → 12px 的那一階；0 和 auto 保留）。最後讓卡片內距跟著所在的欄寬：主欄的寬卡片用 --space-5，卡片所在的欄寬小於 20rem 時（側欄、手機）降成 --space-4。主欄與側欄已經是 container（第 12 課）。

練習 4：為什麼要把變數分成 palette 與語意變數兩層？

✓ b：元件用 --color-accent，深色模式把它指向 --brown-300 就好；如果元件直接用 --brown-700，每個元件都要為深色模式再寫一次。a 錯：變數的值可以是任何東西，包括直接寫色碼。c 錯：多一層代入不會更快，差別也小到量不出來。d 錯：搜尋引擎不讀 CSS 變數的名字。

練習 5：只寫 :root { color-scheme: light dark; }，系統是深色時會發生什麼事？

✓ b：color-scheme 告訴瀏覽器頁面支援兩種配色，瀏覽器只調整它自己負責畫的部分；你寫的 color: #35251b 要靠語意變數或 light-dark() 切換。a 錯：瀏覽器不知道你的品牌色深色版是什麼。c 錯：沒寫任何自訂顏色的頁面，光靠它就會變深色。d 錯：寫 light dark 是跟隨偏好，強制要寫單一個 dark。

練習 6：做色階時用 oklch() 只改 L，比用 hsl() 只改 L 好在哪裡？

✓ b：HSL 的 L 是數學上的明度，黃色與藍色同樣 50% 實際亮度差十幾倍；oklch 的 L 照人眼感受設計，改 L 得到的色階亮度均勻。a 錯：檔案大小不是重點。c 錯：任何顏色寫法都能放進變數。d 錯：對比還是要算，oklch 只是讓你比較容易一次挑對。

常見錯誤

  • 元件直接用原始色：.btn { background: var(--brown-700) } 看起來有用變數，但深色模式、品牌改版時還是要逐一改元件。元件只用語意變數。
  • 深色模式用 invert 濾鏡：照片、品牌色、陰影全部錯，例外處理比正常做還麻煩。換語意變數。
  • 忘記 color-scheme：深色頁面上出現白色的輸入框與亮色捲軸；light-dark() 也不會切換。
  • 只檢查淺色模式的對比：深色模式的次要文字、連結最常不到 4.5:1。兩個主題都要算。
  • data-theme 被 media query 蓋掉：@media 不增加權重，同權重時後面的勝出。用 :root:not([data-theme="light"]) 或 :root[data-theme] 處理優先順序，四種組合都測。
  • 變數名稱拼錯沒發現：var() 找不到變數時屬性變成 unset，不會報錯。在 DevTools 的 Styles 面板看變數有沒有被標示為未定義。
  • 局部覆寫主色，衍生色沒跟著變：衍生變數在宣告它的元素上就代入完了。覆寫時一起重新宣告，或在元件規則裡現算。

補充與查表

var() 預設值裡的逗號：var(--名字, 預設值) 第一個逗號後面的全部都是預設值，所以預設值裡可以有逗號，例如 var(--font, "Noto Sans TC", sans-serif)。要串好幾層預設值時，寫成巢狀的 var(--a, var(--b, 16px))；寫成 var(--a, --b, 16px) 的話，預設值是「--b, 16px」這串文字，不是你要的意思。

在 JavaScript、Vue 裡讀寫變數，以及 @property：

  • 讀：getComputedStyle(el).getPropertyValue('--color-accent')；寫：el.style.setProperty('--card-pad', '24px')。改變數比逐一改元素的樣式簡單，而且 CSS 那邊不用知道 JavaScript 的存在。
  • Vue SFC 的 <style> 裡用 v-bind(color)，編譯後就是一個加了雜湊名稱的 custom property，由 Vue 設在元件的根元素上。
  • @property 可以註冊變數的型別、是否繼承與初始值。註冊成 <color> 之後，不合法的值會改用 initial-value，變數也可以做 transition。一般主題變數不需要它，知道有這個工具就好。

color-mix() 省略色彩空間：規範允許省略 in …（預設 oklab），但這是後來才加的寫法，實務上一律寫出來。

小結

  • 寫死的色碼換品牌色改不乾淨、深色模式要整份重寫、也看不出用途。替設計決策取名字，就是設計變數。
  • custom properties 以 -- 開頭、用 var() 讀取、會繼承，可以在任何元素上局部覆寫；var(--x, 預設值) 處理沒定義的情況。代入後不合法時屬性變成 unset，不會退回前一條宣告，Console 也不報錯，要在 DevTools 的 Styles 面板查。
  • 變數分兩層：palette 描述外觀，語意變數描述用途；元件只用語意變數，換主題只改語意層。
  • oklch() 固定色相、改亮度 L 做色階，亮度均勻、對比好預測（白底文字約 L ≤ 0.55，深底約 L ≥ 0.65）；每次調色都重算 4.5:1。color-mix(in oklch, …) 從主色算出 hover 等狀態色；衍生色在宣告它的元素上就算好，局部覆寫主色時要一起重新宣告或在元件裡現算。
  • 深色模式：color-scheme: light dark 讓瀏覽器的控制項跟著變，語意變數用 media query 或 light-dark() 切換；使用者用 data-theme 手動選擇時要勝過系統偏好，四種組合都要測。
  • 間距用 rem 定義 4／8 為基準的刻度，元件只挑刻度上的值；在窄的容器裡改成「換一階」，不要發明新值。最後用 lint 與兩個主題的驗收讓團隊守住變數。
