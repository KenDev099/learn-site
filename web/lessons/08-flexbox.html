階段 2：CSS 與版面基本功 · 第 8 課

Flexbox

第 7 課把菜單卡片在 320px 手機上撐破的問題修好了。接下來要做咖啡店菜單頁上三個元件：頁首要把 logo、選單、購物車排成一行，購物車靠最右；菜單卡片要縮圖在左、文字在右，品名再長也不能撐破卡片；商品頁的口味標籤和兩顆按鈕，寬螢幕並排、手機上下排。這三個元件有同一個問題：一排東西要怎麼分配一行的空間。正常流只會把 block 一個一個往下疊，做不到這件事；Flexbox 就是為它設計的。

這課從頁首開始，一路做到商品頁的按鈕群。每做一個元件都會遇到一個新問題，解掉它就多學會 Flexbox 的一塊。最後兩節處理上線前一定會碰到的事：設計稿要手機版換順序怎麼辦，版面不對時怎麼查。

這課的路線：
  1. 頁首怎麼排成一行、購物車怎麼推到最右邊（開場問題的最小答案）；接著問為什麼一個屬性叫 justify、一個叫 align：主軸與交錯軸。
  2. 菜單卡片的文字區怎麼占滿縮圖右邊的空間：flex-grow、flex-shrink、flex-basis 怎麼分配多出來和不夠的空間，flex: 1 和 flex: auto 差在哪。
  3. 長品名為什麼把卡片撐破、省略號為什麼不出現：flex 項目的最小尺寸與 min-width: 0。
  4. 商品頁的標籤和按鈕怎麼不寫 media query 就自己換行：flex-wrap，以及它排不出整齊格線的原因。
  5. 設計稿要手機版換順序時為什麼不用 order；版面不對時 DevTools 怎麼看。
這課會用到：
  • 第 7 課的正常流：block 元素各占一行、由上往下排；inline 元素在一行裡由左往右排。
  • 第 7 課的溢出處理：長單字用 overflow-wrap: anywhere 拆開；單行省略號是 white-space: nowrap＋overflow: hidden＋text-overflow: ellipsis 三件一起寫。

頁首的 logo、選單、購物車怎麼排成一行？

先從頁首開始。咖啡店的頁首 HTML 是這樣，順序就是螢幕閱讀器與鍵盤會走的順序，這一點最後一節會再用到：

<header class="site-header">
  <a class="logo" href="/">豆留咖啡</a>
  <nav class="main-nav" aria-label="主選單">
    <ul>
      <li><a href="/menu/">菜單</a></li>
      <li><a href="/stores/">門市</a></li>
      <li><a href="/about/">關於我們</a></li>
    </ul>
  </nav>
  <button class="cart" type="button">購物車</button>
</header>

什麼 CSS 都不寫，畫面是三行。原因是第 7 課的正常流：<a> 和 <button> 是 inline，本來可以並排；但夾在中間的 <nav> 是 block，block 一定自己占一整行，所以 logo 在第一行、選單在第二行、購物車被擠到第三行。我們要的是「三個東西並排在同一行」，這不是正常流能表達的事。

Flexbox 的做法是：在父元素寫一行，改變它的子元素怎麼排。

.site-header {
  display: flex;
}

寫了這行之後，頁首裡出現兩個角色。往後整課都用這兩個名字，先把它們分清楚：

  • flex 容器（flex container）：寫了 display: flex 的元素，這裡是 .site-header。容器上的屬性決定「子元素怎麼排」。
  • flex 項目（flex item）：容器的直接子元素，這裡是 logo、nav、button 三個。不管它們原本是 block 還是 inline，現在都改由容器來排，排成一行。孫元素（nav 裡的 li）不是，它們照原本的方式排：li 是 block，選單會變成三行直排，ul 還帶著預設的上下 margin 和項目符號。選單本身也是「一排東西」，所以要在 ul 再開一層 flex，並清掉清單的預設樣式（下面的程式碼會寫）。

現在三個項目由左到右排在一行，每個的寬度是它內容需要的寬度，三個加起來比頁首窄，右邊空了一大塊。這一塊沒有人用的空間，Flexbox 叫它剩餘空間。整課的問題幾乎都可以換成「剩餘空間要放在哪裡、要分給誰」。

設計稿要的是「logo、選單靠左，購物車靠最右」，換句話說：剩餘空間要整塊放在選單和購物車之間。有兩種常見寫法，結果不一樣：

寫法結果適合
容器 justify-content: space-between剩下的空間平均放到項目之間：logo 在最左、購物車在最右，選單被推到正中間只有兩個項目，或真的要平均分散
購物車 margin-left: auto剩下的空間全部給購物車左邊的 margin：logo、選單靠左，購物車被推到最右「前面幾個靠左、最後一個靠右」這類分組

space-between 是容器層級的規則：它不知道你想把哪幾個項目分成一組，只會把剩餘空間平均切給每一個間隔。三個項目有兩個間隔，所以選單會落在正中間。margin-left: auto 則是寫在某一個項目上：flex 項目上的 margin: auto 會吃掉那個方向所有剩下的空間，等於說「把剩餘空間全部塞在我的左邊」。這是 Flexbox 裡最實用的技巧之一。想讓選單和購物車都靠右，就把 margin-left: auto 改寫在選單上，剩餘空間就塞在 logo 和選單之間。

排好位置後還有兩個細節。logo 字大、選單字小，三個項目高度不同，預設的對齊會讓它們看起來歪的（下一節會解釋為什麼）；容器加 align-items: center 讓它們在垂直方向置中。項目之間要有間距，在容器加 gap: 16px，每兩個項目之間就有固定 16px。頁首的最小版本完成了：

.site-header {
  display: flex;
  align-items: center;
  gap: 16px;
}
.main-nav ul {
  display: flex;      /* 選單本身也是一排，再開一層 flex */
  gap: 16px;
  margin: 0;
  padding: 0;
  list-style: none;
}
.cart {
  margin-left: auto;
}

為什麼用 gap，不在每個項目加 margin-right？margin 是項目自己的，最後一個項目後面也會多出一段空白；之後項目換行時，上下兩行之間也沒有間距。gap 是容器的規則，只放在項目「之間」，換行後上下也有間距。

頁首能動了，但剛才用了兩個屬性：一個叫 justify-content，一個叫 align-items。為什麼名字不一樣？如果把頁首改成直的（例如手機的側邊選單），它們會不會還是一個管水平、一個管垂直？

為什麼一個叫 justify、一個叫 align？主軸與交錯軸

答案是：Flexbox 不講「水平」和「垂直」，它講兩條軸。這兩條軸是 Flexbox 所有對齊屬性的基礎，名字搞混了，之後每個屬性都會記錯。

  • 主軸（main axis）：項目排列的方向，由容器的 flex-direction 決定。預設 row 是由左到右（跟文字方向一樣），所以頁首的三個項目才會橫著排；改成 column 就是由上到下。
  • 交錯軸（cross axis）：跟主軸垂直的那條。主軸是橫的，交錯軸就是直的；主軸是直的，交錯軸就是橫的。

有了兩條軸，名字就說得通了：justify-content 永遠管主軸，處理「剩餘空間在主軸上怎麼放」；align-items 永遠管交錯軸，處理「每個項目在交錯軸上怎麼對齊」。頁首的主軸是橫的，所以 justify 剛好在管水平、align 剛好在管垂直，但這只是 row 時的巧合。

切成 flex-direction: column 時，兩條軸對調：justify-content: center 變成垂直置中、align-items: center 變成水平置中。所以要記的是「justify 管主軸、align 管交錯軸」，不要記「justify 是水平」；後者在 column 方向的元件上一定會用錯。

這幾個容器與項目上的屬性整理成一張表，之後寫元件時回來查，不用背：

屬性寫在管哪條軸常用值
flex-direction容器決定主軸方向row（預設）、column
justify-content容器主軸：剩下的空間怎麼放flex-start（預設）、center、flex-end、space-between
align-items容器交錯軸：每個項目在自己那一行裡怎麼對齊stretch（預設）、center、flex-start、baseline
align-self項目交錯軸：只改這一個項目的對齊同 align-items
gap容器項目之間的固定間距（兩個值時是「行之間 欄之間」）16px、8px 16px

交錯軸的預設值：stretch，以及什麼時候改成 baseline

上一節說頁首「不寫 align-items 會歪」，原因在 align-items 的預設值 stretch：沒有設高度的項目會被拉到跟這一行最高的項目一樣高。頁首裡沒設高度的項目都被拉到這一行最高的那個項目的高度：選單的小字貼在頂端，跟 logo 的大字對不齊，購物車按鈕的框被拉高，看起來就歪了。改成 center 後，每個項目保持自己的高度、在交錯軸上置中。

stretch 不是壞事。兩張卡片並排時，內容短的那張也會跟長的一樣高，這通常是你要的。但它也會讓按鈕、圖片被拉高變形，遇到這種項目就改成 center 或 flex-start；只有一個項目要例外時，在那個項目上寫 align-self。

還有一種情況 center 也不對：品名用大字、價格用小字並排。center 對齊的是兩個盒子的中線，字的大小不同，兩行字的底部就會上下錯開。baseline 讓每個項目第一行文字的基線（字母底部那條線）對齊，看起來才像同一行字。菜單卡片的價格列會這樣寫：

.price-row {
  display: flex;
  align-items: baseline;   /* 「拿鐵」和「110 元」的字底對齊 */
  gap: 8px;
}

到這裡，頁首完成了：我們知道剩餘空間怎麼放（justify-content、margin auto），項目在交錯軸怎麼對齊（align-items）。但這兩件事都把項目的寬度當成固定的，每個項目就是內容那麼寬。下一個元件是菜單卡片，它的文字區不能只有內容那麼寬，要長大占滿縮圖右邊的所有空間。項目自己的寬度要怎麼決定？

菜單卡片的文字區怎麼占滿剩下的空間？flex-grow、flex-shrink、flex-basis

菜單卡片 .menu-item 是 flex 容器，裡面兩個項目：左邊 96px 的縮圖 .thumb，右邊是品名與說明的文字區 .text。設計稿要文字區占滿縮圖右邊剩下的全部寬度，品名「拿鐵」很短的卡片也一樣，這樣每張卡片的右緣才對齊。

上一節的 justify-content、margin auto 只能決定剩餘空間「放在哪個空隙」，空隙裡什麼都沒有。這裡要的是把剩餘空間「分給某個項目」，讓那個項目本身變寬。反過來，手機上卡片很窄時，項目加起來比容器還寬，差的那一段也要從項目身上縮回來。Flexbox 用每個項目上的三個屬性決定它怎麼參與分配：

  • flex-basis：分配之前的起始大小。預設 auto，意思是「有寫 width 就用 width，沒寫就用內容的寬度」。瀏覽器先把每個項目都擺成 basis 的大小，再看剩多少、差多少。
  • flex-grow：有剩餘空間時，這個項目分幾份。預設 0，不長大。所以頁首的三個項目都只有內容那麼寬，剩餘空間才會留在空隙裡。
  • flex-shrink：空間不夠時，這個項目縮多少。預設 1，會縮。縮的量按 flex-shrink × flex-basis 的比例分攤，起始越大的縮越多。

所以文字區要占滿，就是讓它的 flex-grow 大於 0：縮圖的 grow 是預設 0，文字區寫 1，剩餘空間全部歸文字區。實際上通常不分開寫三個屬性，而是用簡寫 flex: <grow> <shrink> <basis>。簡寫有幾個常見的值，名字很像、行為不同，下面這幾個最常見（依 MDN 的 flex 頁面）：

寫法等於行為常見用途
不寫（flex: initial）0 1 auto內容多寬就多寬，不長大，空間不夠會縮大部分項目
flex: 11 1 0%從 0 開始，剩餘空間按 grow 比例分好幾欄要一樣寬；某一塊吃掉剩下的空間
flex: auto1 1 auto從內容寬開始，再平分剩下的內容多的那個分得比較寬
flex: none0 0 auto完全固定，不長大也不縮圖示、縮圖、頭像
flex: 0 0 200px—固定 200px固定寬的側欄
flex: 1 1 240px—從 240px 開始，可長大可縮小配合 flex-wrap 的自動換行

最容易混的是 flex: 1 和 flex: auto。兩者的 grow、shrink 一樣，差別只在 basis，也就是分配的起點：flex: 1 的 basis 是 0，所有項目從 0 開始、整個容器按比例平分；flex: auto 的 basis 是內容寬，先各自拿到內容需要的寬度，再平分剩下的。用兩個項目算一次就清楚：

菜單卡片只有文字區會長大，縮圖不長大，所以文字區寫 flex: 1 或 flex: auto 都能占滿剩餘空間。兩者的差別要等空間不夠、開始縮的時候才看得出來，這正是手機上會發生的事：下一節修好撐破問題後，會看到 flex: auto 怎麼把縮圖一起拖下水。

縮小用同一套規則反過來算。容器只剩 300px，A、B 都是 flex: 0 1 200px，加起來 400，差 100。兩者的 shrink 一樣、basis 一樣大，各縮 50，都是 150。把 A 改成 flex-shrink: 0，A 保持 200，100 全部由 B 縮，B 剩 100。換到卡片上：縮圖的 shrink 預設是 1，表示空間不夠時它也會被拿去縮。縮圖要永遠 96px，就要明確寫 flex-shrink: 0（或 flex: none）。

照這套規則，手機上卡片變窄時，文字區應該會乖乖縮、品名換行才對。但實際把一個很長的英文品名放進 320px 的手機，卡片還是被撐出畫面。shrink 明明是 1，文字區為什麼不縮？

長品名為什麼把卡片撐破、省略號為什麼不出現？

答案是：項目再怎麼縮，也不會比它的最小尺寸窄，而 flex 項目的最小尺寸預設比你想的大。

先重現問題。卡片的品名是 Supercalifragilisticespresso Tonic，在 320px 的手機上整張卡片伸出畫面。第 7 課教過長單字用 overflow-wrap: anywhere 拆開，在 .name 加上去之後還是撐破。要看懂原因，先認識一個詞：

最小內容尺寸（min-content）是內容能縮到的最小寬度，取的是裡面最寬、拆不開的那一段：最長的那個不能拆的單字，或一張圖片，或 white-space: nowrap 的一整行。第 7 課的 width: min-content 用的就是它。overflow-wrap: anywhere 產生的斷點算進 min-content，break-word 不算。

一般 block 元素的 min-width 預設 auto 等於 0，可以縮到比內容窄，內容放不下就換行或溢出。但 flex 項目的 min-width: auto 會算成它的 min-content（MDN min-width 頁面）。規範這樣設計，是為了讓 flex 項目預設不會被擠到比內容還窄、文字疊在一起。代價是：flex-shrink 想把文字區縮小，縮到 min-content 就停了，剩下不夠的部分只能溢出容器，把卡片撐破。

用這兩件事回頭看這張卡片，因果分三步：

  1. 文字區 .text 的 min-content，是它裡面最寬、拆不開的那一段。
  2. 品名加了 overflow-wrap: anywhere，長單字可以在任何位置拆開，這些斷點算進 min-content，所以單看品名，它的 min-content 已經很小，本來可以縮。如果用的是 break-word，或什麼都沒寫，最長的那個單字就會把 min-content 撐大。
  3. 但卡片還有一行說明 .desc，它寫了 white-space: nowrap 加 text-overflow: ellipsis，整行文字不能換行。這一整行就成了 .text 的 min-content，文字區縮不到比它窄，品名也就沒機會換行。

省略號不出現也是同一個原因。省略號只在文字比它的容器寬時才出現；文字區被撐成 .desc 整行那麼寬，.desc 永遠放得下整行，根本沒被擠到。撐破和省略號失效是同一件事的兩個現象，「省略號在 flex 裡失效」幾乎都是這個原因。

修法是讓文字區允許縮到比內容窄，把它的最小尺寸改成 0；縮進來之後，裡面的長品名才有機會換行，說明才有機會被截斷：

.text {
  flex: 1;          /* 占滿縮圖右邊剩下的空間 */
  min-width: 0;     /* 允許縮到比內容窄，裡面的文字才有機會換行、省略 */
}
.name {
  overflow-wrap: anywhere;   /* 長單字放不下時可以拆開 */
}
.thumb {
  flex-shrink: 0;   /* 縮圖永遠 96px，不參與縮小 */
}

min-width: 0 要寫在被撐開的那個 flex 項目上，這裡是 .text，不是寫在 .name 或容器上：被 min-width: auto 卡住的是 flex 項目本身，.name 只是文字區裡的一般 block。巢狀好幾層 flex 時，從容器到長文字的路徑上，每一層 flex 項目都可能要寫。直排的版面是同一個問題換成高度，見課末「補充與查表」。

這就是上一節說 flex: 1 和 flex: auto 縮的時候不一樣的地方。縮圖的 flex-shrink: 0 看起來可有可無：沒寫的時候縮圖也沒被壓縮。但那是巧合，因為圖片的 min-content 剛好是 96px，它本來就縮不下去。如果文字區寫的是 flex: auto（起始寬度是整段文字的寬），又有人加了一條 .menu-item > * { min-width: 0 }，兩者都能縮到 0，不足的空間會按 basis 比例分攤，縮圖就被擠扁了。固定大小的東西要明確說「我不縮」，不要依賴巧合。

在 .text 加 overflow: hidden 也能讓它縮進來，但會同時裁掉內容，例如焦點外框，細節見課末。只是要能縮，寫 min-width: 0 意圖最清楚。

💡 實務上：版面要用「最長的真實資料」測過才算完成
設計稿上的品名通常是「拿鐵」，上線後真正撐破版面的是後台新增的長品名、顧客的英文全名、翻譯後變長的按鈕字，或沒有空格的網址與訂單編號。卡片、列表列、頁首這類「左邊固定、右邊放文字」的元件，寫完先在 320px 塞一段超長、不能斷的字串試試看。資深工程師 review 這類元件時，第一個會問的是「名字很長會怎樣」，並確認文字區有 min-width: 0、固定大小的縮圖或圖示有 flex-shrink: 0。內容要截斷還是換行，要先跟設計或 PM 確認：品名被省略號截掉，顧客可能點錯商品。

菜單卡片完成了。但到目前為止，空間不夠時我們只有一種處理：讓項目縮。商品頁的口味標籤有七個，手機上不管怎麼縮都擠不進一行；兩顆按鈕縮到太窄也很難按。這時要的不是縮，而是換到下一行。

商品頁的標籤和按鈕怎麼自己換行？flex-wrap

Flexbox 預設 flex-wrap: nowrap：所有項目硬擠在同一行，擠不下就縮，縮到最小尺寸還放不下就溢出。前兩個元件都在這個預設下運作。加上 flex-wrap: wrap，放不下的項目就換到下一行：

.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;          /* 左右、上下都是 8px */
}

口味標籤這樣寫，寬螢幕一行、手機兩三行，不用寫任何 media query。第一節說 gap 換行後上下也有間距，指的就是這裡。

換不換行是怎麼決定的？瀏覽器拿每個項目的 flex-basis（夾在 min-width 與 max-width 之間）依序放，加上 gap 超過這一行就換行；放好之後，每一行再各自用 grow、shrink 分配那一行的空間。也就是說，basis 決定換行，grow 決定換行之後怎麼填滿。這兩步分開想，下面的按鈕群就好懂了。

不用 media query 的按鈕群

商品頁的兩顆按鈕（加入購物車、立即結帳）在寬螢幕各占一半、窄的時候上下排：

.actions {
  display: flex;
  flex-wrap: wrap;
  gap: 12px;
}
.actions button {
  flex: 1 1 240px;   /* 每顆至少想要 240px，放得下兩顆就並排，再一起長大 */
}

容器 640px 時，240 + 12 + 240 放得下，兩顆並排再平分剩下的；容器 300px 時第二顆換到下一行，每一行只有一顆，各自長到占滿。切換點跟著容器寬度，不是整個視窗：同一組按鈕放進窄側欄也會自動上下排。

這裡不能偷懶寫 flex: 1。它的 basis 是 0，瀏覽器判斷換行時把每顆按鈕當成 0 寬（實際上會被 min-content 撐到文字那麼寬），只要兩顆按鈕的文字本身還擠得下就不會換行，320px 的手機上會變成兩顆很窄的按鈕。要在某個寬度換行，就要用 basis 說出那個寬度。

頁首在 320px 的手機上也有同樣的問題：logo、選單、購物車擠不進一行。練習 1 會讓你把這一節的換行和第一節的 margin auto 組合起來。

用 flex 做卡片格線的問題

按鈕群的寫法這麼方便，很容易想拿它排整頁的菜單卡片（flex: 1 1 240px 加 wrap）。它也能自動換行，但最後一列只有兩張時，那兩張會長大到各占一半，比上面的卡片寬。原因就是上面說的兩步：Flexbox 換行後每一行各自分配空間，一次只看一行，不知道上一行的欄寬，所以排不出「欄對齊」的格線。要每一列都對齊的二維版面，用第 9 課的 Grid。

💡 實務上：Flexbox 管「一排東西」，整頁格線交給 Grid
工作中大部分的小元件都是一維的：頁首、工具列、表單裡「輸入框＋按鈕」那一列、標籤列、卡片內部的「縮圖＋文字」、對話框底部的按鈕群，這些用 Flexbox 最直接。需要欄與列都對齊的東西，例如商品卡片牆、後台的整頁版面，才換成 Grid。常見的組合是「外層 Grid 排版面，每張卡片裡面用 Flexbox 排內容」，兩者搭配使用，不是二選一。看到為了讓最後一列對齊而算 calc() 寬度、補空白元素的 flex 寫法，通常就是該換 Grid 的訊號。

三個元件都做完了。上線前，設計師補了一張手機版的設計稿：「手機上把購物車移到 logo 旁邊，選單放到下一行。」改 HTML 要動到模板，Flexbox 剛好有一個只要一行 CSS 就能改順序的屬性。可以用嗎？

設計稿要手機版換順序，可以用 order 嗎？

Flexbox 確實可以只改畫面上的順序：項目的 order（預設 0，小的排前面），或容器的 flex-direction: row-reverse／column-reverse。問題在「只改畫面」：它們不動 DOM 順序，而下面這些都照 DOM 走：

  • 按 Tab 的焦點順序（第 5 課）：畫面上購物車在 logo 旁邊，焦點卻要走完整個選單才到它，鍵盤使用者看到焦點在畫面上亂跳。
  • 螢幕閱讀器朗讀的順序。
  • 選取、複製文字的順序。

這違反 WCAG 2.4.3 焦點順序（Focus Order）。這就是第一節說「HTML 的順序就是鍵盤會走的順序」的原因：要改順序，就改 HTML 的順序。如果不同寬度真的需要不同順序，先確認畫面上的兩種順序閱讀起來都合理，而且 DOM 順序是比較重要的那一個。只有純裝飾、不能聚焦、不影響閱讀的東西，才可以放心用 order。

回到設計師的需求，比較好的做法是回頭討論一個不用換順序的版本。例如手機上讓 logo 自己一行、選單和購物車排在第二行、購物車靠右：購物車一樣好找，DOM 順序完全不變，Tab 從 logo、選單一路走到購物車，跟眼睛看的順序一致。這就是練習 1 的版面。

💡 實務上：設計稿要求手機版換順序時，先改 HTML 或回頭跟設計討論
常見情境是設計稿寫「手機版把購物車移到最前面」或「商品圖在桌機放右邊、手機放上面」，直接寫 order 最快，但鍵盤與螢幕閱讀器使用者會遇到焦點亂跳。比較好的做法是先問：兩種順序哪一個在閱讀上比較合理？通常能把 HTML 改成那個順序，另一種寬度再用排版去配合（例如圖片在 DOM 裡放前面，桌機用 Grid 擺到右邊）。code review 時看到 order 或 row-reverse 用在連結、按鈕這類可聚焦的元素上，值得停下來問一句，上線前也用 Tab 實際走一遍。

寫法都會了，但實際做元件時，畫面不對的時候不會告訴你是哪一條規則在作怪。最後一節把這課遇到的問題反過來整理：看到某個現象，先查什麼。

版面不對時，怎麼查是哪一條規則？

flex 版面出問題時，先讓 DevTools 把每個項目的範圍畫出來，再依現象對照前面的小節：

  • 看 flex 的版面：DevTools 的 Elements 面板裡，flex 容器旁邊有一個 flex 標籤，點下去頁面上會畫出每個項目和 gap 的範圍；Styles 面板裡 display: flex 旁邊的小圖示可以直接點選 justify-content、align-items 的值，邊點邊看。
  • 項目超出容器（菜單卡片那一節）：先找哪個 flex 項目比預期寬，看它裡面是不是有長單字、nowrap、固定寬的圖片；在那個項目上試 min-width: 0。
  • 某個項目被壓扁：它的 flex-shrink 是 1；固定大小的東西寫 flex-shrink: 0。
  • 對齊沒反應：確認屬性寫在對的地方（justify-content、align-items 寫在容器，align-self、margin auto 寫在項目），再確認主軸方向。justify-content 沒效果常常是因為某個項目有 flex: 1，已經把剩餘空間吃光了：沒有剩餘空間，就沒有東西可以放。

DevTools 的版面工具在第 18 課會完整介紹。

補充與查表

  • 用 overflow 讓 flex 項目能縮：把 overflow 設成 hidden、auto 這類會變成捲動容器的值，也會讓 min-width: auto 算成 0（MDN：捲動容器的自動最小尺寸是 0；clip 不是捲動容器，沒有這個效果），但它同時會裁掉內容，例如焦點外框。只是要「能縮」就寫 min-width: 0，意圖最清楚。
  • column 方向的同一個問題：column 方向的版面（例如側欄裡的捲動清單）是同一個問題換成高度：min-height: auto，修法是 min-height: 0。
  • gap 的支援度：flex 容器的 gap 已經是第 4 課提過的 Baseline widely available，不需要備案。

練習

練習 1：做咖啡店的頁首。HTML 的順序固定是 logo、主選單、購物車按鈕，不能改。768px 以上三者在同一行、垂直置中：logo 靠左，主選單緊接在 logo 後面，購物車按鈕靠最右。320px 寬時放不下一行：logo 自己一行，主選單換到第二行靠左，購物車按鈕跟主選單在同一行的最右邊。整頁不能橫向捲動，不能用 position: absolute、float、order 或 row-reverse。提示：先想「多出來的空間要放在哪裡」。

練習 2：菜單的每一張卡片 .menu-item 是 flex 容器，左邊是 96px 的縮圖，右邊是文字區 .text。長英文品名讓卡片撐出畫面，說明的省略號也沒出現。修正後：縮圖保持 96×96，而且明確設定不會被壓縮；文字區占滿縮圖右邊剩下的空間（短品名的卡片也一樣）；長品名在卡片裡換行；說明維持一行，放不下的部分顯示省略號。HTML 不能改，不能用 overflow 把卡片或列表裁掉。

練習 3：商品頁有一排口味標籤和兩顆按鈕。標籤依內容寬度排列、放不下就換行，標籤之間左右、上下都是 8px（第一個標籤貼齊左邊）。按鈕群（加入購物車、立即結帳）每顆至少要 240px 寬：放得下兩顆時並排、各占一半，放不下時上下排、各占滿一整列。不能用 media query。HTML 不能改。

練習 4：flex: 1 等於哪一個寫法？

✓ b：簡寫只給一個數字時，它是 flex-grow，flex-shrink 補 1，flex-basis 補 0%。所以每個項目都從 0 開始分空間，grow 一樣就一樣寬。c 是 flex: auto，從內容寬開始，內容多的比較寬。d 的 basis 還是 auto，結果跟 c 一樣。a 的 shrink 是 0，空間不夠時不會縮。

練習 5：flex 項目裡有一個很長的英文單字，把整個容器撐破了。最常見的原因是什麼？

✓ b：在被撐開的那個項目上寫 min-width: 0 讓它能縮，再用 overflow-wrap: anywhere 讓長單字拆開。a、d 錯：這是規範定義的行為。c 錯：wrap 只讓項目換到下一行，那個項目自己還是比容器寬。

練習 6：用 order: -1 把「立即點餐」按鈕排到畫面最前面，會有什麼副作用？

✓ b：order 只改畫面順序，Tab 與朗讀順序照 DOM，違反 WCAG 2.4.3 焦點順序。要改順序就改 HTML。c 錯：order 不影響搜尋引擎讀到的內容順序，問題在使用者。d 錯：order 對 flex 與 grid 項目都有效。

常見錯誤

  • 用 order、row-reverse 改順序：只改畫面，焦點與朗讀順序照 DOM，鍵盤使用者會迷路。要改順序就改 HTML。
  • 忘了 min-width: 0：flex 項目不會縮到比 min-content 窄，長單字、nowrap 的省略號會把它撐破。寫在被撐開的那個項目上，再配合 overflow-wrap: anywhere。
  • 固定大小的東西沒寫 flex-shrink: 0：縮圖、圖示、頭像在空間不夠時被壓扁。
  • 用 space-between 做「最後一個靠右」：中間的項目會被推到正中間。要分組靠右用 margin-left: auto。
  • 用 margin 做項目之間的間距：最後一個多出空白、換行後上下沒有間距。用 gap。
  • 想換行卻寫 flex: 1：basis 是 0，幾乎總是放得下，不會在你想要的寬度換行。要換行就給 basis，例如 flex: 1 1 240px。
  • 用 flex 做二維格線：每一行各算各的，最後一列的卡片會被拉寬、欄對不齊。二維版面用 Grid。

小結

  • 頁首：display: flex 讓直接子元素變成 flex 項目排成一行。整課的問題都是「剩餘空間放哪、分給誰」：margin-left: auto 把剩餘空間整塊塞在某個項目左邊，space-between 則平均分到每個間隔；項目之間的間距用 gap。
  • 主軸由 flex-direction 決定，justify-content 管主軸、align-items／align-self 管交錯軸，column 時兩條軸對調。align-items 預設 stretch，高度不同的項目改 center，大小字並排用 baseline。
  • 菜單卡片：flex: grow shrink basis，basis 是起點，grow 分剩下的，shrink 按 shrink × basis 分攤不足的。flex: 1 是 1 1 0%，flex: auto 是 1 1 auto，flex: none 是 0 0 auto。
  • flex 項目預設 min-width: auto（＝min-content），長品名、nowrap 的說明會撐破它、讓省略號失效：在被撐開的項目寫 min-width: 0；固定大小的縮圖寫 flex-shrink: 0。
  • 商品頁：flex-wrap: wrap 時 basis 決定換不換行、grow 決定換行後怎麼填滿，有 basis 的項目（flex: 1 1 240px）能跟著容器寬度換行，不用 media query。每一行各算各的，所以排不出欄對齊的格線。
  • order 與 reverse 只改畫面，不改焦點與朗讀順序；要改順序就改 DOM，或跟設計討論不用換順序的版本。
