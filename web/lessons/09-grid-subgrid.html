階段 2：CSS 與版面基本功 · 第 9 課

Grid 與 subgrid

咖啡店首頁要改版，設計稿交到你手上：最上面是頁首和冬季主打的大圖，中間是菜單區，十張商品卡片「桌機一列四張、平板兩張、手機一張」，右邊有一條門市資訊的側欄，最下面是頁尾。設計師另外標了兩個要求：最後一列的卡片要跟上面一樣寬；每張卡片裡的品名、描述、價格、「加入購物車」按鈕，左右要對在同一條線上。

用第 8 課的 Flexbox 排卡片，這兩個要求剛好都做不到：最後一列的卡片會被拉得特別寬，描述長短不一的卡片，價格和按鈕會高高低低。這課從這個首頁出發，一路做完卡片格線、整頁版面、跨欄的主打卡片和卡片內的對齊。用到的工具是 CSS Grid：它同時管「列」與「欄」兩個方向，讓所有項目對齊到同一組格線上。

這課的路線：
  1. Flexbox 排卡片為什麼最後一列會被拉寬？Grid 怎麼解決（開場問題的最小答案），display: grid 之後瀏覽器建立了哪些東西。
  2. 欄寬怎麼算、欄數怎麼跟著螢幕變：fr、minmax()，以及不寫 media query 做到「四張、兩張、一張」的 auto-fill。
  3. 卡片區外面的整頁版面：用 grid-template-areas 把首頁「畫」出來，同時不讓畫面順序和鍵盤順序對不上。
  4. 本月主打的卡片要跨整列，卡片裡的價格和按鈕要對齊：span 與 subgrid。
  5. 回頭看整個首頁：哪裡該用 Flexbox、哪裡該用 Grid。
這課會用到：
  • 第 8 課的 Flexbox：flex-wrap: wrap 讓放不下的項目換到下一行，gap 設定項目之間的間距，flex: 1 讓項目分掉剩餘空間。
  • 第 6 課提過的 @media：條件成立才套用裡面的規則，例如 @media (min-width: 48rem) { … } 只在畫面至少 768px 寬時生效。

Flexbox 排卡片，為什麼最後一列被拉寬？

先用已經會的工具試試看。第 8 課用 flex-wrap 做過會自動換行的元件，拿同一招排菜單區的十張卡片，設計稿說卡片最小 280px：

.menu {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}
.card {
  flex: 1 1 280px;   /* 從 280px 開始，有剩餘空間就伸展 */
}

桌機寬 1280px，.menu 左右各有 24px padding，內容寬 1232px。一列放得下 4 張（4 × 280 + 3 × 16 = 1168），放第 5 張就超過（5 × 280 + 4 × 16 = 1464）。十張卡片排成 4、4、2 三列。

問題出在 Flexbox 的運作方式：每一列各自分配剩餘空間。換行之後，每一列都是一個獨立的 flex 行，第 8 課教過的 flex-grow 只在這一行裡面分空間，不會看上一行的卡片多寬。前兩列各有 4 張，扣掉 3 個 gap 再平分，每張 (1232 − 48) ÷ 4 = 296px；第三列只有 2 張，扣掉 1 個 gap 平分，每張 (1232 − 16) ÷ 2 = 608px，比上面寬了一倍。

這不是哪個值寫錯，是 Flexbox 的設計：它一次只看一個方向，列與列之間沒有共同的「欄」。想讓所有卡片對齊到同樣的欄，需要一個先把欄畫好、再把卡片放進去的工具，這就是 Grid。同一個菜單區用 Grid 寫：

.menu {
  display: grid;
  grid-template-columns: repeat(4, 1fr);   /* 四欄，平分寬度 */
  gap: 16px;
}

卡片本身什麼都不用寫，寬度由它所在的欄決定。三列共用同一組四條欄，第三列只有 2 張，它們也只占前兩欄、跟上面同寬，後面兩格空著。這就是開場第一個要求的答案。

不過這段 CSS 只寫了三行，背後瀏覽器建立了一整套東西：欄、列、格線、格子。後面要讓卡片跨欄、讓卡片裡的元素對齊，都要指名這些東西，所以先把它們認清楚。

display: grid 之後，瀏覽器建立了什麼？

對元素寫 display: grid，它就成為格線容器（grid container），它的直接子元素成為格線項目（grid item）。在首頁的菜單區，.menu 是格線容器，十張 .card 是格線項目。

注意「直接子元素」這幾個字。卡片裡面的品名、描述、價格、按鈕是 .menu 的孫元素，它們不是格線項目，不會被放進 .menu 的格線，仍在卡片裡照正常流由上往下排。這點跟 Flexbox 一樣，也正是開場第二個要求（卡片內容對齊）用一般 Grid 做不到的原因，這課最後會用 subgrid 解決。

容器裡的格線由下面幾樣東西組成。圖上是一個三欄兩列的格線：

名詞意思
格線（grid line）分隔欄與列的線，有編號，從 1 開始；負數從另一端數，-1 是最後一條
軌道（track）兩條相鄰格線之間的一整欄或一整列
格子（cell）一欄與一列交叉的那一格，最小的單位
區域（area）一個或多個相鄰格子組成的矩形，項目可以放進一個區域
gap軌道之間的空隙。跟 Flexbox 的 gap 一樣，只在項目之間，最外圍不會多

格線的編號後面會一直用到：3 欄就有 4 條欄格線，第 1 條在最左、第 4 條在最右，最右那條也可以寫成 -1。要讓本月主打的卡片「從最左到最右」，靠的就是這組編號。

再看列。菜單區的 CSS 只寫了 grid-template-columns，沒有定義任何列，十張卡片卻排成了三列。原因是項目依 DOM 順序一格一格往右填，一列填滿就換下一列，不夠的列由瀏覽器自動長出來。寫在 template 裡的軌道叫顯式格線（explicit grid）；沒有寫、自動長出來的軌道叫隱式格線（implicit grid）。隱式的列有多高由 grid-auto-rows 決定，預設是 auto，也就是由那一列的內容高度決定。

如果想讓只有一行描述的卡片也不要太扁，可以給隱式列一個最小高度：

.menu {
  display: grid;
  grid-template-columns: repeat(4, 1fr);  /* 顯式：4 欄 */
  grid-auto-rows: minmax(120px, auto);    /* 隱式的每一列：至少 120px，內容多就長高 */
  gap: 16px;
}

這種「只定義欄、列自動長」的寫法是卡片格線最常見的形狀：卡片數量由後台決定，你不知道會有幾列，也不需要知道。

同一列的卡片還會自動一樣高。格線項目預設會被拉伸，填滿它所在的那一列，而那一列的高度由列裡最高的卡片決定，所以同一列的卡片高度自然一致，不用設 height（預設值的細節見課末）。

到這裡開場的第一個要求已經解決，但 repeat(4, 1fr) 留下兩個問題：1fr 到底是多寬，為什麼不寫 25%？欄數寫死成 4，手機上怎麼辦？下一節先回答第一個。

1fr 到底多寬？為什麼不寫 25%？

先看為什麼不寫 25%。四欄各 25% 加起來剛好是容器內容寬的 100%，也就是 1232px，但三個 gap 還要再占 48px，總共 1280px，比容器寬 48px，最右邊的卡片會超出去。百分比是照容器的寬算的，不會先扣掉 gap。

fr 就是為了這件事設計的單位。fr 是 fraction（份數）：瀏覽器先把固定大小的軌道和所有 gap 從容器寬度扣掉，剩下的空間再按 fr 的比例分。菜單區的 repeat(4, 1fr) 在 1232px 寬時，先扣 3 個 gap 共 48px，剩下 1184px 分成 4 份，每欄 296px，加起來剛好填滿、不會超出。repeat(4, 1fr) 只是 1fr 1fr 1fr 1fr 的簡寫。

fr 也能跟固定寬度混用。例如左邊主內容、右邊 240px 側欄寫 1fr 240px：240px 和 gap 先扣，剩下的全部給主內容。寫 1fr 2fr 則是剩餘空間按 1：2 分。

第三個常用的工具是 minmax(min, max)，它讓一條軌道有上下限：minmax(200px, 1fr) 是「至少 200px，有剩餘空間就跟其他 1fr 一起分」。下一節做「放得下幾張就放幾張」時，靠的就是它。其他可用的軌道值（auto、min-content、max-content）整理在課末的表，用到再查。

1fr 會被內容撐開

理解 minmax 之後，可以看一個上線後才會出現的問題。首頁的卡片描述是店長在後台填的。某天店長在一張卡片的描述裡貼了一整串外送平台的網址，那一欄突然比其他欄寬，整頁還開始橫向捲動。

原因是單獨寫 1fr 時，它其實是 minmax(auto, 1fr)：上限是分剩餘空間，下限是 auto，也就是項目的最小內容寬度。第 7 課講過 min-content：內容換行換到不能再換時的寬度，這裡的最小內容寬度指的就是它。一串沒有空白的網址不能換行，它多長，這欄的下限就多寬。這跟第 8 課 flex 項目預設 min-width: auto 是同一件事：軌道不會縮到比裡面最長的那個不能換行的東西還窄。

修法是把下限改成 0，讓欄寬固定是平分的結果，再讓內容在欄裡自己處理：

.menu {
  display: grid;
  grid-template-columns: repeat(4, 1fr);             /* 描述裡有長網址的那欄會撐寬 */
  grid-template-columns: repeat(4, minmax(0, 1fr));  /* 下限改成 0：四欄固定平分，長網址留在欄裡 */
}

改成 minmax(0, 1fr) 之後，長內容會在欄裡溢出，接著依內容種類處理：<pre>、表格加 overflow-x: auto 讓它自己捲動，網址用第 7 課的 overflow-wrap: anywhere 拆開。另一個寫法是對項目本身設 min-width: 0，效果一樣。內容都是短文字的欄不需要特別處理；放使用者輸入、程式碼、表格的欄才需要。

💡 實務上：會放使用者內容的欄，上線前用「最長的資料」測一次
這個問題很少在設計稿上出現，因為設計稿用的是剛好的假文字，通常是上線後客服回報「整頁可以左右滑」。首頁的卡片描述、咖啡店後台訂單詳細頁的顧客備註，都是別人輸入的內容。資深工程師做兩欄以上的版面時，會先問「這欄會放什麼內容、誰輸入的」：寫死的短文字不用管，使用者輸入、程式碼、表格、網址就先加 minmax(0, 1fr) 和對應的捲動或換行。測試資料也會刻意放一筆超長的，而不是只用設計稿上的假文字。

欄寬算清楚了，但欄數還寫死在 4。手機寬 320px，扣掉 padding 內容剩 272px，四欄每欄只剩 (272 − 48) ÷ 4 = 56px，連品名都放不下。設計要的是「桌機四張、平板兩張、手機一張」。

不寫 media query，欄數怎麼跟著寬度變？

直覺的做法是寫兩個 @media，在不同寬度換成 2 欄、4 欄。但設計稿真正的規格其實是「卡片最小 280px，放得下幾張就放幾張」，四、二、一只是這個規格在三種螢幕上的結果。Grid 可以直接表達這個規格：把 repeat() 的次數從固定的 4 換成 auto-fill，欄寬用上一節的 minmax()：

.menu {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
  gap: 16px;
}

瀏覽器分兩步算。第一步，把每欄當成最小值 280px，連 gap 一起算出容器放得下幾欄；第二步，決定欄數之後，用 1fr 把剩下的空間平分給這些欄。拿首頁的三種寬度驗算：

  • 桌機，內容寬 1232px：5 欄要 5 × 280 + 4 × 16 = 1464，太寬；4 欄要 4 × 280 + 3 × 16 = 1168，放得下。所以 4 欄，每欄 (1232 − 48) ÷ 4 = 296px。
  • 平板 768px，內容寬 720px：3 欄要 3 × 280 + 2 × 16 = 872，太寬；2 欄要 576，放得下。所以 2 欄，每欄 (720 − 16) ÷ 2 = 352px。
  • 手機 320px，內容寬 272px：連 1 欄 280px 都放不下。

前兩種寬度都對了，而且完全沒寫 media query：容器變窄，欄數自動變少。第三種寬度出了問題，下面就處理它。

手機上的陷阱：下限比容器還寬

minmax(280px, 1fr) 的 280px 是硬下限。auto-fill 至少會產生 1 欄，這 1 欄不能比 280px 窄，於是卡片比 272px 的容器寬 8px，整頁可以左右滑。這也違反第 7 課提過的 WCAG 1.4.10 Reflow：內容在窄螢幕上不該需要橫向捲動。

要的效果是「容器夠寬時下限是 280px，容器比 280px 窄時下限就是容器寬」，寫成：

grid-template-columns: repeat(auto-fill, minmax(min(280px, 100%), 1fr));

min(280px, 100%) 取兩者較小的：容器夠寬時是 280px，容器只有 272px 時是 100%（272px），一張卡片剛好撐滿。min() 這類比較函式在第 13 課會完整介紹，這裡記住這個固定寫法即可。這一行就是菜單區最後的版本，桌機、平板、手機都正確。

回頭看上一節的長網址：這裡的下限已經是固定值 min(280px, 100%)，不再是 auto，所以不需要再寫 minmax(0, …)，長網址也不會把欄撐寬。但網址仍然比卡片寬，會溢出卡片外，所以卡片描述還是要加 overflow-wrap: anywhere。

auto-fill 與 auto-fit 的差別

你在別的專案裡可能看過 auto-fit。兩者算出的欄數一樣，只差在「項目太少、填不滿一列」的時候。假設首頁之後要加一個「季節限定」分類，容器放得下 4 欄，但這個分類只有 2 項商品：

auto-fill 保留那兩個空欄，兩張卡片維持一欄的寬度；auto-fit 把沒有項目的欄收合成 0 寬，1fr 的欄就分到那些空間，兩張卡片各占一半。

怎麼選：菜單、商品列表這種「卡片寬度要一致」的用 auto-fill，不管有幾項都維持同樣大小；想讓少量項目撐滿整列（例如首頁只有 2～3 個促銷方塊）用 auto-fit。不確定時選 auto-fill，只有 1 項商品時不會出現一張超寬的卡片。

💡 實務上：auto-fill 的欄數是瀏覽器算的，先跟設計對齊期待
商品列表、後台的統計卡片、文章列表，大多用這一行就夠了，比用 media query 在每個螢幕寬度各寫一次欄數好維護。要注意的是欄數由容器寬度決定，不會剛好是設計稿上的「桌機 4、平板 2、手機 1」：某些寬度可能是 3 欄，側欄展開或收起時欄數也會跟著變。動手前先跟設計確認「每張卡片最小多寬」才是規格，而不是固定欄數；如果設計真的要求每個寬度都是指定欄數（例如報表要對齊列印格式），就改用 repeat(4, 1fr) 配 media query，不要硬湊 minmax 的數字。

菜單區完成了，但它只是首頁的一塊。設計稿上，菜單區的上面還有頁首和主打大圖，右邊有門市資訊側欄，下面有頁尾，這些區塊本身也要排版，而且手機和桌機的排法不一樣。

菜單區外面的整頁版面怎麼排？

主視覺是首頁最上面那張大圖橫幅，業界常叫 hero。把設計稿的整頁版面寫清楚：手機上由上而下是頁首、主視覺、菜單、門市資訊、頁尾；桌機上頁首、主視覺、頁尾都占滿整列，中間菜單在左，門市資訊在右，是 20rem 寬的側欄。rem 是以根元素字級為準的單位，預設字級 16px 時 20rem 就是 320px。

這次的區塊數量固定、每塊都有名字，跟菜單區「數量不定的卡片自動往下排」不一樣。Grid 為這種版面提供了 grid-template-areas：在容器上用字串把版面的形狀「畫」出來，每個區塊再用名字放進去。

body {
  display: grid;
  gap: 16px;
  grid-template-areas:          /* 手機（預設）：一欄 */
    "header"
    "hero"
    "menu"
    "store"
    "footer";
}
.site-header { grid-area: header; }
.hero        { grid-area: hero; }
.menu        { grid-area: menu; }
.store       { grid-area: store; }
.site-footer { grid-area: footer; }

@media (min-width: 48rem) {     /* 768px 以上：兩欄 */
  body {
    grid-template-columns: 1fr 20rem;
    grid-template-areas:
      "header header"
      "hero   hero"
      "menu   store"
      "footer footer";
  }
}

讀這段 CSS 的方法：每個字串是一列，字串裡用空白分開的每個名字是一格。桌機版的 "header header" 表示頁首占了這一列的兩格，也就是跨整列；"menu store" 表示這一列左格放菜單、右格放門市資訊，右格的寬度由 grid-template-columns 的 20rem 決定。每個區塊用 grid-area: 名字 放進同名的區域，名字是自己取的，不需要跟 class 或標籤一樣。

畫的時候有幾條規則，違反任何一條，整個 grid-template-areas 都會失效，瀏覽器直接忽略它，DevTools 會在那一行畫刪除線，版面退回一欄：

  • 每一列的格數要一樣。桌機版每個字串都是兩個名字。
  • 同一個名字出現在好幾格，就是一個跨多格的區域；區域一定要是矩形，L 形是無效的。
  • 不放東西的格子寫 .（一個或連續多個點都可以），不能留空。

這種寫法的好處是可讀：看 CSS 就看得到版面的形狀，換版面只改容器的一個屬性，五個區塊的 CSS 不用動。這裡先寫手機版、再用 @media (min-width: 48rem) 為寬螢幕加規則，這種順序叫 mobile-first，第 11 課會詳細講斷點怎麼選。

畫面順序要跟 DOM 順序一致

grid-template-areas 讓你可以把任何元素放到畫面任何位置，例如把 HTML 裡排在後面的門市側欄畫到最左邊。這很方便，也很危險：鍵盤的 Tab 順序和螢幕閱讀器的朗讀順序一律照 DOM 順序，不管畫面怎麼排。

假設設計改成側欄在左、菜單在右，你只改了 CSS。看得到畫面的鍵盤使用者按 Tab，焦點會先跳到右邊的菜單，再跳回左邊的側欄，畫面上看起來是亂跳。這違反第 5 課提過的 WCAG 2.4.3 焦點順序。另一條相關的是 WCAG 1.3.2 有意義的順序（Meaningful Sequence），屬於 A 級：順序會影響意思的內容，程式讀到的順序要跟畫面呈現的一致。螢幕閱讀器使用者聽到的是 DOM 順序，看畫面的人看到的是 CSS 順序，兩者不一致時，同一頁就有兩種讀法。

原則是：先把 DOM 排成合理的閱讀順序，再讓各寬度的版面都依這個順序由上而下、由左而右擺放。首頁的 DOM 是 header、hero、menu、store、footer，桌機版 menu 在左、store 在右，順序沒變，所以上面的寫法是安全的。如果設計堅持側欄要在左邊，正確的做法是跟設計討論，或是改 DOM 順序（側欄的內容在閱讀上真的比較前面時），不是只用 CSS 搬。

自己檢查的方法：打開頁面，不用滑鼠，從頭按 Tab 走一遍，看焦點是不是一路由上往下、由左往右移動。用 order（第 8 課）、grid-area、grid-row 把元素換到別的位置時，都要這樣走一次。

整頁的骨架完成了，回到菜單區。設計稿上第一張卡片是「本月主打」，要比其他卡片大，橫跨整列。整頁版面能用區域名字，是因為區塊數量固定；菜單區的欄數是 auto-fill 算出來的，桌機 4 欄、手機 1 欄，沒辦法先畫好一張固定的區域圖。這時要用另一種方式指定位置。

本月主打的卡片怎麼跨整列？

到目前為止，菜單區的卡片都沒有指定位置，是瀏覽器幫它們找格子。這叫自動放置（auto-placement）：依 DOM 順序，一格一格往後找空格，一列滿了就換下一列。要讓某個項目佔更多格，就用第二節的格線編號或 span 告訴瀏覽器：

寫法意思
grid-column: 1 / -1從第 1 條欄格線到最後一條：跨整列。欄數是 auto-fill 算出來的也有效（只要有顯式格線）
grid-column: span 2從自動放置的位置開始，往後跨 2 欄
grid-column: 2 / 4從第 2 條欄格線到第 4 條，也就是第 2、3 欄
grid-row: span 4往下跨 4 列（下一節的 subgrid 會用到）

本月主打要跨整列，但整列有幾欄要看螢幕寬度。1 / -1 剛好不用知道欄數：從最左的第 1 條格線，到最右、倒數第 1 條格線。auto-fill 在桌機算出 4 欄時它跨 4 欄，手機 1 欄時它跨 1 欄：

.card.featured {
  grid-column: 1 / -1;
}

跨欄有個副作用：可能留下洞。假設改成第三張卡片要 span 2，而它到的時候這一列只剩 1 欄，放不下，它就換到下一列，原本那一格空著。grid-auto-flow: dense 會讓後面的小項目回頭補洞，畫面比較整齊，但代價是畫面順序不再是 DOM 順序：第 5 張卡片可能出現在第 4 張前面，上一節講的焦點順序問題又回來了。商品、文章這種有閱讀順序的內容不要用 dense；只有順序無所謂的內容（例如照片牆）才考慮。

跨欄解決了主打卡片。表格最後一行的 grid-row: span 4 還沒用到，它是開場第二個要求的關鍵：讓卡片裡的品名、描述、價格、按鈕對齊。

卡片裡的價格和按鈕，怎麼跨卡片對齊？

看菜單區的實際畫面。每張卡片裡有品名、描述、價格、加入購物車按鈕；品名有的一行有的兩行，描述長短不一，結果同一列的卡片，價格高低不齊，按鈕也沒有對齊。

原因在第二節說過：只有直接子元素是格線項目。卡片是 .menu 的格線項目，所以卡片之間是對齊的；卡片裡的品名、價格是孫元素，不在 .menu 的格線上，每張卡片各排各的。描述多一行，下面的價格就往下推一行，隔壁卡片不會知道。

不用新工具的話，常見的替代做法都有缺點。把卡片改成 flex column、按鈕加 margin-top: auto，只能把按鈕推到卡片底部，價格還是不齊。給描述固定 height 或估一個 min-height，文案一改、使用者把字放大、換成英文版，描述就溢出或留下一大片空白。問題的根源是每張卡片的「描述那一列」各自決定高度，需要的是讓所有卡片的描述共用同一列。

subgrid 做的就是這件事。對一個格線項目寫 subgrid，它自己也變成格線容器，但不建立新的軌道，直接沿用父格線上它所跨過的那幾條軌道。讓每張卡片在 .menu 裡往下跨 4 列，卡片內的 4 個元素就各放進其中一列。這 4 列是 .menu 的列，同一排卡片共用：描述那一列的高度，由這一排描述最長的那張卡片決定，所有卡片的價格自然落在同一條線上。

.menu {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(280px, 100%), 1fr));
  gap: 16px;
}
.card {
  display: grid;
  grid-row: span 4;                 /* ① 卡片在外層跨 4 列（品名、描述、價格、按鈕） */
  grid-template-rows: subgrid;      /* ② 這 4 列直接用外層的，不自己建 */
  row-gap: 8px;                     /* ③ 卡片內的間距；不寫會沿用外層的 16px */
  padding: 16px;
}

① 的 span 4 決定卡片在外層占幾列，4 要等於卡片裡的子元素數量，每個子元素才有自己的一列。少寫的話，多出來的子元素沒有自己的軌道，會擠進最後一列，跟原本在那一列的元素疊在一起；完全沒寫 span，卡片只占一列，4 個元素全部疊在同一格裡。

② 的 grid-template-rows: subgrid 讓卡片的列直接用外層的那 4 列。③ 的 row-gap 是因為 subgrid 預設也沿用父格線的 gap：不寫的話，品名和描述之間會隔 16px，比設計的卡片內間距大。這裡只覆寫卡片裡面的間距，外層一排卡片和下一排卡片之間，用的仍是 .menu 的 16px，不受影響。

你可能會擔心外層的列數：.menu 只定義了欄，沒有定義列。不用擔心，這些列都是第二節講的隱式格線，十張卡片、每張 4 列，瀏覽器自動長出需要的列。手機上一欄時，每張卡片佔 4 列、依序往下排，一樣正確。

最後，按鈕會自動貼在卡片底部：卡片的高度剛好是 4 列的總和，最後一列放的就是按鈕。開場的兩個要求到這裡都做完了。subgrid 也能用在欄（grid-template-columns: subgrid），瀏覽器支援度與 DevTools 怎麼看 subgrid 見課末。

💡 實務上：subgrid 的卡片要固定結構，元素不能時有時無
商品卡片的內容通常來自後台或 API，品名長短、描述有沒有填都不一定，這正是 subgrid 派上用場的地方。最常見的坑是「沒填描述就不輸出那個 <p>」：卡片只剩 3 個元素，價格跑到描述那一列，跟隔壁卡片對不齊。做法是讓每張卡片都輸出同樣的元素（沒有描述就放一個空的 <p>）。之後要在卡片裡加「新品」標籤這類元素時，也要記得同時改 span 的數字。做成共用元件時，在元件說明寫清楚「要放在外層 Grid 裡、固定 N 列」，別人放進輪播或側欄時才知道要怎麼用。

整個首頁從卡片格線、整頁骨架到卡片內容都用 Grid 做完了。但首頁也有第 8 課用 Flexbox 做的地方，例如頁首的 logo 和選單。接到下一個版面時，該怎麼判斷用哪一個？

回頭看首頁：哪裡用 Flexbox、哪裡用 Grid？

兩者不是誰取代誰。判斷時問一個問題：大小由內容決定，還是由版面決定？

頁首的 logo、選單、購物車，每個項目多寬由它自己的文字決定，排成一行就好，不需要跟別的列對齊，這是 Flexbox 的工作。菜單區的卡片剛好相反：卡片多寬由「欄」決定，跟裡面的文字無關，而且每一列都要對齊同一組欄，這是 Grid 的工作。這課開場遇到的問題，正是用「內容決定大小」的工具去做「版面決定大小」的事。把首頁和常見的元件照這個問題分一遍：

情況用原因
頁首的 logo、選單、按鈕排成一列Flexbox一維；每個項目多寬由內容決定
口味標籤、篩選按鈕自動換行Flexbox每個標籤寬度不同，換行後不需要上下對齊
商品卡片格線Grid二維；所有卡片同寬，最後一列也要對齊
整頁版面（頁首、主內容、側欄、頁尾）Grid先決定區域，再把內容放進去；換版面只改容器
卡片內容跨卡片對齊Grid＋subgrid巢狀元素要對齊到同一組格線
表單：label 與輸入框兩欄對齊Gridlabel 欄寬由最長的 label 決定（max-content 1fr）

兩者常常一起用：Grid 排卡片，卡片裡的按鈕列（加入購物車、收藏）用 Flexbox 排在一起。寫的過程中也有判斷訊號：發現自己在 flex 項目上寫 width: 25%、calc((100% - 48px) / 4) 來湊對齊，就是在用 Flexbox 模擬欄，該換成 Grid；發現自己在 grid 上寫了一堆 auto 欄只為了把東西排成一列，Flexbox 比較直接。

下面的練習把這課的三段工作各做一次：菜單卡片格線、首頁的整頁版面、用 subgrid 對齊卡片內容。

補充與查表

主線用不到、但寫版面或查問題時會用到的細節。

軌道大小的所有寫法（查表用，不用背）

值意思例子
240px固定寬度側欄固定 240px
25%容器內容寬的 25%。不扣 gap，4 × 25% 再加 gap 就超出容器少用，用 fr 取代
1frfr（fraction）：把扣掉固定軌道與 gap 之後的剩餘空間按比例分。1fr 2fr 是 1：2主欄 1fr 配 240px 側欄
auto依內容決定，有剩餘空間時可以被拉伸按鈕欄、標籤欄
min-content／max-content內容最窄（最長的字）／完全不換行的寬度，第 7 課教過價格欄 max-content

repeat() 裡也可以放多個值：repeat(2, 200px 1fr) 等於 200px 1fr 200px 1fr。

同一列為什麼自動等高

格線項目在列方向的對齊由 align-items 決定，它的預設值是 normal，對一般的區塊元素效果就是 stretch：項目被拉伸到填滿整列的高度。所以同一列的卡片高度一致；如果對容器寫 align-items: start，卡片就會回到各自內容的高度。

subgrid 用在欄

欄也可以用 subgrid（grid-template-columns: subgrid），用在「表單的 label 欄要跨區塊對齊」這類情況：每個區塊沿用外層的欄，所有區塊的 label 欄寬一致。

支援度

subgrid 在 2026-03-15 成為 Baseline widely available（web-features 3.44.0），Grid 本身是 2020 年。現在可以直接用，不用寫備用方案。

用 DevTools 看格線

在 Chrome DevTools 的 Elements 面板，格線容器旁邊有一個 grid 標籤（subgrid 是 subgrid），點下去頁面上會畫出格線與編號、區域名稱。版面不對時先打開它看項目落在哪一格，第 18 課會完整介紹。

練習

練習 1：排菜單卡片格線。起始 CSS 已設定 body 的 margin 為 0、.menu 的 padding 為 24px，所以 320px 寬時內容只剩 272px。要求：卡片最小 280px、可以伸展平分整列；320px 寬時一欄且不溢出；1280px 寬時一列 4 張；卡片間距 16px；最後一列的卡片跟其他列一樣寬。不能用 media query。HTML 不能改。

練習 2：用 grid-template-areas 排首頁。區域名稱用 header、hero、menu、store、footer。手機（小於 48rem）一欄，由上而下是 header、hero、menu、store、footer；48rem（768px）以上，header、hero、footer 跨整列，menu 在左、store 是右邊 20rem 寬的側欄，區域之間 16px。DOM 順序已經是合理的閱讀順序，HTML 不能改；每個寬度的畫面順序都要跟 DOM 順序一致（由上而下、由左而右）。

練習 3：三張卡片的品名與描述長度不同，價格和按鈕高高低低。用 subgrid 讓所有卡片的品名、描述、價格、按鈕各自對齊在同一條水平線上，按鈕貼在卡片底部，卡片內的間距 8px。不能給任何內容設固定高度。外層 .cards 的格線已經寫好，HTML 不能改。

練習 4：grid-template-columns: repeat(auto-fill, minmax(240px, 1fr)) 放在內容只有 200px 寬的容器裡，會怎樣？

✓ b：minmax 的最小值是硬下限，放不下時 auto-fill 仍至少產生 1 欄，這一欄就是 240px。改成 minmax(min(240px, 100%), 1fr)，容器比 240px 窄時下限就變成容器寬。a 錯：只有寫了 min(…, 100%) 才會縮。c 錯：不會少於 1 欄。d 錯：auto-fill 與 auto-fit 只差在空欄要不要收合，跟溢出無關。

練習 5：repeat(auto-fill, …) 和 repeat(auto-fit, …) 什麼時候看得出差別？

✓ b：兩者算出的欄數一樣；auto-fit 在放好項目後把沒有項目的欄當成 0 寬，1fr 的欄就分到那些空間。項目夠多、每一欄都有東西時，結果完全相同，所以 a 只在這種情況下成立。c、d 跟這個差別無關。

練習 6：什麼時候該用 subgrid？

✓ b：只有直接子元素是格線項目，卡片裡的元素原本各排各的；subgrid 讓卡片沿用外層的軌道，同一列的高度由所有卡片共同決定，內容才對得齊。a 是 CSS 繼承，跟格線無關。c：一維、內容決定寬度的頁首用 Flexbox。d：表格資料用 <table>（第 3 課），subgrid 用在任何需要跨元件對齊的版面。

常見錯誤

  • 用 Flexbox 做二維卡片格線：每一列各自分配空間，最後一列被拉寬。卡片格線用 Grid，欄由容器決定。
  • 用百分比排欄：25% 25% 25% 25% 加上 gap 一定超出容器。用 fr，gap 會先扣掉。
  • 1fr 被長內容撐開：單獨的 1fr 是 minmax(auto, 1fr)，不會比最長的不可換行內容窄。放程式碼、網址、表格的欄寫 minmax(0, 1fr)，再讓內容自己捲動或換行。
  • minmax(280px, 1fr) 在手機溢出：容器扣掉 padding 後可能比下限還窄。下限寫成 min(280px, 100%)。
  • grid-template-areas 每列格數不同，或區域不是矩形：整個屬性無效，版面突然全部變一欄。在 DevTools 看那一行是不是被畫了刪除線。
  • 用區域、order 或 dense 打亂順序：Tab 與螢幕閱讀器照 DOM 順序走，跟畫面不一致。先把 DOM 排成閱讀順序，版面依這個順序擺。
  • 固定描述高度來對齊卡片：文案一改就溢出或留白。用 subgrid，並記得 grid-row: span N 的 N 要等於卡片裡的元素數。

小結

  • Flexbox 換行後每一列各自分配空間，所以最後一列被拉寬；Grid 先畫好欄，所有列共用。display: grid 只讓直接子元素放進格線，基本單位是格線（有編號，-1 是最後一條）、軌道、格子、區域；沒定義的列自動產生，大小由 grid-auto-rows 決定。
  • fr 分配扣掉固定軌道與 gap 後的剩餘空間，所以不用百分比；1fr 的下限是 auto，會被長內容撐開，需要時改成 minmax(0, 1fr)。
  • repeat(auto-fill, minmax(min(280px, 100%), 1fr))：規格是「卡片最小多寬」，不寫 media query 也會自動換欄，手機上不溢出。auto-fit 只在項目填不滿一列時不同：空欄收合、項目伸展。
  • 區塊固定的整頁版面用 grid-template-areas 畫出來，換版面只改容器；各寬度的畫面順序都要跟 DOM 順序一致。
  • 數量不定的格線用編號放置：grid-column: 1 / -1 跨整列、span N 跨 N 格；dense 會打亂順序，有閱讀順序的內容不用。
  • subgrid：卡片 grid-row: span 4; grid-template-rows: subgrid，卡片內容沿用外層的列，跨卡片對齊；gap 會繼承，自己用 row-gap 覆寫。
  • 大小由內容決定用 Flexbox，由版面決定用 Grid；兩者常一起用。
